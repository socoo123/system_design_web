## 内容与纠错

主线为“资源/成功 → 三夜事务 → HELD所有权 → Redis准入 → 未知提交 → 暂停恢复”。完整假设和九个常见错误移入 details，核心失败分支与代码保持展开。新增七段同源代码，原12张闪卡保留并同步，增加固定回执与迟到收款两张，共14张统一 `cards-grid`。英文与中文同步，不新增重复静态总图或D2。

| 发现/缺口 | 最终处理 |
|---|---|
| 原文将创建重放写成“返回同hold当前态”，与Ch18原创建回执契约不一致 | 固定回放原201/hold_id/HELD/deadline；owner鉴权的GET另查当前态。旧回执不授权再次付款/履约。 |
| 文字说明三夜事务却没有展开身份、库存不足和拒绝回执之间的竞争 | 先认领唯一身份，SAVEPOINT后做所有库存/hold；确定不足只回滚allocation，保留身份同提交REJECTED和outbox。未知异常全回滚，COMMIT未知保持同身份核查。 |
| 房型三夜可用可能被理解为同一物理房间三夜连续可用 | 明确计数池不提供同房承诺；要求全程同房则选择兼容三夜的物理房并占全部房晚。 |
| 汇总reserved不能说明归属；scope或命令可被误用 | 从不可变hold归属查scope，锁后复核同fence，限定CONFIRM/EXPIRE，验证owner/order与完整expected_items及每条scope。终态/逐夜计数/outbox同事务。 |
| 预算容易将500个新token等同全部DB尝试预算 | Lua是固定Redis计时秒的新token上限，边界可突发；外层DB调度器另限含重复/冲突重试的所有创建尝试和硬并发，查询另计。未声称实现全层调度器。 |
| 准入、取消、终态回补只有抽象文字 | 实际单hash Lua核对完整绑定/epoch/version；取消与CREATE争同唯一身份，持久墓碑先关闭迟到写；未知/无所有权不回补。 |
| 原D4两键标签与本次单hash实现分叉；D5F4“只有取消/释放可发终态收据”过窄 | D4F4/F5标签改 `gate:{sku}:e7 · stock + ledger`；D5F4图注区分HELD/CONFIRMED可同步但不加配额，取消/拒绝/释放才恢复。 |
| 大快照一次unpack会达到Lua栈上限，重放安装还可能重置已变动free | 安装器完整验证后ready=0、分块HSET、最终ready=1；同份已开放快照重放只读，未开放同份可继续。epoch独立键与DB recovery_id排除旧控制器。实际5000身份安装通过。 |
| Redis与OrderAPI若共用一个sent位，会把一端ACK当另一端成功 | schema/model实际增加两份 `deliveries(event_id,destination,sent)`；事务外发送、持久ACK后仅标该目的地。各目的地重复仍依赖各自幂等。 |

Ch18只读核对，未修改。库存确认仅接收其验真/不可变订单绑定后的内部命令。RELEASED、EXPIRED_NOT_CONFIRMED或未知结果不等于资金失败，Ch18继续承担真实capture的退款/核对/pending责任，绝不盲目复活库存。

## 交叉复核返修

Ch20作者独立复核发现1项P1：固定计时秒允许边界突发，原文却把`10000/500=20s`称墙钟最短入闸时长。已同步D4F5图内nominal标签、中英图注/正文、500预算闪卡、README与验证标签，改为名义稳态等效时长并明确无该墙钟硬下界。例如每固定秒500个，在t=0.999秒及t=1…19秒各一批，20个桶累计10,000个，首末批只隔18.001秒，足以反证旧下界；这只是算术轨迹，不冒充真实压测。Lua策略、model与schema未变；24组合/116翻帧/7复制、D4两主题全组渲染及390修正帧目视重验通过，关闭结论等待复核者独立重验。

Ch20复核者另发现1项P1：无hold的REJECTED/CANCELLED也路由到hold投影，原SQLite TEXT主键容许NULL并ACK。已改显式REQUEST_TERMINAL/HOLD_STATE，前者仅为有闸请求投Redis，本地仍按原请求身份查询；hold接收器在inbox/ACK前验类型/非空身份/版本/状态，投影PK显式NOT NULL。保留两用户独立库存不足、错路由拒绝、缺失/空身份与错类型不ACK、数据库拒NULL的11项新增检查。model/schema及四段伪代码、正文/README同步；关闭结论由独立复核者重验。

## 文件与关键实现

[示例契约与运行方式](../../examples/ch21/README.md)。页面七段经 `sync.mjs --check` 逐字匹配。

| 代码 | 提供者、输出与失败边界 |
|---|---|
| `create.pseudo` | PG18风格伪代码；DB唯一约束、行锁、SAVEPOINT与事务提供原子性。完整输入意图/请求身份 → 固定创建/拒绝回执；不存在已提交CLAIMED中间态。 |
| `finish.pseudo` | fence共享锁→hold排他锁→有序库存；锁后取DB当前时刻，完整本单所有权转换成CONFIRMED或RELEASED，任一步失败全回滚。 |
| `admit.lua` | 实际Redis7+；一hash读判并以一次HSET扣提示数/存token。只返回准入，不能授权库存成功，脚本错误不是关系事务回滚。 |
| `resolve.pseudo` | 同owner/op/key上的取消墓碑；唯一竞争等旧创建提交/回滚，关闭迟到写后由DB确定收据，空SELECT不是恢复授权。 |
| `receipt.lua` | 实际Redis7+；核对principal/digest/q/epoch与状态版本，无所有权加零次、终态最多一次回补，乱序HELD不倒退，确认不加free。 |
| `recover.pseudo` + `install.lua` | 全部库存转换停写，排空后计入全部HELD/CONFIRMED和仍可重放身份；校验安装摘要后按epoch/recovery_id恢复。安装器20,000身份/4MB上限，超出保持关闭。 |
| `delivery.pseudo` | HOLD_STATE与REQUEST_TERMINAL分型，holdless请求仅投Redis；hold接收器拒绝无身份ACK。两目的地任务/ACK独立，outbox发送后才标当前任务；下游inbox与完整状态投影共事务，旧版本不能覆盖终态。 |

`schema.sql`与`model.py`是Python3标准库SQLite契约模型，不是PG或Java编译示例。`BEGIN IMMEDIATE`串行化全库写者，比正文PG18锁更粗。SQL注入的 `model_now()`只模拟锁内时间；生产PG使用锁后 `clock_timestamp()`。模型的确认绑定/可信准入epoch/外部send-ACK是显式适配契约，不是签名或Redis签发验证。

## 实际代码验证

[120项结果](ch21-code-results.json)逐条记录；[九项命令日志](ch21-checks.txt)与[命令结果](ch21-checks.json)。全部实际运行，无未通过项。

- 三夜正常q=1；q=2第二夜失败、缺失房晚和第一夜后注入异常；完整事务/身份回滚及确定拒绝重放。改变数量/日期/order/policy同key冲突，非正整数/布尔/重复资源/空明细拒绝。
- 16个真实SQLite线程同时争最后一份仅一个成功；12个同身份请求只有一hold和同回执。COMMIT成功后模拟丢ACK，查询/重放原回执而不取消。
- 旧CREATE持未提交身份时，另线程取消确实等待；旧提交后解析出原HELD。取消先提交则迟到CREATE只回放墓碑。跨owner同文本key独立，不可通过变body取消。
- 截止等号拒绝确认、到期释放；确认先赢不再到期回补。A释放、B重新占用后，重复释放/迟到确认A都不动B归属。错误owner/order/kind、缺失明细拒绝；释放第一夜后故障使状态、全部计数、事件同时回滚。
- 实际Redis7.2.5的准入/收据/安装器：24客户端争最后准入仅一胜，同身份不二扣、量变冲突、无TTL丢账本、错owner不恢复、终态乱序和ACK丢失重放、无token不造配额、confirmed不恢复、固定秒500与回拨不重开桶。实际“先HSET后脚本报错”负例保留写入，验证不回滚。
- 安装5000个终态身份跨越单次unpack容量；未开放部分基线拒绝准入后安全完成，已开放同份安装重放不重置free，不同基线拒绝。
- 一份SQLite权威快照含过期未释放HELD、CONFIRMED、RELEASED、REJECTED、CANCELLED；pause同时挡创建/确认/释放，实装e8并检查安装ACK后resume；旧e7创建和当前闸上的旧收据被挡，原e7的活跃hold释放发e8事件、仅加一次。旧控制器不能恢复新暂停。
- 独立下游DB执行inbox+投影回滚、ACK丢失去重、旧版本不覆盖和同event换body冲突。实际relay发送后崩溃保留pending，重发同event后只标OrderAPI目的地，Redis未ACK任务仍pending。
- 自设算式独立复算：约2.700617/s、18,250,000库存行、2.5倍入口差额、750<800预算、平均在途10、名义稳态等效20秒（非固定窗墙钟硬下界）、最多300次竞争尝试。
