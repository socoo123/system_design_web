30 秒开场：统一入口，保留不同后端的约束 Opening: one entry, explicit backend constraints

中文

我设计给聊天后端与内部 Agent 使用的 LLM API 网关。先用租户身份和模型别名固定候选能力，再同时检查入口请求速率、租户累计预算、deployment 的 token 速率与并发。默认对可复用任务做 exact 答案缓存，miss 才经 Adapter 调上游；流事件逐跳返回，usage 按真实 attempt 结算。首响应提交前可按允许名单试一个备用池，提交后故障就终止这条流。语义缓存只对经验证的 FAQ 开启，不默认拿相近问题的旧答案替代新请求。

先问七件事：只调用外部 API 还是混合本地、调用方指定真实模型还是别名、需要文本还是工具/结构化输出、数据允许哪些地域与供应商、是否允许降级、超额是立即拒绝还是独立批处理、是否愿意复用旧答案。回答改变路由和预算，不能把所有客户端都降成同一种便宜模型。教学入口选 POST /v1/chat/completions 与 SSE，这是本题契约，不是“所有 2026 API 都只能用它”。新增其他接口要重新定义事件与 usage。

Ch17 的鉴权、连接治理仍适用；这里增加按 token 的准入和模型契约。Ch29 负责 GPU/KV，Ch30 与 Ch31 负责知识检索。网关转交工具片段但不执行工具动作；一次模型重试也不等于工具副作用安全重试。把职责限制在入口治理，才能用每条故障路径回答何时还允许继续。

English

This gateway serves chat backends and internal agents. Identity and model aliases determine eligible capabilities; admission checks entry rate, tenant budget, deployment token rate and concurrency. Exact answer reuse is opt-in for reusable tasks; misses invoke an adapter and usage settles by attempt. One allowed fallback is possible before response commitment; later failure terminates the stream. Semantic reuse is limited to validated FAQ routes.

Clarify external/local inference, model selection, text/tools/schema, residency/providers, downgrade permission, rejection versus a separate batch lane, and answer reuse. Our teaching contract uses POST /v1/chat/completions with SSE; it is not a universal requirement for current APIs. Other endpoints require their own event and usage contracts.

Ch17 supplies entry controls, Ch29 inference, and Ch30/Ch31 retrieval. Forwarding tool fragments does not execute or authorize retried tool side effects.

入口闭环：状态留在 Ledger，答案走旁路 Entry loop: durable state and side answer reuse

正常路径与先后顺序 Normal path and ordering

中文

Client 的 POST 先到 Edge，校验凭证、正文大小和入口 RPM；LLM GW 从可信身份取 tenant，再固定请求摘要与路由计划。客户端的 tenant header 和任意 base URL 都不能直接决定权限或上游。网关先判断任务是否允许复用并构造完整键，缓存命中也必须重新授权与记服务用量。miss 再取得租户预算 hold、选具体 deployment 的速率和并发额度，经 Adapter dispatch。输出沿 Backend A → Adapter → LLM GW → Edge → Client 走，每跳都有 deadline、取消和流事件解析。

高层图把同进程的策略藏在 LLM GW 里，把跨进程的依赖画成来回调用。Answer cache 是旁路派生答案，Ledger 是共享权威执行与预算，二者不能合并成一个 Redis key 然后靠过期恢复。可以用同一持久库做 quota 和 execution 的事务，入口短窗口 limiter 则按 Ch04 的算法另做。Ledger 不可用时，对受硬预算约束的新 miss 拒绝准入，不能每个网关进程临时发明一份余额。

English

Edge validates credentials, body limits and entry RPM. LLM GW derives trusted tenant identity, pins a digest/route plan and checks reuse. Hits reauthorize and record service; misses reserve budget and acquire deployment rate/concurrency admission before Adapter dispatch. Output returns Backend A → Adapter → LLM GW → Edge → Client with deadlines, cancellation and parsing at each hop.

The diagram separates in-process policy from remote dependencies. Answer cache is derived data; Ledger is authoritative shared execution/budget state. Use one durable transactional store for quota/execution and separate short-window rate limiting from Ch04. If hard-budget Ledger admission is unavailable, reject new misses.

容量推导：20 QPS 也可能是百万 token Sizing: small QPS, large token volume

中文

按 A1–A3 全 miss 计算：20×60=1,200 次/分钟。输入是1,200×2,000=2,400,000 token/分钟，输出是1,200×400=480,000，合计2,880,000，即2.88M。预算预留则是1,200×(2,000+1,000)=3,600,000，足足比实际均值多720,000。这说明“本月均值花得起”不能证明“本分钟的保守准入放得进”；输出上限瞎设得很大，会在生成之前就挤占别人额度。

输入和输出分开保存，再按版本化单价算费用 I×p_in+O×p_out；缓存输入、隐藏推理、embedding 和失败 attempt 另保留类别。这里不用某天的报价，避免让设计随价目失效。OpenAI 的速率说明同时列请求和 token 限额，失败请求也会消耗窗口；它给出的估算规则并不是本章 quota 的 input+cap 公式。[2] Claude 文档还分 RPM、ITPM 与 OTPM。[4] 统一入口能统一治理，不能把这几种计量强行改成同一个桶。

English

Assuming all misses: 20×60=1,200 RPM, giving 2.4M input and 0.48M output TPM, 2.88M total. Conservative input+cap reservations are 3.6M, 720,000 above actual mean. Affordable average spend does not prove conservative admission capacity; oversized caps reserve capacity before generation.

Store input/output and priced categories separately; cost is I×p_in+O×p_out under a price revision. Supplier limits differ from our quota formula: OpenAI documents request/token limits and unsuccessful-request consumption [2], while Claude separates RPM/ITPM/OTPM [4].

替代方案与网关故障域 Alternatives and gateway failure domains

中文

单一模型的小产品可以先在业务服务里做一个薄适配器，但只要多个团队共享 key，分散的预算、fallback 和缓存规则就容易漂移。抽成网关的代价是又加了一层关键依赖：配置错误、凭证撤销和 Ledger 故障可能同时影响所有模型。部署多份无状态 LLM GW 可以分摊连接，不能把共享配额复制几份。健康检查既看网络是否可达，也看 deployment 的能力、错误类型和剩余容量；探针成功不代表长 prompt 还能准入。

公网入口只列完成设计需要的接口：文本 completion、单独计费的 embedding、授权后可见的 model 别名列表。OpenAI-compatible 不是完整能力证明；vLLM 的公开文档同样列出支持条件和参数差异。[12] Adapter 维护能力矩阵并拒绝不支持的字段，比悄悄丢掉 schema、工具或身份参数更可审计。版本升级先用固定回归请求比对事件和 usage，再改路由计划。

English

A thin business-side adapter can suffice for one model; shared keys across teams favor centralized policy. The gateway adds shared failures: bad configuration, revoked credentials and Ledger loss can affect every model. Replicate stateless gateways without duplicating shared quota. Reachable probes do not prove workload capacity.

Expose only necessary completion, independently accounted embedding and authorized alias listing. Compatibility is not proof of all capabilities: vLLM documents support conditions and differences [12]. Maintain a capability matrix, reject unsupported fields, and regression-test event/usage changes before route upgrades.

路由与降级：先过滤，再问能不能换 Routing and fallback: eligibility before replacement

为什么 model 不是一条任意 URL Why a model alias is not an arbitrary URL

中文

模型别名映射到固定版本的 route plan；候选每个都带真实模型 revision、地域、能力、窗口和限额共享组。先过滤用户是否获准、数据能否出域、tools/JSON/图片等能力是否满足、输入加输出预算能否放进窗口，再在剩下的候选里按健康、延迟与成本排序。A5 的8,000+1,000=9,000，能放入 A 的10,000窗口，却不能落到4,000窗口。不能为了保住200悄悄截前半段历史；调用方若允许摘要压缩，那是另一个显式任务。

计划 p12 固定一次请求的判断条件，部署滚动升级后新请求可用 p13，旧请求仍记录 p12 和实际 served model。降级授权要涵盖具体质量/能力，不能只写“支持 fallback”。要求严格结构化输出的路由可以接受同能力的另一个 deployment，却拒绝小模型；地域限制也不会因为主池超时就自动解除。缓存查到 Backend B 的旧答案时，仍须按同一契约判断是否可复用。

English

Aliases pin a route plan with model revision, residency, capability, context and shared-limit groups. Filter those constraints before health/latency/cost ranking. An 8,000+1,000 budget fits A’s 10,000 context but not a 4,000 candidate; truncation or summarization requires explicit authorization.

Pin p12 for the request and record the actual served model. Downgrade permission must cover capabilities and quality; structured-output or residency constraints remain during failure. Cached B answers face the same eligibility gate.

失败分类与两次调用的成本 Failure classes and a two-attempt budget

中文

没有公开响应头时，上游暂时限流或可恢复故障才进入可重试分支；坏参数、无权限和安全拒绝沿原契约返回，不能用备用模型规避拒绝。请求发出去后的超时是未知执行：原上游可能已生成并收费，只是本地没收到。严格只付一次的任务宁可报 UNKNOWN；允许额外成本的只读生成可记录原 attempt 未决，再预留第二 attempt。所谓“没出首 token 就能换”仍不够，SDK 可能已经向客户端发了200响应头或角色事件。边界必须是公共响应是否提交。

本章最多两次物理调用，原调用加一个 fallback，不再叠一次短重试。所有 SDK/代理重试都计入上限，能关闭则关闭。全请求都走第二次时，20×2=40 dispatch/s；两次都计满预留的短时需求最多7.2M token/分钟，但要按实际分池与共享组核算，不把两个不同限额当成一只大桶。LiteLLM 的 Router 原文确有模型组路由、fallback 和重试设置；我们的两次上限与未知状态是本题约束，不能说成该产品天然提供端到端 exactly-once。[5]

English

Before public headers, eligible transient limits/errors can branch. Bad requests, authorization failures and refusals retain the original contract. Post-dispatch timeout is unknown remote execution: one-charge tasks report UNKNOWN; cost-tolerant read-only generation may reserve a second attempt while retaining the unresolved first. The boundary is public response commitment, not merely first text token.

Cap total physical calls at two, including SDK/proxy retries. Worst-case dispatch is 40/s and two full reservations are up to 7.2M token/min, still accounted per deployment/shared group. LiteLLM documents routing, fallbacks and retries [5]; our bounds do not imply product-wide exactly-once.

deadline、备用余量与拒绝码 Deadlines, spare capacity and rejection

中文

A7 把首响应2秒分成准入0.2、主池等待0.8、切换0.2、备用等待0.7，合计1.9秒、只留0.1秒。这是预算，网络抖动和排队都消耗它；fallback 再套一份2秒就破坏了总 deadline。可恢复429若带 Retry-After，要看剩余时间是否容得下，容不下便拒绝；故障时随机退避、短熔断冷却和探测恢复防止所有客户端同时重打。两个 provider key 若实际共用组织级限额，换 key 不增加容量。

入口租户速率不足用明确的429；累计额度耗尽用稳定的 quota_exhausted 错误分类，状态码由本服务契约固定，不能把所有厂商都说成402。没有合格后端才在提交前503；Retry-After 只在有合理等待建议时给，不保证该时刻就有模型。离线批处理可以独立做有界持久队列和到期取消，交互聊天不为过载排无界队列。备用池必须预留正常流量加故障转入的幸存容量，本地引擎也需要同样的能力与压测证据。

English

The two-second first-response proposal sums to 1.9 s with 0.1 s headroom. Queueing and network jitter spend it; fallback cannot reset the deadline. Honor Retry-After only within the remaining budget, use jitter/cooldowns, and do not treat keys sharing an organization limit as new capacity.

Classify entry rate rejection as 429, cumulative exhaustion as a stable quota_exhausted contract, and no eligible backend as precommit 503. Retry-After is a wait suggestion, not a capacity guarantee. Separate bounded persistent batch queues from chat and benchmark standby survivor capacity.

记账闭环：预留、结算与不知道 Accounting loop: held, settled and unknown

一次预留不等于一次外部执行 One reservation is not one remote execution

中文

Ledger 的主键是 tenant+rid，请求正文摘要不一致就冲突；同一个 rid 正在进行时返回明确的 in_progress，不再调用模型。预算行在事务中检查 limit−settled−held 是否够本次 hold，把 hold、请求状态和幂等结果一起写入。唯一约束阻止两台网关各建一张预留，行锁或条件更新序列化同一租户的余额判断。[9] 单纯先 SELECT 余额再 INSERT 两行，会让并发都看见旧余额。高吞吐时可按租户分区或下发有持久回收规则的份额；当前20/s先保留一个可解释的事务边界。

attempt a1 先落 DISPATCH_INTENT，再交 Adapter 发上游；收到有效 usage 才把该 attempt 结算。网关租约/代次可以阻止旧进程改 Ledger，不能让外部供应商忘掉已执行的请求。崩溃在 intent 和网络之间，恢复者无法仅靠本库区分“未发”和“已生成”。本题禁止盲目重 dispatch；如果供应商明示支持幂等/查结果才使用该能力，否则保留 UNKNOWN。HTTP POST 本身没有可自由自动重试的幂等保证。[8]

English

Use tenant+rid with a body digest; existing work returns in_progress rather than another call. Atomically check available budget and write hold/execution/idempotent result. Unique constraints [9] plus row locking or conditional updates serialize admission; select-then-insert alone races. At 20/s keep a clear transactional boundary before distributing credits.

Persist DISPATCH_INTENT before Adapter dispatch and settle only evidence for that attempt. Owner epochs fence local Ledger changes, not remote execution. Crashes between intent and sending remain UNKNOWN; redispatch requires explicit supplier idempotency/result support. POST alone is not retry-safe [8].

三份账如何结算 How three accounts remain distinct

中文

租户累计 quota 是 settled+held：A3 中先hold3,000，最终input2,000、output400，转settled2,400并释放600。结算事件唯一键(rid,attempt,settlement)与余额变更同事务；尾帧重复到达或者回调重投，只返回已经结算的结果。若输入只是估计，就按最终模板/tokenizer给安全裕量并强制请求大小和输出上限；估少了可以补记费用，却不能补救曾越过的硬预算。不能严格上界时就把quota声明为软预算，或者对最坏输入预留。

短时速率账按入口请求和实际上游 attempt 分开。缓存命中仍消耗入口 RPM，但不 dispatch inference，就不消耗那一次模型调用的供应商额度；语义 embedding 另记。供应商可能按估计值或不同 token 类别限流，本地拿最终usage退租户hold，不意味着供应商窗口也退回来。不要把 Redis 速率预约、DB quota 和供应商账单做成跨库“恰好一次扣款”的承诺；速率预约失败或落盘失败时保守浪费一点瞬时容量，比放出未获准的请求更容易解释。

English

Quota equals settled+held: hold 3,000, settle actual 2,400, release 600. Unique settlement and balance mutation share one transaction. Repeated events reuse the settlement result. Conservative final-input counting and enforced caps are needed for hard budget bounds; later correction cannot undo past overspend.

Entry rate and upstream attempt rate are separate. Hits consume entry RPM but no inference dispatch; embedding has separate accounting. Releasing local quota does not refund supplier rate windows. Conservative loss of temporary admission credit is preferable to claiming a cross-store exactly-once debit.

流尾丢失，恢复谁来负责 Who owns missing stream-tail evidence

中文

OpenAI 的 Chat Completions 流可以请求 include_usage，最后 usage 包可能在中断/取消时收不到。[1] Adapter 不能把空字段转成0，也不能用收到的chunk数量补一个“精确”usage。Claude 的 message_delta 用量是累计值，直接把每次累计output_tokens求和会重复计费。[3] 适配层保存来源、上游请求id、模型revision和计量类别；客户端服务费与供应商实际支出分开，尤其缓存回放和fallback的失败尝试不能假装是同一条免费调用。

客户端取消或网关崩溃后，Reconciler 读取未决 attempt，用支持的请求查询/账单导出核对；图上的报告路径是条件能力，并非所有 API 都能按id查usage。没有精确证据则保留provisional估计和争议状态，按已公布的结算规则处理，而不是定时器到点就把hold退干净。恢复租约允许其他进程接手核账，不允许接手重生成；已活跃的流不迁移到另一网关继续拼接。最终usage晚到仍按同一唯一结算键修正，保留估算到权威结果的审计链。

English

OpenAI Chat Completions can request include_usage, but interruption/cancellation can lose the final usage chunk [1]. Missing is not zero, and chunk count is not exact tokens. Claude message_delta usage is cumulative [3], so summing cumulative counts double-charges. Preserve source, upstream request ID, revision and categories; service billing and supplier spend remain separate.

Reconciler uses supported request/report evidence; not every API offers per-ID usage retrieval. Without evidence retain provisional/disputed accounting under declared rules rather than TTL-refund all holds. Recovery ownership permits reconciliation, not regeneration or live-stream migration. Late authoritative usage amends the same idempotent accounting chain.

exact 答案缓存：条件相等，仍要验证 Exact answers: matching conditions still require validation

完整键与授权的因果关系 Why complete keys and authorization matter

中文

exact 缓存键由canonical全请求、模型/route revision、数据revision、tenant和权限指纹组成。全请求包含system/developer消息、所有历史角色和顺序、tools、tool_choice、response schema、temperature/top_p、输出上限及影响答案的其他字段；不要为了命中率合并字符串空格或删除看似重复的历史。权限指纹可按已批准的共享组构造，个性化路径直接按用户隔离。每次hit仍验证当前权利，权限撤销或策略版本更新使旧条目失去资格；缓存id不可成为绕过授权的凭证。

别名重指向另一模型却只hash别名，会把旧模型答案复用到新契约。固定revision可收住变化；上游若只提供漂移别名而无法固定实际版本，这条路由就保守禁缓存或通过显式generation切断旧命中。fallback生成的答案写明Backend B，只有后续同样允许B质量的请求才能用。temperature=0也不是逐字确定的证明；调用方允许复用某次历史输出，是独立于“模型再次生成必然相同”的产品选择。

English

Canonicalize the full request without erasing meaningful whitespace/history; include model/route/data revisions and tenant/access scope. Request fields cover messages, tools, schema, sampling and caps. Reauthorize every hit; revoked access invalidates eligibility. Personalized paths isolate users, and cache IDs are not permissions.

An alias alone can collide across model changes. Pin revisions or disable reuse for drifting aliases. Cached B outputs require B-eligible quality. Reusing an earlier output is an explicit product choice, independent of deterministic regeneration.

写入条件、流式回放与新鲜度 Publication, streaming replay and freshness

中文

命中前要拿到完整entry状态、served model、创建时间与有效版本，验证成功才交付。stream=true仍返回一致的SSE事件形状：新的交付id、按契约重放delta、正确结束与本次usage元数据。原生成prompt/completion计量留在entry审计字段，本次upstream_usage为零不能冒充客户端也免费；客户端收费规则与cache_hit公开。miss结束后，只有完整终止且通过输出格式/任务验证的答案才SET；错误EOF、取消、半个tool JSON和拒绝片段都不能标COMPLETE。

TTL试60秒是陈旧上界的一部分，不能证明FAQ或外部事实在这分钟不变。数据修订号、提示词revision和授权变化用新键或明确拒绝，已经在传的一条流仍有检查与发送竞争，需要按本产品撤销策略终止，不能宣称瞬时收回已发字节。动态工具结果、实时余额和用户私人内容先bypass；对静态且允许复用的结果才讨论命中率。供应商的prompt caching复用输入前缀计算，[10] 仍然会生成新的输出；它与本节整份答案复用是两层收益。

English

Validate complete state, served model, age and revisions before replay. Stream hits use a new delivery ID, declared delta/terminal/usage semantics and public cache_hit metadata; supplier spend and client pricing differ. Publish only complete, validated results, never error EOF, cancellation or incomplete tool JSON.

A 60-s trial TTL does not prove facts remain fresh. Data/prompt/access revisions invalidate eligibility; revocation still races already-sent bytes. Bypass dynamic/private actions. Supplier prompt caching reuses input-prefix computation [10], rather than this section’s complete answer.

缓存故障不扩大上游授权 Cache failure does not widen origin admission

中文

缓存lookup有独立短超时，失败当miss；生成仍受Ledger和deployment准入。我们估算故意取全miss，20/s都已经有容量去处，就不把不存在的命中收益花两遍。将来业务拿到实测hit率后可以比较正常成本，但备用配额和故障时的拒绝策略仍按cache全失效验收。热门同键可合并生成，但每个观看者独立鉴权，取消一个等待者不能取消其他人仍要的生成；合并复杂性不应在还没证明热键之前进入第一版。

English

Bound cache lookup separately; misses still require Ledger/deployment admission. All-miss sizing avoids spending hypothetical savings twice. Later measured hit rates reduce normal cost but do not replace cache-loss testing. Hot-key coalescing needs per-watcher authorization and independent cancellation, so defer it until measured demand justifies complexity.

语义复用：相似候选通过哪道门 Semantic reuse: the candidate acceptance gate

先冻结硬条件，再只放松一处 Freeze hard fields before approximating one field

中文

语义模式必须显式opt-in，第一版只给固定FAQ。沿用exact的权限、模型、系统、历史、参数和数据namespace，把最后一句用户文本换成向量查询；历史不同就不能跨namespace复用。Embedding服务也收到原始文本，受同样出域许可、输入长度、deadline与预算治理。模型revision变化后旧向量不能继续比较，切换namespace并重建；embedding失败直接走正常生成，不能把失败当作“距离无限小”。

候选entry仍需完整状态、当前授权与新鲜度检查，然后比较任务要求的实体、日期、金额和否定。通用自由文本没有一个规则就能证明两题等价，所以无法验证的路由保持关闭；固定FAQ可绑定同一个已批准问题id与答案revision，再判断改写是否还表达同一意图。工具动作、医疗交易等高风险路径不能把“分数够高”当授权。缓存检索只复用旧答案，没有像RAG那样检索新证据并重新生成，不能借用检索Recall替它证明答对。

English

Opt in fixed FAQ only. Freeze access, model, system/history, parameters and data namespace; vectorize only final-user text. Embedding obeys residency, length, deadline and budget. Embedding changes require a new namespace; dependency failure bypasses reuse.

Check complete state, authorization, freshness and task-specific entities/dates/amounts/negation. General free text lacks a universal equivalence proof, so keep unvalidated routes off. Approved FAQ IDs/revisions can constrain paraphrase reuse; similarity does not authorize actions, and RAG recall does not prove cached-answer correctness.

删除魔法阈值，画出错答 Replace magic thresholds with a wrong-answer example

中文

图中cosine0.96是假设A11的玩具数。“允许取消订单”和“不允许取消订单”可能很接近，用户意图却相反；金额100与1,000、今天与下个月同样如此。阈值提高可以减少近似命中，却不保证漏网反例为零。不要背0.9当行业正确默认：不同embedding、归一化和score语义不共用这个值。Azure的语义缓存策略甚至规定更低的score-threshold代表更高相似要求，并提供vary-by隔离用户/组；它的参数不是本图cosine的大小方向。[11]

验收集应包含真实任务、改写、否定、实体变化、权限不同和知识更新，用相同固定版本先生成或标注可接受答案。参数在调参集上选，冻结验证集单独测；不要一边看错答一边把阈值调到刚好过这一批。观察到零错答只说明有限样本里没发现问题，不能报零风险保证。任何scope泄漏都必须计独立的授权失败，不能和语义错答平均成一个漂亮百分比。

English

Toy cosine 0.96 can join opposing cancellation intent; amounts and dates produce similar hazards. Higher thresholds are not zero-error proofs and score meanings differ. Azure’s score-threshold has the opposite direction from cosine and supports user/group vary-by partitioning [11].

Include paraphrases, negation, entities, access changes and updates under fixed versions. Tune separately from held-out validation; zero observed errors is not a zero-risk guarantee. Report authorization leaks independently rather than dilute them into semantic error averages.

收益必须扣掉 embedding 与错误成本 Savings subtract embedding and error cost

中文

A12的500条查询命中40次，40/500=8%；其中1次错误，1/40=2.5%是命中内错答率。1/500=0.2%是总体错答，两者分母不同。如果任务不接受2.5%的错误复用，这个门就关掉，不能因为92%的请求正常生成把它稀释。每秒20条全部做embedding，而仅8%复用，理想情况下只省1.6次生成/秒，仍有18.4次生成；收益是1.6×单次生成成本减20×embedding成本，再减查cache开销与错误修复代价。这个命中率只是玩具样本，不能代入全站月账单。

上线先按路由小流量与影子对比，分别记合法命中、拒绝原因、错答与依赖时延。影子生成本身也烧token，必须预算。停止开关应能回到exact或全miss路径；新鲜度和授权gate保持一样。相似度带来的收益需要数据证明，图上最关键的一笔是“拒绝后正常生成”，因为这条路径决定错误候选有没有真的伤到用户。

English

The toy set gives 40/500=8% reuse and 1/40=2.5% wrong hits, versus 1/500=0.2% overall. Reject unacceptable conditional error rather than dilute it. At 20/s, 8% ideally saves 1.6 generations/s while requiring 20 embeddings and 18.4 live generations: subtract embedding, lookup and remediation cost. Do not extrapolate the toy rate to monthly billing.

Roll out per route with budgeted shadow generation, separate acceptance/rejection/error metrics and a switch back to exact/all-miss. Preserve freshness/access gates. The rejection-to-generation route determines whether a bad candidate reaches users.

SSE 与恢复：已提交的流如何结束 SSE and recovery: ending a committed stream

事件转换、首响应与不可拼流 Events, first response and no stream splicing

中文

POST的客户端用fetch或SDK读取text/event-stream；原生EventSource的接口不能承载这份POST正文。[7] 网络chunk可能切开UTF-8字符和一个JSON事件，Adapter先做增量解码/事件拼接再转换，不能按一次read当一个token。相同schema透传也要保留完整事件界限；跨协议翻译要映射角色、文本、工具片段、错误、usage与终止。Claude有命名事件和流内error，[3] OpenAI的delta与usage形状不同，缺失的能力要显式拒绝而不是抹成空字符串。

LLM GW在发公共响应头之前先CAS持久COMMITTED标记。CAS到flush之间可能崩溃，这会保守地禁止本来还没发到客户端的请求重试；反过来先发再记，会给恢复者留下“看似未提交、实际已发半条”的危险窗口。任何公开头、角色事件或心跳都算提交，客户端还没看见文字也不能换模型。一旦提交，上游故障只能沿Adapter→LLM GW→Edge→Client回错误事件或异常EOF，不能改成HTTP503、补成功[DONE]或将两家答案连成一句。

English

Use fetch/SDK for POST event-stream responses; native EventSource does not carry this POST body [7]. Incrementally decode UTF-8 and assemble events across network reads. Translate roles, text/tools, errors, usage and termination; Claude named/error events [3] differ from OpenAI chunks.

CAS durable COMMITTED before public headers. A crash before flush conservatively prohibits retry; send-before-record risks reexecution after partial delivery. Headers, roles and heartbeats all commit. Later failure returns a declared error/EOF through every hop, never HTTP 503, successful DONE or spliced model output.

取消、缓冲与连接容量 Cancellation, buffers and connection capacity

中文

Client断开后Edge取消网关请求，网关取消Adapter，再取消Backend A。取消尽力而为：在途计算可能继续一会，已经产生的usage仍要记账。写下游慢时把每流可积压字节封顶64 KiB，读上游受背压约束；如果HTTP库偷偷把后续流全部读进内存，外层buffer上限没有意义。10秒写堵塞就abort，断开客户端并记明确终止原因，不能无限缓存几分钟的输出。心跳只维持连接活性，不证明模型有进度；首响应、总生成、空闲读和写堵塞使用不同deadline。

按A8，首token已在0.5秒出现，后面399个间隔是399/50=7.98秒；总时长0.5+7.98=8.48秒，粗估约8.5秒，每秒20次得到20×8.48=169.6，约170条平均并发。这个除法假设输出类别与速率口径一致，不适用于隐藏推理很多的路由；尾部与故障时实际占用要压测。设200条准入上限时，200×64×1,024=13,107,200 B=12.5 MiB，仅是缓冲，不含TLS、socket、SDK对象和缓存答案。增加网关副本能分摊连接，上游共享并发总额度不能跟着复制；满了在提交前拒绝，慢流结束才释放物理连接额度，UNKNOWN quota另由核账释放。

English

Disconnect cancellation propagates Edge → LLM GW → Adapter → Backend A best effort; in-flight work may still cost tokens. Bound each stream to 64 KiB across libraries, propagate backpressure and abort after ten seconds stalled writes. Heartbeats prove connection liveness, not model progress; distinguish first-response, total, idle-read and blocked-write deadlines.

The first token arrives at 0.5 s; 399 subsequent intervals take 399/50=7.98 s, giving 8.48 s≈8.5 s and 20×8.48=169.6≈170 mean streams. Hidden reasoning and tail/failure occupancy need measurement. 200×64×1,024=13,107,200 B=12.5 MiB bounds buffers only. Gateway replicas share upstream admission; connection release is separate from unresolved quota.

验收与口述收尾 Acceptance and interview close

中文

故障演练至少覆盖：两台网关同rid、余额刚够一个请求时的竞争、intent后崩溃、上游成功回包丢失、尾usage缺失、重复结算、已发头后429、慢客户端、缓存权限撤销、模型revision切换和共享配额同时耗尽。每种都看客户端实际收到什么、attempt是否又dispatch、hold是否仍可追踪、实际费用是否重复。指标分入口请求与上游attempt，记录requested alias、served model、route revision、cache类型、排队/首事件/结束时延和UNKNOWN年龄；默认日志不存完整prompt及凭证，调试采样按任务权限治理。

收尾沿六个末帧说：统一入口后先按能力与权限选池，2.88M实际TPM和3.6M预留分开；Ledger先意图后dispatch，usage落账只结一次，UNKNOWN有恢复者。exact验证完整条件，语义相似只拿候选，拒绝走正常生成；首响应提交前可试允许的备用，提交后只能终止原流。最后170并发是均值、12.5 MiB是buffer边界，备用质量与幸存吞吐都须验证。这些路径讲清之后，再决定是否加入更多后端、队列和复用复杂度。

English

Exercise duplicate rid, concurrent last-budget admission, post-intent crashes, lost successful replies, missing/repeated usage, post-header errors, slow clients, revocation, revisions and shared-capacity failure. Observe actual delivery, dispatch count, traceable holds and charges. Separate entry/attempt metrics and record route/model/reuse/timing/UNKNOWN age without default prompt or credential logging.

Close on the six final frames: capability/access routing; separate 2.88M actual and 3.6M reserved TPM; intent-before-dispatch, one settlement and owned UNKNOWN recovery; validated exact reuse and gated semantic candidates; permitted precommit fallback and terminal postcommit errors. Mean 170 concurrency and a 12.5-MiB buffer bound do not prove quality or survivor throughput.
