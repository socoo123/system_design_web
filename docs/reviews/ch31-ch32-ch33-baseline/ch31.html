30 秒开场：先定搜索的契约 Opening: define the search contract

中文

我设计一套给 RAG 后端调用的向量检索服务。调用方已经算好 embedding；本服务接收向量、k 与 metadata filter，返回 id、version、score 和检索状态。先按原向量、图边与复制预算决定单片结构：热数据放得下就比较 HNSW，内存紧则比较 IVF-PQ 或按 SSD 设计的图索引。过滤由 planner 按允许集规模选路；写入先持久 WAL，能搜到的位点另算。最后用分片切容量、副本撑读与故障，任何候选都带同一模型和权限边界。

澄清七件事：N 与维度、距离/模型版本、峰值与 p95、过滤通过率及向量相关性、流式写与删除频率、写后是否立刻读、租户隔离要求。要求“向量越近越好”还不够：内积越大越好，L2 距离越小越好，cosine 需要一致归一化。返回分数要声明单位与排序方向，否则 coordinator 会把不同片的结果排反。

本章只打开 Ch30 调用的存储引擎，切分、query embedding、BM25 融合、语义 rerank 与答案生成仍由 Ch30 负责。原向量 rescore 是重新计算同一个向量距离，不是让 CrossEncoder 判断文字相关性。算法库能做索引，但在线服务还要承担认证、版本、日志、恢复与查询契约；选一个产品名并不会自动回答这些窗口。

English

This service accepts already-computed vectors from RAG and returns IDs, versions, scores, and search status. Size raw vectors, graph links, and copies before comparing hot-memory HNSW with IVF-PQ or SSD-oriented graphs. A filter planner selects by allowed-set size; WAL durability and search visibility have separate watermarks. Shards divide data, replicas supply reads/failover, and all candidates share model and access scope.

Clarify count/dimension, metric/model revision, peak/p95, predicate acceptance and vector correlation, update/delete rates, read-after-write needs, and tenant isolation. Inner products rank high first, L2 low first, and cosine needs consistent normalization. Define score units/direction before distributed merging.

Ch30 owns chunking, query embeddings, lexical fusion, semantic reranking, and generation. Vector rescoring recomputes the same vector metric rather than CrossEncoder relevance. An indexing library still needs authentication, versions, logging, recovery, and query contracts.

查询闭环：先把谁返回给谁画准 Query loop: return through the owner

正常路径与接口边界 Normal path and API boundary

中文

一次 POST /v1/vectors/search 由 Query svc 认证身份、限定 collection，验证 vector 的维度、有限数值、model_id 与 metric；用户 filter 与服务端 tenant 条件取交集。响应包含 id/version/score、index generation、覆盖分片与 complete 标志，便于上游区分“真没近邻”和“搜索失败”。A2 的 50 ms 包括服务排队、内部网络、搜索与归并，不含上游 embedding；不能只量引擎内循环就宣布达标。

Index replica 搜索自己 pin 的 growing 与 sealed 状态，检查候选的最新可见版本和谓词，必要时取 Vector Store 的原向量重算，然后回 Query svc，再回 Caller。原向量键用 collection/model/id/version，不能用裸 id 取到另一版本的向量。所有片使用一致的距离约定；Faiss 的 L2 返回平方距离，cosine 可映射到归一化后的内积 [2]。对零向量要拒绝或定义专门行为，不能除以零后把 NaN 排进候选。

先看字节：一条 768×4=3,072 B。1M 是 3.072 GB，10M 是 30.72 GB，100M 是 307.2 GB；后者除以 2³⁰ 约 286.1 GiB。按四片均匀切开，每片裸向量 76.8 GB≈71.53 GiB；128 GiB×70%=89.6 GiB，只剩约 18.07 GiB 放图、ID、payload 倒排与其他热态。这个余量是否够，要测对象开销和构建峰值，不能把“裸向量放得下”说成“一台索引副本放得下”。

二副本让原向量热拷贝至少 307.2×2=614.4 GB≈572.2 GiB，不是把数据集扩成两亿条。备份、日志保留、immutable 文件和临时重建不在这个乘法里。相反，如果原向量冷放 SSD，RAM 预算只计热结构与页缓存，就要把查询随机 I/O 放进延迟实验；把 RAM 变小同时继续承诺全热 HNSW 的时延，是把两个方案的好处拼在一起。

为什么要 ANN：假设每次独立读取整份原向量，200×307.2=61,440 GB/s=61.44 TB/s 的逻辑读取。实际批量 GPU 精确距离可共享读取，允许集很小也可以精确扫，所以这不是“精确 kNN 永远不行”的证明；它否决的是本题未经批处理与硬件验证就默认全库扫描。入口还要限制 k、并发与每租户候选预算，避免一个大 k 请求消耗整片的搜索时间。

English

Query svc authenticates POST /v1/vectors/search, constrains collection, and validates dimension, finite values, model, and metric. Intersect user filters with trusted tenant scope. Return ID/version/score, generation, covered shards, and complete status so upstream separates empty matches from failures. A2’s fifty milliseconds includes queuing, internal networking, search, and merging, but excludes embedding.

Each Index replica searches pinned growing/sealed state, checks latest visible versions and predicates, optionally fetches original vectors, and returns through Query svc to Caller. Fetch keys include collection/model/ID/version. Shards agree on scoring: Faiss L2 reports squared distance; normalized inner product supports cosine [2]. Reject or explicitly handle zero vectors instead of producing NaN.

Each vector uses 3,072 B. 1M, 10M, and 100M require 3.072, 30.72, and 307.2 GB respectively; the latter is 286.1 GiB. Four uniform shards need 76.8 GB≈71.53 GiB raw each. A 70% budget on 128 GiB gives 89.6 GiB, leaving about 18.07 GiB for graph, IDs, scalar indexes, and other hot state. Measure object/build overhead before claiming a replica fits.

Two raw copies require at least 614.4 GB≈572.2 GiB rather than doubling logical points. Backups, retained logs, immutable artifacts, and rebuild workspace are additional. Keeping raw vectors on SSD reduces RAM but adds random-I/O latency; validate that alternative separately from a fully hot index.

At independent full scans, 200×307.2 GB=61.44 TB/s logical reads. Batched GPU exact search may share reads, and small allowed sets can be scanned exactly; the calculation rejects an unvalidated default full scan rather than exact kNN in all settings. Cap k, concurrency, and per-tenant candidate work.

HNSW：上层导航，底层保留候选 HNSW: navigate above, explore below

正常路径：图内访问不是跨服务请求 Normal path: graph visits stay inside the replica

中文

第二组是第一组 Index replica 内的算法示意，Search worker 是其执行逻辑。HNSW 把一部分向量放在高层，节点出现在哪一层由随机层级决定，越高越稀疏；查询从入口沿更近的点走，逐层下降，底层扩大候选探索 [3]。图中的 F 在两个层级都表示同一向量，0.8/0.3/0.1 是说明距离下降的玩具值，没有业务阈值含义。上层少走几步并不证明底层一定找到真最近邻。

A4 把 M 定为 16，是邻接规模的起点；ef_construction=128 控制插入时探索候选，ef_search=64 控制查询时保留的搜索候选宽度。k=10 是输出数量。ef_search 一般不应小于 k，但它不等于固定访问次数，更不等于召回百分比；过滤、图质量与距离分布都会改变实际访问量。提高它往往增加工作以改善召回，收益必须在同一负载和截止时间内比较。

邻接预算也要算。用简化的底层最多 2M 个、每 ID 4 B 的槽位模型，每点 2×16×4=128 B，1 亿点约 12.8 GB，每片约 3.2 GB。这只是槽位预算，不含高层边、邻接容器、锁、对齐、版本表和存储引擎的对象开销；Faiss 文档也把图项写成带实现系数的估算 [1]。ID 若需 8 B，该槽位账就翻倍，不能把 12.8 GB 当所有 HNSW 实现的实测占用。

HNSW 能增量插点，仍要定义版本更新：有的库不支持物理删除图节点，Faiss HNSW 就明确限制删除 [1]。在线层可以先把旧版本置为不可返回，再异步重建或压实；旧点当导航桥时只能读邻接，不能进入结果。不同引擎的墓碑与图修复方法不一样，不能把“算法支持增量插入”扩写成“修改删除均免费且没有图退化”。

选择它的代价是大量不连续访问。热图和热向量都在 RAM 时可以少算距离；冷页被换到盘上，同样几十次导航会变成多次随机 I/O。替代方案包括 scalar quantization 减向量热字节、分片减每台状态，或使用专为 SSD 安排搜索访问的图。每次换结构，都重新量 filtered Recall、冷热 p95、建图时间与删除后退化，而不是把 HNSW 的延迟标签复制到下一种索引。

English

The second deck opens Index replica internals; Search worker is execution logic. HNSW uses randomly assigned sparse upper layers, navigates toward closer points, descends, and broadens bottom-layer exploration [3]. F denotes the same vector at both layers. Toy distances 0.8/0.3/0.1 illustrate improvement rather than business cutoffs; reaching a good entry does not prove exact nearest neighbors.

A4 starts M at sixteen, ef_construction at 128, and ef_search at sixty-four. M budgets adjacency; construction width and query frontier width differ from output k=10. ef_search should generally cover k, but neither fixes visits nor guarantees recall. Predicates, graph quality, and geometry affect work. Evaluate increased width under identical load and deadlines.

A simplified base-layer slot budget of 2M four-byte IDs gives 128 B/point, 12.8 GB/100M, and 3.2 GB/shard. This excludes upper layers, containers, locks, alignment, versions, and engine objects. Faiss uses an implementation-dependent graph coefficient [1]. Eight-byte IDs double the slot budget; the estimate is not a universal measured footprint.

Incremental insertion still needs version handling. Faiss HNSW does not support physical vector removal [1]; a service may exclude old versions before rebuilding. Old graph nodes may provide adjacency without becoming results. Tombstones and repair differ across engines; insertion support does not make updates/deletes free or prevent degradation.

Graph exploration makes nonsequential reads. Hot RAM limits distance work; cold pages turn navigation into random I/O. Compare scalar quantization, smaller shards, or SSD-designed graphs, then remeasure filtered recall, hot/cold p95, build time, and deletion degradation.

IVF-PQ：少探 list，距离先在短码上算 IVF-PQ: probe fewer lists and score codes

正常路径与编码账 Normal path and encoding budget

中文

IVF 先用训练过的质心把向量分入 list。查询选择最近的 nprobe 个质心，只在这些 list 中找候选；IVF-Flat 在 list 内比较原向量，IVF-PQ 则比较压缩短码。PQ 把每条向量分成子空间，每段训练 codebook，查询对各 code 算查表距离；在 residual IVF-PQ 中编码的是相对粗质心的残差 [1][4]。这两层分别减少候选数量与候选字节，不能把只压短码的 flat PQ 误称为非全量扫描。

A5 选 m=96，768/96=8 维一段；nbits=8 给每段 256 个 codeword 的表示空间。一条 code 占 96×8/8=96 B，裸向量对短码为 3,072/96=32 倍。再加每点 8 B ID，100M×104=10.4 GB；质心、codebook、list 容器和标量索引另算 [1]。训练共享的 codebook 不是每向量再复制一份；只有把 byte 账按真正的存储布局算，32 倍才不会变成整服务的压缩宣传。

四片均匀时每片 25M 条，平均每 list 为 25,000,000/4,096≈6,103.5 条。探 16 个约扫 97,656.25 个 code，code+ID 约 10.15625 MB/片/查询；四片约 40.625 MB，峰值 200/s 对应约 8.125 GB/s 逻辑短码读取。该估算假设 list 均匀、无过滤剪减，尚未加入质心距离、缓存复用和查表 CPU。一个热点 list 装下远多于平均的向量，会让 nprobe 相同的两次查询耗时完全不同。

粗搜取每片最多 100 个候选，读取 100×3,072=307,200 B 原向量，四片最多 1,228,800 B；200/s 约 245.76 MB/s 的逻辑原向量读取。这仍有离散随机 I/O，不能用顺序带宽证明 p95。读取时匹配 version，重新按原始精度算距离并排序；候选已缺失或过期则按预算补召回。准确 rescore 可以消掉量化后的排序误差，不能补回 nprobe 从没到过的桶。

SQ8 是每维约一字节，100M×768=76.8 GB 原向量编码，约为 float32 的四分之一 [1]；图边并没有随之缩四倍。它的召回损失也不能保证小于某个数字，应和 PQ、原始精度一同测。OPQ 可在 PQ 前学习变换；DiskANN 2019 的设计把压缩导航信息留 RAM、图与高精度访问放 SSD，FreshDiskANN 2021 讨论流式更新 [6][7]。这是不同设计选项，论文的机器配置和语料成绩不能直接换成本题 768 维且带 ACL 的容量承诺。

IVF 的质心与 PQ codebook 依赖训练分布。新语料集中到一个区域时可能出现 list 失衡、量化误差和召回漂移；先按新数据切片测，不是每 insert 都重做 k-means。需要重建时冻结一份训练/数据快照，回放后续 upsert 和 delete，再切 manifest；旧 short code 不能配新 codebook。同一维度但不同 embedding 模型也不是同一空间，要用另一 collection/model generation。

English

IVF assigns vectors to trained coarse lists and probes the nearest nprobe lists. IVF-Flat compares full vectors; IVF-PQ scores compressed subspace codes, often coding residuals to coarse centroids [1][4]. IVF reduces candidate count, PQ reduces bytes. Flat PQ still scans all codes.

A5 splits 768 dimensions into 96 eight-dimensional subspaces. Eight bits represent 256 codewords/subspace; codes use 96 B. Raw/code ratio is 3,072/96=32. Eight-byte IDs bring 100M to 10.4 GB before centroids, shared codebooks, lists, and scalar indexes [1]. Do not repeat shared codebook bytes per point or claim a thirty-twofold whole-service reduction.

At uniform 25M/shard and 4,096 lists, the average is 6,103.5 points/list. Sixteen probes scan about 97,656.25 codes or 10.15625 MB codes/IDs per shard/query. Four shards imply 40.625 MB/query and 8.125 GB/s at 200/s. This logical-read estimate excludes filter savings, centroid scoring, cache reuse, and CPU. List skew changes latency at identical nprobe.

At most 100 raw candidates/shard require 307,200 B; four shards need at most 1,228,800 B/query or 245.76 MB/s at 200/s. Random I/O still matters. Fetch matching versions, recompute exact distances, and refill missing/stale candidates within budget. Rescoring fixes ordering error within the shortlist but cannot retrieve an unprobed list.

SQ8 uses about one byte/dimension: 76.8 GB for 100M, one-quarter of float32 [1]. Graph memory is unchanged and recall losses require measurement. OPQ learns a pre-PQ transform. DiskANN 2019 combines compressed RAM navigation with SSD graph/high-precision access; FreshDiskANN 2021 studies streaming updates [6][7]. Their datasets and machines do not prove this filtered 768-dimensional workload.

New distributions may cause list skew, quantization error, and recall drift. Measure changed slices before rebuilding; insertion does not require rerunning k-means each time. Rebuild a snapshot, replay later upserts/deletes, and publish a manifest. Never mix new codebooks with old codes or same-dimensional embeddings from different models.

过滤：允许返回和允许导航要分清 Filtering: eligibility differs from navigation

从允许集到两条搜索路线 From the allowed set to two search paths

中文

谓词通过率 s 表示集合中符合条件的比例，s 越小，过滤越严。Filter planner 用 payload 倒排、范围索引与 live mask 估允许集，选择精确子集扫或约束图搜索。它必须观察本地片的基数：全局 0.1% 不代表每片相同。统计可能过时，最终候选仍要用同一可读状态的谓词和版本复查；过滤误估只可以造成慢或少，不能变成越租户输出。

pre-filter 不必等于精确扫：先构造 bitset 后也可以把它传给 ANN 搜索。本章把小集合精确扫作为一条明确的路线，A7 的门槛 5,000 对应 15.36 MB 原向量；若在 SSD 上随机读 5,000 条，工作可能比热图更贵。过了这个门槛也不是必选 HNSW：大允许集、相似性很弱的集合，可以换其他 filter-aware 结构，planner 由实际成本与查询截止时间决定。

post-filter 的危险在于候选不足。全库 top-100 若只过 0.1%，独立均匀假设下期望剩 100×0.001=0.1 条；为了期望拿到 10 条，L≈10/0.001=10,000。恰好期望 10 不代表高概率有 10，更不代表 Recall@10 达标。若允许点在向量空间离 query 很远，命中与谓词强相关，这个 k/s 公式也会失效；不能固定把 k 乘十就承诺严过滤召回。

图上 A 与 B 符合谓词，X 不符合。直接把 X 的邻接扩展也砍掉，A 就发现不了 B；结果资格和导航资格不是一件事。有的过滤图实现允许经过不合格点寻找邻居，有的扩充连接或在查询时检查两跳。ACORN-1 的邻居扩展提供一种思路，论文也保留非常小集合的 pre-filter fallback [5]。读取 X 邻接只是内部导航，X 的 ID、payload 与 score 不进入对外结果；该示意既不是任意连通性证明，也不是完整算法实现。

候选集不足可以增加 ef_search/nprobe 或继续扫描，但每次都要尊重租户、live 版本、访问次数和截止时间。pgvector v0.8.0 的迭代扫描展示了搜索后过滤不足时继续扫描以及设置上限的做法 [8]；本服务的 planner 是设计选择，不是宣称 pgvector 用了 ACORN。允许集只有三条时，k=10 可以返回三条并声明集合已尽；预算用尽但允许集更大则声明近似短缺，两者不能都标成“没有更多”。

多租户隔离是返回正确性，不是平均召回指标。身份决定 mandatory tenant 范围，客户端不能自报另一个 tenant；Query svc 和 replica 都检查这项契约。若威胁模型不允许跨租户邻接读取的侧信道，就把租户拆物理索引/collection，代价是小索引数量、运维与碎片。引擎 filter 只处理索引中的权限投影；文档 ACL 变更若另有权威来源，上游仍按 Ch30 复查，不能让一个滞后的 metadata 字符串代替实时授权。

English

Acceptance s is the fraction matching the predicate; smaller s means stronger filtering. Planner estimates local allowed-set cardinality from scalar indexes and live masks, then selects exact subset or constrained graph search. Global selectivity need not hold per shard. Final predicates/versions use coherent readable state; stale statistics may hurt cost/recall but cannot authorize cross-tenant output.

Prefiltering can construct a bitset for ANN rather than force brute force. This design explicitly scans small sets: 5,000 vectors cost 15.36 MB raw, but 5,000 SSD random reads may exceed hot-graph cost. Larger sets need workload-specific filter-aware alternatives and deadline-aware planning.

At independent uniform s=0.001, postfiltering one hundred candidates yields 0.1 match in expectation; expecting ten requires about 10,000 candidates. Expectation is neither high-probability fill nor Recall@10. Correlations between predicates and vector geometry invalidate k/s, so a fixed tenfold oversample cannot guarantee restrictive-query recall.

A/B pass while X fails. Pruning X adjacency prevents discovering B; result eligibility differs from navigation. Implementations can navigate through rejected points, densify links, or inspect two-hop neighbors. ACORN-1 motivates expansion and retains small-set fallback [5]. Reading X adjacency does not expose its ID/payload/score. The schematic is not a universal connectivity proof or complete algorithm.

Refill may raise ef_search/nprobe or continue scanning under unchanged tenant/live constraints and work/deadline caps. pgvector v0.8.0 illustrates capped iterative scans after post-scan filtering [8], not ACORN. Authentication controls mandatory tenant scope, verified by Query svc and replicas. 写入：持久确认、可搜位点、段发布三件事 Writes: durable ack, searchable position, segment publication

正常路径：WAL 不直接等于搜索结果 Normal path: WAL is not a search result

中文

写请求带 operation_id、collection/model、id、version、vector 和 metadata。Ingest svc 验证后路由到该 id 所在片，以单片有序复制日志记录整条变化；图把日志复制封装为 Shard WAL 的持久提交契约，节点故障不丢确认写的承诺依赖复制协议与故障模型。不能先写本地文件就当可抵御整盘丢失，也不能把元数据 Raft 误当所有 point 写都走共识；不同产品在这些边界上有不同选择 [11]。

先达到持久提交，再给 Writer 返回 202 和 shard/epoch/LSN token。响应丢失后用同一 operation_id 重试，日志或其持久幂等结果返回原位点，不能为一次重试生成另一个较新版本。重放按 id 的版本应用，旧 upsert 不覆盖新 delete；版本由可信上游顺序或服务端 CAS 决定，同版本不同正文当冲突。幂等结果保留期与上游重试期要匹配，超过保留期的请求不能继续宣称自动去重。

Apply worker 连续推进 searchable LSN，表示截至此位置的所有 upsert/delete 都已进入可查询状态；它不是“某条最大 LSN 已处理”。一个洞还没补上，就不能跨过去。向量、payload、live-version 表与标量索引要通过一次原子 snapshot 发布或受同一可读版本约束，避免向量已在图里而 tenant 过滤还旧。对于未完成 ANN 建图的 growing，可以先精确搜索有限增量，所以可见不必等于高性能索引已建好。

Milvus 文档把 growing、sealed 和历史查询的 handoff 分开，且新数据与历史段需要一起汇总 [9]；本图借用这个生命周期，用单片 WAL/Manifest 表达本章的设计，并非复制其整套实现。到 b 冻结的数据进入 Builder，b 之后仍留在 growing delta。Builder 写不可变 sealed artifact，检查 checksum、codebook/metric/model 与加载可读回执，随后 CAS 发布 manifest。发布前旧 growing 路线仍服务，失败的构建不会变成搜索空窗。

查询 pin 的 manifest 命名 sealed≤b 与 delta>b，或使用有重叠但按 id/version 去重的过渡形式；无论如何不能有空洞。发布是切引用，不是在活跃查询脚下替换文件。旧请求结束再回收旧段；Builder 若读到旧代次就 CAS 失败并重取，不能覆盖较新的 manifest。扩容搬片也要先复制快照、按位点追增量、验证目标可读，然后更新路由代次与 drain，不能仅改变 hash 模数就让半份数据消失。

删除作为日志里的新版本 tombstone，在 live mask 中压掉同 id 的所有较旧段；搜索到旧候选后也必须检查它是否仍为该读取快照的有效版本。不能先把旧向量排进 local top-k、归并之后才删，否则 k 里会被墓碑占掉。即使最后过滤阻止错误返回，旧节点仍可能耗掉 ANN 的候选预算，所以要有界 refill，长期还要 compact/重建减少无效遍历。compact 是回收字节与修复性能，不是删除开始生效的时刻。默认旧读在可见边界内仍可能看到删前快照；需要确认删除后不再返回时，携带删除 token 或要求最新读取。权限撤销仍走上游权威检查。

默认最多旧 2 s 是 A10 的 bounded 契约，不是 eventual 的同义词。服务用当前采样的日志屏障/时间水位求所需位点，屏障采样年龄加上时钟误差也要落在 2 s 以内，只有 replica 连续 searchable 位点达到它才读；没有可验证的新鲜度证明，或者证明过期，就等待、换合格副本或失败。Milvus Guarantee/Service timestamp 比较给出相似的“先追齐再搜”机制 [10]。超时不允许默默把 bounded 请求转为无限陈旧的 eventual 请求。

写后读携带 token，只证明该片已纳入这条写及此前有序日志，仍返回近似 top-k；这条向量可能不在真 top-k 中，不能用 search 是否命中判断写是否丢失。读取最新时需要每片取一个当前屏障并追到该位点，原始 WAL 副本 ack 不能替代 search-ready。若要求跨片单一时间点的线性/事务快照，还要全局时间戳、MVCC 与协调协议；本章的每片位点向量只定义各片读界限，不把它冒充跨片原子快照。

English

Writes carry operation ID, collection/model, ID/version, vector, and metadata. Ingest validates and routes to an ordered replicated shard log. Shard WAL encapsulates a durable commit contract tied to replication and failure assumptions. Local file writes alone do not tolerate whole-disk loss, and metadata consensus does not imply all point writes use that protocol [11].

After durable commit, return 202 with shard/epoch/LSN. Retries preserve the operation ID and committed position, not a new revision. Ordered version application prevents older upserts resurrecting newer deletes. Trusted upstream order or CAS governs versions; identical versions with different bodies conflict. Durable deduplication retention must cover the retry window; do not promise deduplication after expiry.

Searchable LSN is a contiguous prefix including every prior upsert/delete, not the largest individually processed position. Publish vectors, payload, latest-version tables, and scalar indexes coherently via atomic snapshots or shared read versions. Small growing deltas can be searched exactly before ANN construction finishes, separating visibility from optimized indexing.

Milvus separates growing/sealed lifecycle and historical handoff while aggregating both data classes [9]. This chapter uses that lifecycle with its own shard-WAL/Manifest design. Freeze at b while later writes stay growing. Verify immutable artifacts, checksum, codebook/metric/model, and load readiness, then CAS-publish the manifest. Keep the old query route during failed builds.

Pinned manifests combine sealed≤b and delta>b or an overlapping transition deduplicated by ID/version, always without gaps. Switch references rather than files under active readers; drain before retirement. Stale builders lose CAS and retry. Resharding similarly requires snapshot copy, replay, readiness, route-generation publication, and draining rather than changing the hash modulus immediately.

A versioned tombstone hides all older segment versions. Check validity before local top-k so stale points do not consume final slots. They may still consume ANN exploration budget, requiring bounded refill and later compaction/rebuild. Compaction reclaims bytes and improves traversal; it does not define the start of delete visibility. Bounded stale reads may still see a pre-delete snapshot; carry the delete token or request fresh reads to require exclusion. Authoritative upstream checks still govern permission revocation.

A10 bounded staleness of two seconds differs from eventual convergence. Obtain a current log/time barrier and keep barrier age plus clock uncertainty within two seconds and read only replicas whose contiguous searchable watermark covers the required cut; missing or expired proof causes waiting, eligible rerouting, or failure. Milvus compares Guarantee and Service timestamps similarly [10]. Do not silently downgrade bounded requests on timeout.

A read-after-write token establishes one shard’s ordered prefix while search remains approximate; a written vector need not belong to true top-k. Fresh per-shard reads require current barriers and search-ready state, not WAL acknowledgements alone. A single cross-shard transactional/linearizable snapshot additionally needs global timestamps, MVCC, and coordination. This chapter’s per-shard cut vector does not claim cross-shard atomicity.

中文

按 hash(id) 分四片，各片都是同一模型空间中的子集。Query svc pin 路由代次，从每个相关片选一份满足读取条件的副本，并行带着同一 vector、filter、k 与片位点发出去。每片对自己的 growing/sealed 结果做版本/权限检查，得到 local top-k，回 Query svc 合并，再回 Caller。相关片集合必须有完备路由依据；任意语义/类目分片不是天然错误，但只探“看着像”的一个类目可能漏掉跨类近邻，要明确近似路由误差或搜索所有可能片。

如果每片返回同一快照/谓词与评分规则下的精确 top-k，全局真 top-k 不可能在某片排到 k 之后：那片至少已有 k 个更好对象挡在它前面。因而四片每片十条，只需合并最多四十项。ANN 时这个论证只说明归并策略，不会消掉每片漏召回；量化片要先按同一 metric rescore 再比较，否则不同片的误差分布会把 PQ 分数错当可直接比较的精确距离。多段去重也要在片内完成，不能靠 coordinator 删除旧版本后硬凑 k。

全局 200/s 查询广播四片，是每片 200/s、全体 800 次片搜索/s，不是每片 50/s。若两副本每份教学预算 120/s，稳态轮流各接 100/s，使用率 100/120≈83.3%；掉一份后另一份要接 200/s，超过预算 1.67 倍。要满足故障时不丢吞吐，每片幸存副本须在同 Recall/过滤/时延目标下测到至少 200/s，或增加副本、预留容量与限流降级。这个 120 是说明故障算术的假设，不是图索引性能常数。

请求延迟由最慢相关片和归并决定，不能把四片各自 p95 当全局 p95。举个独立分布假设：某阈值每片 95% 都能赶上，四片同时赶上的概率 0.95⁴≈81.45%；现实片之间共享负载，独立性也可能不成立。增加 shard 会减每台内存，也会增加 fan-out、连接、候选工作与尾风险。所以先按体积与故障容量选片数，再实测完整查询，不用盲目加片代替副本吞吐规划。

S1 Replica A 追不上要求位点时，它把拒绝沿回程送 Query svc；svc 只能重试同片、同 collection/model 与读取条件的 B。A 与 B 不能同时各占一个片结果，迟到回复要按请求/片/尝试身份丢弃。截止时缺一个相关片，本题默认 complete=false 并返回服务错误；若上游显式允许部分结果，可以带 covered_shards 与 partial 状态返回。空数组在完整查询下可能是合法空集，在缺片下不是“无匹配”。

索引改版时不是只换一个文件名。新 manifest 绑定 model/metric/normalization/codebook、快照截止与追齐位点；快照后持续回放包含删除的变化，核验计数、版本与过滤召回后发布。普通索引重建可以仍用原模型，换 embedding 则需要上游提供新模型向量并隔离 collection。回退旧索引时它也必须持续追写，或明确承认陈旧并阻断新鲜读取；“旧文件还在”不等于能够安全回退。
