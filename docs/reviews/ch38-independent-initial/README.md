# Ch38 executable teaching examples

Run from the repository root. Java17 (JDK, no dependencies), Python3.10+ standard library and SQLite3 are sufficient:

```sh
node examples/ch38/sync.mjs --check
PYTHONDONTWRITEBYTECODE=1 python3 examples/ch38/run.py
mkdir -p /tmp/ch38-java
/Library/Java/JavaVirtualMachines/jdk-17.0.10.jdk/Contents/Home/bin/javac -d /tmp/ch38-java examples/ch38/AgeBudget.java examples/ch38/SingleFlight.java
/Library/Java/JavaVirtualMachines/jdk-17.0.10.jdk/Contents/Home/bin/java -cp /tmp/ch38-java AgeBudget
/Library/Java/JavaVirtualMachines/jdk-17.0.10.jdk/Contents/Home/bin/java -cp /tmp/ch38-java SingleFlight
```

- `AgeBudget.java`: fixed evidence from authoritative read START, a five-second L1 copy cap, a two-second inter-node clock margin, a one-second final-send margin, and capped/floored shared HTTP lifetime. Negative evidence has five seconds, positive twenty. `n=0` provides no shared freshness; it does not by itself prohibit a currently valid direct response. Expired evidence fails `canSend` and cannot produce 200/304/404. Use one now sample for eligibility and shared lifetime at final response construction; abandon unless the entire interval from that check through final transport send fits the declared one-second bound. Trusted clocks must stay within ±1s and fail closed when unhealthy; timestamps and arithmetic use realistic epoch milliseconds, not arbitrary untrusted long inputs.
- `SingleFlight.java`: one `ConcurrentHashMap` per process, one active loader per key, private waiter futures, executor rejection/failure propagation. Waiter `orTimeout`/cancel cannot cancel the leader. A stuck loader remains registered until it actually returns; production adapters need a bounded physical query or confirmed cancellation. A logical timeout must not release real origin permits early. Multiple Group instances/processes can each lead; `join` does not add cross-process coordination, authority, authorization or age checks. The caller validates each result's evidence at send time.
- `cache.pseudo`: page contract. `cache.py` implements it using a real SQLite file as the single write authority. `BEGIN IMMEDIATE` serializes claim/invalidate/fill across independent processes, and time is sampled after acquiring the write lock. `metadata.floor` never decreases; values are evictable, metadata is retained in this model. Missing metadata and wrong runtime epoch reject old tokens. Runtime restart rotates epoch and clears values/leases atomically. Unique UUID tickets are unguessable teaching identities, not authentication credentials.
- `http.pseudo`: policy, not an HTTP parser. Before shared lookup, a strict route policy passes Authorization/Cookie/personalized traffic. The origin still authenticates it. It requires a proper RFC parser and selected representation, handles GET conditionals with weak comparison/list/`*`, and reads a fresh primary snapshot for authoritative validation. It uses weak ETags to cover semantic identity across a declared renderer/representation version; transformations need their own valid validator policy. A 304 applies only to an existing selected representation. Missing rows use explicit 404 life; unavailable Store returns 503 no-store, not 404.

Evidence is supplied by a trusted App loader after it receives a NEW token: begin a new primary snapshot after the claim, capture `observed` before the query, and preserve that timestamp/deadline across every cache copy. Cache cannot prove that a compromised loader read primary, or stop one from inventing a larger version or a new timestamp. `fill` validates the claimed fixed lifetime and a plausible future timestamp but is not cryptographic attestation. Existing rows and absence/deletions must carry a monotonic per-key revision; a missing-row absence needs a revision/tombstone authority, not a guessed zero once a higher floor exists. The outbox/HTTP policy discussion is not implemented here; row/outbox atomicity, CDN receipts/Age, authorization and clock health are external prerequisites.

Metadata is never silently evicted in this adapter. For production reclamation, fence outstanding tickets and establish a new epoch or authoritative floor before accepting fills. A cache replacement without persisted floors is safe only under the declared new-primary loader contract and shared hard-age fallback; it is not immediate global freshness. This example is not a replicated cache, Redis Lua implementation, production rate limiter, HTTP cache, purge API, network partition/clock fault experiment, load test or durability benchmark. SQLite process contention proves its file transaction boundary only. The Java tests demonstrate local concurrency only.
