## 改动与纠错

- 以“合同 → 全局请求 → 令牌变化 → 原子实现 → 严格窗口反例 → 故障返回 → 复盘”整理正文，去掉重复说明；完整假设、算法对比与扩展取舍分层折叠，核心代码和失败边界默认可见。中文、英文与12张闪卡同步。旧停工草稿仅逐段审查后作为文字参考，所有动画先从授权基线重新抽取。
- 补充同源的32行 Redis Lua 教学示例、精确日志伪代码、网关三种返回路径伪代码、HTTP响应示例。不存在无实现的 `atomic()`；Redis EVAL覆盖TIME、GET、补充、判定、单一SET PX，解释了进程锁与共享权威的不同边界。
- 回拨保留last，TTL与等待均增加回拨欠时。反例：空桶last领先100秒，需先追平100秒再补满60秒；固定120秒TTL会提前重建满桶，现TTL约220秒、1-token等待约115秒。补明实现按毫秒计量，与连续真实时间比较有不足1ms补充量的边界量化误差。仍明确不保证向前跳钟、驱逐、复制丢失时的真实时间包络。
- 校验cost、版本、数值与JSON；存储的JSON `false`/`null`也必须报错，不能把它们误当不存在而发满桶。唯一SET PX避免“先写状态、后设TTL失败”部分写问题，但不声称Lua有自动回滚或强一致切主。
- 未知扣减不自动重试/退款；正常预检仍查权威。应急包络只覆盖fallback流量，Service同时保护正常+降级总量和并发；重启/抖动/成员替换不得重复领满桶。
- 保留并复算：B+rT在60秒上界8；t=20等待5秒；加权4.5对实际8的反例；候选成本6.5+1=7.5；4×50+4×500T=200+2,000T；百万桶两份约400 MB。全部业务/容量数字标教学假设。
- 删除旧英文未转义 `count<L` 所在段并以正确转义的伪代码解释精确日志；Ch39/42“待上线”改为可访问的延伸入口。移除历史过期配额头草案旁支，保留429/503/Retry-After的规范依据。
