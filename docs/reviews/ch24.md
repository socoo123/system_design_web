## 代码、原子边界与验证

[examples/ch24/README.md](../../examples/ch24/README.md)列运行方式、依赖和简化范围；源码与页面由 [sync.mjs](../../examples/ch24/sync.mjs)检查完全一致。

| 共享源 | 保证及限制 |
|---|---|
| `keys.sql`、`create.pseudo` | 请求键和业务意图独立，摘要冲突拒绝；T1同库保存意图/尝试/命令。仅重启已识别的唯一竞争，不吞任意错误。 |
| `dispatch.pseudo` | SENT先持久、固定重放窗、迟到失败不覆盖成功；依赖渠道契约，本地无PSP fence。 |
| `webhook.pseudo` | raw-body SDK验签契约、持久inbox后ACK、业务核验和可恢复claim。没有自造通用签名算法。 |
| `capture.pseudo` | 一次完整capture，两条完整且按币种平衡的分录、状态和paid事件同提交；校验来源金额/账户，效果键冲突比较绑定。 |
| `reserve_refund.pseudo`、`refund_result.pseudo` | 同付款聚合锁、累计额度/预留约束；UNKNOWN不释放；成功与失败各只结转一次，反向分录/事件同提交。 |
| `reconcile.pseudo` | 报告/快照范围和可重复run；缺记修复走同一效果门，case只在已知提交后关闭，不产生新扣款。 |

[model.py](../../examples/ch24/model.py)用实际SQLite事务执行对应契约，[check.py](../../examples/ch24/check.py)当前 **70项通过**，见 [ch24-code-results.json](ch24-code-results.json)。覆盖正常路径、同键/换header、两连接创单、两连接争抢退款、回包丢失、固定重放窗、成功后迟到超时、认证失败边界、重复event/不同event同capture、错金额/账户/币种、第二capture、分录中途崩溃全回滚、UNKNOWN预留、退款重复/旧失败、补账后工单关闭前崩溃、历史防改及真实NULL拒绝。

SQLite用BEGIN IMMEDIATE串行写者，证明的是本地事务/约束反例，不是PostgreSQL行锁/复制切主。提供商仅独立contract fixture；`verified=True`表示已满足上游契约，不是实际签名校验。普通行CHECK不保证跨分录SUM，完整账依赖受控Posting过程/权限或可靠延迟约束；示例触发器只保护历史UPDATE/DELETE。伪代码没有冒称可编译Java。
