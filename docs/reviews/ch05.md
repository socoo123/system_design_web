## 发现与纠正

| 原状态 / 风险 | 最终处理 | 验证 |
|---|---|---|
| 环定位只有文字，空环、碰撞没有实现 | Java 明确拒空、重复 token；无符号排序；lower_bound 使用 `>=`，越界回首项，单节点覆盖全环 | Java 端点、碰撞、高位、单节点、wrap 测试 |

| 本地原子发布容易被误当全局权威 | 明示消费已验证、epoch 与内容摘要绑定的已提交清单；本地 CAS 不实现共识，不给候选直接服务权 | 正文、代码注释、闪卡一致 |

## 数值复算

- 取模 3→4：完整余数周期 12，9 个改变，75%；10→11 改变 10/11，约 909,091/百万 key。
- A2 新增 S3@25：只有 11–25 共 15/100 改变；删除 S1 后 S2 为 50/100；这组坐标不等于随机模型的 1/4。
- A3 删除 S1 的两个 token：(10,30] 的 20% 交 S2，(80,95] 的 15% 交 S0，最终 S0/S2=45%/55%。
- 相同独立均匀 token 数的随机模型：新增期望 K/(n+1)，删除期望 K/n；它们是 key 数期望，不是字节、QPS 或最坏负载保证。
- 100×160×16 B=256,000 B=256 KB 原始条目/Router，未计对象与容器。
- 90,909×1,000 B≈90.91 MB，10 MB/s 下理想 9.09 s，不计追平、副本与索引。
- 热点 owner：4,000+6,000/10=4,600/s；故障后均值 10,000/9≈1,111/s 不限制最忙机器。
- 冷机回源 10,000/11 + 10,000×10/11×5%=1,363.64/s；预算 800/s 要求新机命中至少 62%，仅均匀请求模型。

## 一手来源核对

2026-10-22 使用浏览工具重新打开以下原始来源，并定位所支持内容；页面引用的可变文档检查日期同步更新。

1. [Karger et al., 1997](https://people.csail.mit.edu/karger/Papers/web.pdf)：成员变化下映射平滑性与客户端不同视图；不解释为强一致读写。
2. [Dynamo, 2007 §§4.2–4.3](https://www.allthingsdistributed.com/files/amazon-dynamo-sosp2007.pdf)：多个 token、128 位 key 标识、异构容量与物理 owner 去重的复制选择。
3. [Richard Jones 原文, 2007](https://www.metabrew.com/article/libketama-consistent-hashing-algo-memcached-clients)：100–200 点、32 位 continuum、末端回绕。
4. [libketama 原始源码](https://raw.githubusercontent.com/RJ/ketama/master/libketama/ketama.c)：`floorf(pct * 40.0 * numservers)`、每个摘要拆四个32位点、理想同权重40×4=160点；实际浮点与floor取整可能改变点数。不是把128位摘要当环宽。
5. [Lamping/Veach, 2014 Figure 2](https://arxiv.org/pdf/1406.2294)：连续编号桶限制；表中0.0996996、0.0315723为空间份额相对标准差，不是最大负载或SLA。
6. [Cassandra 官方架构](https://cassandra.apache.org/doc/latest/cassandra/architecture/dynamo.html)：Token、Endpoint、Host ID、vnode 与成员传播；不声明易变的默认 token 数。
7. [Redis Cluster 官方规范](https://redis.io/docs/latest/operate/oss_and_stack/reference/cluster-spec/)：16,384 固定 slot、MIGRATING/IMPORTING、ASK/MOVED；本章暂停模型没有伪称 Redis 的具体实现。
8. [Maglev 原论文, 2016 §5.3](https://www.usenix.org/system/files/conference/nsdi16/nsdi16-paper-eisenbud.pdf)：软件网络LB、默认65,537表项及生成开销；不同于通用KV固定token环。
