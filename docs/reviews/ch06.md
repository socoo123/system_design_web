## 一手来源（本轮实际浏览核对，2026-10-22）

1. [Dynamo SOSP 2007](https://www.allthingsdistributed.com/files/amazon-dynamo-sosp2007.pdf)，§4.3–4.7：不同物理副本、不可变版本、向量祖先/兄弟、读 context 写回、sloppy preference list、目标 hint 与交还、Merkle 范围修复。购物车删除可因合并复现，不能声称简单并集无损。

3. [Cassandra Hints](https://cassandra.apache.org/doc/latest/cassandra/managing/operating/hints.html)，Hinted Handoff、Application、配置表：三副本两份 ACK、原 mutation 戳重放、max_hint_window=3h 是生成新hint的故障窗口。
4. [RocksDB Basic Operations](https://github.com/facebook/rocksdb/wiki/Basic-Operations)，Synchronous Writes / Non-sync Writes：sync 与 OS 缓存及机器故障区别。本章明确启用 WAL 和同步。
5. [RocksDB Overview](https://github.com/facebook/rocksdb/wiki/RocksDB-Overview)，Persistence、Memtable Pipelining、Compaction：日志恢复、冻结后 flush、不可变 SST 与后台合并；容量放大因子并非产品常量。
6. [RocksDB Bloom Filter](https://github.com/facebook/rocksdb/wiki/RocksDB-Bloom-Filter)，Configuration basics / Life Cycle：约9.9bit/key→1%误报，每个SST过滤器；本章10bit口算独立标注。
7. [Cassandra Tombstones](https://cassandra.apache.org/doc/latest/cassandra/managing/operating/compaction/tombstones.html)，Zombies / Deletion：864000s默认、相关旧SST覆盖、only_purge_repaired_tombstones 可选；不将到期当充分条件。
8. [Redis Cluster specification](https://redis.io/docs/latest/operate/oss_and_stack/reference/cluster-spec/)，Write safety / Key distribution：16384 slots、异步复制与已确认写丢失窗口，不套用对等副本 quorum。
9. [Cassandra Read repair](https://cassandra.apache.org/doc/latest/cassandra/managing/operating/read_repair.html)，Monotonic Quorum Reads / BLOCKING：失败少数写的读回退与默认阻塞修复；摘要读可降低完整 value 传输。

## 主代理预审返修：APPLY 校验顺序

主代理指出并由作者确认的 P1 已修：原 APPLY 先 append/sync 再调用可能拒绝同版本不同内容的 winner，存在非法记录进入 WAL 后恢复重放失败的窗口。现同一 guard 内先读全版本并计算 `next=winner(...)`，通过校验后 append/sync，最后发布 next；同步中断仍不 ACK。中文/英文/同源伪代码同步，图仍是 WAL 后发布可读状态，无需改动画。Java 增加非法 mutation 在日志轨迹写入前拒绝，现 **20 场景**通过；同源与事件模型重验通过。该日志轨迹不冒充真实掉电测试。
