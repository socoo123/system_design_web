30 秒开场：先固定附近商家，再谈变化 The 30-second open: places first, then extensions

我默认做附近商家和公开地点。客户端给一个点和半径，服务返回半径内按距离排序的最近二十个地点。先用格子键粗筛，查全圆覆盖的格子，再算距离和营业条件。地点详情是权威，空间索引是派生。数据量和地点写入不大，先允许单库；出现热格才加缓存、局部拆分。题目若改成附近的人，才加位置上报、短保留和受众权限，并把索引晚到的漏召回说清楚。

澄清只问会改图的条件：对象是公开地点还是私人移动端，半径上限是多少，最近二十是精确还是允许近似，编辑多久可见，以及这一轮的查询量。地图瓦片、路网导航、供需撮合各有自己的数据模型，当前问题只做到半径召回。空结果不自动扩大半径，类型过滤也不暗中变成推荐排序。

以下容量、延迟、命中率和保留都是 assumption，用来继续设计，没有借用某家地图产品的内部数字。容量统一用十进制：一 KB 是一千字节，一 GB 是十亿字节；带宽先算字节每秒，换比特再乘八。半径在接口里用米，图中用公里，比较之前先换单位。

I assume nearby businesses and published places. A client supplies a point and radius and gets the nearest twenty eligible places within that radius. Cells provide coarse recall; read every covered cell, then calculate distance and business filters. Place details are authoritative and the spatial index is derived. The small catalog and edit rate permit one database initially; add cache and local splits when a cell becomes hot. Only the mover extension adds reports, short retention and audience permissions, with an explicit async recall gap.

Clarify only what changes the drawing: published places or private movers, maximum radius, exact or approximate nearest twenty, edit visibility, and query volume. Map tiles, routing and matching have different models. This scope ends at radius recall. Empty results do not silently enlarge the radius; type filtering does not become recommendation ranking.

Capacity, latency, hit rates and retention below are assumptions, not internal metrics from a maps company. Use decimal units: one KB is 1,000 bytes and one GB is 1 billion bytes. Calculate bytes/s before multiplying by eight for bits/s. API radii are metres and diagrams use kilometres; convert before comparing.

权威地点与派生索引：先画完整查询 Authoritative places and a derived index: complete the query

路径、替代和代价

正常路径从 Client 经 Edge 到 Location Service。服务先验证半径和类型，算保守覆盖，再读 Spatial Index 的候选。候选带地点 id、坐标和版本，足够先过滤距离；留下来的地点再按 id 到 Location Store 补营业状态、公开权限和摘要。最终列表沿 Service → Edge → Client 返回。不能让索引直接答客户端，那里还没有执行响应权限。

权威行按 entity_id 存放，空间成员按 cell_id 与 entity_id 联合定位。前者擅长编辑某地点，后者擅长读取某区域，同一个哈希键不同时满足这两种访问。详情的删除标记和权限版本应在输出前检查；只有一个旧成员 id，而权威行已删除，就丢掉这个候选。详情不可读时也不能把未经权限确认的私人坐标当降级内容返回。

单库替代值得先说清。公开地点写约 0.13 次/秒，PostGIS 的 geography 型 ST_DWithin 接受米，默认用椭球测距，并利用空间索引做外接框预筛 [3]。一次事务里修改地点和数据库自己的索引，少掉跨系统事件窗口。独立经纬度 B 树有时也能利用选择性，不能断言永远没用；问题是它们没有直接组织二维邻域，要用实际候选和执行计划判断。

本章继续拆开索引，是为了练地理键、扇出和热格迁移，不能说单库已经被这些数字淘汰。独立索引把读取负载和权威编辑分开，代价是重建、版本和晚到窗口。图中异步变体使用 outbox：权威行与待投递事件同事务，relay 才能在进程重启后继续投递。队列不是第二份权威，也不能提高地点本身的事务正确性。

设计取舍要带失败行为。数据库自己维护同步索引时，索引维护失败会使编辑事务失败；独立派生索引时，编辑可以确认但查询晚到。前者实现更紧凑，后者可独立扩读取，两种都需要写在接口契约里。不要一面承诺写后一搜必见，一面让 200 在索引还没处理时返回。

Path, alternative and cost

The normal route is Client to Edge to Location Service. Validate radius and type, form a conservative cover, and recall from Spatial Index. Candidates carry ID, coordinates and version for distance filtering. Selected IDs are hydrated from Location Store for business state, visibility and summaries. Return Service to Edge to Client. An index cannot answer clients before response policy runs.

Authority is keyed by entity_id; spatial membership by cell_id plus entity_id. One edits an entity and the other reads an area. One hash key does not optimize both. Check deletion and permission versions before output. Drop a stale member whose authoritative row is deleted. If authority is unavailable, unverified private coordinates are not an acceptable fallback.

A single-database alternative deserves an explicit place. At about 0.13 place edits/s, PostGIS geography ST_DWithin takes metres, uses spheroidal measurement by default and applies an index-assisted bounding-box prefilter [3]. Editing the row and its database-maintained index in one transaction removes a cross-system event gap. Independent latitude/longitude B-trees may help with selectivity; judge plans and candidates rather than calling them universally useless.

This chapter separates the index to teach geographic keys, fan-out and migration, not because these numbers rule out a single database. A separate projection isolates recall load but adds rebuilds, versions and delayed visibility. The async variant commits authority and outbox together so a restarted relay can continue publishing. The queue is not another authority and does not itself improve transaction correctness.

Each choice needs failure behavior. A database-maintained synchronous index can fail the edit transaction. A separate projection can acknowledge an edit before recall catches up. The former is compact; the latter scales reads independently. Both need an API contract. Immediate write-then-search visibility conflicts with acknowledging before projection applies.

半径与格子：前缀不能代替覆盖 Radius and cells: prefixes do not replace covering

尺寸如何推动查询

geohash 把经纬度比特交错，五个比特写一个字符。长度六共三十比特，经纬度各十五。按 A6，纬度边为 180 ÷ 32,768 × 111 ≈ 0.610 km；经度边为 360 ÷ 32,768 × 111 × cos40° ≈ 0.934 km。经度距离随纬度变化，长度相同不等于全球边长相同。Redis GEO 的交错编码与内部区间查询有原文说明 [1]，此处边长是本章按覆盖假设计算。

图把查询点放在格心，所以可以逐格核算。圆向北伸一公里，北邻远边在 1.5 × 0.610 ≈ 0.915 km，圆超过它，还触到第二格。格心外接盒为三列五行，十五格；四角离圆心的最近距离约 √(0.467² + 0.915²) ≈ 1.027 km，超过半径，所以圆相交只有十一格。十一是这幅图的结果，不能背成任何位置的一公里固定扇出。

任意对齐的外接盒，单轴格数上界取 ceil(直径 ÷ 边长) + 1。一公里圆得到纬度 ceil(2 ÷ 0.610)+1 = 5，经度 ceil(2 ÷ 0.934)+1 = 4，最多二十格。按盒保守召回会多拿圈外候选，但不会因少查格而漏静态地点；再做格圆相交可省部分读取。覆盖计算要包含边界点，不把浮点误差变成对面几米的店消失。

两个相近的点跨过编码边界可以没有长公共前缀。北京附近示例 wx4g0b 的南邻为 wx4fbz，LIKE wx4g0% 扫不到它。查询要枚举覆盖格，而不是先把公共前缀缩到百公里宽再扫描。跨国际日期变更线时把经度区间拆为两段；高纬度要重算地面边长。这里四十度的二十格预算不能直接搬到极区。

两公里的外接盒上界约 (ceil(4 ÷ 0.610)+1) × (ceil(4 ÷ 0.934)+1) = 8 × 6 = 48 格。五公里仍用长度六会到十八乘十二，即 216 格。长度五在四十度约 3.74 × 4.88 km，五公里外接盒最多四乘四，十六个前缀范围。我们维护按完整 geohash 排序的成员行，所以粗前缀能做范围读取；若只有离散长度六的 Redis key，就不能凭空读取一个不存在的长度五聚合 key。

少十六个范围请求没有消掉密度。半径从一到五公里，圆面积变为二十五倍，同样均匀密度下候选也约二十五倍，距离过滤和带宽仍变重。API 要同时限制半径、候选工作量和并发。五十公里被拒绝是产品边界；保留长度六时外接盒约 166 × 109 ≈ 1.8 万格，只说明放任这个半径的访问代价。

H3 可以换掉格子编码，不会换掉覆盖责任。gridDisk(k) 的 k 是图上的网格距离，输出顺序也不保证 [5]；它不是公里。官方统计每层都有十二个五边形，并且同分辨率面积随位置变化 [4]，所以「六邻居精确等距」不能当球面事实。S2、H3 或 geohash 都应使用可靠覆盖实现，并在召回后测距；库名不能代替证明半径圆被完整罩住。

How dimensions change the query

Geohash interleaves coordinate bits, encoding five bits per character. Six characters are thirty bits, fifteen per axis. Under A6, height is 180 ÷ 32,768 × 111 ≈ 0.610 km and width is 360 ÷ 32,768 × 111 × cos40° ≈ 0.934 km. Equal precision does not imply equal ground width worldwide. Redis describes interleaving and internal range queries [1]; the cell dimensions here are our calculation.

The point is at a cell center. One kilometre reaches beyond the immediate northern neighbor because its far edge is 1.5 × 0.610 ≈ 0.915 km away. The centered bounding box has three columns and five rows, fifteen cells. Its four corner cells begin at √(0.467² + 0.915²) ≈ 1.027 km, outside the radius. Only eleven cells intersect this circle. Eleven is specific to this drawing.

For arbitrary alignment, each axis uses ceil(diameter ÷ edge) + 1 cells. A 1 km radius yields 5 latitude cells and 4 longitude cells, at most twenty in the bounding box. Conservative box recall includes outsiders but avoids missing static places through undercoverage; cell-circle intersection can reduce reads. Include boundary points and avoid floating-point undercoverage.

Nearby points can cross an encoding border and lose their long common prefix. Around Beijing, wx4g0b has southern neighbor wx4fbz, outside LIKE wx4g0%. Enumerate the cover rather than scan a hundred-kilometre common prefix. Split longitude ranges at the date line, and recalculate ground width at high latitudes. The 40-degree twenty-cell budget is not a polar bound.

A 2 km radius has a worst-case box of 8 × 6 = 48 cells. A 5 km radius on length six reaches 18 × 12 = 216. Length five is about 3.74 × 4.88 km at 40 degrees, giving up to 4 × 4 = 16 prefix ranges. Our member rows are ordered by full geohash, allowing coarse range reads. Independent length-six Redis keys do not magically provide an aggregate length-five key.

Sixteen range requests do not remove density. Raising radius from one to five kilometres makes area 25× larger and candidates about 25× larger under uniform density. Filtering and bandwidth remain expensive. Bound radius, candidate work and concurrency. Rejecting fifty kilometres is a product rule; its roughly 166 × 109 ≈ 18,000 length-six cells demonstrate the cost of allowing it.

H3 changes encoding, not the responsibility to cover. gridDisk(k) uses grid distance and has no guaranteed output order [5]; k is not kilometres. Official tables give twelve pentagons per resolution and position-dependent areas [4], so exact equidistance is not a global fact. H3, S2 and geohash all require a reliable cover and post-recall distance checks. A library name does not prove a complete radius cover.

查询闭环：缓存旁路，排序不能提前 The query loop: side cache and global ranking

正常、边界和失败预算

Location Service 对覆盖中的每个 cell 发并行读取，先查 Cell Cache，命中拿到一个成员快照，未命中由服务自己读 Spatial Index，再回填缓存。缓存没有直接连索引的回源箭头；这是 look-aside。成员快照包含坐标、版本和 observed_at，单纯 id 列表还要补坐标才能排序。补详情只针对留下的候选，省掉不在半径内的店名和营业时间读取。

排序顺序是合并、按 entity_id 去重、距离过滤、业务过滤，再选全局最近二十。去重选较新的权威版本，并检查删除状态。同一成员可能在两个格出现，原因是迁移或先加后删。任意从每格截二十会漏：一个格子里前二十个都是不营业的店，第二十一个营业，过滤后它应当被返回。精确最近结果需要继续读取或可证明的距离下界，不能用随机截断冒充完整结果。

Redis 单个 GEO key 很适合原型，GEOSEARCH 支持半径和按距离排序。COUNT ANY 会提前停止，不保证拿到最近的那些匹配 [2]。原型也需要类型、权限和新鲜度过滤。文档说明球面 Haversine 在最坏情形误差可达约 0.5% [1]；一公里对应约五米量级，适合普通附近列表，边界严格或测量场景应选明确的椭球模型。模型误差和 GPS 误差要分开说。

缓存键为 cell_id、route_epoch 和 cell_version，不用原始查询经纬度。Location Store 的 entity_version 标记某实体更新，cell_version 标记某格成员快照变化，两个版本不能混为一列。索引读取要把版本与成员作为同一快照返回，晚到回填只能写相同版本的键；查询读取当前格版本或接受有界旧快照，不能一边要求强新鲜一边不付版本读取成本。

A4 的 TTL 最多两秒，只限制缓存驻留，不能修复尚未到索引的新写。索引目标两秒加缓存最多两秒，正常路径可见延迟可能接近四秒，还未计网络和采样间隔；索引积压时没有四秒保证。失效通知可以缩短常见窗口，但 TTL 是丢失通知后的兜底。回填、重试、缓存命中都保留原 observed_at，响应时再判断年龄，不让旧 GPS 随缓存续命。

按 A3，热格只传 id 是 10,000 × 16 = 160 KB，222 × 160 KB ≈ 35.6 MB/s。实际用于距离过滤的六十四字节成员快照是 640 KB，约 142 MB/s。公开地点或允许有界旧快照的热点九成命中时，回源约 22.2 次/秒、约 14.2 MB/s，这是目标而非测量。移动热格四百写/秒若每次换 cell_version，又要求读当前版本，会频繁换键，不能继承九成命中，必须重新量。缓存整层宕机则 222 次/秒全回源，超过 A4 的一百上限，合并回源之外仍要限流；不能把同键合并当跨所有进程天然只有一次。

Normal path, boundaries and failure budget

Location Service reads covered cells in parallel. A Cell Cache hit returns a snapshot; on a miss the service reads Spatial Index and fills cache. There is no cache-to-index load arrow: this is look-aside. Snapshots include coordinates, versions and observed_at. IDs alone require coordinate hydration before ranking. Fetch detail fields only for retained candidates.

Merge, deduplicate entity_id, filter distance and business rules, then select the global nearest twenty. Keep the newer authoritative version and check deletion. Migration or add-before-remove can duplicate membership. Arbitrary twenty-per-cell truncation can miss the twenty-first shop when the first twenty are closed. Exact nearest results need continuation or a provable distance bound, not random truncation.

One Redis GEO key is useful for a prototype. GEOSEARCH provides radius and distance ordering; COUNT ANY stops early and does not guarantee the closest matches [2]. Type, policy and freshness filtering still apply. Redis documents up to about 0.5% spherical Haversine error [1], roughly five metres at 1 km. Strict boundaries or measurement need a chosen spheroidal model. Model error is separate from GPS error.

Cache keys contain cell_id, route_epoch and cell_version, not raw query coordinates. Entity versions describe entity changes; cell versions describe membership snapshots. Read version and members atomically. A late fill writes only its matching version key. Queries must obtain the current cell version or explicitly accept bounded-old snapshots; strict freshness has a version-read cost.

A4 caps cache residence at two seconds, not projection delay. A two-second projection target plus up to two seconds cached can approach four seconds before network and sampling; backlog removes that bound. Invalidation improves common cases, with TTL covering lost invalidations. Fills, retries and hits preserve observed_at. Check age at response time.

A3 gives 10,000 × 16 = 160 KB of IDs and 222 × 160 KB ≈ 35.6 MB/s. The full sixty-four-byte snapshot is 640 KB and about 142 MB/s. A 90% hit target for places or bounded-old snapshots leaves about 22.2 origin reads/s and 14.2 MB/s, not a measurement. A mover cell with 400 version-changing writes/s and strict current-version reads frequently changes keys and needs a new measured hit rate. Whole-cache loss sends all 222/s to origin, exceeding A4’s 100/s cap. Coalescing per key does not automatically coalesce across all processes.

移动端扩展：持久化成功仍可能漏新格 Mover extension: durable success can still miss the new cell

版本、空洞与观测时钟

公开地点主线不需要持续 GPS。若改成附近的人或车，A5 的 80,000 × 4 ÷ 60 = 5,333.33 次/秒才把写路径变热。每条原始最新行九十六字节，80,000 × 96 = 7.68 MB；若每次追加历史，5,333.33 × 96 × 86,400 = 44.2368 GB/天，三份行拷贝约 132.71 GB/天。事务日志、事件队列、索引和备份另计，这个大小不能当真实采购容量。

请求先验证 entity 属主、共享状态、坐标范围和采样年龄。Redis GEO 只接受经度 ±180°、纬度约 ±85.05112878° [1]，不能把这个实现限制说成所有地理索引的极区限制。客户端 observed_at 是观测时间，accepted_at 是服务收到时间，二者分开。设备时钟可能错，所以限制未来偏差、拒绝过老样本，并使用服务确认的设备会话与递增序号防止乱序回退。重试带稳定 request_id；相同 request_id 先读回已提交结果，再看额度，避免成功的重试变成第五次上报而得到 429。

权威事务锁定实体的新版本，把 latest、entity_version 和 outbox 事件一起提交。事件带 event_id、entity_id、版本、旧格、新格、坐标和原观测时间。Debezium 的 outbox 原文说明事件 id 可用于去重，aggregateid 可用于消息键及分区内顺序 [6]；本章把 entity_id 作为聚合键。确认丢在网络上可以重试，不能再次递增版本或重新计一次接受额度。

Writer 按实体有序消费，同格移动也要更新坐标，不能只处理 cell_id 改变。新格插入以版本比较保护，旧格删除仅删除不新于被替换版本的成员。版本四十二的删除如果晚于四十三到达，不能把实体重新进入旧格的四十三删掉。先加新格后删旧格，重复投递可重放，完成两步才 ack；删后崩溃会让人彻底消失，所以不选先删。

先加后删只关闭应用事件时的删除空洞，关不掉事件到达之前的召回缺口。权威已到新格，索引还在旧格，查询只覆盖新格就根本拿不到这个 entity_id。拿旧候选再读权威能剔除已离开的对象，但无法找回一个从未召回的对象。产品允许最终可见就公开这个窗口；必须写后查到则等待 Writer 水位，或在读中合并受限的最新写召回层，增加同步依赖与成本。

队列积压两秒时约有 5,333 × 2 ≈ 10,667 条待处理；它们可能同格更新，也可能多次跨格。两秒是 p99 工作目标，宕机时积压继续长，不能承诺「最多落后两秒」。对账按权威版本修复派生索引，长期丢事件不能仅靠正常队列重试治好。outbox 保留到确认投递并有重放余量，但位置事件也会包含历史样本，短保留、访问限制与备份删除都要覆盖它。

四次/分钟是额度，不是采样时钟。客户端若一分钟初连报四次，后五十多秒不再被接受，三十秒新鲜度会让它从附近列表消失。若产品要稳定显示，就规定发送节奏、允许替换尚未处理的旧点，或提高预算，并重算容量。示例车速六十公里/小时约 16.7 米/秒，两秒移动约三十三米，三十秒约五百米；落在距离桶里也仍可能跨格，不能用桶宽否定漏召回。

Versions, recall gaps and the observation clock

Published places need no continuous GPS. The mover extension makes A5’s 80,000 × 4 ÷ 60 = 5,333.33 writes/s relevant. Raw latest rows total 80,000 × 96 = 7.68 MB. Appending every report produces 5,333.33 × 96 × 86,400 = 44.2368 GB/day, about 132.71 GB/day for three row copies. Logs, events, indexes and backups are separate; these are not procurement figures.

Validate ownership, sharing, coordinate range and sample age. Redis GEO accepts longitude ±180° and latitude about ±85.05112878° [1]; that is an implementation limit, not a universal polar limit for geographic indexes. observed_at is sampling time; accepted_at is arrival time. Bound future clock skew, reject old samples, and use server-confirmed device sessions plus sequence numbers against reordering. A stable request_id retrieves a committed retry before charging quota, so a successful retry does not become a fifth report and a 429.

One authoritative transaction commits latest, entity_version and outbox. Events carry event ID, entity ID, version, old/new cells, coordinates and original observation time. Debezium documents event IDs for deduplication and aggregateid for keys and partition ordering [6]; our aggregate key is entity_id. A lost response may be retried without another version or quota charge.

Writer consumes in entity order, including coordinate changes inside one cell. Inserts compare versions; removal deletes only membership no newer than the replaced version. A delayed v42 removal must not delete v43 that re-entered the old cell. Add new before removing old, replay duplicates, and acknowledge after both. Delete-first followed by a crash would erase recall.

Add-before-remove closes an apply-time deletion gap, not the delivery-time recall gap. Authority can be in the new cell while the index remains old. A query covering only the new cell never recalls the entity ID. Authority validation can discard wrong recalled objects but cannot recover an unrecalled object. Expose eventual visibility, or wait for a watermark / merge a bounded recent-write recall layer at additional cost.

A two-second backlog holds about 5,333 × 2 ≈ 10,667 events, including same-cell changes and repeated moves. Two seconds is a p99 target; outages keep increasing lag. Reconcile authority versions against projection. Normal retries do not repair permanently lost events. Retain outbox until delivery is confirmed with replay headroom, but these events also contain historical samples and need short retention, access controls and backup deletion.

Four/minute is a quota, not a clock. Four reports at the minute’s start can leave over fifty seconds without an accepted sample, causing a thirty-second freshness check to hide the mover. Stable display requires paced reporting, replacing pending older samples or a larger budget with recalculation. Sixty km/h is about 16.7 m/s: thirty-three metres in two seconds and five hundred in thirty seconds. A bucket does not prevent cell crossings.

热格拆分：复制、双读、水位、回收 Hot-cell splits: copy, dual reads, watermark and retirement

一笔热点如何安全变成四笔

热点先定位到 cell:wx4g0b 这个键。A3 的 222 次读/秒和一万个成员，可能先卡网络与距离计算。移动扩展的六千实体每分钟四次，是 6,000 × 4 ÷ 60 = 400 次写/秒；邻格可以很冷。空间键让一个区域可单独处理，按 entity_id 哈希均分会使一次附近查询广播到所有存储片。空间键也不保证相邻键在同机，一致性哈希仍可能把二十个格分散到多台。

先试热点快照缓存和读副本，量出压力后再四分父格。两个额外空间比特是本章自定义的四等分，每个孩子约父格四分之一；再加一个完整 geohash 字符是五比特、三十二格，两者不能混写。借鉴层级划分不等于采用 S2 的球面编号，也不允许查询方猜哪些父格已经拆开。路由目录记录父格状态、孩子列表与 epoch。

迁移先保持父格服务，以一个版本水位取成员快照，Index Writer 复制到孩子，随后重放水位之后的新增、移动和删除。Writer 的版本比较要覆盖删除墓碑，否则复制一条老记录就可能复活已删地点。复制失败继续用父格；不能为了「拆分已启动」让读者跳进空孩子。

读者在迁移 epoch 里查询父格加相交孩子，按 entity_id 与版本去重。孩子全部追到切换水位后，发布新 epoch。旧读者持有 e 的路由缓存最长五秒，还可能有在途读取，因此保留父格到缓存期限和读者租约都结束。只等固定五秒却不考虑在途请求，最后一条旧请求仍可能读到已回收的父格。

拆分增加读取开销。一个二十格覆盖中只替换一个热父格，稳态最多 20 − 1 + 4 = 23 次成员读取；迁移双读时最多 20 + 4 = 24。如果二十格全部拆开，可能八十次。只有相交孩子需要查，但不能保证永远只碰一个。四分若只是逻辑 key 而仍在同一台机器，不会增加物理写容量；部署映射和孩子放置也要随拆分更新。

空间四分不保证负载四等分。看台上的实体可以全部挤在一个孩子，400 次写/秒仍击中一个 key，其他三个空着。这时继续局部拆、提高该片预算，或对移动端在权威事务前限流。已经确认的事件不能被 Writer 的过载门丢掉；让用户得到 200 却不进索引，会把背压偷偷变成长期漏召回。

How one hotspot safely becomes four

Locate the hotspot at cell:wx4g0b. A3’s 222 reads/s and ten thousand members may stress bytes and distance CPU first. Six thousand movers at four reports/minute give 400 writes/s; neighbors may be cold. Spatial keys isolate one region. Hashing by entity_id instead broadcasts nearby reads, while hashing spatial keys still does not guarantee adjacent cells share a machine.

Try cached snapshots and read replicas before splitting a measured hotspot. Our two-bit custom subdivision gives four quarter-sized children; a full extra geohash character gives thirty-two, not four. Borrowing hierarchical subdivision does not adopt S2 spherical IDs. A routing directory records parent state, children and epoch.

Keep the parent serving. Take a snapshot at a version watermark, copy to children, then replay inserts, moves and deletes after that watermark. Version guards include deletion tombstones so an old copied row cannot revive a deleted place. If copying fails, remain on the parent rather than direct queries to empty children.

During migration, readers query parent plus intersecting children and deduplicate by entity and version. Publish a new epoch only after every child passes the cutover watermark. Old route caches may last five seconds, with reads still in flight. Keep the parent until both route lifetimes and reader leases expire. Waiting five seconds alone misses outstanding readers.

Splitting adds fan-out. Replacing one cell of a twenty-cell cover gives at most 20 − 1 + 4 = 23 steady-state reads; dual-reading during migration gives 20 + 4 = 24. Splitting all twenty can give eighty. Read only intersecting children but do not assume just one. Four logical keys on the same machine do not increase physical write capacity; update placement as well.

Spatial subdivision need not balance load. All movers may occupy one stand and one child, leaving 400 writes/s on one key. Split further, raise that shard’s budget or reject reports before authority commits. Writer overload must not discard acknowledged events: a 200 followed by no projection turns backpressure into permanent recall loss.

故障与隐私：陈旧结果必须有边界 Failures and privacy: stale results need a boundary

失败行为与数据边界

先区分故障部件。Index Writer 停了，Location Service 健康且索引可读，查询可以继续但越来越旧；整个服务层不可用，Edge 只能路由到健康实例，没有实例就让 GET、PUT 都返回 503。索引不可读由 Service 本地超时检测产生 503，红线表示失败依赖传播，不是索引真的发送 HTTP 503；不能返回完整空列表。若部分格子超时，默认失败；产品允许部分召回时显式 partial=true，不能声称结果就是全局最近二十。

位置新鲜度从可信的 observed_at 算，而不是服务接受时间。三十秒前采样、现在才到的包，不能在 accepted_at 上拿到新的三十秒。查询在每次输出时检查年龄，即使成员由缓存命中而来；Redis EXPIRE 针对整个 key 的寿命 [7]，不会为一个 GEO sorted set 的每位成员独立建立位置新鲜度。清理任务删除过龄成员是节省空间，在线年龄判断才决定可否显示。

地点的时钟不同。一个餐馆的坐标一年没改，并不表示它早就过期。A8 的二十四小时指目录复制或同步水位落后多久，不是 now 减 last_modified。索引长期未追上时标降级或失败；未修改且权威仍公开的地点持续有效。移动端与地点不能拿一个 TTL 同时代表真实性和业务可见性。

私人经纬度留在服务信任边界内。公开商户明确发布的图钉可以返回；私人移动端先确认共享许可与受众，默认不给陌生人查，属主读取自己的最新位置走有凭证的权威读。撤回共享时权限判断不得依赖旧格快照，权限依赖不可用就拒绝私人结果。删除和撤回还要让缓存、事件及备份按保留策略失效。

一百米距离桶只降低单次响应精度，不能保证匿名。攻击者从三个不同查询中心拿到三个距离环，再求交集，就能缩小位置区域；排序、成员是否出现、稳定 id 也泄漏约束。授权受众、限制查询中心变化与频率、减少稳定标识和短保留一起减风险，桶不是这些控制的替代。W3C Geolocation 原文要求位置接收方按约定目的使用、保护访问并提供更新删除能力 [8]，它没有承诺某个桶宽能阻止定位。

监控要对准失败契约：覆盖格数、每格成员和读取字节、完整与部分响应比例、索引可见延迟、样本观测年龄、路由 epoch 错误、每键缓存回源和拒绝率。只盯 HTTP 200 看不见新格漏召回和旧样本续命；只盯平均索引延迟也会遗漏尾部积压。用已知跨格样本校验召回，能发现「索引看起来健康但边界店消失」这类功能错误。

Failure behavior and data boundary

Distinguish failed components. With Writer stopped, a healthy Location Service can query a readable but aging index. If all service instances are unavailable, Edge cannot preserve query logic: both GET and PUT return 503. For an unreadable index, Service detects the local timeout and produces 503; red arrows represent dependency-failure propagation, not an HTTP packet sent by the index. A timed-out cell either fails the request or returns explicitly partial results; partial recall cannot claim the exact global nearest twenty.

Use trusted observed_at, not acceptance time. A sample taken thirty seconds ago and arriving now does not gain another thirty seconds. Check age on every response, even a cache hit. Redis EXPIRE concerns a whole key [7], not independent freshness for every GEO sorted-set member. Background cleanup saves space; online age checks decide visibility.

Places use a different clock. A restaurant unchanged for a year is not expired. A8’s twenty-four-hour bound is projection or synchronization watermark lag, not now minus last_modified. Mark prolonged projection lag degraded or unavailable; unchanged, still-public authoritative places remain valid. One TTL cannot represent validity and visibility for both places and movers.

Private coordinates stay within the service boundary. Published merchant pins may be returned. Private movers require a sharing grant and audience; strangers are denied by default. Owners read their latest row through authenticated authority access. Revocation cannot depend on an old cell snapshot, and unavailable authorization fails private results closed. Apply deletion and retention to caches, events and backups.

A 100 m distance bucket reduces one response’s precision, not anonymity. Three probing centers yield three annuli whose intersection narrows location. Rank, membership and stable identifiers leak constraints too. Audience authorization, probe/rate controls, fewer stable identifiers and short retention reduce risk together. W3C Geolocation discusses purpose-limited use, protection and update/delete access [8]; it makes no claim that a bucket width prevents inference.

Monitor covered cells, candidates and bytes per cell, complete versus partial responses, visibility lag, observation age, route epoch errors, cache origin loads and rejection rates. HTTP 200 does not reveal new-cell misses or renewed stale samples; mean lag misses tails. Known cross-border samples can expose disappearing nearby places even when the index appears healthy.

追问与容易翻车的答案 Follow-ups and answers that fail

「只做商家，一台数据库够吗？」够当第一版。原始索引约 128 MB、编辑约 0.13 次/秒，优先验证真实执行计划与 p99。空间索引、只读副本与缓存都是可选增量。只有某片工作集或热点超预算才拆；不要拿一千万日活、某图商峰值或年份替代当前输入。

「上报成功后查不到，读权威不就好了？」自己读自己能直接查 entity_id，但附近查询没有那个 id。漏的是召回，新格里没有成员，回表无从开始。强制可见要等投影水位或合并新写召回，支付额外同步代价；仅把过滤改成强一致不会解决。

「半径放大，但范围请求更少，所以更快？」未必。精度降低把多次 key 定位收成较少的范围请求，但一公里到五公里面积二十五倍，候选仍增长。候选下界、距离计算和详情过滤都要进预算。原型用 COUNT ANY 更快时也要承认最近排序变成近似。

「每三秒上报一次呢？」A5 改为每分钟二十次，80,000 × 20 ÷ 60 ≈ 26,667 次/秒，是原预算五倍。相同九十六字节历史是约 221.18 GB/天，最新工作集仍只是一行每实体。Writer 并行度、队列分区和热格负载才需要跟着变；版本和新鲜度规则不能省。

“One database for places?” It is a valid first version: about 128 MB raw index and 0.13 edits/s. Validate actual plans and p99. Spatial indexes, read replicas and caches are optional increments. Split when a measured shard or hotspot exceeds budget, not because of a DAU slogan, vendor peak or year.

“Why not read authority when an acknowledged report is missing?” Owners can read their entity ID, but nearby recall has not obtained that ID. A missing new-cell member cannot start a hydration read. Strong visibility requires a projection watermark or recent-write recall layer. Stronger filtering alone does not fix recall.

“Larger radius with fewer ranges must be faster?” Not necessarily. Coarser precision reduces range requests while a one-to-five-kilometre change grows area 25×. Candidate work, distances and details still grow. Using COUNT ANY for speed also requires admitting approximate nearest results.

“Reports every three seconds?” Change A5 to twenty/minute: 80,000 × 20 ÷ 60 ≈ 26,667/s, five times the base. Ninety-six-byte history is about 221.18 GB/day; latest rows still keep one per entity. Revisit Writer concurrency, queue partitions and hot-cell load without dropping versions or freshness.

收尾：三个约束必须落到图上 Close: three constraints must change the drawing

第一条是覆盖完整。六位 geohash 在四十度约 0.934 × 0.610 km，一公里圆在格心碰十一格，任意中心外接盒最多二十；先粗筛再距滤，跨格与前缀断裂都要召回。第二条是状态与时钟。权威最新行、事务 outbox、投影水位、缓存年龄和采样年龄分别回答不同问题，200 不承担未发生的索引可见。第三条是热点与权限。只对打满的格子复制并追增量、双读切换、等旧读者再回收；私人位置的受众授权先于返回距离桶。

可以把面试终图收成一条查询、一个权威行、一个派生格索引。单库仍是地点主线的有效方案；异步 Writer、局部拆分和移动端写路径都是约束变化后有原因地长出来的笔。下一章 Ch20 继续把这里点到的队列分区、重放和消费确认展开。

First, complete coverage: at 40 degrees a six-character cell is about 0.934 × 0.610 km; a centered 1 km circle touches eleven cells and an arbitrary-center box at most twenty. Recall then measure, including cross-border prefix breaks. Second, state and clocks: latest authority, outbox, visibility watermark, cache age and sample age answer different questions. A 200 cannot assert unperformed projection. Third, hotspots and permissions: copy/replay a measured hot cell, dual-read through cutover and wait for old readers; authorize private audiences before returning buckets.

The interview ends with one query, one authoritative latest row and one derived spatial index. One database remains valid for places. Async Writer, local splits and mover reports are added only when constraints change. Ch20 expands the queue partitions, replay and acknowledgment introduced here.
