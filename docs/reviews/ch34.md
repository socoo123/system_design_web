## 主线与实现

先完成[完整预检](ch34-preflight.md)，再重排为“持久接单/领取 → 固定输入的step → workflow业务边 → 两库恢复 → handoff → 审批/取消 → 补偿”。去掉重复开场、故障结论和旧新版本比较；A1–A12与详细容量收进details，双语同步。保留正常路径、每种失败窗口和容量推导。13张网格闪卡同步，新增已存模型输出复用卡；handoff卡明确A的grant不授权B。

4段页面代码逐字同源，[同步脚本](../../examples/ch34/sync.mjs)检查：

- [claim.sql](../../examples/ch34/claim.sql)：真实SQLite条件领取、DB时间、epoch/version与状态门；实际在BEGIN IMMEDIATE内执行。RETURNING行不是COMMIT承诺，模糊ACK先查回。
- [step.pseudo](../../examples/ch34/step.pseudo)：逻辑step与物理attempt分开；固定模型/工具/流程/输入revision、检索/时间/随机值，已提交输出复用；明确前置事务产生`attemptVersion`，结果事务不能误用旧入参version。
- [resume.pseudo](../../examples/ch34/resume.pseudo)：先持久停车再释放槽，批准早到后复读，权威完整binding、唯一decision与pause/version CAS；决定/READY/outbox同事务。
- [recover.pseudo](../../examples/ch34/recover.pseudo)：先查原key；同key重放前还有owner/cancel/deadline事务门。UNKNOWN保留，取消后迟到效果照样记账；补偿与人工case均保留稳定身份/义务。

[可执行适配](../../examples/ch34/model.py)和[运行说明](../../examples/ch34/README.md)用Python标准库、两个独立SQLite数据库与多连接真实事务。当前run/step、last_seq及事件形成逻辑checkpoint；不是完整历史快照引擎。一个库不包住另一个库或HTTP；`Gateway`是窄化可信业务回执fixture，未伪装成生产工具平台。

## 纠错与边界

| 发现 | 修正 |
|---|---|
| 只叙述CAS/事务，没有可追踪实现 | 给真实SQL与三个分开的本库事务契约；网络永远在事务外，检查返回行/版本。 |
| “模型重跑”与历史重放易混淆 | 固定非确定性输入，复用已存输出；未存输出可有界重求且另计费用。已存intent不随新输出变化。 |
| LangGraph旧durable-execution链接现重定向 | 分开引用Persistence与Checkpointers；明确从旧checkpoint replay重跑后续LLM/API/interrupt，sync/async/exit落盘差异。 |
| 旧Ch33审批说明缺Agent/route，handoff可能误读为继承grant | 正文、图注、伪代码与闪卡同步完整binding；换Agent必须重新校验/批准。 |
| 实施中适配允许第二个动作并发dispatch | 主代理提前用新输入复现P1。作者加入所有其他DISPATCHING/UNKNOWN的串行门；即使传新version也拒绝。历史多在途状态逐个核账。 |
| 取消后第一个已知失败可能把仍有第二个在途的run关成CANCELLED | 未清动作优先：仍有DISPATCHING/UNKNOWN就保留CANCEL_REQUESTED且可重新claim，之后可靠迟到成功进入补偿。作者实际反例已覆盖。 |
| 独立复核P1：取消后observe局部status被run下一状态覆盖，OBSERVED把SUCCESS误写COMPENSATING | 分离动作outcome与next_status；新增取消后SUCCESS/FAILED_KNOWN事件精确断言。动作表、回执和事件保持同一结果。独立重验另记。 |
| 独立复核P1：已经observe成功再取消会停在CANCEL_REQUESTED，重复回执早返无法启动补偿 | cancel事务按在途/已确认效果/无义务分类；已确认成功直接COMPENSATING，全已知失败CANCELLED，终态保留。新增完整退款与重复取消回归。独立重验另记。 |
| 结果事务仍可能被误读为验前置旧version | 伪代码明确attemptVersion；claim/start-step/续租等返回锁内确定的token，不在释放锁后读取他人的新owner当自己的权利。 |
| SQLite版本按RETURNING误写3.35 | unixepoch从3.38新增；SQL注释、README、页面与引用全部同步最低3.38。本地实际3.51.0。 |
| 独立窄屏P2：320对照模式长代码标签挤Copy换行 | 仅将3个data-language缩为Pseudocode · step/recovery/resume；代码内容、共享CSS不变。6个真实320主题/语言组合的24个Copy按钮最终高度均28.34375px，保持单行。 |
| 取消/期限或TTL可能被误读为清空未知账 | 停前向工作；保留原key/route与未知义务。重放需有效契约，超期核查/人工；补偿成功不是DONE。 |

## 实际验证

[执行结果](ch34-code-results.json)：**101项检查通过，其中15项容量/单位复算**。Python3.11.8、SQLite3.51.0；临时两个独立数据库，多连接真实事务，不留pyc。

- 接单ACK丢失读回、同键换内容/actor冲突；6路并发claim只有一个owner；精确租约到期接管与旧epoch/version拒绝。
- 输入中的检索/时间/随机值固定，缺usage仍预留；迟到可信usage只结算一次。已存输出不新建attempt；未提交输出可变化，旧owner输出不能替换。角色revision不匹配不得静默重用步骤或发旧Agent动作。
- 真SQLite触发器让checkpoint事件插入失败，检查输出、动作与事件一起回滚；业务库回执插入失败也让扣款回滚，分别核实两个本库边界。
- 审批先于本地park、11个binding字段变化拒绝、grant过期/拒绝不恢复、6路重复恢复一次READY；8轮双连接取消/恢复竞争不复活。
- 一个动作DISPATCHING或UNKNOWN时第二动作被拒，即使使用最新version。取消后旧请求迟到成功仍记effect；6路同key业务重放只执行一次，原key换参数拒绝。
- 补偿原效果关联与唯一身份、退款后丢回包仍UNKNOWN、不提前COMPENSATED、同key查回只退款一次；人工case稳定防重、持久回执先于relay确认、确认不删UNKNOWN。
- 手工构造历史两在途状态：第一笔已知失败后仍CANCEL_REQUESTED，可再claim，第二笔迟到成功进入COMPENSATING，关闭初始P1的恢复缺口。
- 取消后动作结果与OBSERVED事件分别保持SUCCESS/FAILED_KNOWN；已观察成功后取消立即可补偿至COMPENSATED，无需靠重复回执修状态；全已知失败直接CANCELLED，重复取消保持COMPENSATED。
