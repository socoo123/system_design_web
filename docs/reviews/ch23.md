## 主线与纠错

按“成功/预算 → 结算身份与版本 → 同分全序 → 单次观察/分页 → 热点分片 → 恢复/最终快照”整理。原容量表放入 details，关键失败分支和代码保持展开。新增六段同源代码，闪卡按新主线整理为 17 张，统一 `.cards-grid`；双语、图注和复盘同步。没有为图数配额新增静态图或 D2。

| 原缺口/容易误读处 | 本次处理 |
|---|---|
| 身份仅 `(game,match,player,kind)`，修订、赛季和载荷冲突未闭合 | 唯一身份加入 season/revision；绑定完整规范化意图，异载荷冲突，同载荷返回原回执；处罚必须新修订。 |
| 更高 authority_seq 可能被误当作没有漏局的证明 | 明确每个 game/season/player 的持久单调完整累计前缀；若是独立增量，须先账本去重求和，不能丢旧事件。上游账本未在本例实现。 |
| 去重保留期、归档重放和两目的地 ACK 未落地 | 不做任意 TTL/GC；永久关门、重放栅栏和在途排空后才清理；global/region 独立 ACK，原回执不随当前分数变化。 |
| 独立复核P1：按接收端当前同分猜达成秒，会因乱序得到不同名次 | 权威完整快照同时给出score与achieved_second，接收端按更高版本一起覆盖；来源在规范顺序保持连续同分时间，处罚返回旧分用新修订时间。保留首次0分、连续同0分来源时间，以及全部6个v1/v2/v3到达排列的SQLite/真实Redis收敛探针。 |
| “脚本原子、先 ZADD 再版本”容易被误作错误回滚与故障恢复证明 | 实际 Lua 先做类型/输入/scope/epoch 校验；相同版本核对 C 与状态一致。运行时错误与 failover 隔离整 epoch、不推进；真实 Lua 写后报错仍留值反例已跑。控制器/健康协议是外部依赖。 |
| epoch 与不可变数据集混用，活榜分页未定义 | 明确存储 epoch 内数据仍可变；精确分页绑定保留的 snapshot_id/比较器/scope，签名/鉴权由 HTTP 适配器负责；过期 410。给出活榜 offset 重复/遗漏反例。 |
| 切桶后的 exact 标签缺完整来源证明 | manifest 绑定不可变 snapshot、scope、routing、order 与完整桶集；缺桶/混快照/重复玩家/未排序/partial 均拒绝。完整回包字段的真实性仍由存储适配器负责。 |
| 重建时基线/尾流、校验和切换可能混时刻 | 要求无缝快照/提交流边界、保留日志；最终短暂停权威写、排空、固定 W、停止投影写者、按固定集合校验后 fenced CAS；不把目录 CAS 当全球快照。CDC/控制器未实现。 |
| head 的 30 秒可能被读成事实最新 30 秒 | 限制的是自成功捕获的完整快照年龄，缓存命中不续期；另外显示源应用水位/滞后。投影 p99+2秒刷新可接近4秒，不是硬界。 |
| 新 snapshot_id 可能触发重复发全部原奖 | 明确新版本只产生差额/追回义务，不以新快照 ID 重发全部原奖；资金/下游幂等留给 Ch24。 |

重建的每代消费进度必须独立于旧投影的 ACK，尾流来自保留的变更流；不能拿旧 epoch 的 delivered 位跳过 E+1 的构建。页面描述的是上述协议依赖，不宣称现有单进程探针实现了重建/CDC。
