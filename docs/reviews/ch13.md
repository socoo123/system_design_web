## 保证与纠错结果

| 原缺口 | 最终行为与边界 |
|---|---|
| 相同版本直接算已应用 | external 严格递增写；409 后 realtime GET：更高版本可确认过时，同版本同摘要才是重放，同版本异摘要停源分区。未知写/读结果不推进 checkpoint。 |
| 长期墓碑只是文字要求 | 删除也对同 ID 执行 INDEX，写无旧正文的 `deleted=true` 记录，版本与替换同一原子操作；所有查询强制 deleted=false。示例不物理回收/不复用 ID，重建也灌入保留删除版本。物理 DELETE 版本受 gc_deletes 清理，不能作为永久保证。 |
| 缓存回填可能延长旧快照 | 捕获同一配置 g 供具体索引/分析规则/缓存键使用。绝对 not_after 从查询开始计，迟到填充不续命、读取仍校验。跨节点时钟需已知误差，33 秒是健康目标预算。 |
| 跨系统“原子切别名和缓存世代” | 发布一份配置指针；旧请求继续写旧键，新请求用新具体索引/命名空间，不声称 ES alias 与独立缓存同事务。 |
| 局部 top-k 与全语料 BM25 混淆 | 证明只对约定同一总序成立。Java 按固定 score/tie 合并；分片本地统计的数值排序可执行，但不等于全语料 BM25。全局词项统计需额外通信。 |
| 缺片与过滤后短页未分清 | 默认缺片/超时/fetch 失败整页 503，无成功 cursor/完整缓存。可选 partial 仅为带 missing 的近似首屏。PIT 完整页的 complete 表示必要分片齐全，truncated 另表扫描预算耗尽。 |
| 过滤掉全部候选后锚点可能停住 | 每条候选先推进 last_scanned_sort 再查权威。每页最多扫描 100 个，预算耗尽可空页+truncated+推进后的 cursor；真正到达快照末尾才结束。最新 PIT ID 每轮更新，context 变化/伪造/过期均拒绝。 |
| “严格删除立即生效”易被绝对化 | 权威检查覆盖缓存与旧 PIT，失败关闭；承诺反映检查前已提交的删除/撤权，不声称能撤回之后已在途响应。逻辑 tombstone 不代表旧段/备份立即物理擦除。 |
