## 纠错与关键边界

| 原缺口 / 实施期发现 | 最终行为 |
|---|---|
| 零代码、熔断仅外链Ch42 | 展开受理/消费SQL与本地熔断状态；读重试把时间、配额、熔断和槽位责任串到同一调用。 |
| 初稿worker要求220ms阶段仍完整剩220ms，任何正调度延迟都会拒绝 | 已改明确100ms有用下限，220ms为含调度的上限。Java覆盖1ns/1ms正延迟、100ms边界、99.999999ms拒绝与回程余量。主代理提前只读发现与作者同刻修正，不冒称正式独立复核关闭。 |
| 初稿异常可能只释放槽而未finish半开票据 | 预期网络错误归一为依赖FAILURE，意外本地异常显式catch/IGNORED并收尾；executor拒绝也finish/release/STOP。票据完成去重，避免探针遗漏。 |
| “700ms预算”可能被读成端到端硬承诺 | 中英/图注/终图改“planned”，晚醒与调度可吃100ms余量。worker临发不足100ms停止，始终保留140ms完成预算；不声称OS或网络硬实时。 |
| 20/s额外预算没有窗口口径，容易被实现成每实例桶 | 明确共享权威以固定秒条件计数used<20，200原始+20额外=220准入；边界可能集中，不是严格滑动限额或物理网络匀速。 |
| Stripe幂等引用泛化 | 重新核查后限定API v1首响应/参数比较；说明裁剪后可重执行、v2语义不同，本章7天结果+永久映射为自定政策。 |
| READ COMMITTED冲突/查询及延迟FK缺少近旁来源 | 补PostgreSQL18隔离/CREATE TABLE一手来源；查询为空不能据此宣称旧事务已回滚，UNKNOWN同K恢复。 |

## 独立复核期间：额度异常也要统一收尾

Ch43独立复核发现P1：初稿把共享额度适配器放在worker的try外，额度SDK/解析异常会漏
`finish(ticket)`和`release(slot)`，半开探针与舱壁可能长期占用。现整个worker的临发检查、
额度与Inventory I/O共用外层try/catch/finally；finally补一次IGNORED finish（票据去重）并
归还已经终止的本地槽。意外本地异常不再绕过收尾。

额度一次调用的截止为`min(now+10ms, attempt_end−100ms)`，遵守取消，不做SDK自动重试；
三态统一为GRANTED/DENIED/UNKNOWN，仅GRANTED可继续，返回后临发再核时间。
UNKNOWN可能已经消耗额度，允许浪费令牌，不能以新额度调用追扣。若本地I/O仍活，
调用方timeout仍不释放槽；这不是远端rollback证明。

Java17实际guardedBody增加额度异常、未知结果、额度完成晚于有用下限及正常探针成功的
资源收尾验证；不冒充真实quota SDK/服务。正文、README和同源摘录已同步。
11条本地命令、4段同源及21项算术通过；受影响320/390×两主题×三语言12组合、
72次翻帧和4段复制另见 [quota浏览](ch44-quota-browser-results.json)。
Ch43以自己的新输入重验，包括Error和仍活额度线程，独立关闭见
[ch44独立quota重验](ch44-independent-quota-after.json)；正式整章独立签字由复核者另发。
