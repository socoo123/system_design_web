| 机制 | 关键实现与边界 |
|---|---|
| 可用目标与负载口径 | 等容量P2C先筛READY/当前健康快照，抽两个不同候选。`observedActive`是一个入口观测的未结束attempt，不是全局精确负载；快照为空拒绝是显式政策，不冒充Envoy默认panic行为。 |
| App并发准入 | 一台App一把锁检查incarnation、READY、锁后monotonic deadline和limit，再记录permit；本例零队列。两个入口争最后一额度仅一者成功；真实handler/stream完成后才释放，重复/错Gate完成不双减。 |
| 计划下线 | `beginDrain(expectedIncarnation,revision,budget)`先校验代次再本地拒新，随后协调器发布移除。精确代次/revision的可信确认与真实active=0允许干净退出；重复drain不续长截止。 |
| 截止与恢复 | 截止返回FORCE_REQUIRED，不清在途、不把cancel当完成。物理退出由supervisor观察。DRAINING/UNHEALTHY旧门不再READY；新进程使用新incarnation，旧命令/回调不能影响它，禁止同进程另建Gate隐藏旧工作。 |
| 写结果未知 | 具体提交→丢201→原键查结果轨迹；主体/资源/参数绑定、同库效果/结果与留存期为Ch24依赖，不把本章扩为第二套订单/支付工程。此项是契约推演，没有冒称实际业务DB实验。 |

完整代码为 [LoadBalancing.java](../../examples/ch39/LoadBalancing.java)、[线程/异常验证](../../examples/ch39/LoadBalancingTest.java) 与[运行和集成前提](../../examples/ch39/README.md)。三个页面摘录由 `sync.mjs` 按命名区域逐字同步，只去公共缩进；它们是可运行完整示例的教学摘录，不是可单独编译的完整类。

正常轨迹实际执行：两个READY候选active=8/2选后者；WARMING拒绝，READY发一个permit，真实完成释放；本地关门后新请求拒绝，确认移除且旧请求结束则CLEAN_EXIT。关键反例实际执行：双入口最后一额度、锁等待跨deadline、重复完成、drain截止仍有活工作、缺ACK、迟到探测/代次/ACK/drain与旧回调。受控clock配合真实Java线程复现锁等待，不能把它称为真实网络超时实验。
