## 主代理预审与独立计算

[算术与反例记录](ch06-ch07-ch08-numeric-review.json)独立复算：Ch06固定热点两副本各18,000读/s，超过12,000预算50%；三副本分摊仍约14,667。写入只在A形成新值时，先读AB可见新值，异步修复前再读BC可返回旧值。strict集合相交与sloppy集合空交集分别枚举，不将R+W>N称为线性一致性协议。

Ch07中41位毫秒时间约69.682842年；4,096/ms为编码槽位上限。号段库存1,100个在正常5,000/s时只支持0.22秒，故障接管10,000/s后只支持0.11秒。全零元组产生0，正数契约必须显式排除。恢复同worker旧窗口并重置序列会重复；新窗口必须与所有已授窗口不重叠，不能把进程重启当作新数值命名空间。

Ch08的20ms热点串行工作理论上限50/s；1,000次获取、80%成功加释放为1,800条命令，重试成功后还要再计释放。客户端预算10−0.1−0.2=9.7秒；新世代34仅被签发、尚未安装到资源时，资源的旧值32仍可接受33，不能把发号时间当作旧写全被阻断的时刻。

主代理实际抽核了[Dynamo原论文](https://www.allthingsdistributed.com/files/amazon-dynamo-sosp2007.pdf)、[Cassandra读修复](https://cassandra.apache.org/doc/latest/cassandra/managing/operating/read_repair.html)、[Twitter历史Snowflake源码](https://github.com/twitter-archive/snowflake/blob/snowflake-2010/src/main/scala/com/twitter/service/snowflake/IdWorker.scala)、[UUID标准](https://www.rfc-editor.org/rfc/rfc9562.html)、[Redis WAIT](https://redis.io/docs/latest/commands/wait/)及[etcd API guarantees](https://etcd.io/docs/v3.6/learning/api_guarantees/)。Cassandra阻塞修复针对失败少数写的读回退；Twitter源码只保护本地状态，未提供本章的持久窗口管理；WAIT和revision接口不能替外部资源实现业务原子校验。各章作者与独立记录有更细的事实对应来源。

## 复核返修

本批共关闭 **3项P1、1项P2**，均在Ch06；Ch07和Ch08独立复核无新增阻断问题。

- **WAL校验顺序（P1）**：原伪代码先持久化，再调用可能拒绝同版本不同内容的合并函数。改为同一key/epoch保护内先校验并计算next，再WAL同步、最后发布可读状态，避免无效记录先进入恢复日志。
- **向量actor因果前提（P1）**：两个客户端共用协调节点counter，即使计数递增，也可能把未见并发错误当祖先。明确actor必须是携带自身完整前序context的串行因果writer，并发writer用不同actor；增加共享actor失败反例和独立writer正例，不把纯函数当完整Dynamo协议。
- **墓碑GC的旧请求来源（P1）**：副本全部修复并清墓碑后，客户端迟到PUT仍能复活值。默认保留墓碑、不实现GC；任何清除方案必须覆盖客户端重试、在途RPC、hint、备份与退役副本的全部旧写准入，或保留所有写入口都验证的持久删除水位。新增实际Java反例；水位仍属压缩墓碑。
- **代码性质标签（P2）**：伪代码由笼统text改为quorum write/read标签；Java明确是完整可运行示例的节选并链接源文件。

作者同步正文、英文、闪卡和代码源；复核者重新执行并核对关闭。Ch06最终Java为23个场景（含64个合法LWW组合），另有7条ACK事件轨迹；Ch07独立追加12个边界断言；Ch08在作者18条预算断言外独立追加9条截止点/晚到OK/单调时钟回绕检查。
