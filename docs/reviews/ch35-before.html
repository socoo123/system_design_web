30 秒开场：平台管版本、设备和上线承诺Opening: versions, devices and serving promises

中文

我设计一个内部多租户 LLM 托管平台，主模型峰值 20 req/s，小模型单独预算。业务通过 Ch32 Gateway 进入，Inference Router 固定完整 serving tuple，只有匹配版本、健康且有真实准入额度的 Model Worker 才接单。控制面把不可变 artifact、部署 desired 和单调路由 revision 存下来，再协调 GPU 放置、加载、预热和 drain。生产副本跨三台机器，容量按实测 goodput 与单机故障验算；新权重先灰度，坏了用更高 revision 选回健康旧版本，旧流保持原版本到物理退休。租户既有 token 账，也有 GPU 占用与隔离边界。

先问七件事：多少模型与版本、请求长度分布、是否流式与最长时限、在线和批能否分池、哪些租户要求私有设备、允许哪一级故障、全量发布时愿不愿付双跑容量。默认一个地域，机器故障可降级，可接受有界路由传播；不承诺跨地域无损续写。训练与完整 MLOps 不展开，LoRA 只讨论 base 兼容和版本绑定。

Ch29 解释单次推理与 KV 页，Ch32 管 API 路由和 token 账，本章负责它们背后的模型托管。不能把 registry→scheduler→pool 画成每个 token 的必经路，也不能把调度器当成轮询 HTTP 负载均衡。关键问题是“谁证明这个 endpoint 真能承接这条请求”。

English

Design an internal multi-tenant LLM hosting platform: main-model peak 20 req/s, smaller model separately budgeted. Ch32 Gateway calls Inference Router, which pins a full serving tuple and admits only matching, healthy Model Workers with real capacity. Persist immutable artifacts, deployment desired state and monotonic route revisions; reconcile GPU placement, load, warmup and drain. Spread prod across three machines and size by measured goodput/node loss. Roll back via a higher revision selecting healthy old content; pin existing streams until physical retirement. Separate token accounting, GPU occupancy and isolation.

Clarify model/version count, length distributions, streaming/deadlines, online/batch separation, private devices, tolerated failures and willingness to pay for overlap. Assume one region, degraded node-loss service and bounded route propagation, without seamless cross-region continuation. Training/full MLOps stay outside scope; LoRA discussion covers compatible bases and version identity.

Ch29 explains per-request inference/KV pages, Ch32 owns business API routing/token accounting, and this chapter hosts their models. Registry/scheduler/pool are not a token pipeline. Placement differs from HTTP endpoint selection; ask who proves an endpoint can accept this request.

请求面与控制面：token 回程和就绪回路分别闭合Request and control planes: close both loops

正常路径：固定一次，再逐跳返回Normal path: pin once, return hop by hop

中文

Gateway 交入可信 tenant、model 别名、输入与期限。Inference Router 从一个原子快照取出 route revision、完整 bundle、候选 endpoint 与隔离政策，为请求固定选择；后续重试只能落在契约允许的同一组合。数据走 Gateway→Router→Model Worker，再逐跳返回。Router 可以把选择和转发做在同一组件，也可以把 Endpoint Picker 拆成只给代理选端点的服务；公开 Gateway API Inference Extension 的 picker 就属于后一类，不能把 picker 错画成承载全部 token 的代理。[5]

平台热路径不逐次下载权重，也不等待 Fleet Controller 排卡。Registry 管已封存的版本与别名，Platform Store 保存它以及 desired 部署、路由快照。Fleet Controller 读取期望数量，放置副本、加载、预热，把 worker 上报的 observed 状态持久化。两个回路在“允许路由的 endpoint 集合”相交。论文或产品里的多个控制器可在白板上收成这一个角色，但组件的权威和同步边界仍须说明。[10]

English

Gateway supplies trusted tenant, alias, input and deadline. Router pins route revision, coherent bundle, eligible endpoints and policy from one atomic snapshot; retries obey that bundle. Data goes Gateway→Router→Model Worker and reverses. Selection/forwarding may be combined, or a separate Endpoint Picker may only advise the proxy, as in Gateway API Inference Extension [5]; do not draw the picker as carrying all tokens.

No per-request weight downloads or wait for Fleet Controller. Platform Store holds sealed registry records, desired deployments and routing snapshots. Fleet Controller places/loads/warms replicas and persists observed state. The planes intersect at eligible endpoints. Multiple implementation controllers may collapse into this whiteboard role while authority/synchrony stay explicit [10].

决策与代价：期望先持久，协调可重试Choice and cost: durable intent, retryable reconciliation

中文

一条扩容命令不足以承诺多副本。把 deployment_id、bundle_hash、replica_id、设备集合和 generation 先写成 desired，每次协调比较实际差额。创建用稳定 replica_id，回包丢失查现有资源；多个控制器通过条件写争拥有权，设备分配也必须唯一预占，不能仅靠“我看这张卡空着”。新 owner 代次更高，节点 agent 拒绝旧代次控制命令与旧 ready 报告。这里的节点隔离仍由具体进程/设备管理完成，库里的 epoch 不会自动杀死旧进程。

代价是状态库、协调扫描与一段期望不等于实际的时间。简单内部平台可先人工设 desired，由一个控制器反复协调；无需第一天就把每个策略拆成服务。在线请求选择仍依据可服务的实际状态，不能直接拿 desired=9 当作已有九台。扩容失败留下明确 reason：设备不足、分组放置不满足、artifact 不可读或预热失败，才能让运维知道该补卡还是回退版本。

English

Persist deployment/bundle/replica/device/generation intent, then reconcile actual gaps. Stable replica IDs let uncertain create calls query existing resources. Conditional ownership and unique device reservations prevent double placement; agents reject stale control generations/readiness. Database epochs do not physically kill old processes.

Costs include durable state, scans and convergence delay. Start with manually set desired and one controller if sufficient. Routing uses observed serving capacity, never desired=9 as nine ready workers. Persist causes such as device shortage, group-placement failure, unreadable artifacts and failed warmup to guide repair.

故障窗口：控制面失联，数据面也有期限Failure window: control loss has a finite serving contract

中文

控制面慢了，当前可用 worker 不应立即全部停，但旧快照也不能无限有效。A9 的快照带权威签名、issued/expiry 与 revision，本地按最坏时钟误差提前截止；网络隔离不刷新 issued 时间。Router 缓存没有新增批准能力，到期停止新准入，已接收的流继续按固定 bundle 和 60 s 请求期限退休。恢复先获取当前完整快照，再重新放行；变更事件只提醒重新读，丢事件由轮询补齐。

这个选择会牺牲长时间控制面故障期间的新请求可用性，换来版本与隔离政策的有界陈旧。允许缓存一直服务是另一种取舍，但撤销的旧版本和租户政策也会一直有效，必须让面试官确认这层业务代价。不要声称“控制面完全不在可用性链上”，也不要宣称写了路由库就让所有 Router 瞬间切换。

English

Healthy workers need not stop immediately during control delay, but A9 snapshots carry signed issuance/expiry/revision and conservatively expire under bounded clock error. Isolation never refreshes issuance. Routers stop new admission after expiry; accepted streams retain bundle and sixty-second lifetime. Recover by reading a full current snapshot; hints trigger reads and polling repairs missed hints.

This trades new-request availability during long control loss for bounded version/policy staleness. Indefinite cache serving is possible only if business accepts indefinitely effective old versions/policies. Control remains a bounded dependency; a store commit does not instantly update every router.

模型仓库：不可变内容，到可路由 READYModel registry: immutable content to routable READY

正常路径：先封存内容，再登记组合Normal path: seal content, then register the bundle

中文

发布者只获指定模型与环境的写权限。先把所有 shard、tokenizer/config 与可选 adapter 上传对象存储，逐文件校验后封存 manifest，manifest_hash 成为内容身份。Registry API 确认对象完整可读，才在 Platform Store 登记 release。多文件版本不能只固定一个主文件 hash；下载逐个使用同一不可变 revision，避免主分支在下载中途变化，Hugging Face 的 commit revision 下载提供了这个版本固定工具。[2]

Serving bundle 至少钉住权重、tokenizer、prompt、engine image digest、量化与运行配置、可选 adapter 及 base 身份。prod/canary 是可变名字，解析一次得到 bundle；MLflow aliases 是公开的可变版本引用，不能把这个特性当作厂商自动提供本章所有原子发布保证。[1] 把别名映射、路由权重、批准者、发布幂等键和 revision 放在一次事务里，两个发布者按 expected_revision CAS 竞争。相同键不同内容报冲突，不允许后到者覆盖前一结果。

English

Publishers get scoped model/environment authority. Upload all shards, tokenizer/config and optional adapters; verify per-file hashes and seal a manifest. Registry API confirms complete readable objects before registration. Pin every file to the same immutable revision, rather than one main-file digest or a moving branch; Hugging Face commit revision downloads supply that primitive [2].

Pin weights, tokenizer, prompt, engine image digest, quantization/runtime configuration and optional adapter/base. Resolve mutable prod/canary once. MLflow aliases illustrate mutable references [1], not all this chapter’s atomic guarantees. Atomically write alias targets/weights/approver/idempotency key/revision; concurrent publishers CAS expected_revision and reject conflicting same-key input.

选择与代价：prompt 独立开发，上线仍固定全组合Choice and cost: independent prompt development, coherent serving

中文

Prompt 单独灰可以复用已加载权重，减少第二份权重占用，但长 system prompt、更多工具 schema 或解码上限仍增加 prefill、KV 和驻留时间，不能写“几乎零 GPU 成本”。prompt、权重和 tokenizer 分开取最新值会形成未测组合，Router 必须携带同一 bundle。LoRA 作为小 artifact 绑定兼容 base 与精度配置；引擎支持热挂也仍要测试加载能力和租户授权，不能让任意上传包接到任意 base。

代价是版本组合数与兼容验证，收益是能追溯输出到底来自什么。所有日志用 request_id、bundle_hash、route_revision 与 replica generation 关联，不能只打 model=prod。回滚选旧内容时路由 revision 继续增长：r41 指 v2，r42 指回 v1；客户端不能拿“v1 较旧”拒绝合法回退。内容身份和发布序号解决的不是同一件事。

English

Prompt trials reuse loaded weights and save a duplicate weight allocation, but longer prompts/tool schemas/output caps increase prefill, KV and residence. Independently resolving latest prompt/weights/tokenizer creates untested combinations; carry one bundle. LoRA pins a compatible base/precision configuration, and hot-attachment still requires capability/authorization validation.

Compatibility testing and combination management cost work, but logs can trace request_id/bundle_hash/route_revision/replica generation instead of only model=prod. Rollback increases the routing revision: r41 selects v2, r42 selects v1. Older content may be selected by a newer valid publication.

失败窗口：对象提交、加载完成和 READY 都不等价Failure windows: object commit, load and READY differ

中文

对象已封存而 registry 事务失败，留下不可达的孤儿，按引用和留存清理；先写可用版本再异步上传，则请求可能读到缺片，所以顺序不能反。注册成功只证明版本存在，不证明设备可服务。Worker 拉 manifest、验 hash、加载指定镜像和设备组，再跑覆盖代表性长度的 warmup。READY 上报含 replica_id、generation、bundle_hash 和设备身份，控制器只接受当前代次的完整证明；旧进程迟到 ready 不得复活它。

A6 取 40 GB÷2 GB/s=20 s，另加 100 s 校验/加载/预热，共 120 s。这是组合与链路的假设，不是“70B 一律分钟级”的公开规律。九份完全冷拉为 9×40=360 GB；若对象出口合计仍只有 2 GB/s，光下载的总工作就至少 180 s，不能把九台当作各有独享 2 GB/s。节点内容缓存可省重复字节，但共享盘和解包 CPU 仍要限并发，损坏缓存必须校验后重新取。

English

Sealed bytes without registry commit become unreferenced cleanup candidates; publishing before asynchronous upload exposes missing shards. Registration proves existence, not serving. Worker verifies hashes, image/device group and representative warmup, then reports replica/generation/bundle/device identity. Only current complete proof publishes endpoints; late old-process readiness cannot revive them.

A6: 40 GB/2 GB/s=20 s, plus 100 s gives 120 s. This is not a universal 70B loading claim. Nine cold copies total 360 GB; with only 2 GB/s aggregate egress, download work alone needs at least 180 s. Content caches save repeated bytes but still need integrity checks, concurrency limits and disk/CPU budgets.

GPU 放置与容量：先算正常，再算失去一台GPU placement and capacity: normal load, then node loss

正常路径：三笔算术分别约束副本数Normal path: three independent sizing constraints

中文

先算占用下界：A1 的 20 req/s×8 s=160 条平均活跃序列，A2 的 32 槽给出 ceil(160÷32)=5。五台的总槽恰好等于平均需求，长度波动就可能排队，而且这个除法没有证明每秒能生成多少 token。再取独立 goodput 假设 4 req/s，正常按 80% 留余量，每副本规划 4×0.8=3.2 req/s，ceil(20÷3.2)=7。vLLM 调参文档把 max_num_seqs、batch token 和 KV 资源一起讨论；max_num_seqs 不是自动转换成服务吞吐的单位。[6]

接着算故障。七个副本均匀放三台，分布 3/2/2，最大故障丢三台 replica，剩四台容量 4×4=16 req/s，低于 20；即使还剩 128 槽，也不能覆盖平均 160。选择 3/3/3 共九台，正常 9×4=36 req/s、9×32=288 槽；失去最大机器后剩六台，24 req/s 和 192 槽。正常吞吐使用率 20÷36≈55.6%，故障期间 20÷24≈83.3%。降级超过正常 80% 规划，必须另验 SLO，否则继续拒绝部分请求。

English

Occupancy lower bound: 20 req/s×8 s=160 mean active, ceil(160/32)=5. Five replicas barely cover mean occupancy and do not prove token throughput. Independently assume 4 req/s goodput, use 80% planning headroom: 3.2 each, ceil(20/3.2)=7. vLLM discusses sequence/batch-token limits and KV resource together [6]; sequence count is not a throughput unit.

Seven spread 3/2/2 lose three replicas on the largest-node failure: four survivors provide 16 req/s and 128 slots, below 20 and 160. Nine spread 3/3/3 provide 36 req/s/288 slots; six survivors provide 24 req/s/192 slots. Normal use is 55.6%, degraded use 83.3%, above the normal 80% planning target. Validate degraded SLO or reject some arrivals.

放置选择：硬过滤、故障域、再 binpackPlacement choice: hard filters, domains, then packing

中文

设备内存、互联拓扑、镜像兼容、租户隔离先作硬过滤。对在线生产副本按机器故障域 spread，再在合格节点内 pack 小模型或同等级工作；NodeResourcesFit 的 MostAllocated 偏向已分配高的节点，但不会替你创造应用级显存隔离。[3] 拓扑 spread 可以约束故障域分布，某些约束不满足时应 Pending，不应偷偷挤回同一个故障域。[4] 副本分布本身只是减少同时丢失，幸存吞吐仍按上一段重新算。

多卡副本要整体预留它需要的设备与网络，在整组可加载后才 ready，部分卡到位不能上路由。本文故意固定一张卡一个 replica，所以九个 prod replica 等于九张卡；如果每个用两卡，主模型生产部分就是十八卡，再加灰度和其他池另算。扩容可由队列、TTFT 与活跃占用共同触发，但冷加载期间不涨可用预算。不能只按 GPU 利用率低就缩容，prefill/decode 混合、带宽瓶颈和热回滚保留都会让这个单指标误导。

English

Hard-filter memory/interconnect/image/tenant requirements. Spread prod across machine domains, then pack eligible small/equivalent workloads. MostAllocated favors highly allocated nodes [3], not application memory isolation. Spread constraints may require Pending rather than collapsing domains [4]; independently recompute surviving goodput.

Reserve an entire multi-GPU/interconnect group and publish only when all members load. This example deliberately uses one GPU/replica; two each would make prod eighteen devices before other pools. Scale on queues, TTFT and occupancy together, but cold loaders add no ready capacity. Low utilization alone can reflect bandwidth limits, workload mix or hot rollback reserves.

替代与故障：资源不足时写明降级承诺Alternatives and failure: disclose degraded guarantees

中文

预算只够七台，就保留 spread 并声明单机故障只能服务 16 req/s，至少拒绝 4 req/s，比例 4÷20=20%，不能叫“全峰值 HA”。两台机器各放足完整 20 req/s 的热容量也能容忍单机，但设备数量与机型适配的账不同；三台九副本只是本题选定的配置。模型越来越大时先调整每副本 goodput、卡组和分布，不要把九台背成行业标准。

English

With only seven replicas, explicitly offer 16 req/s after node loss and reject at least 4 req/s, or 20% of arrivals. Two machines each carrying the full peak could also survive one loss at a different device/layout cost. Three machines/nine replicas are chosen assumptions, not an industry constant. Recompute as goodput/GPU groups change.

Initial overlap adds one canary/two small-model replicas: twelve GPUs. One canary handles the 10% request share but cannot serve a 50% share unchanged. 槽位准入：从 HELD 到物理 RELEASEDSlot admission: HELD to physical RELEASED

正常路径：提示选端点，原子动作占容量Normal path: hints select, atomic actions reserve

中文

Routing 先过滤租户、bundle、ready、故障域和快照新鲜度，再按预计 queue、KV 亲和与成本评分。异步 queue_length 只是提示，两台 Router 同时看见最后一槽会超卖，所以选中后还要原子 reserve。本文用持久 Permit Ledger（部署在 Platform Store 的表）在同一事务内检查租户占用、replica 容量与 worker epoch，建立唯一 request_key→permit。卡端 Ch29 仍最终验证实际 KV 与执行预算；拿到平台槽不能强迫引擎超过自己的显存门。

HELD 记录完整请求摘要、bundle、worker、代次与准入期限。派发前 CAS 标记 dispatching，Worker 原子消费同一 permit 后接纳 RUNNING；重复 RPC 查回接纳记录，不创建第二条生成。Worker 接收回包丢失，Router 先查询 k9，查不到也不能立刻判断未执行。需要进程崩溃恢复时，permit 的接纳身份必须可靠留存，或者隔离旧进程/设备后才允许新的执行代次，不能在仅有进程内去重表的重启上承诺恰好一次。

English

Filter tenant/bundle/readiness/domain/freshness, then score queue/KV/cost. Stale queue hints cannot serialize two routers. A persistent Permit Ledger in Platform Store atomically checks tenant/replica/worker epoch and maps request key to permit. Ch29 still enforces physical KV/execution capacity; a platform slot cannot force memory overcommit.

HELD pins digest/bundle/worker/epoch/deadline. CAS dispatching before sending; worker consumes one permit and records acceptance. Duplicate calls retrieve it. Lost acknowledgment triggers k9 query, not assumed nonexecution. Crash recovery requires durable acceptance identity or fencing/reset of old work before a new execution generation; process-memory deduplication alone cannot promise once-only restart behavior.

选择与代价：队列有硬期限，额度有真实成本Choice and cost: bounded queues, realistic demand

中文

A7 的平均等待目标 0.2 s，稳态 20×0.2=4 条平均排队。四不是队列最大值，另外设硬上限 40、每条准入期限 200 ms；任何维度先满就拒绝或进入用户明确同意的批池，不能拿 40 条排队换无限 TTFT。200 ms 是准入阶段预算，1 s TTFT 目标还要留给 prefill 与首 token。共享租户设活跃 16 上限，公平队列按预计输入/输出工作量调度；一条长上下文并不等于一条短聊天，不能只 round-robin 请求个数。

中央事务成本在本章 20 req/s 下足够作为清楚起点。更高规模可把设备信用按 epoch 分给各 Router，跨分片租户额度用保守子预算，宁可暂时少放不能超分；租约回收仍要证明旧信用不会再消费。任何快速优化都不能倒退成“每个进程各给 tenant 16 个槽”。把 RPM/TPM 成功当作槽位许可也会失败：Token 账保护流量与花费，permit 保护当前设备占用。

English

A7 mean wait 0.2 s implies four mean queued. Separately cap forty and enforce actual 200-ms admission deadlines; refuse overload or explicitly route to an agreed batch tier. Admission is only part of the one-second TTFT budget. Tenant cap sixteen and cost-aware fair queues distinguish long-context work from short chats.

At twenty req/s a central transaction is a clear starting point. At higher scale, allocate conservative epoch-scoped device credits and tenant sub-budgets; prove old credits cannot be consumed before reclaim. Never grant sixteen independently per process. RPM/TPM constrain rate/cost, while permits constrain present physical occupancy.

故障窗口：取消、过期和未知都不能提前 releaseFailure window: cancel, expiry and UNKNOWN do not imply release

中文

RUNNING 收到完成或取消进入 RETIRING。关闭 SSE 不证明 GPU kernel 已停；必须等引擎停止生成、完成设备 fence，才唯一 release 租户与 replica 占用。图里绿色边是物理完成确认，不是仅收到 HTTP cancel 200。取消 RPC 丢失就查询原 permit，不能超时后把额度赠给下一条。A7 的 60 s 是强制请求期限，超时触发终止流程，仍不绕开退休确认。

只有仍处于未派发 HELD 的记录能与 dispatch CAS 竞争而过期；派发已赢或 UNKNOWN 就留待核实。节点失联时更要隔离设备信用，排除它的 endpoint，等待进程/设备 fencing 或 reset。新 owner epoch 只能拒绝旧提交，不能证明物理工作不存在。设备重置会中断该故障域上的所有流；已发送 token 的请求明确失败，客户端若选择重新生成应使用新的业务请求，不能暗中在另一个版本无缝续写。[6]

English

Completion/cancel moves RUNNING to RETIRING. Closed SSE does not prove kernels ended; engine termination/fence precedes unique tenant/replica release. The green edge is physical completion, not HTTP cancel 200. Uncertain cancellation queries the original permit. Sixty seconds triggers termination but does not bypass retirement.

Only undispatched HELD can expire by racing dispatch CAS. Accepted/UNKNOWN dispatch stays unresolved. Remove unreachable endpoints and quarantine credits until process/device fencing/reset; owner epochs reject commits without stopping hardware. Reset breaks affected streams. After sent tokens, report failure; explicit regeneration is a new request, never silently continue under another version [6].

多租户与 KV 亲和：先隔离，再谈命中Tenants and KV affinity: boundaries before hits

正常路径：可信 namespace 与准确内容身份Normal path: trusted namespace and exact content identity

中文

身份从 Gateway 受信任上下文取得，用户字段不能指定别人的 tenant、namespace 或 salt。候选 endpoint 必须满足模型组合、权限、隔离等级、位置与健康，KV 命中只是其后的评分。缓存属于 Worker，本章图把 Prefix Cache 单独展开以标出复用边界，页分配仍在 Ch29；它与 Ch32 的语义答案缓存不同，不按句子相似度复用。新权重、tokenizer、adapter 改动会改变计算含义，必须固定确切身份和 token 前缀。

vLLM 安全文档明确把共享前缀缓存的 TTFT 差异视为 timing side channel，并提供 cache_salt 限制复用。[8] 本平台为租户注入稳定的秘密 namespace，不跨边界命中，日志也不记录原始敏感前缀。不能把这个风险写成“缓存一定返回别人答案”；正确引擎复用相同前缀状态不会自动混出其他输出，风险是观察是否存在某前缀与实现错误。salt 也不替代对象授权、进程隔离或资源公平。

English

Derive tenant/namespace/salt from trusted Gateway context. Filter bundle/authority/isolation/location/health before scoring prefix hits. Worker-local Prefix Cache is expanded only to show reuse; Ch29 owns pages. It differs from Ch32 semantic answer caching and requires exact computational identity/token prefix.

vLLM documents shared-prefix TTFT timing side channels and cache_salt-based reuse boundaries [8]. Inject a stable secret namespace per tenant and avoid raw sensitive-prefix logs. Correct reuse does not automatically return another user’s answer; existence inference and implementation faults are the risks. Salting is not authorization, process isolation or fairness.

决策与代价：私有 replica 必须说明实际设备边界Choice and cost: define the private resource boundary

中文

共享池通过租户上限和公平队列降低 noisy neighbor；敏感 B 用专用进程与明确独占或硬件分区的设备。NVIDIA 24.9.1 文档区分 MIG 的内存/故障隔离与 time-slicing：后者没有同等级隔离，申请两个共享份额也不自动保证两倍算力。[7] 专用 replica 仍 time-slice 同一卡，不能当作硬隔离；MIG 也只在支持的设备与 profile 上切分，宿主机 CPU、网络、控制面和机房故障仍共享。

约束是不能让私有数据偷偷进入共享执行，所以私有池满时宁可拒绝，或者经过显式业务策略改为同等级备用私有池。这个选择多付空闲设备与失去跨租户 prefix 命中的成本，换来清楚的边界。批与在线也分不同容量预算；批被抢占需持久进度或明确允许重跑，不能让抢占中的卡立即计作在线热容量。无需画供应商 SKU 表，面试要回答隔离哪类资源、还有哪些共同故障。

English

Use tenant caps/fair queues in shared tiers; sensitive B gets a dedicated process and explicit exclusive/hardware-partitioned devices. NVIDIA 24.9.1 distinguishes MIG memory/fault isolation from time-slicing and notes shared requests do not guarantee proportional compute [7]. Dedicated replicas time-slicing one card are not hardware isolation. MIG availability/profile fit matters; host CPU/network/control/facility failures remain shared.

A full private tier rejects or explicitly uses an equivalent private backup. Idle devices and lost cross-tenant prefix reuse buy a defined boundary. Separate online/batch budgets; preempted batch devices are not immediately warm online capacity. Explain isolated resources/shared failures rather than SKU lists.

替代与失败：命中率不能压过截止时间Alternatives and failure: cache preference yields to deadlines

中文

命中机队列长，另一合格机虽然没有 prefix 却能在期限内完成 prefill，就选后者。亲和指标陈旧只影响优化，不得影响原子准入正确性。会话并不要求永久粘住一个 replica；下一请求可以在同版本重新 prefill，正在输出的单条流则必须固定 worker/attempt，设备失败后的恢复契约回到 Ch29。共享 prefix 必须有内容兼容验证，新版本可保留旧 namespace 到 drain 完成，而不是全局误删正在用的页。

配额中的一条请求不代表相同资源。A8 的 16×4,000=64,000 个总 token 工作量示例，而 16×32,000=512,000，是八倍；这不是 KV 字节数，KV 要看有效上下文、模型头维和精度。需要同时限制输入长度、输出预算、活跃占用和 batch token，按租户拆等待与拒绝指标。提升总体利用率若靠一个租户占满长 prefill、让其他租户 TTFT 越线，就不算达成平台目标。

English

Choose another eligible uncached worker when it can finish prefill within deadline sooner. Stale affinity affects optimization, not atomic admission. A session may re-prefill on the same version next request; an active stream stays on one worker/attempt with Ch29 recovery semantics. Drain old namespaces instead of deleting pages still in use.

Sixteen requests of 4,000 versus 32,000 total tokens give 64,000 versus 512,000, an eightfold work example, not KV bytes. KV depends on live context/model geometry/precision. Bound lengths/output/active occupancy/batch tokens and inspect tenant wait/rejection. Higher aggregate utilization that violates others’ TTFT is not the platform objective.

灰度回滚：切的是新单，保留的是热容量Canary and rollback: new admissions and warm capacity

正常路径：READY 才给权重，观察够了再 rampNormal path: readiness, then traffic, then guarded ramp

中文

新 bundle 加载、warmup 和容量证明全部通过后才进路由快照。A10 的 10% 在 20 req/s 下为 2 req/s，一台 canary 的 4 req/s 假设留有余量；按请求权重分不表示 GPU 工作同样 10%，长输出、长上下文和质量变化都可能增加驻留。观察至少 5 分钟且至少 600 个可比样本，2×300=600；低流量要延长，缺数据时冻结扩展，不能拿“等了五分钟”当通过。快速严重故障可以立即撤，慢 ramp 仍保留质量人工抽查。

指标按 bundle、tenant、长度桶与 endpoint generation 拆错误率、TTFT、输出速度、拒绝和质量。A11 示例坏版本 5% 错误，在 10% 流量下聚合只有 0.10×0.05=0.005，即 0.5%，低于 1% 全局门槛；集群均值会掩盖它。p95 也不能把两份分位数简单加权，必须用分布或同类请求单独看。版本间流量构成不同，比较前固定分桶，否则短请求更多的版本会看起来无条件更快。

English

Only load/warmup/capacity-proven bundles enter a route snapshot. At twenty req/s, 10% is two req/s with one assumed 4-req/s canary. Request weight is not equal GPU-work share. Observe ≥5 min and ≥600 comparable samples: 2×300=600. Lower traffic extends observation; missing evidence freezes ramps. Severe regressions may roll back immediately; quality still needs review.

Slice errors/TTFT/output speed/rejections/quality by bundle, tenant, length bucket and generation. A 5%-failing canary at 10% share contributes only 0.5% aggregate, below a 1% global gate. Do not linearly mix p95 values; compare distributions/comparable cohorts rather than favoring the version receiving shorter inputs.

回退选择：更高 revision，健康旧组合Rollback choice: higher revision, healthy old bundle

中文

Rollback 在权威库原子写更高 revision，指向完整旧 bundle、路由权重和允许的 endpoint 集合，同事务记录审计与发布结果。发布通知是提醒，Router 按 current_revision 获取快照；乱序事件不让 revision 倒退。A9 提供五秒以内快照租约，加时钟保守截止的约束；回退后最多在旧租约有效窗口仍有新单去坏版本，这个传播边界要坦白，要求更快撤销就推失效并等待相关 Router/Worker 确认或封锁入口，不能只改别名宣称即时全局撤销。

新准入 permit 的派发期限不得超过它所依赖快照的有效期，Worker 也验证签名、tuple、epoch 和准入有效期。已有 RUNNING 流按接收时契约保留原版本与 request deadline，不每个 token 重读 prod。坏版本的在途可以选择尽力终止并给明确错误，但不能把 v1 的后半段接在 v2 之前发出的 token 后面。回退前还要验证旧 v1 健康、与客户端契约兼容且有完整峰值容量；损坏旧版本或同一机房故障不能靠别名自救。

English

Atomically publish a higher revision selecting the entire old bundle/weights/endpoints and audit/result. Hints prompt current-revision reads; out-of-order events never lower revision. Five-second leases with conservative clock handling bound old admissions, not instant global withdrawal. Faster revocation requires invalidation plus acknowledgments or ingress fencing.

A permit cannot outlive its admission snapshot; workers validate signature/tuple/epoch/admission expiry. Existing streams retain their received contract and deadline rather than rereading prod per token. Explicitly terminate faulty in-flight streams if desired, never splice v1 behind v2 tokens. Validate old health/compatibility/full peak capacity; aliases cannot repair a bad old release or a shared facility loss.

发布代价与 drain：卸卡后就不是热回滚Rollout cost and drain: unloading ends hot rollback

中文

10% 通过不等于可以用同一 canary 顶全量。每次提高权重之前先按新请求分布补 ready 容量，再校验幸存条件；最终新 v2 九台接全量，旧 v1 九台保留 A12 的 30 分钟热窗。窗口内若坏，回到旧容量；窗口后把旧版本标记停止新准入，收敛 Router 快照并等待已接纳 permit 全部物理退休才释放设备。长流到 60 s 触发终止，但 release 仍以完成/fence 确认为准；健康退休也要处理卡端回包丢失。

KServe 本次核对的 Next 文档用两个版本的相对权重实现切流，示例 9:1 对应 90/10，并提示从零权重转非零可能有 backend 预热问题。[9] 它的某些 promotion 步骤会释放旧 GPU；本章为了保留热回滚明确选择继续付旧容量，不能直接套“资源对象还在”当作旧模型已热。七天 artifact 保留支持冷恢复，30 分钟热窗支持快速回退，二者账不同。预算只够 12 卡时可收旧换新，但要把恢复降级为至少含重新加载的冷回退。

English

Ten-percent success does not let one canary serve full traffic. Grow ready capacity and validate surviving conditions before ramps. Nine new replicas serve full load while nine old stay for the thirty-minute window. Then stop old admissions, converge snapshots and wait for all accepted work to physically retire before releasing devices. Sixty seconds triggers termination, not premature release; completion acknowledgments may also be lost.

The checked KServe Next documentation uses relative weights, with 9:1 yielding 90/10, and warns of backend warmup on zero-to-nonzero changes [9]. Some promotion steps free old GPUs; this design deliberately retains them. Resource objects/artifacts alone are not warm models. Seven-day artifacts enable cold recovery; thirty-minute devices enable hot rollback. A twelve-GPU budget can reclaim old capacity only with disclosed cold-reload recovery.
