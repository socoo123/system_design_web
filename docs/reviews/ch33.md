## 纠错与事实边界

| 旧稿缺口/易误读 | 本轮明确的契约 |
|---|---|
| grant未完整列Agent/工具名/目的端；执行再验只见泛称 | 冻结完整主体、工具/route、规范参数、资源ID/version、policy和期限；旧key不可换调用者/Adapter重用，dispatch事务复查。 |
| 过期混用DENIED与EXPIRED | 未发出统一DENIED(reason=expired)，发出后不靠过期删除UNKNOWN。 |
| 解析isError后即可归工具失败 | isError本身不证明无副作用；FAILED_KNOWN必须有业务契约/回执，缺证据UNKNOWN。 |
| 当前version若先于回执检查，会使已成功重放误失败 | 业务端先比对原key回执，只有新效果走当前资源条件。已有v4→v5成功可正确重放。 |
| 缺回执/owner epoch/TTL可能被误读为可以重做 | 缺回执不能排除在途旧请求；epoch只挡本库旧写；UNKNOWN及动作身份墓碑保留。 |
| 取消释放资源泛称 | 本地等待/缓冲可结束；仍可能活跃的远端工作不立即归还额度，需要终止证据或后端硬上限。取消后可靠迟到成功必须保留。 |
| 两attempt宣称≤120/s粗上界 | 只对N个逻辑动作给≤2N总调用数；任意秒的聚集需要速率准入，不能靠attempt数保证。 |
| Stripe包括500首次结果/24h未标版本 | 限定API v1；本轮官方页已区分v2，不推广到其他API/工具。 |
| hash摘要被说成不能反推出秘密 | 低熵输入可猜测；不把hash当保密或认证，审计不存原始密钥/私有全文。 |

## 实际验证

[代码结果](ch33-code-results.json)：**110项检查通过，其中12项容量/单位复算**。场景包括：

- 参数类型/重复键/字节与嵌套；同intent改参数/actor/Agent、外租户资源、错审批者/动作绑定；6并发批准、6并发claim、6并发业务同key重放。
- 工具/route/policy/禁用变更、用户/Agent撤销、backend在claim后独立撤销、批准和dispatch的精确过期边界、v4竞争v5。
- dispatch前崩溃与远端提交后丢回包；缺回执仍UNKNOWN、原key安全重放、期限后停止重放、晚到原请求继续完成。
- 真实SQLite触发器让审计插入失败、业务回执插入失败、本地终态写入失败，分别验证本库回滚/两库不能原子、恢复查回；旧epoch结果拒写而远端仍可提交。
- claim前/后取消、8次双连接取消/claim竞争、取消后迟到成功、响应体压缩后保留key/binding/outcome墓碑且不重做效果。
