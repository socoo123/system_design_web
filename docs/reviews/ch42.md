## 发现与修正

| 级别 / 原缺口 | 修正和关闭证据 |
|---|---|
| P1 · 初版IoGate只在call线程核deadline，worker可能迟到后仍发I/O | 主代理用ThreadFactory闸门实际复现。现worker真正调用前核同一deadline与reply状态；作者用闸门把worker暂停到调用方50ms实际超时后，验证不启动I/O且归还一次permit。不是硬实时屏障，正文说明检查后仍可能抢占。 |
| P1 · 初版SQLite复合主键身份列未NOT NULL | 主代理实际以NULL scope连调两次得到两份增量。现inbox/ledger身份列显式NOT NULL与非空检查，handler/pseudo写前拒绝NULL、空白和非规范身份；作者真实SQL验证二层拒绝后余额不变。 |
| P2 · Java夹具把permit已归还当作SynchronousQueue worker已空闲 | 核心fail-fast拒绝合法；正常/超时在途/异常/关闭拒绝改为独立Gate，避免夹具从错误就绪推断产生偶发失败。未用sleep掩盖。 |
| 旧文“classic group”泛指普通消费组；D1头注“offset is next position” | 全章改为traditional consumer group，并区分classic/consumer协议；D1改为提交的是next position且在持久处理后。以Kafka4.1原文核查。 |
| 旧文“真实I/O许可”易被读成远端执行上限 | 明确本地同步适配器、Future/本地socket/远端效果三层生命周期；本地终止不证明远端结束或rollback。D5对应字样同步。 |
| DLQ后的严格顺序与跨重启attempt边界仅泛述 | 明确提交前需持久实体阻塞且新owner加载，或保留失败位置停整个分区；跨重启重试次数需持久attempt记录。 |
| 容器退出缺少实施路径 | 增加关本地门、继续poll、安全提交、截止重放伪码；说明preStop计入宽限、端点更新并行、替代Pod不撤销旧效果。 |
