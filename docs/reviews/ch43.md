## 实施结果

- A01–A08 已按清单完成作者修正。代码展示从 0 增至 3 段：2 段 Java17 可运行源码摘录，1 段明确标识的伪代码；单份程序配双语解释。闪卡 12→15，原 12 张保留并同步，新增外排、缺 run 和位点洞问题。
- 开场、Dremel 实验段和收尾删除重复罗列；正文按扫描预算→有界分治→提交/读取→回收/回放组织。未以字数或固定图数凑内容。
- A3 明确为获授权的全表查询；需 tenant_id 行过滤时新增 4 列/50 GB/25 s 单查/50 s 双并发反例。三列 37.5 GB 仅数据页预算，删除元数据/字段等额外 I/O 另算。
- Catalog 展示自定义事务协议：条件更新 current 与 accepted(table,batch,digest,result) 同库同事务，唯一约束绑定身份；UNKNOWN 本地超时、单次查无记录不能判失败，在途发布未终结不能 GC。明确不是 Iceberg API。
- 补 pin/过期和 GC/候选发布的并发协调要求，普通可达扫描或 TTL 不能代替 fence。Replay 统一 next-offset 半开 `[S,H)`，明确连续完成前缀、稳定源身份与业务去重身份的不同，以及切换后接续。

实施期新问题 A09（P1）由主代理读第一份 Java 草稿发现：按 DirectoryStream 枚举现存 run 会在完整 run 丢失时漏算。已改为以记录的 count 构建有限 fan-in 的预期 `run-i` 路径；每份必须打开成功。新增 aggregate 层 Iterator 注入：run-0 落盘后、归并前删除，运行确认失败。此问题是草稿静态发现后修复，未把旧版本动态复现写成事实。主代理另有修后新输入验证，独立证据由主代理维护。

独立复核返修 A10（P1）：ch45_author 用 `B=9 / F=2 / 3行` 在最后一次 `hasNext` 删除唯一 run；原 `count=1` 跳过归并，返回不存在路径。已在最终返回前实际以 READ 打开候选并读一个字节，单 run 分支同样失败关闭；新增同轨迹反例，Java17 运行通过。页面与 README 同步说明：这只验证交接瞬间可读，不消除未来删除竞态，交接后保留、不可变身份与发布/GC fence 仍由调用/发布层负责。原复核者用其原探针及最终冻结源重验通过，A10/R43-01已关闭，见 [独立终签](./ch43-independent-final.json)。
