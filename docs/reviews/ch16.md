## 实施前发现与关闭方式

| 原缺口 | 本轮修正 |
|---|---|
| 删除 root 后保留回复容器，与一级查询只筛 visible 矛盾 | `ever_public` 首次公开后永不清零；一级取曾公开容器，当前不可用只输出 generic unavailable、结构 ID 和原排序时间。SQL 不输出其审核状态、正文、作者与引用。从未公开的 root 完全排除。 |
| parent_id/root_id 的归属仅靠口述，未给读取落点 | 明确同帖复合外键与其局限；root 从鉴权父行派生，父/root/时间/ID 不变。SQL 先 LIMIT 20，再每 root LATERAL LIMIT 3；楼内续页锚在该楼最后预览。 |
| 连续目标态重试被概括成永久幂等 | 一个 hash 一次 HSET 保持成员/total/delta；连续相同目标不重复计数。不同目标按服务端接收顺序，明确延迟旧 like 可能覆盖新 unlike。操作顺序保证需要另加持久成员版本。 |
| A8 允许成员一起丢，却说计数可重建 | 无耐久成员不能精确重建；键缺失拒写。任何 restart/failover/snapshot restore 后，入口恢复栅栏暂停，即使旧 hash ready=1 也不自动恢复。保持只读，或产品显式新代清零/隔离旧批；本代码不实现生命周期检测。 |
| 批次只写“唯一号防重”，未覆盖重用载荷和增减乱序 | 同评论仅一批 in-flight，旧批 ACK 后才冻结下一批。新 delta 继续累积。唯一账本与增量同事务，冲突后新语句读 payload 并比较；丢 ACK 重试原 ID/载荷。 |
| 评论请求键只绑定作者和正文摘要 | 回执键为 `(post,user,key)`，意图绑定 post/parent/body/attachments/policy。改变父节点也拒绝。Guard 事务明确由同一帖子分片权威库实现。 |
| 缓存文字有租约，草稿伪代码却让 BUSY 等待者继续查库 | BUSY 只有限等待 owner 的有效页，超时 503；CACHE_UNAVAILABLE 可在全局配额下旁路且不填。只有 owner/旁路消耗回源许可。 |
| 五秒撤回尚未落到查询与发送时点 | fresh authority statement 前捕获绝对 not_after，禁止旧事务/滞后副本；扣时钟和发送余量，迟到查询不缓存、不发送、不重置有效期。 |
| response/accepted/202/503/200 等入口文字横跨边界，503 贴 Edge | 按问题家族覆盖 D1/D4/D5/D6 全帧，移边界给文字留通道；D6F5 的 503 独立下移。实际目视与几何复查通过。 |

`python3 examples/ch16/verify.py`：**67 项通过**，详细名称与限制见 [执行结果](ch16-code-results.json)。

- **真实 Redis 7.2.5：**在隔离临时目录、Unix socket、port 0、无 RDB/AOF 的实例执行原 Lua。验证正常 like/unlike、连续重试、16 worker 并发提交 64 次同用户只加一次、64 个独立用户全部计入、冻结与 ACK、单批 in-flight、新负 delta 保留、错载荷 ACK、缺键/错类型/错数字/错成员拒写。实际执行脚本先写后报错，见证 Redis 不回滚早先写入；实际执行延迟旧 like 覆盖 unlike，核对接收顺序承诺。结束后关进程并删除临时目录。
- **实际 SQLite：**用真实约束、索引、事务及 8 worker 执行 32 次跨连接并发重放验证同批重放一次、换载荷拒绝、丢 ACK、缺 count、增量失败与账本一起回滚。验证同时间 keyset/插入、OFFSET 重复负例、从未公开排除、已删除/重审 root 脱敏、可见后代保留、跨帖外键、从父行派生 root。构造 10 万回复热楼，20 个 root 各最多 3 条预览，展开从本楼最后预览续读；全局 LIMIT 饥饿负例成立。
- **契约探针：**签名 cursor 的帖子/root/order/limit/篡改/过期拒绝，晚审核通过需刷新；审核摘要与版本条件、重复决定无重复 outbox、删除前后六种串行顺序；缓存 token 拒旧填充、绝对过期、BUSY 等待者不回源、故障旁路共享配额。

这些范围分别记录，不能把 SQLite 的 `BEGIN IMMEDIATE` 并发当成 PostgreSQL 行锁证明，
也不能把逐 root SQLite 探测当作执行过 PostgreSQL LATERAL。未启动 PostgreSQL，未编译 Java（本章无 Java）。
