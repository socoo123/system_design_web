LLM 推理服务LLM inference service

约 35 分钟 · 前置：Ch03、Ch04 · 6 组 / 31 帧演进图~35 min · after Ch03, Ch04 · 6 decks / 31 evolution frames

本章核心：先守承诺，再提高利用率Core: honor commitments before improving utilization

准入分两关：等待描述有界、租户份额有界；上卡时一次承诺 prompt + 最大输出的页信用，逐轮再核计算预算。

取消分两步：先停后续调度，相关 GPU 访问全退休后才释放引用和信用。旧 generation、旧 worker boot 的消息不能碰新池。

容量分三账：显存能放多少、目标延迟下能服务多少、用户收到多少，分别计算和测量。

Two admission gates: bound waiting descriptions and tenant shares. Commit prompt-plus-output-cap page credits at GPU admission, then check compute budgets each iteration.

Two cancellation steps: stop future scheduling, then release references and credits after every relevant GPU access retires. Old generations and worker boots cannot touch a new pool.

Three capacity ledgers: memory fit, service at target latency, and client delivery require separate calculations and measurements.

设计范围与可替换的假设Scope and replaceable assumptions

设计自托管、单地域、单模型的在线文本聊天服务。起点是同卡 prefill + decode；离线摘要另队列、另池。RAG只在前面准备 prompt。先问输入/输出长度分布、TTFT与输出停顿目标、模型版本以及是否允许显式续写。

主路径 Client → API gateway → Scheduler → GPU worker，输出逐跳返回。分页管存放，continuous batching管每轮成员；内核优化不能替代租户公平或生命周期。

示例接口 POST /v1/chat/completions、stream=true：浏览器用fetch发POST并解析SSE格式响应。原生EventSource不直接发该POST；事件id/Last-Event-ID也不会替服务器保存token日志或KV。[9]

Self-host one model for online text chat in one region, initially colocating prefill and decode. Offline summaries have another queue and pool. RAG prepares the prompt upstream. Clarify length distributions, first-token and stall targets, model identity, and explicit continuation.

The path is Client → API gateway → Scheduler → GPU worker, with every return hop. Paging manages placement; continuous batching selects each iteration’s members. Kernel optimization does not provide tenant fairness or lifecycle safety.

The illustrative API is POST /v1/chat/completions, stream=true. Browsers use fetch for POST and parse an SSE-format response. Native EventSource does not directly issue this POST; event IDs and Last-Event-ID supply neither a server token log nor KV recovery. [9]

估算：128条信用不是128条的吞吐Estimate: 128 reservations do not establish throughput

全注意力KV：2 × 32层 × 8 KV head × 128维 × 2 B = 128 KiB/token。16 token页是2 MiB；ceil((2,048 + 512) ÷ 16) = 160页 = 320 MiB/请求。40 GiB = 40,960 MiB，因此最多128条满额信用；第129条会超出320 MiB。这里使用KV head，且不含权重等运行时开销。

Little定律必须圈同一个边界。令λ是稳定准入并退出GPU的尝试率（含取消），W是从GPU准入到引用/信用释放的平均驻留时间，排队不计入W。若λ=10/s且W=6s，平均活动60条，保守信用18.75 GiB；若持续30/s仍保持6s，条件需求是180条/56.25 GiB，超过单池。它说明需要拒绝、扩容或改预算，不能从128÷6反推单卡产能。

算力容量另做负载基准：假设最大接纳率C=12 req/s时仍有≥99%请求同时达到TTFT≤800ms和该请求最大worker ITL≤50ms，规划用70%，即8.4 req/s。峰值30需ceil(30÷8.4)=4个副本；同预算N−1需5个，剩余33.6 req/s。12尚未实测；只给“goodput=12”也不能把它直接当总完成率或排队服务率。

Full-attention KV is 2 × 32 layers × 8 KV heads × 128 dimensions × 2 B = 128 KiB/token. A sixteen-token block is 2 MiB. ceil((2,048 + 512) ÷ 16) = 160 blocks = 320 MiB/request. Forty GiB is 40,960 MiB and fits 128 full-cap reservations; number 129 exceeds it by 320 MiB. Count KV heads, excluding weights and other runtime overhead.

Little’s law needs one boundary. Let λ be stable admitted/departing attempts per second, including cancellation, and W mean residence from GPU admission through reference/credit release, excluding queueing. At λ=10/s and W=6s, mean active count is sixty and conservative credits are 18.75 GiB. Sustained thirty/s with W still six requires 180 requests/56.25 GiB. This conditional demand exceeds one pool and requires rejection, expansion, or a changed budget. It does not infer compute capacity from 128÷6.

Benchmark compute separately. Suppose maximum admission C=12 req/s still gives ≥99% of requests both TTFT≤800ms and maximum worker ITL within that request≤50ms. Plan at 70%, or 8.4 req/s. Peak thirty needs ceil(30÷8.4)=4 replicas; five preserve the same N−1 budget, leaving 33.6 req/s. Twelve is unmeasured. A goodput of twelve alone is not total completion rate or a queue service rate.

完整需求、权重与长上下文复算Demand, weights, and longer-context calculations

权重 8×10⁹×2=16 GB≈14.9 GiB。输入需求平均20,480、峰值61,440 token/s；输出平均2,560、峰值7,680 token/s，假定均接纳并按均值256输出。租户输入4,096 token/s约容许2条标准prompt/s，但长输出仍需输出预留与活动上限。

Weights are 8×10⁹×2=16 GB≈14.9 GiB. Input demand averages 20,480 and peaks at 61,440 tokens/s; output averages 2,560 and peaks at 7,680 tokens/s if all requests complete with mean output 256. A 4,096 input-token/s quota permits about two standard prompts/s, while long outputs still need output reservations and active caps.

Changing input to 8,192 with output cap 512 needs 8,704×128 KiB=1,088 MiB; 40,960÷1,088≈37.65 fits thirty-seven reservations. Remeasure prefill and workspace peaks. Weight-only quantization keeps KV bytes/token unchanged but may enlarge the usable pool.

在线闭环：排队不占KV，上卡才作承诺Online loop: queue without KV, commit at admission

网关固定model/template/tokenizer并按实际token校验长度。主体/key/规范正文哈希在共享Attempt Store绑定一次尝试，重复请求不重复扣输入/输出配额；换网关仍读同一记录。持久尝试与配额若跨库，必须用可恢复预留/撤销协议。下面从已持久受理且配额就绪的请求开始，不拿本地队列当持久去重。

Scheduler对一个worker boot独占调度；等待只保存有界描述。租户轮转避免被一个租户的队头堵住，分别限制队列数、活动序列与页信用。期限和数量是两条限制：若总完成率假设12/s，100条相当于约8.33秒工作量，远超600ms；限制成7条也不是p99证明。

The gateway fixes model/template/tokenizer and validates actual token lengths. A shared Attempt Store binds principal/key/canonical-body hash to one attempt; input/output quota is reserved once across retries and gateway changes. Separate stores require recoverable reserve/revoke steps. The next listing starts with a durable claim and ready quota; a local queue is not durable deduplication.

One scheduler exclusively controls a worker boot. Waiting stores bounded descriptions. Rotate tenants and separately bound queued count, active sequences, and page credits. Deadlines and counts are separate limits: at an assumed total completion rate of twelve/s, one hundred requests represent about 8.33 seconds of work, exceeding 600ms. Capping at seven still does not prove p99.

队列满也是持久终态，配额释放要可恢复A full queue is a durable terminal result with recoverable quota release

输入已预留token配额，所以429不能只丢掉HTTP请求。先在Attempt同库事务写终态/原429结果与唯一attempt结算事件；同key以后仍取该429，即使队列已空也不再入队。quota服务按attempt原子释放未消费预留，relay确认后才ACK；回包丢失或释放后未ACK都可重复。依赖故障时保留pending结算并持续重试，不能承诺故障期固定秒数退款。

首次GPU提交前先条件取得RUN_GRANTED；拒绝事务只允许仍为ASSIGNED的owner，因此与启动竞争最多一个获胜。已经启动/结果未知不能用“未消费”全退。该段为教学伪代码，另有实际双SQLite适配验证事务/重投，未运行跨机配额服务。

Input quota is already reserved, so 429 cannot merely discard HTTP state. Commit the terminal attempt, original 429 result, and a unique attempt settlement event in one database transaction. Same-key retries keep that 429 even after capacity returns. The quota authority atomically releases unused reservations once per attempt; acknowledge the outbox only after confirmation. Lost replies and release-before-ACK crashes safely retry. Outages retain pending settlement for recovery, without a fixed refund-time promise.

Before first GPU submission, conditionally obtain RUN_GRANTED. Rejection accepts only the still-ASSIGNED owner, so it races execution with one winner. Started or unknown execution cannot receive a blanket unused refund. This is teaching pseudocode, with an actual two-SQLite adaptation for transaction/redelivery checks, not a cross-machine quota experiment.

KV分页：信用、物理页和共享引用Paged KV: credits, physical pages, and shared references

图的L0/L1/L2映射到P7/P2/P9，表示物理地址可分散；attention按block table读KV。演示页4个状态：7→8填P2，8→9才加P9；它不同于容量假设的16 token页。PagedAttention减少连续分配造成的碎片，不自动解决逻辑超订。[2]

保守策略为每个请求预留prompt+最大输出的完整信用，物理页随实际状态增长。即使物理页空着，也可能已承诺给活动请求未来输出；只有总承诺有余量才再准入。下面Java17可运行模型把信用补判扣与物理分配串行化在一个worker的CPU锁内；分布式尝试身份仍由共享记录负责。

L0/L1/L2 map to P7/P2/P9: physical blocks may be scattered while attention follows the block table. Toy pages hold four states; 7→8 fills P2 and 8→9 adds P9. Capacity assumptions use sixteen-token pages. PagedAttention reduces contiguous-allocation fragmentation without solving logical overcommit. [2]

Our conservative policy reserves prompt-plus-output-cap credits while allocating physical blocks on demand. Empty physical blocks may already be promised to active requests’ future output. Admission needs uncommitted credits. This runnable Java17 model serializes credit checks/debits and allocation under one worker’s CPU lock; shared records separately govern distributed attempt identity.

public synchronized boolean admit(Owner owner, int prompt, int maxOutput) {
    long total = (long) prompt + maxOutput;
    if (prompt <= 0 || maxOutput <= 0 || total > contextLimit)
        throw new IllegalArgumentException("Token limits");
    if (!healthy || !boot.equals(owner.boot())) return false;
    int need = (int) ((total + BLOCK - 1) / BLOCK);
    Generation prior = generations.get(owner);
    if (prior != null) {
        if (prior.credits != need) throw new IllegalArgumentException("Changed request");
        return prior.state == State.RUNNING;
    }
    boolean oldOwnerLive = generations.entrySet().stream().anyMatch(e ->
            e.getKey().attempt().equals(owner.attempt()) && e.getValue().state != State.RELEASED);
    if (oldOwnerLive || need > pool.length - reserved) return false;
    generations.put(owner, new Generation(need));
    reserved += need;                    // promise full output; allocate no page yet
    return true;
}

public synchronized Handle allocate(Owner owner) {
    Generation gen = mutable(owner);
    if (gen.pages.size() >= gen.credits) throw new IllegalStateException("Credit exhausted");
    for (int i = 0; i < pool.length; i++) {
        Page page = pool[i];
        if (page.refs != 0 || page.pins != 0) continue;
        page.incarnation = Math.incrementExact(page.incarnation);
        page.cached = page.sealed = false; // evict an unused cache entry if needed
        page.refs = 1;
        Handle h = new Handle(boot, i, page.incarnation);
        gen.pages.add(h);
        return h;
    }
    throw new IllegalStateException("Pool accounting violated");
}

输入owner=(attempt,generation,worker boot)、prompt与最大输出；输出信用是否受理、或一个带incarnation的页Handle。源码的generation保留页集合，页分别计活动引用refs和在途访问pins。只共享已完成的不可变完整块；未满尾页共享/COW不在此模型中。真实引擎若超订、COW或有隐藏workspace，必须另外补入同一预算。

前缀命中比较token与计算身份，固定模型/LoRA、位置语义和信任域。vLLM v0.15.1按父哈希、块token与额外身份缓存完整块；cache salt隔离复用，本设计由服务器按信任域赋值。APC减少重复prefill，不减少待生成后缀步数；miss正常重算。模型升级换命名空间，输出额度不随命中减少。[5] [6]

完整前缀可在refs=0时留作可驱逐缓存；有refs或pins就不能复用地址。本策略不把共享收益卖成更多信用，简化最坏输出承诺；活页超订则需明确抢占/重算以及被抢占请求的延迟代价。

Inputs are owner=(attempt,generation,worker boot), prompt, and output cap. Outputs are admission or an incarnation-stamped block Handle. The source tracks a generation’s page set, with separate active references and in-flight pins per page. It shares only complete immutable blocks; partial-tail sharing/COW is outside this model. Real overcommit, COW, and hidden workspaces need the same explicit budget.

Model upgrades change namespaces and hits never bypass output quota. [5] [6]

逐轮batch：换成员，也要限制本轮工作Iteration batching: change members and bound work

t轮A/B/C，B结束并退休引用；t+1可考虑D prefill，t+2 D decode。Orca的iteration-level scheduling消除整请求batch屏障；D仍会因页、计算或公平等待多轮。CPU选成员和chunk，attention内核执行；FlashAttention优化IO，不替调度器实现公平。[1] [4]

每租户保留deficit和请求游标，成本由context、phase与token数计；余额跨轮累积、上限至少容纳最大合法chunk。轮转起点防同一租户总先占剩余预算。准入还限租户活动数/页份额；单轮选出每条请求最多一个chunk或一个decode步。高权重是相对份额，不是硬实时保证。

Iteration t has A/B/C. B finishes and retires references; t+1 may admit D’s prefill and t+2 decodes D. Orca’s iteration scheduling removes the whole-request batch barrier, but pages, compute, and fairness may still delay D many rounds. CPU selects members/chunks and kernels execute. FlashAttention optimizes IO rather than scheduler fairness. [1] [4]

Keep tenant deficits and request cursors. Charge by context, phase, and token count; carry balances across rounds with a cap large enough for the largest legal chunk. Rotate the first tenant so the same tenant does not always consume residual budget first. Admission also caps tenant active/page shares. Each request contributes at most one chunk or decode step per iteration. Weights are relative shares, not real-time guarantees.

延迟指标必须写清起止点Latency metrics need explicit endpoints

客户端TTFT从发送请求到收到首个内容，含排队、网络和flush；A6是单次条件预算50+等待+150≤800，分量p99不能相加。worker ITL统计相邻token-ready时间差；客户端SSE块可合并多个token，块到达间隔另报，不冒充GPU步时长。

TPOT用同一worker时间轴的(末token−首token)/(N−1)，N=1无此平均值；它会掩盖单步停顿。256个输出有255个后续间隔，固定20ms例子是5.1s；另加假设200ms首段约5.3s。ITL p99=50ms不能当每步硬上限，也不能推整请求总时长。goodput计每秒联合达标的完成请求，分母/联合达标比例另报；TTFT和ITL各自p99不等于99%请求联合达标。

Client TTFT spans request send to first content, including queueing, network, and flush. A6’s 50+wait+150≤800 is a conditional per-request budget, not summed p99s. Worker ITL is the gap between adjacent token-ready times. SSE chunks may combine tokens, so separately report client chunk-arrival gaps rather than calling them GPU step times.

TPOT is (last token−first token)/(N−1) on the same worker clock; it is undefined for N=1 and may hide a stall. 256 outputs have 255 later gaps: at fixed twenty ms, 5.1s, or approximately 5.3s with an assumed 200ms first-token path. A fifty-ms ITL p99 is no hard step or total-duration bound. Goodput counts jointly compliant completions/s; also report its denominator and joint attainment. Separate TTFT/ITL p99s do not establish 99% joint request attainment.

取消与完成：先退休访问，再释放页Cancel and completion: retire accesses before releasing pages

对应图的RUNNING → CANCEL_PENDING → RETIRED → RELEASED。Java把等待退休记作RETIRING；inFlight==0是进入RETIRED并立即释放的条件，不多存一个瞬态字段。发GPU前，ticket固定owner/页快照并pin；取消只标停止，EOS与取消用同一锁竞争首个停止原因。

The diagram is RUNNING → CANCEL_PENDING → RETIRED → RELEASED. Java calls the waiting state RETIRING; inFlight==0 allows RETIRED and immediate release without storing that transient phase. Before launch, a ticket snapshots owners/pages and pins them. Cancel marks stop; EOS and cancel contend for the first stop reason under the same lock.

public synchronized Ticket issue(List<Owner> batch) {
    if (!healthy || batch.isEmpty() || new HashSet<>(batch).size() != batch.size())
        throw new IllegalArgumentException("Invalid batch");
    List<Hold> holds = new ArrayList<>();
    for (Owner owner : batch) {
        Generation gen = mutable(owner);
        if (gen.pages.isEmpty()) throw new IllegalStateException("Missing KV");
        holds.add(new Hold(owner, List.copyOf(gen.pages)));
    }                                   // validate everything before mutating
    long id = Math.incrementExact(nextTicket);
    for (Hold hold : holds) {
        generations.get(hold.owner()).inFlight++;
        for (Handle h : hold.pages()) page(h).pins++;
    }
    nextTicket = id;
    launches.put(id, List.copyOf(holds));
    return new Ticket(boot, id);          // pin before submitting any GPU access
}

public synchronized boolean stop(Owner owner, Reason reason) {
    Objects.requireNonNull(reason);
    Generation gen = generations.get(owner);
    if (!healthy || gen == null || gen.state != State.RUNNING) return false;
    gen.reason = reason;                 // first stop/EOS wins
    gen.state = State.RETIRING;           // prevents all later issue calls
    releaseIfRetired(gen);
    return true;
}

真实适配器必须把所有读写KV、block table和相关copy的stream依赖纳入同一完成证据。CUDA event只证明其捕获工作/依赖完成；不能随手查一个不相关stream就还页。下面模型由测试手工调用complete模拟“证据已成立”，没有执行CUDA。[10]

A real adapter must cover every stream dependency accessing KV, block tables, or related copies. A CUDA event proves completion only for the work/dependencies it captures; querying an unrelated stream cannot authorize release. public synchronized boolean complete(Ticket ticket, Set<Owner> eos) {
    if (!healthy || !boot.equals(ticket.boot())) return false;
    List<Hold> holds = launches.remove(ticket.id());
    if (holds == null) return false;      // duplicate/old completion
    for (Hold hold : holds) {
        for (Handle h : hold.pages()) page(h).pins--;
        Generation gen = generations.get(hold.owner());
        gen.inFlight--;
        if (eos.contains(hold.owner()) && gen.state == State.RUNNING) {
            gen.reason = Reason.EOS;
            gen.state = State.RETIRING;
        }
        releaseIfRetired(gen);
    }
    return true;
}

private void releaseIfRetired(Generation gen) {
    if (gen.state != State.RETIRING || gen.inFlight != 0) return;
    for (Handle h : gen.pages) page(h).refs--;
    gen.pages.clear();
    reserved -= gen.credits;             // return promise exactly once
    gen.state = State.RELEASED;
    // A page is reusable only at refs==0 && pins==0; cached data may remain.
}
