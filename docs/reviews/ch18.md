## 文件与关键实现

页面`chapters/ch18.html`；[示例说明](../../examples/ch18/README.md)；6段同源伪代码：

| 文件 | 保证与简化 |
|---|---|
| `checkout.pseudo`，29行 | user/key/摘要与原创建回执；原子整篮预留、固定SKU锁序、唯一竞争后新语句读取，任何未提交异常回滚。明确拒绝结果不永久保存。 |
| `holds.pseudo`，28行 | 调用者持订单锁至提交，本单预留/完整明细/库存计数/订单状态/outbox共事务。finish不是另开事务或魔法atomic。 |
| `attempt.pseudo`，26行 | 锁内新尝试门槛、外调前稳定参数、条件UNKNOWN不覆盖终态，provider_binding恢复字段一致，持久未终结尝试可扫描恢复。 |
| `capture.pseudo`，40行 | 全球收款身份唯一裁决，订单锁内一次对象绑定、字段校验、接受/退款/人工核对三个责任分支。正常关闭冲突不会吞收款；真正异常不标已处理。 |
| `delivery.pseudo`，29行 | 完整付款inbox、ACK后sent、下游inbox+Job同事务；明确不把持久任务冒充外部发货/退款exactly-once。 |
| `scan.pseudo`，15行 | 固定cutoff、连续500行分页、失败仍可发现、下一轮重启最老到期行、同一close锁内复核。 |

## 实际验证与限制

[99项代码结果](ch18-code-results.json) / [执行日志](ch18-tests.txt)：

- 正常整篮下单、创建回包丢失后24路同键重放，报价过期仍返回原创建回执；跨用户同key、换意图、非法数量/重复SKU、币种/地址/owner不符拒绝。
- 第二SKU不足与中途故障全部回滚；12路竞争最后一件仅一单成功。关闭中途故障回滚订单状态、两份预留、库存及事件；重复关单不占另一单的聚合预留。实际复现了只看reserved的危险负例。
- 24路start-payment只建一份尝试；UNKNOWN挡新笔，伪造NO_CAPTURE拒绝，确证终态可下一笔。首次对象未知可由合法capture只绑定一次；迟到timeout不覆盖CAPTURED，后续REVIEW也不降级已验真事实。
- 同capture不同event一次履约；不同capture单独RefundDue；金额/币种/归属/未知attempt保留REVIEW，不发货。关单先退款、付款先不释放均实际执行；Barrier起跑10次真实SQLite线程竞态覆盖两种赢家。
- 收款终结第一SKU后注入异常，全事务回滚后原证据可恢复；完整inbox提交、capture提交而inbox未DONE崩溃、重复处理、不可变capture冲突保留READY均执行。
- 入口签名/账户/环境/授权非capture用显式契约输入拒绝；这不是实际验签。broker ACK丢失重复同event；消费事务失败全回滚，两个event描述同order仍只一份Job。
- 503单跨越500批大小连续扫描，故障行下一轮找回；付款在候选读出后、关单锁前胜出，不释放。主要占货/积压/存储算式独立复算。
