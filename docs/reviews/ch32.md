| 展示源 | 性质与保证 | 边界 |
|---|---|---|
| `route.pseudo` | 可信身份、能力/地域/质量/上下文过滤、原rid复查、缓存当前授权、miss准入 | 策略伪代码；缓存服务记录与真实授权适配未实现 |

| `ledger.py#settle` | attempt唯一结算；绑定精确上游request id/model；重复不扣，冲突核账 | 最终证据必须由可信Adapter/Reconciler认证；无真实provider |
| `stream.pseudo` | selected attempt/owner提交屏障、截止时间、串行背压、有界事件和取消 | 协议伪代码；不冒充实现了HTTP解析/无预取/远端取消完成 |

完整实现、运行命令与限制见 [examples/ch32/README.md](../../examples/ch32/README.md)。
`reserve_fallback` 与 `claim_commit` 同库竞争，旧a1 hold不转给a2，晚a1只能补usage。
成本UNKNOWN与错误类别分开：只有受信Adapter的暂时限流/服务器故障/发送后超时可进入备用白名单；拒绝、权限/schema、解析、超大事件、取消和写堵塞都不能换池。
上界失效仍记录真实债务并封禁，不回滚证据掩盖超额。provisional保留估算，最终结算冲突不偷偷覆盖。

## 原问题与更正

- 原“最多两次，所以最坏40/s、7.2M/min”收紧为同一1200请求集合最多2400调用/7.2M工作量；只有同窗/稳态才能写40/s。跨窗重试仍需真实共享组限流。与主代理、Ch33同步该口径。
- 任意新settlement event id不能给同一attempt再扣；相同最终payload幂等，冲突转核账。晚usage固定原预算周期。
- COMMITTED由selected attempt/owner、未失败、未关闭条件仲裁，与fallback串行；首文字前的头/role/heartbeat/空成功也提交。查询到旧COMMITTED不重新授权flush。
- 取消不证明上游完成，不释放UNKNOWN预算或马上复用远端并发credit；已关闭本地连接可释放本地资源。
- usage缺失不当0；Claude累计usage不相加；缓存key一致仍需当前授权及served model/route/data元数据资格。
