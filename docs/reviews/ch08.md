## 纠错与明确边界

| 原问题/不足 | 本轮处理与依据 |
|---|---|
| 追加 600 次重试便断言总量 2,400，未计重试成功后的释放 | 明确“追加尝试全部 busy”才是 2,400；成功重试另计释放 |
| 扣减 SQL 未要求正 amount | 两条 SQL 增加 amount>0；fencing 同时要求正 f，并声明 BIGINT 合法域；反例验证负扣减不增库存 |
| 获取只有 OK 条件，未展示未知/迟到分支 | 获取伪代码区分 OK、busy、unknown；从发出请求前单调计时扣剩余，及时 owner 清理，不开始未知业务 |
| 只有 owner 释放代码，无 owner 续租落点 | 新增原子 GET/PEXPIRE Lua；错误/超时按无法证明持有处理，限定字符串 owner，不冒充 Redisson hash 锁 |
| 续约成功可能被误解为接收后重新享有完整 TTL | Java17 限制一笔在途，从发送时算；先验旧截止点，LOST 不可逆，晚到 OK 不复活。仅本地派发预算，不证明分布式排他 |
| 旧 owner b 与重试 owner b 同名，易暗示跨尝试复用 | 图 1 失败尝试改 b0，成功重试为新 b；身份不当顺序令牌 |
| 图 3 请求标签 “promote; NX b” 易暗示 Worker 发起提升 | 改为 “NX b after promotion”；保留控制面提升是前提的图注 |
| 图 5 CAS 标签在上方，与下方真实请求线脱离 | 仅移动 d5s5 的标签至其下方请求线旁，未改变路径/帧序 |
| 看门狗图的旧客户端在 45 s 仍发续租，与新预算 helper 不同 | 图注明确此为旧客户端反例；新 helper 会先 LOST，不再发新请求；Lua 仍防御晚到包 |

保留并加强：fence 必须与成功持有绑定；独立 INCR 的 100/101 反例；单节点脚本原子性不能弥补切主计数回退；资源接受 34 后才拒 33；库存失败不提升 fence；严格小于只支持每世代一次变更，未知提交用业务回执；安装新世代与等号验写是另一份交接契约。图 `max_fence` 对应代码 `last_fence`，已明说。

时钟：200 ms 只是教学余量；客户端单调时钟不能修复服务端墙钟 TTL 跳变。WAIT 的同连接/实际副本数/不回滚与 Redlock 的独立主、多数、时间/清理条件均重新核验。

## 实现与验证

[运行说明](../../examples/ch08/README.md)，[机器结果](ch08-code-results.json)。七段代码均以 `data-source` 与源文件逐字检查，Java 页面取明确标记的同源节选。

1. **Redis 7.2.5 实例实测**：复用已有编译二进制 `/tmp/redis-7.2.5/src/redis-server`，新临时目录/Unix socket，TCP port=0，不连接用户实例，完成后 terminate/wait 清理。正常 SET/释放/续租、busy、20 客户端仅一获锁、20 错 owner 不删除、旧 owner 过期后不能续/删新任、坏 TTL 不修改、故意丢弃获取回包仍有锁、GET→过期→B→DEL 的真实反例均通过。
2. **SQL 谓词实测与契约轨迹**：两条原 SQL 用 SQLite 绑定参数执行，覆盖正常 34、旧 33、同号重试、负数/无效号、库存不足、发号但未安装、版本 12/13；额外 SQLite 事务轨迹覆盖相同请求回执回放、载荷冲突、提交前失败全回滚、最后库存。**不是 PostgreSQL 并发验证**；PG 的重检/快照语义另由官方文档核验。
3. **Java17 真实编译运行**：JDK 17.0.10，`javac -d /tmp/ch08-java ...` + `java -cp /tmp/ch08-java LeaseBudgetTest`，18 条断言通过。包括获取未知/迟到、发送时间预算、单在途、旧截止点已过而续租 OK、unknown/abandon 后不复活。注入单调时间测试，本地类没有 Redis 客户端或锁服务实现。
4. **独立复算**：10,000×10%=1,000；1,000+800=1,800；全部 busy 的追加重试 200×3=600；60/10=6；1/0.020=50；100×0.020=2；10−0.1−0.2=9.7；9.7−8=1.7；45−11=34 > 40−11=29。100/101 是可枚举错误交错，不伪称协调器故障实验。

`python3 examples/ch08/verify.py /tmp/redis-7.2.5/src/redis-server` 共 **12 类检查**通过（含同源与数字）。Java 的 18 条断言单独统计。
