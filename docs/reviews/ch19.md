## 实施前缺口与修正

| 原缺口 | 修正与证据 |
|---|---|
| 先拿旧索引坐标距滤，再回表补详情 | 候选按id合并后先读权威状态/坐标，再做权限、业务、年龄和最终距离。Java实际验证旧版本候选可使用新权威坐标；不能用旧距离提前丢id。 |
| 近邻“精确”混用当前权威全集、异步候选和距离模型 | 主线同步数据库可在同一快照精确查询；独立异步索引公开各格 `index_as_of`，只精确排序已召回候选。Java覆盖与Haversine明确共用自选球面，不声称椭球/GPS真值精确。未召回进圈实体的缺口无法靠回表补回。 |
| 覆盖只有文字，反经线/极区/浮点边界没有实现 | 同源Java生成保守闭区间；经度拆段、触极点全经度、超预算抛错不截断。真实Java正向球面目的点采样验证与九格漏召回反例通过。 |
| “event_id去重、entity_id保序”隐含relay已实现有序 | 明确relay须保持发布顺序；版本守卫允许重复重放，不能由同一partition自动推出发布顺序或exactly-once。 |
| 上报回执、额度和版本只靠口述 | 实体锁下先回放完整意图回执，再检查会话/序号、采样和额度；最新行、额度、版本、outbox、回执同实体分片事务。SQLite实际执行同key并发及不同请求争最后额度、引擎级outbox失败回滚。 |
| 先加后删未落到持久墓碑与同格移动 | 每格guard事务同时更新成员和revision，跨格无原子事务，全部成功才ACK。v43重返后迟到v42不能删除，删除墓碑阻止旧复制复活；同格移动不自删。 |
| 迁移的“cutover version”可被误读为最大实体版本 | 用每来源日志分区连续offset向量S/W；暂停/排空投影者取一致父格快照，复制+重放后全部分区到W才目录CAS。明确entity哈希源可能需要所有分区参与。 |
| 缺更新前坐标/墓碑位置导致孩子映射不完整 | 事件保留before/after点供各代路由，复制无孩子坐标墓碑到四孩子。实际SQLite确认旧复制不能覆盖新replay，广泛墓碑不删除更新版本LIVE。 |
| 回收写成lease/TTL二选一，切换后旧父格可能冻结 | 宽限期持续双投影；旧路由到期且旧读者完成才回收，存储验证epoch拒迟到者。协议探针分别拒绝只满足其中一个条件。 |
| 缓存TTL和回填可能给旧快照续命 | snapshot从开始索引读起带绝对not_after，晚回填/命中不重置。设备观测年龄另计可验证时钟误差与sendBy截止；没有误差上界只能称接收年龄。 |
