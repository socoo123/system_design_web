30 秒开场：把有状态的 GPU 讲清Opening: explain stateful GPU serving

中文

我设计自托管、单模型的在线聊天服务。网关鉴权并按 token 限流，Scheduler 把请求放进有界队列，检查页信用和计算预算后分配 GPU worker。worker 先 prefill 建 KV，再逐步 decode，token 经 Scheduler、网关回客户端。KV 分页解决怎么放，continuous batching 解决每轮谁进入；吞吐和 TTFT、TPOT 用实际负载基准测试确认。取消等本轮 GPU 访问退休再还页。流中断保留尝试身份，续写是用户明确发起的新请求；同卡干扰严重且搬得起 KV 时再考虑阶段分离。

澄清先问：自托管还是调用外部服务，输入和输出的长度分布，用户等待首段与相邻输出的目标，是否单模型，是否支持显式续写，在线和离线是否必须隔离。这里固定为文本聊天、单地域、一个模型副本先跑同卡；离线摘要另队列、另池。RAG 会在请求前准备 prompt，向量检索和训练平台属于后续章节。

请求外壳可以用 POST /v1/chat/completions、stream=true，这是本章示例接口。浏览器通过 fetch 发送 POST，再解析 SSE 格式响应；原生 EventSource 是基于 URL 建立流的接口，不能把这个 POST 直接交给它。SSE 的事件 id 和重连信息帮助标记事件位置，不会替服务器保存输出，也不会保存 GPU 状态 [9]。

English

This design self-hosts one model for online chat. API gateway authenticates and limits tokens; Scheduler queues requests and checks page credits plus compute budgets before assigning a GPU worker. The worker builds KV in prefill and decodes step by step. Tokens return through Scheduler and the gateway. Paging decides memory placement, and continuous batching decides membership per iteration. Benchmark the workload for throughput, TTFT, and TPOT. Cancel retires GPU accesses before releasing pages. Interruption retains attempt identity; continuation is an explicit new request. Consider phase separation when interference is serious and KV transfer is affordable.

Clarify hosting, input and output length distributions, first-token and inter-token targets, model count, explicit continuation, and online/offline isolation. We assume text chat, one region, and a colocated model replica initially. Offline summaries use another queue and pool. RAG prepares prompts before inference; retrieval and training are later chapters.

The illustrative interface is POST /v1/chat/completions with stream=true. A browser uses fetch for POST and parses an SSE-format response; native EventSource establishes a URL-based stream and does not directly issue this POST. Event IDs and reconnection metadata locate events, without storing server output or GPU state [9].

估算：显存能放下，算力还要另验Estimate: memory fit still needs compute validation

中文

全注意力的 KV 按 K、V 两份乘层数、KV head、head dim 和元素字节数：2 × 32 × 8 × 128 × 2 = 131,072 B = 128 KiB/token。用的是 KV head，不是 query head；改成 32 个 KV head 就乘 4。该公式不含权重、激活、block table 和其他运行时开销。权重是 8 × 109 × 2 = 16 × 109 B ≈ 14.9 GiB，与请求数无关。

生产页含 16 个 token，16 × 128 KiB = 2 MiB。2,048 + 512 = 2,560 token 的保守承诺需要 ceil(2,560 ÷ 16) = 160 页，也就是 320 MiB。40 GiB = 40,960 MiB，40,960 ÷ 320 = 128 条满额信用。若有非整页长度，先向上取整再乘页大小；不能用未取整字节绕过尾页浪费。

128 是显存信用上限，不是 batch 的最佳大小。旧版把 128 ÷ 6 ≈ 21.3 req/s 当单卡完成能力，这需要先证明满并发下仍有 6 秒平均占用、prefill 吞吐和 20 ms 的轮次，不能从显存反推这些条件。Little 定律在稳定系统中给出平均在途 L = λW；10 × 6 = 60 条，保守信用约 60 × 320 MiB = 18.75 GiB。若峰值 30 都能稳定完成且 W 仍为 6，才会得到 180 条、56.25 GiB；这个条件需求超过 40 GiB，说明必须拒绝、扩容或改变预算，不是证明无限队列真的稳定。

算力用独立基准测试。若按 A7 的负载分布、两个延迟目标和所需达标比例测出每副本 goodput 为 12 req/s，计划值是 12 × 70% = 8.4。峰值 ceil(30 ÷ 8.4) = 4 个副本，若要求退出一个仍守计划预算，就配 5；剩余 4 × 8.4 = 33.6。这里的 12 是条件例子，本轮没有跑 GPU 压测。4 台既不由 128 推出，也不由论文倍数推出。

输入需求平均 10 × 2,048 = 20,480 token/s，峰值 61,440；输出平均需求 10 × 256 = 2,560 token/s，峰值 7,680，成立条件是请求被接纳并按此分布完成。它们是流量需求，不是单卡实测产能。输入配额例 4,096 token/s 对标准 prompt 约允许 2 req/s，但短 prompt 长输出仍能占大量 decode，因此还要预留输出配额、限制并发和公平调度。

English

For full attention, multiply two tensors K and V by layers, KV heads, head dimension, and bytes: 2 × 32 × 8 × 128 × 2 = 131,072 B = 128 KiB/token. Use KV heads rather than query heads; thirty-two KV heads multiply this by four. The formula excludes weights, activations, block tables, and runtime overhead. Weights are 8 × 109 × 2 = 16 × 109 B ≈ 14.9 GiB, independent of request count.

A production block contains sixteen tokens: 16 × 128 KiB = 2 MiB. A 2,048 + 512 = 2,560-token commitment requires ceil(2,560 ÷ 16) = 160 blocks, or 320 MiB. Forty GiB is 40,960 MiB, so 40,960 ÷ 320 = 128 full-cap reservations. Round lengths to whole blocks before counting bytes.

128 limits memory credits, not optimal batch size. The old 128 ÷ 6 ≈ 21.3 req/s inference required independent evidence that six-second occupancy, prefill throughput, and twenty-ms iterations held at full concurrency. Little’s law gives average in-flight L = λW for a stable system: 10 × 6 = 60 requests, or 18.75 GiB of conservative credits. Only if all peak arrivals complete stably with W still six seconds does 30 × 6 imply 180 requests and 56.25 GiB. That conditional demand exceeds forty GiB and forces rejection, expansion, or a changed budget; it does not establish stability of an unlimited queue.

Benchmark compute separately. If the workload, both latency targets, and required attainment fraction yield twelve goodput req/s per replica, plan at 12 × 70% = 8.4. Peak needs ceil(30 ÷ 8.4) = 4 replicas. Five provide N+1: four survivors have 33.6 planned req/s. Twelve is a conditional example; no GPU benchmark was run here. Neither memory credits nor a paper’s speedup determines these four replicas.

Input demand averages 10 × 2,048 = 20,480 token/s and peaks at 61,440. Output demand averages 10 × 256 = 2,560 token/s and peaks at 7,680 if requests are admitted and completed with this distribution. These describe demand, not measured card capacity. A 4,096 input-token/s tenant quota allows about two standard prompts per second. Short prompts with long output can still consume decode, requiring output credits, concurrency limits, and fairness.

在线闭环：等待与 GPU 所有权分开Online loop: separate waiting from GPU ownership

正常路径与为什么这样拆Normal path and why these components exist

中文

Client 提交 messages、输出上限和幂等 key。网关用固定模型版本的 tokenizer 计算实际长度，检查上下文上限，校验租户输入和预留输出配额。之后用主体、key 与 body hash 在 Attempt Store 条件创建尝试；同 key 不同正文返回冲突。共享记录使换一台网关仍能识别原尝试，网关本地字典不具备这项保证。配额预留绑定 attempt，重复请求不重复扣；结果记录和配额若跨库，还要有可恢复的预留/撤销步骤，不能声称两次写天然原子。

Scheduler 条件绑定 owner worker 和单调 epoch，把待运行描述放进有界在线队列。请求上卡前原子领取页信用，再按 iteration token 预算启动。prefill 为输入建 K/V，计算得到首个输出；之后每轮处理新 token 并追加它的状态。实际缓存 token 与对外输出数量可以相差一个，因为首 token 已采样却尚未作为下一步输入，容量按 prompt + 输出上限取安全侧。所有 delta 经 worker→Scheduler→API gateway→Client，一条连接不会每个 token 重新选 worker。

等待队列里的请求没有 KV；已经在卡上的请求才有工作集。模型权重从对象存储加载并常驻，ready 还要求 KV 池、内核和健康状态可用。扩出新 worker 只接新工作，不能自动接管旧 worker 的 KV。权重大小不能给出冷启动秒数：对象读取、设备搬运、图捕获和预热都有开销，要记录实际 ready 时间，提前准备容量。

English

Client submits messages, output cap, and a dedupe key. The gateway tokenizes with a fixed model version, validates context length, and checks input plus reserved output quota. It conditionally creates an Attempt Store record keyed by principal, key, and body hash; conflicting payloads fail. Shared records survive a gateway change; a local dictionary does not. Quota reservations bind to the attempt and are not charged again on retry. Separate quota and result stores require recoverable reserve/revoke steps rather than an invented cross-store atomic write.

Scheduler conditionally assigns a worker and increasing owner epoch, then parks the description in a bounded queue. Admission atomically claims page credits and respects the iteration token budget. Prefill builds input KV and samples the first output; subsequent iterations process new tokens and append their states. Cached state count can differ from emitted token count by one because a sampled token may not yet be processed as the next input. Prompt plus output cap is conservative. Every delta returns worker→Scheduler→API gateway→Client; a stream does not choose another worker per token.

Waiting descriptions own no KV; active requests own a working set. Weights load from object storage and remain resident. Readiness also requires a usable KV pool, kernels, and health. New workers serve new work rather than automatically inheriting old KV. Weight bytes do not establish cold-start duration: reads, transfer, graph capture, and warmup need measurement and advance capacity preparation.

替代、过载和接口边界Alternatives, overload, and API boundaries

中文

在线队列非空时，离线长摘要不能随意插进同一轮。另池隔离牺牲共享利用率，换来在线资源不会被离线 prefill 占住。流量很小可同池，但要限制离线 chunk、并发和 token 预算；单个正在执行的 chunk 仍可能延迟在线输出，不能只贴一个“高优先级”标签就算隔离完成。

100 条只是描述数上限，不是延迟保证。按示例 μ = 12 req/s 粗算，100 ÷ 12 ≈ 8.3 秒排队量，早已超过 600 ms；即使近似 μ × 0.6 = 7.2，也不能把“队列限 7 条”当 p99 保证，服务时长和可释放信用有方差。按预计等待、最早截止时间和实时页/计算预算共同准入，到期仍未启动就撤销预留并返回过载。

流开始前，租户超额或队列期限无法满足用 429，服务无健康容量用 503，上下文越界用 400；这是本章接口约定，不能仅按“显存满了”机械选状态码。SSE 头已发出后不能改成另一个 HTTP 状态，用终止事件说明失败，socket 不可用时由客户端感知断流。代理缓冲要关闭或限制，应用应及时 flush，否则 GPU 首 token 已出而用户 TTFT 仍很长。

English

With online work pending, offline summaries cannot freely join the same iteration. A separate pool sacrifices shared utilization for isolation from offline prefill. A small deployment may share capacity with bounded offline chunks, concurrency, and tokens. A running chunk can still delay online output; a priority label alone does not provide isolation.

A queue cap of one hundred descriptions is not a latency guarantee. At illustrative μ = 12 req/s, 100 ÷ 12 ≈ 8.3 seconds of queued work exceeds the 600-ms budget. Even μ × 0.6 = 7.2 does not make a seven-request cap a p99 guarantee: duration and release timing vary. Admit using estimated wait, deadlines, and live page/compute budgets. Expired waits revoke reservations and return overload.

Before stream start, our API uses 429 for tenant limits or unacceptable queue delay, 503 for no healthy capacity, and 400 for invalid context length. Memory pressure alone does not choose the status code. After SSE headers, emit a terminal event rather than changing HTTP status; a broken socket is detected by Client. Bound proxy buffering and flush promptly, or client TTFT stays high after the GPU produces its first token.

KV 分页：信用、映射和共享三层账Paged KV: credits, mapping, and sharing

正常路径：逻辑连续，物理不必连续Normal path: ordered logical blocks, scattered physical blocks

中文

图的页表把 R1 的 L0、L1、L2 分别指到 P7、P2、P9；编号散落不是网络跳转。演示页大小 4：7 个 prompt 状态占两页，下一步写第 8 个状态填第二页，第 9 个才需第三页。生产页大小 16 来自 A4，不能把演示页的数字直接套进 320 MiB。PagedAttention 的关键是 attention 可以通过映射访问非连续 KV，减少连续大块预留带来的碎片 [2]。

本章选严格信用：每条活动请求承诺最大长度，但物理页按当前状态增长，未来信用尚未兑现。于是“池有空闲物理页”和“可以承诺新请求”是不同条件。第 129 条会让承诺变成 129 × 320 = 41,280 MiB，比 40,960 MiB 超出 320 MiB。把每次乘法写全，避免只背第 129 条这个结论。真正需要守的是所有承诺之和不超过可用池。

严格信用保守，但在所有输出接近上限时不用临时赶人。替代是按活页准入、预算不够时抢占或重算；这样空闲位置更少，代价是被抢占请求等待变长、重新 prefill 增加计算。分页解决物理碎片，不自动解决逻辑超订。已有请求若已经拿到完整信用，下一页在理论上应有额度；频繁“突然没页”说明共享/COW 开销、页表或激活预算没有算全。

English

R1’s L0, L1, and L2 point to P7, P2, and P9. Scattered IDs are not network hops. With four-state toy pages, seven prompt states occupy two pages; state eight fills page two and state nine requires a third. Production pages hold sixteen states under A4; toy sizes do not determine 320 MiB. PagedAttention uses mapping-aware attention over noncontiguous KV to reduce fragmentation from contiguous reservations [2].

Our conservative policy promises full length per active request while allocating physical pages as states grow. Unused future credits are not yet physical allocations. Free physical pages and available new-request credits are therefore different. The full-cap credit total for request 129 is 129 × 320 = 41,280 MiB, exceeding 40,960 MiB by 320 MiB. Preserve the complete multiplication rather than just memorizing request 129. Total commitments must fit the usable pool.

Strict credits are conservative but avoid emergency eviction when every output approaches its cap. Live-page admission with preemption or recomputation improves utilization while increasing waiting and prefill work for victims. Paging fixes physical fragmentation, not logical overcommit. If a fully credited request unexpectedly lacks a page, recheck sharing/COW overhead, tables, and activation budgets.

前缀缓存的收益和失效边界Prefix reuse and invalidation

中文

前缀复用比较的是实际 token 前缀及其计算身份，不能简单说“多一个空格整段必失效”。不同文本可能分成相同 token，模板或位置变化也可能让看似相同文本变成不同计算。固定模型版本、tokenizer、位置语义和 LoRA，完整块按父哈希、块 token 和额外身份构成键；vLLM v0.15.1 文档还列出 LoRA、多模态哈希与 cache salt，并说明缓存完整块 [5]。模型升级切新命名空间，不能把旧 KV 拿给新权重。

复用时新增请求引用，生成时写入私有尾块；若实现共享未满尾页，就必须 copy-on-write。共享完整前缀还可在请求结束后作为可淘汰缓存保留，所以“引用归零”不等于“当场把物理页擦空”。需要分清活动引用、可驱逐缓存和真正空闲页。保守承诺默认不计命中收益，能简化所有输出变长时的预算；若把共享收益用于提高准入，就必须为尾页复制和缓存驱逐建立同一账本。

APC 减少重复 prefill，不缩短需要生成的后缀步数，官方限制明确如此 [6]。前缀不匹配、页被驱逐或模型身份变化都回到正常计算，不能把 miss 算生成失败。多租户共享还要防时延泄露，本章采用服务器按信任域生成 salt；任由请求者选择别人的 salt 不构成隔离。缓存省算力，不应让一次热命中绕过输出额度。

English

Prefix reuse compares token IDs and computation identity, not a blanket rule that one extra space invalidates everything. Distinct text may tokenize identically; templates and position changes may alter apparently identical text. Fix model version, tokenizer, position semantics, and LoRA. vLLM v0.15.1 keys complete blocks using parent hash, block tokens, and extra identities including LoRA, multimodal hashes, and cache salt [5]. Model upgrades use a new namespace; old KV cannot serve new weights.

Reuse adds an active reference and generation writes a private tail. Sharing a partial tail requires copy-on-write. Completed full prefixes may remain evictable cache entries, so zero active references do not imply immediate physical erasure. Distinguish active refs, evictable cache, and free pages. Conservative commitments ignore cache-hit savings. Using sharing to increase admission requires one ledger for tail copies and eviction.

APC reduces repeated prefill without shortening suffix generation steps [6]. Prefix mismatches, eviction, and model changes compute normally rather than failing generation. To avoid timing leakage across tenants, our server assigns salt by trust domain; a client choosing another tenant’s salt is not isolation. Cache savings do not bypass output quota.

Continuous batching：每轮改变成员Continuous batching: membership per iteration

正常路径与调度层次Normal scheduling and its layers

中文

图按时间累积：t 有 A、B、C，D 等待；B EOS 后退休引用；t+1 检查预算让 D prefill；t+2 D 开始 decode。Orca 提出 iteration-level scheduling 与 selective batching [1]。这解决整请求级批次的进入/退出屏障；实际新请求仍可能因显存、计算、公平性或优先级等待多轮。“下一轮可考虑”不能翻译成“所有新请求最多等一轮”。

CPU Scheduler 决定本轮 token 数、活跃序列和 chunk，GPU 内核执行这些算子。decode 多请求可以分摊权重访问，但每轮成本取决于活跃上下文和内核；128 条长上下文不会天然保持单条请求的 20 ms。调 batch 时同时观察用户间隔、prefill 完成速度和页压力，取延迟与显存约束中更紧的那个。FlashAttention 优化 HBM 与片上 SRAM 的 IO，是 attention 内核 [4]；它不会替你实现租户公平或取消生命周期。

公平至少同时计输入工作、decode 步数和占用页。单租户大量小 prompt 可以用输出填满所有轮次；另一租户的大 prompt 若一直让位也会饿死。用租户队列、受预算限制的加权份额和等待年龄提升选择新工作，限制单轮总 token；这些是本章设计选择，不把某引擎当前默认 FCFS 说成全部场景最优。

English

The history accumulates t with A/B/C and waiting D, B’s EOS retirement, D’s budget-checked prefill in t+1, and D’s decode in t+2. Orca introduced iteration-level scheduling and selective batching [1]. These remove whole-request batch entry/exit barriers. Memory, compute, fairness, and priority can still delay arrivals multiple iterations. Eligible for consideration next iteration does not mean every arrival waits at most one iteration.

CPU Scheduler selects tokens, active sequences, and chunks; GPU kernels execute them. Batched decode can amortize weight access, but cost depends on contexts and kernels. 128 long-context requests need not retain a single request’s twenty-ms gap. Tune batches against user gaps, prefill completion, and page pressure, using the tighter memory or latency constraint. FlashAttention reduces HBM/SRAM IO inside attention [4]; it does not implement tenant fairness or cancellation.

Fairness accounts for input work, decode steps, and page occupancy. One tenant’s short prompts can fill decode iterations with long outputs, while another’s large prompts starve. Our policy uses tenant queues, budgeted weighted shares, and wait-age escalation with a per-iteration token cap. These are design choices, not claims that one engine’s default FCFS is universally optimal.

三种延迟不能用一个 TPS 掩盖Three latency effects cannot hide behind TPS

中文

用户 TTFT 从发送请求计到收到首个内容。A6 的单请求预算是 50 + 排队 + 150 ≤ 800，所以留给等待 600 ms；网络、模板处理和发送缓冲都不能凭空省掉。这是一次请求的预算，不是“50 的 p99 加 150 的 p99”得到整条链 p99，相关性和联合尾部要端到端测量。

首 token 已在 prefill 结束时产生，若输出共 N 个，后续相邻间隔只有 N−1 个。固定间隔 20 ms 的例子：256 个输出剩 255 × 20 = 5,100 ms；加 200 ms 无排队首段预算约 5.3 秒。按 50 ms 算是 255 × 50 = 12.75 秒，但 p99 50 ms 不是每一步的硬上限，不能当总时长保证。输出上限、端到端截止时间和交互产品目标要另定。

TPOT 常用整请求 decode 时长除以输出间隔数，平均值会掩盖某一步停顿；本章另外统计 ITL 的相邻输出间隔 p99。排队影响 TTFT，长输出影响总时长，同轮 prefill 干扰影响 ITL。三个监控要分开。chunked prefill 把长输入切短并与 decode 组批，vLLM v0.15.1 的调优文档说明 token 预算影响 ITL 与 TTFT [7]，它仍是约束下的选择，不保证两边都随 chunk 变小而改善。

English

Client TTFT spans sending the request to receiving first content. A6’s per-request budget is 50 + wait + 150 ≤ 800, leaving 600 ms for waiting. Network, template processing, and send buffering remain. This is a request budget, not a sum of component p99s; correlations and joint tails require end-to-end measurement.

Prefill already produces the first token, so N outputs have N−1 subsequent gaps. With twenty-ms fixed gaps, 256 outputs add 255 × 20 = 5,100 ms; a two-hundred-ms no-queue first-token budget gives about 5.3 seconds total. At fifty-ms gaps the added time is 12.75 seconds. A fifty-ms p99 is not a hard per-step ceiling or total-duration guarantee. Set output caps and end-to-end deadlines separately.

TPOT commonly averages decode time across output intervals and can hide a single stall. We separately measure p99 ITL over individual adjacent-output gaps. Queueing affects TTFT, long output affects total time, and mixed prefill affects ITL. vLLM v0.15.1 tuning explains how chunked-prefill token budgets trade ITL against TTFT [7]; smaller chunks do not guarantee both improve.

取消与内存压力：先退休访问，再归还Cancel and memory pressure: retire accesses before release

正常生命周期与并发竞争Lifecycle and competing events

中文

取消可能来自用户关流、服务 deadline 或缓冲超限。网关向 Scheduler 发 attempt/epoch，Scheduler 只对匹配的 owner 标 CANCEL_PENDING，阻止后续调度。GPU 执行是异步的，已发出的共享 kernel 可以跑完；等访问相关页的 stream/fence 完成，才从请求的 block table 退休引用。EOS 和 cancel 同时发生时，单次状态转换决定谁做清理，重复消息返回已有终态，不能归还两次。

独占页在引用归零后可以复用，共享前缀还被其他请求持有就不能动。前缀缓存留存也要遵守驱逐规则，释放“这条请求的引用”和释放“缓存的物理页”是两步。Q1 只能在账本确认可复用后领页，不能在 CPU 已收到取消而 GPU 还没完成时提前写同一地址。取消之后继续占页的僵尸，会把本来可服务的信用吃掉；监控 cancel→retire→release 三段时间。

慢读者不应该拖住整批 GPU，也不能把每个 delta 无限存进网关。A11 给每流 64 KiB 待发送上限和 2 秒无进展期限；达到限制时暂停该请求的后续调度或取消，其他请求继续。必须先统计已缓存内容和输出额度，不能因为 HTTP 还活着就无限生成。128 条都顶格缓冲是 128 × 64 KiB = 8 MiB/网关承载集合，部署上按实际流数汇总，不能当全站固定值。

English

Cancel originates from client disconnect, service deadline, or buffer limits. The gateway sends attempt/epoch; Scheduler marks only the matching owner CANCEL_PENDING and prevents later scheduling. GPU work is asynchronous, so a shared issued kernel may finish. Retire block-table references after all relevant streams/fences complete. If EOS races cancel, one state transition owns cleanup; duplicate messages return the saved terminal state without releasing twice.

Exclusive pages can be reused at zero references; shared prefixes held elsewhere cannot. Cached prefixes follow eviction rules, separating request-reference release from physical-cache release. Q1 claims pages only after the ledger confirms reuse, not merely when the CPU receives cancel. Zombie ownership consumes capacity; monitor cancel→retire→release intervals.

A slow reader must neither stall the entire batch nor create unlimited gateway buffering. A11 caps pending bytes at 64 KiB per stream and cancels after two seconds without progress. Pause later scheduling for that request or cancel it, while others continue. Track buffered output and quota rather than generating forever while HTTP lives. 128 full buffers total 8 MiB for that gateway’s stream set; aggregate actual stream counts in deployment.

分配拒绝与致命 CUDA 错误分开Allocation denial versus fatal CUDA errors

中文

没有页信用是一条可控准入拒绝：新请求继续等或过载返回，活动请求按已有承诺继续。活页策略中，可在新 kernel 发出前抢占个别序列。实际 OOM 可能来自激活峰值、图捕获工作区或隐藏分配，不能一律说“只失败申请页的那条，其他都继续”。先确认引擎能回滚分配且 CUDA context 健康，才能走局部清理。

非法访存、设备致命错误或进程被杀，按 worker 死亡处理，标记这张 worker 不可准入，终止其全部在途尝试并重启恢复。CUDA Runtime 文档对 illegal address 等错误明确要求重新启动进程 [8]。失效显存并非可原地归还给旧进程的正常池；持久 owner 账本要失效，重启后新 epoch、新池。把全部 OOM 画成“释放一个 block 就好了”会掩盖这条故障域。

English

Missing page credits produce controlled admission denial: new work waits or receives overload while previously committed work continues. Live-page policies may preempt sequences before another kernel is issued. Actual OOM can come from activation peaks, graph workspaces, or hidden allocations, so it is not universally isolated to the requesting sequence. Local rollback requires a healthy context and engine-supported recovery.

Illegal memory access, fatal device errors, or process death are worker loss: remove admission, terminate all in-flight attempts, and restart. CUDA Runtime documentation requires process relaunch for illegal-address errors [8]. Failed device memory is not a reusable pool in the old process. Invalidate durable ownership and restart with a new epoch and pool. Treating every OOM as one block release hides this failure domain.

流中断：尝试幂等不等于 token 送达Interrupted stream: attempt dedupe is not delivery

失败路径与重试语义Failure path and retry semantics

中文

worker decode 中途死亡，KV、采样状态与未保存输出都可能消失。健康探测阻止新准入，匹配 attempt/epoch 的终态更新为 INTERRUPTED；若连接可用，worker 故障经 Scheduler、网关逐跳发终止事件。网关自身死亡时旧 worker 未必死，恢复者先查询并取消旧 owner，或让其执行租约过期并拒绝旧 epoch 的输出，不能仅因为没有 heartbeat 就并发生成第二份。

同 key 重试恢复已保存结果：QUEUED/RUNNING 返回状态并拒绝另开流，DONE 返回完成元数据，INTERRUPTED 示例用 409 提示显式选择。这是本章设计约定，不是所有兼容 API 的默认行为。尚无字节写出也不自动重算，因为“没有记录”可能是记录落后，旧 owner 仍在生成。24 小时保留覆盖 15 分钟重试窗口；过期 key 先人工或产品确认结果，不能无限自动换 key 重发。

网关 seq=37 write 成功，只证明发送调用接受了字节，不能证明 Client 已解析或展示 37。客户端 ack 能标记它处理到哪里，也不能恢复死卡 KV。没有持久输出日志时，连“至少一次送达”都没有证据，更谈不上原 token 恰好一次。若产品需要重放，先把事件按 attempt/seq 持久保存，再发送，客户端去重并提供处理游标，保留期与恢复接口配套；这增加写延迟、存储和日志访问权限，不是本章基线的隐藏功能。

English

Mid-decode worker death can lose KV, sampling state, and unsaved output. Health checks stop new admission; the matching attempt/epoch becomes INTERRUPTED. If the connection works, the terminal event traverses Scheduler and gateway. Gateway death does not prove worker death. A recovery owner first queries and cancels the old owner or waits for its execution lease to expire while fencing old-epoch output. A missing heartbeat alone cannot authorize concurrent duplicate generation.

Same-key retries recover saved state: QUEUED/RUNNING report status without a second stream, DONE reports completion metadata, and INTERRUPTED illustratively returns 409 for explicit choice. This is our API contract, not a universal compatible-server default. Zero recorded writes does not authorize automatic recomputation; records may lag a live owner. Twenty-four-hour retention covers fifteen-minute retries. Expired keys need result confirmation rather than endless automatic new-key retries.

A successful gateway write at seq=37 means bytes were accepted by the send call, not that Client parsed or rendered event 37. Client acknowledgement can identify processing progress without restoring dead KV. Without a durable output log, neither at-least-once nor exactly-once delivery is established. Replay would persist attempt/seq events before sending, deduplicate at Client, and define cursor plus retention. This adds latency, storage, and access controls rather than being a hidden baseline capability.

续写、重新生成和观测Continuation, regeneration, and observation

中文

用户可以明确重新生成整段，也可以提交自己收到的前缀作为新请求。续写用新 key、新显存信用、新 prefill；需要重新校验拼装后的实际 token 长度。把文本塞回 assistant 消息可能加入新的模板控制 token，不能保证等价于原来的原始 token 前缀。若想重算后继续同一 token 串，需要固定模型版本、模板、原始 token 序列和采样状态协议；即便这样也不凭空恢复已丢失的随机状态。

max_tokens 指新的生成额度，减少多少按客户端确认的 token 计，不按网关 write 次数计；SSE 一个 delta 可能对应多个 token 或不完整文本片段。客户端不能拿 UTF-8 字节偏移当 tokenizer 位置。残缺终止事件、断在多字节字符中间和重连重复都要由流解析器处理。没有日志的基线提供明确失败与显式新尝试，不提供“409 body 一定有完整已交付文本”。

观测按端到端与资源分层：用户 TTFT/ITL/总时长，输入/输出 token 需求与 goodput，队列年龄、过期和租户拒绝，预留信用、活页、缓存页与激活峰值，以及取消退休时长和 worker 致命错误。还要统计重试命中、旧 epoch 丢弃和缓冲超限。GPU 利用率高而达标比例下降，可能只是把更多迟到 token 算出来；容量决策必须回到目标负载下的 goodput。

English

A user can explicitly regenerate or submit the actually received prefix in a new request. Continuation uses a new key, credits, and prefill, validating the assembled token length again. Text inserted into an assistant message can introduce template tokens and need not match the old raw prefix. Recomputing the same token sequence requires fixed model/template versions, raw tokens, and a sampling-state protocol; missing random state is not restored automatically.

max_tokens controls the new allowance. Reductions use client-confirmed tokens rather than gateway write calls; one SSE delta may contain multiple tokens or partial text. UTF-8 byte offsets are not tokenizer positions. The parser handles partial terminal events, split multibyte characters, and reconnect duplicates. Without a log, the baseline offers explicit failure and new attempts, not a guaranteed complete delivered prefix in a 409 body.

Observe end-to-end TTFT/ITL/total duration, input/output demand and goodput, queue age/expiry and tenant denials, reserved credits/live/cached pages plus activation peaks, cancellation retirement, and fatal worker errors. Count dedupe hits, rejected old epochs, and buffer caps too. High GPU utilization with falling attainment may just produce more late tokens. Capacity decisions return to workload-specific goodput.

同卡到分离：把搬运和接收确认画出来Colocation to separation: transfer and acceptance

先用测量决定是否拆Use measurements to decide whether to split

中文

prefill 对长 prompt 常偏计算，decode 常偏内存带宽，但具体瓶颈随模型、batch 和硬件变化。两阶段共卡时，长 prefill 会推迟别人的下一个输出；先用 chunk、每轮预算与并发上限调优。如果 TTFT 和 ITL 仍无法同时满足、资源规模足够，再考虑 Prefill worker 与 Decode worker 分池。DistServe 用两个延迟约束下的 goodput 指导分离 [3]；本章不能因为平均显存 18.75 GiB 就宣称同卡已经达标，也不把分离写成所有流量的必选项。

图上的 A、B 是互斥方案，同一请求不同时跑两份。A 是共卡并限制 chunk，B 是目标 decode 页信用先保留，prefill 完成后把 KV 搬给该目标。首个采样 token 或初始 logits 与必要的采样元数据一并传给目标，Decode worker 接受后把首段和后续 delta 送回 Scheduler。目标验模型/LoRA、request、epoch、序列长度和 block manifest，接收成功才发送匹配的接受确认。源端在确认或有隔离保证的撤销完成后退休引用。metadata 到达不是 KV 字节到达，不能在发起复制时就释放源页。

搬运只算输入 KV：2,048 × 128 KiB = 256 MiB = 268,435,456 B。有效带宽假设 10 GB/s = 1010 B/s，纯传输 268,435,456 ÷ 1010 ≈ 26.8 ms。30 req/s 都分离时是 30 × 256 MiB = 7.5 GiB/s ≈ 8.05 GB/s ≈ 64.4 Gb/s，已经占示例有效带宽约 80.5%。这还没算排队、内存复制、握手和重复传输；带宽额定值不是可用值，并发搬运要封顶。

English

Long-prompt prefill often leans compute-bound and decode bandwidth-bound, but model, batch, and hardware change bottlenecks. Colocation can let long prefill delay others’ next output. Mean memory occupancy of 18.75 GiB neither establishes colocation’s SLO compliance nor makes splitting universally necessary.

A and B are mutually exclusive designs; a request does not execute both. A colocates bounded chunks. B first reserves destination decode credits, then transfers completed prompt KV. Transfer the first sampled token or initial logits and required sampling metadata too; Decode worker returns first content and later deltas to Scheduler after acceptance. The destination validates model/LoRA, request, epoch, length, and block manifest before acknowledging acceptance. Source references retire after matching acceptance or fenced abort cleanup. Metadata receipt is not byte receipt, so launching a copy does not authorize source release.

Prompt KV is 2,048 × 128 KiB = 256 MiB = 268,435,456 B. At assumed effective 10 GB/s = 1010 B/s, ideal transfer is 268,435,456 ÷ 1010 ≈ 26.8 ms. Thirty split requests/s demand 30 × 256 MiB = 7.5 GiB/s ≈ 8.05 GB/s ≈ 64.4 Gb/s, about 80.5% of the example effective bandwidth before queues, copies, handshakes, or retries. Rated bandwidth is not usable bandwidth; bound concurrent transfers.

失败窗口与扩缩容Transfer failures and scaling

中文

发送方超时可能只是接收确认丢了，目标已占页。以 transfer id/epoch 查询或重试确认，重复接收返回已有结果；终止时隔离旧 owner，再分别清理两端引用。若目标死了，源端还保留的输入 KV 也只覆盖当时的 prompt，不一定包含后来 decode 的后缀与采样状态。已经流出内容的请求仍走上一组的明确中断或新 prefill，不把“源端还在”当无感恢复保证。

两池分别扩容时同时看 prefill 排队、decode 活跃页和互连。TTFT 紧且 decode 留有空位，增加 prefill；decode 间隔坏、页压力大，就增加或调整 decode。目标不足却无限增加 prefill，只会制造已算完但搬不过去的 KV。缩容先摘新准入，drain 已有尝试到结束或明确取消；截止未到不能把活请求直接搬走。多卡 tensor parallel 时每个 rank 的权重、KV 与通信另算，不能把本章无分片的 40 GiB 除法原样套上去。

对外报告的是达标比例和成本。论文评测中的提升倍数带模型、工作负载、基线和延迟目标，不是生产保证；本章用一组可替换的假设完成白板推导，没有 GPU 实测吞吐。选共卡省搬运和两池闲置，选分离买独立阶段调度，代价是传输协议、重复暂存和更多故障点。两个方案都要守同一条取消、流失败和重试契约。

English

Sender timeout may mean the destination accepted pages but its acknowledgement was lost. Query or retry by transfer ID/epoch; duplicate acceptance returns the saved result. Abort fences ownership and cleans both sides. Even retained source prompt KV need not include later decoded suffix or sampling state. Once content has streamed, use explicit interruption or new prefill rather than a promise of seamless recovery because the source survives.

Scale using prefill wait, decode live pages, and interconnect pressure. Tight TTFT with decode headroom suggests more prefill; poor output gaps or page pressure require decode adjustment. More prefill without destination capacity merely accumulates undeliverable KV. For scale-in, stop new admission and drain or explicitly cancel existing attempts. Do not silently migrate live requests. Tensor-parallel ranks require separate weight, KV, and communication accounting; the unsharded forty-GiB calculation cannot be copied unchanged.

Report attainment and cost. Paper speedups carry models, workloads, baselines, and targets rather than production guarantees. This chapter supplies replaceable whiteboard assumptions without measured GPU throughput. Colocation saves transfers and idle split pools; separation buys independent phase scheduling at the cost of a transfer protocol, duplicate staging, and more failure points. Both retain the same cancel, stream-failure, and retry contract.

最后 20 秒：在线路径 Client→API gateway→Scheduler→GPU worker，token 每跳回来。128 条来自显存信用，不是吞吐承诺；分页管布局、逐轮调度管成员、内核管计算。取消等 GPU 完成再还引用，流中断保留尝试状态，续写显式新 prefill。阶段分离增加 256 MiB prompt KV 的搬运与接受握手，只有 goodput 和成本证据支持时才加。

English

With 8,192 input tokens and the same 512 output cap, 8,704 × 128 KiB = 1,088 MiB; 40,960 ÷ 1,088 ≈ 37.65 fits thirty-seven full-cap reservations. This is only memory capacity; benchmark longer prefill. Changing max_sequences alone does not address expanded input, and quotas plus wait budgets must be revisited.

Closing: Client→API gateway→Scheduler→GPU worker, with every return hop drawn. 128 comes from memory credits, not promised throughput. Paging manages placement, iteration scheduling manages membership, and kernels compute. Cancel waits for GPU completion before reference release. Interruption retains attempt status; continuation explicitly starts new prefill. Phase separation adds a 256-MiB prompt transfer and acceptance protocol only when goodput and cost evidence support it.
