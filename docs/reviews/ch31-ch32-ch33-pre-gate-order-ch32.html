设计 LLM API 网关LLM API gateway

本章核心：先获准，再生成；提交后不换流Core: authorize, reserve, then generate; never splice a committed stream

  • 路由是准入：权限、地域、能力与上下文先过滤，成本排序靠后。
  • 预算按 attempt：持久预占先于网络；UNKNOWN 保留预算，第二次调用另预占。
  • 交付有屏障：公共头、角色、心跳之前记录 COMMITTED，绑定选中的 attempt/owner；后续失败终止原流。
  • Routing is admission: filter access, residency, capabilities and context before ranking cost.
  • Budget per attempt: durable holds precede I/O; UNKNOWN retains its hold and a second attempt needs another.
  • Delivery has a barrier: bind COMMITTED to the selected attempt/owner before public headers, roles or heartbeats. Later failure ends that stream.

30 秒开场与职责The opening and service boundary

我设计给聊天后端与内部 Agent 使用的统一 LLM 入口。Edge 做身份和入口速率；LLM GW 固定模型契约、校验缓存、持久预占预算；Adapter 转换供应商请求与事件。每个物理调用单独记 usage。只允许一次经授权、重新准入的备用调用；公共响应提交后不再更换模型。

This gateway serves chat backends and internal agents. Edge authenticates and limits entry rate; LLM GW pins a model contract, validates cached answers and reserves durable budget; Adapter translates provider requests and events. Record usage separately for every physical attempt. Permit one authorized, readmitted fallback; no model replacement after public response commitment.

Clarify model, residency, tool/schema requirements, extra-attempt cost permission and reusable tasks. Our teaching interface is POST /v1/chat/completions + SSE, not every provider’s only interface. The gateway does not execute tool actions. Ch29 handles inference, Ch30/Ch31 retrieval and Ch33 tool authorization.

全局路径：Ledger 是权威，答案缓存走旁路Global path: authoritative Ledger, side answer cache

用末帧作总图：Client → Edge → LLM GW → Adapter → Backend；回复逐跳返回。Answer cache 只供查询，Ledger 保存请求、attempt 和预算。先验证身份与同 rid 状态，命中也重新授权；miss 获得预算及 deployment 速率/并发许可后才 dispatch。

Use the final frame as the overview: Client → Edge → LLM GW → Adapter → Backend; replies return hop by hop. Answer cache supplies candidates; Ledger owns requests, attempts and budget. Check identity and existing rid state first; hits reauthorize, and misses require budget plus deployment rate/concurrency permits before dispatch.

tenant 来自可信身份，不来自客户端自报 header；别名映射到受控计划，不接受任意 base URL。多份无状态网关共享同一预算权威，Ledger 故障时拒绝受硬预算约束的新 miss。入口 RPM、供应商速率、租户累计 quota 分开：缓存 hit 仍耗入口额度；返还本地 hold 不代表供应商窗口返还。速率服务与 Ledger 跨库时允许保守浪费许可，不承诺跨库原子扣款。

Derive tenant from verified identity and resolve aliases through controlled plans, never arbitrary base URLs. Gateway replicas share one budget authority; reject hard-budget misses when Ledger is unavailable. Entry RPM, provider rate and cumulative quota differ: hits still consume entry admission, and releasing a hold does not refund a provider window. Separate rate/Ledger stores may conservatively waste permits; do not promise an atomic cross-store debit.

路由：硬条件先过滤，备用调用重新准入Routing: filter hard constraints and readmit fallback

便宜不能补偿不合格。固定 plan p12 后，先过滤权限、地域、tools/schema、质量与上下文，再排健康/延迟/成本。8,000 输入+1,000 输出需要 9,000 窗口，不能放到 4,000 的小模型；摘要压缩与质量降级都要显式授权。

Low cost cannot make an ineligible backend valid. Pin plan p12; filter access, residency, tools/schema, quality and context before health/latency/cost. An 8,000-input plus 1,000-output budget needs 9,000 context, not 4,000. Summarization and quality downgrades require explicit permission.

principal = authenticate(credentials)                 # never trust tenant header
tenant = principal.tenant
digest = H(canonical_full_request)                    # includes accepted policy revision
if Ledger.lookup(principal.tenant, rid) exists:
    require same digest and current access
    return recorded status/result                     # no new model dispatch
plan = pin_route_revision(alias)
eligible = [d for d in plan.deployments
    if principal.may_use(d) and data.may_leave_to(d)
    and required_capabilities <= d.capabilities
    and final_input_bound(d) + enforced_output_cap(d) <= d.context
    and caller.accepts(d.quality)]
require eligible is not empty
candidate = AnswerCache.lookup(H(principal.access_scope, digest, plan, data_rev))
if reusable_task and candidate is COMPLETE and current_access(candidate.dependencies):
    if unexpired(candidate) and candidate.served_model in {d.model_revision for d in eligible}
            and candidate.route_revision == plan.revision and candidate.data_revision == data_rev:
        deliver_cache_only_if_unique_record_created(tenant, rid, digest, candidate)
        return recorded status                        # loser never starts another response
pool = rank_by_health_latency_cost(eligible).first
require shared_rate_and_concurrency.admit(pool.limit_group)
created = Ledger.reserve_first(tenant, rid, digest, plan, bound(pool))
if not created: return recorded status                  # concurrent winner owns I/O
Adapter.dispatch_once(created.attempt, pool)             # disable hidden retries
# Cache record uses the same unique (tenant,rid)+digest; service price is separate.
# Rate permits and Ledger are separate stores: lost permits may be wasted.

这是策略伪代码：候选能力来自可信配置；deliver_cache_only_if_unique_record_created 的语义是同一 Ledger 中以 (tenant,rid) 唯一、正文摘要一致的服务记录，竞争者只取已有状态。后面的 SQLite 展示 miss 如何真正建唯一请求与 attempt。缓存返回也必须先取得唯一交付资格并遵守提交屏障；缓存不能重放另一用户的结果。

坏参数、无权限、安全拒绝不进入备用分支。发出请求后超时可能已经生成收费：不允许额外费用就返回 UNKNOWN；允许的只读任务才能保留 a1 未决 hold，再为 a2 预占。所有 SDK/代理隐藏重试关闭或并入合计 ≤2 次。每次 dispatch 都重过所属共享限流组；换 key 不一定换配额。

≤2 只约束同一请求集合：1,200 条最多 2,400 次调用、预留工作量最多 7.2M token。只有 attempt 也落在同一分钟/稳态条件下，才写成约 40/s、7.2M/min；跨窗积压不能推出瞬时上界。首响应预算 0.2+0.8+0.2+0.7=1.9s，只余0.1s，备用不重置总 deadline。429 的有效 Retry-After 容不进剩余时间就停止；quota_exhausted 和提交前无容量 503 使用稳定分类。[2][7]

This is policy pseudocode using trusted capability configuration. The cache-record operation means one service record in the same Ledger under unique (tenant,rid) and a matching body digest; competitors read existing state. SQLite below shows actual miss-side request/attempt creation. Cache delivery also needs unique ownership and the commitment barrier; it cannot replay another user’s result.

Bad parameters, access failures and safety refusals do not authorize fallback. A post-dispatch timeout may have generated billable output: strict one-attempt policy returns UNKNOWN; cost-tolerant read-only work can retain a1’s hold and reserve a2 separately. Disable hidden SDK/proxy retries or count them in the total of at most two. Readmit every dispatch against its shared limit group; another key may share the same quota.

The cap bounds one request cohort: 1,200 logical requests permit at most 2,400 calls and 7.2M reserved token-work. About 40/s and 7.2M/min require matching dispatch windows or steady conditions; cross-window backlog has no such peak bound. The first-response budget 0.2+0.8+0.2+0.7=1.9s leaves 0.1s; fallback never resets the total deadline. Stop when a valid Retry-After exceeds the remaining budget. Use stable quota_exhausted and precommit no-capacity 503 classifications. [2][7]

预算：一条请求，多笔 attempt，分别保留证据Budget: one request, separate attempt holds and evidence

先把责任落盘，再接触网络。(tenant,rid) 绑定原正文摘要与路由计划；重放读取原状态，改正文冲突。每个 attempt 有独立 bound、pool、价格版本和 owner。UNKNOWN 不是免费，也不因租约或 TTL 到期退款。

Persist responsibility before network I/O. Bind (tenant,rid) to the original body digest and route plan. Replays read that state; changed bodies conflict. Each attempt owns a bound, pool, price revision and owner. UNKNOWN is neither free nor automatically refunded by a lease or TTL.

预占与 intent 同事务Hold and intent share one transaction

下面是可运行 Python/SQLite 文件库示例摘录。write_tx 实际执行 BEGIN IMMEDIATE，再 COMMIT/ROLLBACK；条件更新预算、唯一请求、attempt intent 在同一事务。只有 created=True 的原调用者允许发一次网络请求；丢 ACK 后不能凭查询到 intent 再发。SQLite 的写锁跨连接/进程，由数据库实现，粒度比 PG 行锁粗。[8][9]

This runnable Python/SQLite file-database excerpt uses actual BEGIN IMMEDIATE and COMMIT/ROLLBACK in write_tx. Conditional budget mutation, unique request creation and attempt intent share a transaction. Only the original created=True caller may send once; finding an intent after a lost ACK does not authorize redispatch. SQLite serializes writers across connections/processes at coarser granularity than PG row locks. [8][9]

def _hold(db, q, n, pool, bound, owner, price, model):
    changed = db.execute("""UPDATE budgets SET held=held+?
        WHERE tenant=? AND period=? AND blocked=0
          AND cap-settled-held>=?""",
        (bound, q["tenant"], q["period"], bound)).rowcount
    if changed != 1:
        raise Denied("quota_exhausted")
    db.execute("""INSERT INTO attempts
        (tenant,rid,n,pool,price,owner,bound,state,expected_model)
        VALUES(?,?,?,?,?,?,?,'INTENT',?)""",
        (q["tenant"], q["rid"], n, pool, price, owner, bound, model))
    db.execute("UPDATE requests SET selected=? WHERE tenant=? AND rid=?",
               (n, q["tenant"], q["rid"]))


def reserve_first(db, tenant, rid, digest, period, route, pool,
                  bound, owner, allow_extra=False, price="price-v1", model=None):
    valid_bound(bound)
    with write_tx(db):  # BEGIN IMMEDIATE / COMMIT or ROLLBACK
        q = request(db, tenant, rid)
        if q:
            if q["digest"] != digest:
                raise Conflict("rid_body_mismatch")
            return {"created": False, "request": dict(q)}
        db.execute("""INSERT INTO requests
            (tenant,rid,digest,period,route,allow_extra)
            VALUES(?,?,?,?,?,?)""",
            (tenant, rid, digest, period, route, int(allow_extra)))
        q = request(db, tenant, rid)
        _hold(db, q, 1, pool, bound, owner, price, model or pool)
        return {"created": True, "attempt": 1, "owner": owner}

并发只剩一份额度时，一个事务赢、另一个连同请求插入一起回滚。a2 的 reserve_fallback 在同一请求行上检查：允许额外费用、a1 已失败、尚未 committed/closed、owner 匹配、selected=1；再独立加 hold、插入 a2、切 selected=2。旧 a1 仍可结算 usage，但不能再交付或关闭 a2。生产移植到 PG 要为请求/attempt/预算选一致的锁顺序，处理唯一冲突、死锁与提交未知；本章未执行 PG。

With one hold left, one transaction wins and the loser rolls back request creation too. reserve_fallback checks extra-cost permission, failed a1, no commitment/closure, matching owner and selected=1 in the same transaction. It adds another hold, inserts a2 and changes selected to 2. Late a1 may settle usage but cannot deliver or close a2. A PG port needs consistent request/attempt/budget lock order plus unique-conflict, deadlock and unknown-commit handling; PG was not executed here.

结算按 attempt 唯一，不按任意事件编号Settle once per attempt, not once per arbitrary event ID

def settle(db, tenant, rid, n, input_tokens, output_tokens, evidence,
           *, upstream_id, served_model):
    # Evidence is final and authenticated by the trusted adapter/reconciler.
    if any(type(x) is not int or not 0 <= x <= 10**12
           for x in (input_tokens, output_tokens)) or not evidence:
        raise ValueError("final nonnegative usage and evidence required")
    with write_tx(db):
        q, a = request(db, tenant, rid), attempt(db, tenant, rid, n)
        if not q or not a:
            raise Denied("unknown_attempt")
        if not a["upstream_id"] or (upstream_id, served_model) != (
                a["upstream_id"], a["expected_model"]):
            raise Conflict("wrong_usage_source")
        payload = (input_tokens, output_tokens, evidence)
        if a["state"] == "SETTLED":
            if payload != (a["input_tokens"], a["output_tokens"], a["evidence"]):
                raise Conflict("conflicting_final_usage")
            return False
        actual = input_tokens + output_tokens
        db.execute("""UPDATE budgets SET held=held-?, settled=settled+?,
            blocked=CASE WHEN ?>? OR settled+?+held-?>cap THEN 1 ELSE blocked END
            WHERE tenant=? AND period=?""",
            (a["bound"], actual, actual, a["bound"], actual, a["bound"], tenant, q["period"]))
        db.execute("""UPDATE attempts SET state='SETTLED',
            input_tokens=?,output_tokens=?,evidence=?
            WHERE tenant=? AND rid=? AND n=?""",
            (*payload, tenant, rid, n))
        return True

结算以 (tenant,rid,attempt) 为唯一身份；相同最终证据只返回原结果，冲突 usage 转人工核账，不能换 event id 再扣一次。预留3,000、实际2,400：held 减3,000、settled 加2,400，净可用多600。两次均发生则分别结算，总成本可能4,800。所有晚到记录仍属于原预算周期；不能把月末未决 hold 自动清零。

本例只接受可信 Adapter/Reconciler 验证的最终 input/output 证据；先将 upstream request id 与 expected served model 绑定到原 attempt，结算再核对，不能把 a1 的 usage 给 a2。价格版本和来源保存在 attempt，费用按类别另算。输入/输出上界若被违反，仍记录真实债务并阻止新工作，不以回滚证据掩盖超额；这暴露前提失效，不能声称硬预算仍成立。provisional 只作未决估算、不冒充最终 settled；需要估算入账的产品要另建可幂等修正的审计链。

OpenAI Chat Completions 的 include_usage 尾包可能因中断/取消缺失；Claude message_delta 的 usage 是累计值，必须取最终累计值，不能逐条相加。两家速率规则也不同，Claude 分 RPM/ITPM/OTPM。缺 usage 保留 UNKNOWN hold，报告能力存在才按原 attempt 核账；本库 intent 与外部生成无法原子提交，恢复者不盲目重生成。[1][3][4][7]

The unique accounting identity is (tenant,rid,attempt). Identical final evidence returns the prior result; conflicting usage requires review, not another debit under a new event ID. Holding 3,000 then consuming 2,400 subtracts the entire 3,000 hold and adds 2,400 settled, releasing 600 net. Two executed attempts can cost 4,800. Late evidence stays in its original budget period; month boundaries cannot erase pending holds.

The model accepts only final input/output evidence authenticated by the trusted Adapter/Reconciler. Bind the upstream request ID and expected served model to the original attempt and check them at settlement; a1 usage cannot settle a2. Attempts retain source and price revision; compute currency charges by category separately. If a supposed upper bound is violated, record actual debt and block new work rather than roll back evidence. That invalidates the hard-bound premise. Provisional values remain estimates, not final settled charges; provisional debits need their own idempotent adjustment audit chain.

Interrupted/cancelled OpenAI Chat Completions may lose the include_usage tail; Claude message_delta usage is cumulative, so take the final cumulative value rather than sum events. Claude separately limits RPM/ITPM/OTPM. Missing usage retains UNKNOWN holds; use supported reports to reconcile the original attempt. Local intent and external generation cannot commit atomically, so recovery never blindly regenerates. [1][3][4][7]

exact 缓存：键相同，当前授权仍要成立Exact cache: matching keys still require current authorization

缓存是旧答案的复用许可，不是权限凭证。键覆盖完整请求、tenant/权限指纹、路由/模型/数据 revision；命中后再验当前访问权、条目完成状态、原过期时间和 served model 资格。若只是别名重指向新版本，旧答案不能混进新契约。

A cache entry is permission to reuse an old answer, not an access credential. Key the full request, tenant/access scope and route/model/data revisions. Recheck current access, complete state, original expiry and served-model eligibility. Repointing an alias must not mix old answers into a new contract.

canonical request 保留消息角色/顺序/有意义的空白，含系统提示、历史、tools/tool_choice、schema、采样参数与输出上限。个性化请求按用户隔离，批准的共享组才可共用；权限不可验证就拒绝该候选。60秒 TTL 是陈旧界限的一部分，不保证知识一分钟内不变。撤销与发送有竞争，已发字节无法收回，活跃流按产品策略终止。

只发布完整终止且通过格式/任务验证的结果，取消、错误 EOF、半段 tool JSON 不标 COMPLETE。stream hit 使用新的交付 id、公开 cache_hit、按契约返回事件；原始生成 usage 与本次 upstream_usage=0 分开，服务收费也另列。缓存服务故障降为 miss，仍受预算/上游准入；实时余额、动态工具动作优先 bypass。供应商 prompt caching 复用输入前缀计算，仍生成新输出，不等于整份答案缓存。[10]

Canonicalization preserves roles, order and meaningful whitespace, including system/history, tools/tool_choice, schema, sampling and caps. Isolate personalized users; share only approved scopes. Unverifiable access rejects a candidate. A 60-second TTL bounds only part of staleness, not knowledge updates. Revocation races sending: already-delivered bytes cannot be recalled, and active streams follow product termination policy.

Publish only complete, format/task-validated output; cancellation, error EOF and partial tool JSON never become COMPLETE. Hits use a new delivery ID, explicit cache_hit and declared events. Preserve original generation usage separately from this replay’s zero upstream usage and service price. Cache failure becomes a miss under normal budget/provider admission. Bypass live balances and dynamic tool actions. Provider prompt caching reuses input-prefix computation while generating new output; it is a different layer. [10]

语义缓存：相似只召回候选Semantic cache: similarity recalls candidates

默认关闭，只对验收过的 FAQ opt-in。权限、系统提示/历史、参数、模型/数据/embedding revision 固定为精确 namespace，只对最后一句近似检索。Embedding 本身也要出域授权、配额、费用和 deadline；失败走正常生成。

Default off; opt in only validated FAQ routes. Freeze access, system/history, parameters and model/data/embedding revisions in an exact namespace. Approximate only final-user text. Embedding also needs residency authorization, quota, cost and deadlines; failure takes normal generation.

cosine=0.96 是玩具分数，不是正确率。“允许取消”与“不允许取消”、100与1,000、今天与下月都可能接近。候选仍验权限、新鲜度、实体/日期/金额/否定，无法验证等价的自由文本保持关闭；固定 FAQ 可绑定同一批准问题 id 与答案 revision。不同 embedding、metric 和 score 方向不共用魔法阈值。

固定验证集500条、40次复用、1次错答：复用8%，命中内错答1/40=2.5%，总体1/500=0.2%不能替代前者。20/s全做 embedding 时，理想仅省1.6次生成/s，仍有18.4次生成/s；净收益=1.6×生成成本−20×embedding成本−查询与修错成本。授权泄漏独立计数；调参与验证分离，影子生成也预算，开关退回 exact/all miss。

Toy cosine 0.96 is not correctness. Opposing cancellation intent, 100 versus 1,000 and today versus next month may be close. Recheck authorization, freshness, entities, dates, amounts and negation. Keep unvalidated free-text equivalence off; fixed FAQs can bind an approved question ID and answer revision. Different embeddings, metrics and score directions share no magic threshold.

In 500 frozen validation queries with 40 reuses and one error, reuse is 8% and conditional wrong-hit rate is 1/40=2.5%; overall 1/500=0.2% cannot replace it. At 20/s with embeddings for all, ideal savings are only 1.6 generations/s while 18.4/s still generate. Net value subtracts twenty embeddings/s, lookup and remediation cost. Track access leaks separately; separate tuning from validation, budget shadow generation and retain an exact/all-miss switch.

SSE：提交屏障、有界转发与终止SSE: commitment barrier, bounded forwarding and termination

首文字 token 不是边界，公共响应提交才是。Ledger 中的 selected attempt/owner 与 COMMITTED 必须一起判断；fallback 用同一行事务切 selected。先持久提交、后发头，崩溃会保守拒绝本来还没发出的重试；反过来先发头再记账，会让恢复者误以为还能重生成。

First text is not the boundary; public response commitment is. Check selected attempt/owner with COMMITTED in Ledger; fallback changes selected through the same row transaction. Persist before headers: a crash may conservatively reject an unsent retry. Headers-before-record can falsely authorize regeneration after partial delivery.

可运行示例的 claim_commit 实际条件更新为：selected=n、owner匹配、未提交/关闭、attempt未失败。它与 fallback 竞争最多一方获准，晚到 a1 只能补 usage。查询到 COMMITTED 或提交 ACK 未知不等于允许重新 flush；示例没有流迁移、owner接管或持久 token 日志。Edge 必须在屏障前禁止提前200/心跳。

The runnable model’s claim_commit condition requires selected=n, matching owner, no commitment/closure and a nonfailed attempt. It competes with fallback so at most one path wins. Late a1 can only report usage. Observing COMMITTED or an unknown commit ACK does not authorize another flush. There is no stream migration, owner takeover or durable token log in the model. Edge must suppress early 200/heartbeats until the barrier.

# Pseudocode. Awaited writes propagate backpressure; no SDK prefetch.
# Bounded parser/read/encoded-event payloads each <=16 KiB; total budget <=64 KiB.
for event in bounded_utf8_sse(upstream, read_cap=16KiB, event_cap=16KiB):
    require absolute_deadline_not_expired and idle_read_deadline_not_expired
    normalized = Adapter.translate(event, encoded_cap=16KiB)
    if normalized.final_usage:
        require usage_source_matches(attempt, upstream_request_id, served_model)
        Ledger.settle(attempt, authenticated_usage)     # survives old-attempt arrival
    if normalized.error: raise trusted_Adapter_classification(normalized)
    if normalized.success_terminal:
        require validated_complete_output
    if normalized.public_output:
        if not locally_committed:
            won = Ledger.claim_commit(rid, attempt.number, attempt.owner)
            if not won: abort_upstream(); stop         # stale/unknown ACK: never send
            locally_committed = true
            Edge.begin_headers()                      # Edge sends no earlier heartbeat
        await Edge.write_all(normalized, blocked_write_limit=10s)
require valid_protocol_terminal and validated_complete_output
Ledger.close_if_selected(rid, attempt.number, attempt.owner)
AnswerCache.publish_if_reuse_authorized(complete_answer)

on timeout, disconnect, oversized_event, parse_error, classified_upstream_failure:
    abort_upstream_best_effort()
    Ledger.mark_failure(attempt, UNKNOWN_unless_proven_otherwise)
    if locally_committed:
        send_declared_error_if_writable_or_close_EOF()   # no success DONE, no fallback
        Ledger.close_if_selected(rid, attempt.number, attempt.owner)
    else if failure_class in {RATE_TRANSIENT, SERVER_TRANSIENT, DISPATCH_TIMEOUT}
            and policy_allows_extra_cost and deadline_remains:
        acquire_backup_rate_and_concurrency_permit()
        created = Ledger.reserve_fallback(rid, failed_owner, backup, new_bound, new_owner)
        # Same request-row transaction excludes commitment; UNKNOWN a1 stays held.
        if created: dispatch_a2_once()                # <=2 total; no deadline reset
        else: stop_and_recover_status()                # denial/unknown ACK never dispatches
    else:
        Ledger.close_if_selected(rid, attempt.number, attempt.owner)
        return_precommit_error()
# Local socket closure does not prove remote work stopped: retain UNKNOWN usage/slot.
# Cost uncertainty is separate from failure_class. Never fallback on disconnect,
# blocked write, parser/oversize/schema failure, access denial or safety refusal.

这是协议伪代码，未运行网络流。每次写完才读下一事件，16 KiB 的读块/单事件/编码输出限制与无预取合起来约束 ≤64 KiB 的应用载荷缓冲；超大事件拒绝，不能先分配整段再检查。TLS/socket、对象和整份缓存答案另计，真实 HTTP 库必须验证不会偷偷攒流。UTF-8 与 SSE 事件可跨网络 read，不能把 chunk 当 token。POST 用 fetch/SDK，原生 EventSource 不承载该正文；Claude 命名/流内 error 与 OpenAI 形状分别适配。[1][3][6]

公共头、role、heartbeat 或成功终止事件都先过同一屏障。提交后失败只能错误事件/异常 EOF，不改503、不补成功 DONE、不缓存半答。可否备用由可信 Adapter 的错误分类决定，与成本 UNKNOWN 分开；仅暂时限流/服务器故障/发送后超时入白名单，取消、写堵塞、解析/超大事件、schema、权限与安全拒绝都不换池。读空闲、首响应、总时长和写堵塞分别设 deadline；写堵塞10s或客户端断开向上游尽力取消。取消不证明远端停止，也不退 UNKNOWN hold；本地连接资源关闭后可释放，本地复制的远端并发额度要等终态证据或保守隔离，不能立即当空槽复用。

A8 在同一稳态边界取被接纳完成率20/s：首token0.5s，后399个间隔/50=7.98s，总8.48s，L=20×8.48=169.6≈170条平均流。200×64KiB=13,107,200B=12.5MiB只是缓冲上限，不证明尾延迟或故障幸存容量。输出 usage 可包括不可见 token，不能用客户端字数结算。[5]

This protocol pseudocode did not run a network stream. Await each write before reading the next event. A 16-KiB read/event/encoded-output cap plus no prefetch bounds application payload buffers to at most 64 KiB. Reject oversized events before allocation. TLS/socket buffers, objects and complete cached answers are extra; verify the actual HTTP library does not accumulate output. Incrementally decode UTF-8 and SSE across reads; chunks are not tokens. Use fetch/SDK for POST; native EventSource cannot carry that body. Adapt Claude named/in-stream error events separately from OpenAI shapes. [1][3][6]

Headers, roles, heartbeats and successful terminal events all pass the same barrier. Postcommit failure uses error/EOF, never 503, false success DONE or partial cache publication. Trusted Adapter failure classification is separate from cost uncertainty: only transient limits/server errors or dispatch timeout permit fallback. Disconnects, blocked writes, parsing/oversize/schema failures, access denials and safety refusals do not. Separate idle-read, first-response, total and blocked-write deadlines. Ten-second blocked writes or disconnection trigger best-effort cancellation. Cancellation proves neither remote completion nor a quota refund. Closed local connections release local resources; remote concurrency credit waits for terminal evidence or conservative quarantine.

A8 uses twenty admitted completions/s at the same steady boundary: first token at 0.5s plus 399/50=7.98s gives 8.48s; L=20×8.48=169.6≈170 mean streams. 200×64KiB=13,107,200B=12.5MiB bounds buffering, not tails or survivor capacity. Output usage may include invisible tokens, so visible character counts cannot settle it. [5]

复盘：用反例检验承诺Review: test claims with counterexamples

  • 并发最后一份预算：只能一个 hold 成功；重复 rid 不重复 dispatch。
  • intent 后崩溃：不能区分未发/已执行，保留 UNKNOWN；a2 需要额外预算与授权。
  • fallback 与首事件竞争：同一请求行选定 attempt；旧 owner 不能再写流。
  • 重复或冲突 usage：同 attempt 只结一次，冲突转核账，不按新 event id 重扣。
  • 撤销与慢客户端：cache hit 仍授权，写堵塞中止，取消不当退款。

可复现命令与完整源码见 examples/ch32。实际验证范围是 SQLite 本地事务/多连接/进程退出与协议手推；未执行 PG、真实 provider、网络 SSE、生产 tokenizer 或压测。指标分入口与 attempt，记录请求别名/served model/route revision、cache类型、首事件/结束时延和 UNKNOWN 年龄；默认不记录完整 prompt/凭证。

  • Last-budget contention: exactly one hold succeeds; duplicate rid never dispatches again.
  • Post-intent crash: unsent versus executed is ambiguous; retain UNKNOWN, and require separate budget/permission for a2.
  • Fallback versus first event: one request row selects the attempt; the old owner cannot write another stream.
  • Repeated/conflicting usage: settle an attempt once; conflicting evidence requires review, not a new-event debit.
  • Revocation and slow clients: authorize cache hits, abort stalled writes and never equate cancellation with refund.

See examples/ch32 for reproducible commands and full source. Execution covers local SQLite transactions, multiple connections, process exit and manual protocol traces, not PG, real providers, network SSE, production tokenizers or load testing. Separate entry/attempt metrics, record requested alias/served model/route revision, cache type, first/last-event latency and UNKNOWN age. Do not log full prompts or credentials by default.
