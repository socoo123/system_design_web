## 主线与实现

内容收为「四次成功 → 分区日志/顺序 → 复制水位 → 实际完成前缀/交接 → 同库效果与 Kafka 事务 → 切主拒写」。
16 项假设、详细 I/O 预算及扩展追问放入可展开区域；删去重复翻车表/收尾复述。
开头只突出三个决定，关键失败窗口与原容量算式保留。英文同步，14 张闪卡用统一 cards-grid。

原两段公式/API 数据块加清楚标识并同源；新增四段关键实现，共 **6 段同源代码**：

| 页面代码 | 源文件 | 实际保证及边界 |
|---|---|---|
| 留存/I/O 公式 | `capacity.txt` | 教学输入的精确乘法，无吞吐实测 |
| Java 17 完成前缀 | `PartitionProgress.java` | 一区至多一批，按实际交付顺序推进；稀疏 offset 不死等整数缺口；只在单一 poll 线程管理的本地对象 |
| poll/撤销适配器伪码 | `rebalance.pseudo` | 有界工作、显式提交 map、revoked 与 lost 分开、新 tracker 拒旧回调；真实成员 fencing 由 Kafka 提供 |
| PostgreSQL SQL/伪码 | `apply-event.pseudo` / `schema.sql` | 唯一 `(handler,event_id)`、完整意图/原结果、ledger 同库事务；SQL 错误回滚，COMMIT 未知重试原事件 |
| Kafka API 形状伪码 | `kafka-transaction.pseudo` | 纯 transform 输出和组 next offsets 同事务；提交超时不切 abort；没有真实集群执行 |
| 概念接口 | `contracts.txt` | 分清地址、业务身份、组恢复位置和 UNKNOWN，非 Java 签名 |

输入、输出、失败与简化契约在代码旁及 [README](../../examples/ch20/README.md) 中说明。
Java 页面是完整类的节选，全部方法由 poll 线程调用；worker 只投递完成消息。
局部前缀明确使用 `new OffsetAndMetadata(safeNext)` 省略未跟踪 epoch；
整批完成才复用本次 `nextOffsets()` 原元数据，不把批尾 epoch 贴给更早位置。

## 纠错与前提补全

| 原问题/缺口 | 本轮处理 | 一手证据 |
|---|---|---|
| 原正文概括“失败则 abort 并重放”，未区分 commit 超时 | 明确可中止的提交前错误才尝试 abort；commitTransaction 超时只能重试同一 commit 或 close，恢复先 initTransactions，不把 UNKNOWN 说成已中止 | Producer 4.1.2 API [7] |
| 固定 ELR=0 易被当成恢复所有旧版复制语义 | 保留 4.1/ELR=0，核对到 tag4.1.2：strict minISR 在 ISR 低于 min 时停止 HW；成员稳定路径才简化当前 ISR，真实算法还有 maximal ISR/待加入状态 | Topic configs [3]、Partition.scala [16] |
| 连续前缀仅口述，容易整数逐个扫描或提交 poll position | Java 跟踪实际交付 offsets + 该次 poll 终点，稀疏 [41,45,50]/终点53，先完成50仍停41 | Consumer [4]、nextOffsets [14]、真实 Java |
| 撤销和已丢失所有权未落成不同分支 | revoked 有界排空并显式提交安全前缀，finally 关闭；lost 直接关闭不提交；新 assignment 新 tracker | Listener [13] |
| 图中 Join / epoch e+1 容易误读为共享 generation | 改 join / heartbeat，正文/desc/图注明确各成员自己的 member epoch | 4.1 ConsumerGroupHeartbeat [5] |
| 本地去重仅写唯一 event_id，未给完整意图、命名空间和保留期 | 稳定 handler/event_id，逐字段校验本例完整 account/delta；原结果回放；inbox 与 ledger 同事务/同恢复；保留覆盖所有允许重放窗口 | PostgreSQL [15]；SQL 探针 |
| acks、复制与磁盘耐久易混同 | 保留且具体写出 page cache、非每条每副本 fsync、至少一份安全副本与相关失效条件 | Design [1]、Producer configs [2] |

## 独立复核返修：P2 空poll与多分区提交map

Ch19复核者发现原rebalance.pseudo把safe/commit写在for-p外，空poll时p未定义，
多分区时只覆盖最后p。这是有效缺口；原HTML `e540916e…`不再作最终实施版本。
现改每轮含空poll先处理完成邮箱，再注册新工作，然后遍历全部当前ACTIVE trackers建显式map并commitSync；
整批终点复用原元数据，局部或尚无poll时省略未知epoch。提交超时保留UNKNOWN，
ownership/rebalance拒绝后先处理交接，不跨重分配重试旧map。正常revoked仍仅尝试本次合格分区，lost不交。
Java核心未改；页面/README同源同步。作者重新执行39项检查、Java123断言、audit/空白与24浏览器组合、
120翻帧、6段复制及关键交互，全部通过，并目视新的390对照深色适配器代码。
SVG逐字未改：逐帧SHA核对后重新绑定60帧和390截图证据，JSON保留原renderedHtmlSha256与说明，
没有冒称此次重新渲染未变动画。独立问题关闭由Ch19复核者重验，主代理承接最终整合。
