## 主代理独立复算

Ch09 的单机规划预算为 1,000 × 60% = 600 QPS。峰值 11,600 QPS 正常需要 ceil(11,600/600)=20 台；20 台掉一台后仅 19×600=11,400 QPS，低于峰值。若故障后仍遵守此预算，需部署 21 台，失去一台后保有 12,000 QPS。同样条件下十倍流量正常需 194 台，N−1 需 195 台。

其余关键计算：62⁶=56,800,235,584；每天 100 万且无浪费时空间约 155.617 年；独立均匀候选的半概率碰撞阈值约 280,609.8。95% 有效命中留下 580 次/s 回源；800 次/s 上限需要至少 93.1034% 有效命中。冷缓存、键分散时最多拒绝 10,800/s；每日 1 亿请求的 99.99% 成功率预算为 10,000 次错误，可被约 0.926 秒此种故障消耗。均为教学假设下的算术，不是生产测量。

## 主代理审查入口

- Redis 的脚本执行不交错不能直接推导脚本运行时错误回滚。作者采用校验后单个 SET PX，将令牌余额、时间与过期一起写入；需另审 Redis 时间回拨、正跳、驱逐和切主边界。[Redis 官方脚本语义](https://redis.io/docs/latest/develop/programmability/eval-intro/)
- PostgreSQL READ COMMITTED 的每条语句重新取快照；唯一冲突不意味着当前语句可读到冲突行。创建路径遇唯一约束错误应先回滚，再以新语句读取幂等赢家；提交响应丢失不能当作已回滚。[PostgreSQL 18 隔离级别](https://www.postgresql.org/docs/18/transaction-iso.html)
- 实现预审已要求 Ch09 统一 snapshot.row 数据结构、SQL 参数命名、已保存响应变量；最终以作者修订与交叉复核为准。
