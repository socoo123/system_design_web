实施模型：GPT-6.1-Sol / Max。范围仅 `chapters/ch26.html`、`examples/ch26/` 与本章审查材料；共享 UI/脚本/首页/工具/计划未写，未提交、推送或部署。此报告是作者证据，独立复核结论另记。

## 发现与处理

| 发现 | 处理与证据 |
|---|---|
| 原章没有关键实现；整数分配、请求竞争、资金池及恢复安装都停在文字契约 | 在首次解释附近加入六段单份双语说明的同源代码：Java 17 整数计划、Lua 候选、领取/账本/关包/恢复伪代码。源码在 [examples/ch26](../../examples/ch26/README.md)。 |
| 最低每份固定 1 分，未展示参数与溢出边界 | 一般化最低额 m，先验 total/count≥m，金额限制 10¹² 分保证中间乘法不溢出；最后一份取尽，按固定份额身份打乱。图的 m=1 示例保留。 |
| 用户唯一与 HTTP 键竞争没有实现落点 | 请求 `(user,key)` 非空唯一并绑定 packet，先锁请求再锁包；不同键同用户由 `(packet,user)` 业务唯一收口；份额另设 `(packet,share)` 唯一。未知提交结果查询原身份。 |
| 资金预留与退款/领取在途的关系需要可执行说明 | 发送方余额→本包 escrow；资金余额、双分录、inbox 效果身份同事务。真实 SQLite 验证退款600先执行仍留400给已确认领取；EXPIRED 后领取入账继续。 |
| 恢复期/初始化期跨过截止点，旧文只允许 open 关闭，会留下晚资金确认的收口歧义 | 明确教学政策：创建意图+24 h 的 UTC deadline 一次固定，资金/安装/恢复延迟不顺延。fund未知留PENDING_FUND；晚APPLIED后INITIALIZING也能按原期限关闭退未分配总额。OPEN/RECOVERING 同门关闭。此政策替代旧“开放后24h”假设，中英、模型与卡片同步。 |
| “当前epoch条件写”未说明迟到安装如何隔离 | 每代独立命名空间、同packet hash tag，token绑定不可变快照；同token安装只返回状态，不填满已消费List。旧安装只碰旧代，发布重核epoch/token/ready/deadline。 |
| Stripe 行为未限定 API 版本 | 核官方当日页面，首结果/含500、参数比较及至少24h可清理明确限API v1，另写API v2失败续做差异。内部账本去重不照抄有限外部窗口。详见[来源记录](ch26-sources.md)。 |
| D4F5把本地等待超时画成Payment API返回 | 红线改为Relay自身回环，明确“没有Payment回复”，描述、图注、正文与未知结果分支同步。 |
| D1/D6入口标签被虚线边界穿过；D6恢复线路穿说明 | 两组左边界96→72，节点/主路径不变；D6说明上移并提炼到线路左侧。D3原10.17净距已足够，最终撤销无必要的边界移动，保留原SVG字节。 |
| flashcards 容器未用统一网格 | 改为cards-grid，保留12张双语翻卡，补充初始化晚资金/旧安装等新边界。 |

## 数字复算

10M÷86,400=115.7407…/s，十倍1,157.407…/s；50M点击为578.7037…/s及5,787.037…/s。热包最少9,900失败=99%；2 ms→500/s，60%预算300/s，100/s为理论能力20%。元信息1GB/天、claims2GB/天，七天21GB、三份63GB；金额数组80MB/天另计。

拆分上界500/466/299，300+400+100+200=1,000；1,003均分为三份251一份250。关闭1,000=400+0+600+0，退款后400+0+0+600；份数4=1+0+3。完整精确值与量纲留在自检JSON。

## 验证边界与冻结

SQLite实际写锁比PostgreSQL行锁更粗，未运行真实PostgreSQL、复制/切主、跨机时钟或真实机器断电；Lua只跑隔离单机，未验证Cluster重分片/副本故障、OOM及生产压测。认证/群资格、可信资金命令及结果验证是明确的本地适配契约，不等于实现真实SDK验签或资金渠道；Java有限样本不证明真实随机公平。余额教学模型不涵盖多币种、清算、争议或生产钱包。

最终页面与 `examples/ch26/` 全部文件SHA256见 [冻结哈希](ch26-final-hashes.json)。无`.pyc`/`.class`遗留。作者自检通过，等待交叉只读复核；主代理可重跑命令并将新结果另存，避免覆盖本次作者证据。后续如有修复须重新绑定哈希和受影响证据。
