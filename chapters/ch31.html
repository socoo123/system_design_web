向量检索服务Vector search service

约 40 分钟 · 前置：Ch03、Ch30 · 6 组 / 33 帧渐进白板图~40 min · after Ch03, Ch30 · 6 decks / 33 progressive frames

本章核心：近邻可近似，范围与读状态必须精确Core: approximate neighbors, precise scope and read state

给 Ch30 的 RAG 后端提供向量检索：先按字节与过滤形状选索引，再把写入可见性、全分片发布与缺片响应落到控制点。

三个决定：schema 固定模型/维度/metric；候选在同一快照内检查权限与版本；查询 pin 完整 bundle 和每片固定 cut，失败不能装成空集。

Provide vector retrieval to Ch30 RAG. Choose an index from bytes and predicate shape, then implement visibility, all-shard publication and missing-shard responses.

Three decisions: bind model/dimensions/metric in a schema; validate candidate scope and version within one snapshot; pin a complete bundle and fixed per-shard cuts, with explicit failure states.

先定接口与读契约Define the API and read contract

POST /v1/vectors/search 输入已计算的 query vector、model/schema、k、metadata filter 和可选写入 token。Query svc 从身份确定 tenant/collection，用户条件只能缩小范围；输出 id/version/distance、bundle、每片 cut、coverage 与 complete。这里 complete 只表示所有必需分片成功，不表示 ANN 找到了精确 top-k。

schema 由服务端登记且不可变，包含 embedding 模型的具体版本、维度、metric 与归一化规则；bundle 再绑定索引/codebook、路由代次和所有分片根。仅维度相同不能混用两种 embedding。L2 越小越近、内积越大越近；本章统一输出“小为近”的 distance：平方 L2、1−cosine 或负内积。Faiss 的 L2 输出平方距离，cosine 可用双方归一化后的内积 [2]。

本服务不计算 embedding、不做 BM25 融合和语义 rerank；这些仍由 Ch30 负责。原向量 rescore 仅重算同一种距离。权限投影可能落后于文档权威库，Ch30 在读证据与释放回答时仍要复查。

POST /v1/vectors/search takes an already-computed query vector, model/schema, k, metadata predicate and optional write token. Identity fixes tenant/collection; user predicates only narrow scope. Return ID/version/distance, bundle, per-shard cuts, coverage and complete. Here complete means every required shard succeeded, not exact ANN top-k.

An immutable server registry binds the exact embedding model revision, dimensions, metric and normalization. A bundle additionally binds index/codebook, routing generation and all shard roots. Equal dimensions do not make models compatible. Canonical distance ranks low first: squared L2, 1−cosine or negative inner product. Faiss reports squared L2 and supports cosine through normalized inner product [2].

Embedding, lexical fusion and semantic reranking remain in Ch30. Raw-vector rescoring recomputes the same metric. Index-projected permissions may lag the authoritative document store, so Ch30 still rechecks evidence access and response release.

1 亿 × 768 × 4 B = 307.2 GB 原向量；四片每片 76.8 GB，二副本共 614.4 GB。峰值 200 查询/s、k=10、完整查询 p95≤50 ms 是教学目标；所有索引参数与吞吐预算都是假设，未跑真实向量库压测。

100M × 768 × 4 B = 307.2 GB raw vectors; four shards need 76.8 GB each, with 614.4 GB for two copies. Peak 200 queries/s, k=10 and complete-query p95≤50 ms are teaching targets. Index parameters and throughput budgets are assumptions; no vector-database benchmark was run.

查询闭环：索引返回前先核对状态Query loop: validate state before returning

Query svc 先 pin 本次 bundle，再校验 query 的 model/schema 与它完全匹配，以及维度、有限数值、k/并发预算，随后按完整分片集合发出请求。alias 切模型后旧 embedding 要拒绝或由上游重算，不能重新贴标签。Index replica 搜索 pinned growing/sealed 状态，先剔除旧版本、墓碑和不合格候选，再按同一 metric 重算有界短名单，回 Query svc 归并。原向量键必须含 collection/schema/tenant/id/version，不能用裸 id 读错版本。

50 ms 包括排队、内部网络、搜索和归并，不含上游 embedding。若独立扫描全库，每查询搬 307.2 GB、200/s 就是 61.44 TB/s 逻辑读取；这否决本题未经验证的全扫默认值，不否决小允许集精确扫或经硬件验证的批量精确检索。

Query svc first pins this request’s bundle, then validates query model/schema against it, dimensions, finite values, k and concurrency before calling all required shards. After an alias model switch, reject old embeddings or have upstream recompute them; do not relabel them. Replicas search pinned growing/sealed state, exclude stale/deleted/ineligible candidates before local top-k, and rescore a bounded shortlist under the same metric. Raw-vector keys include collection/schema/tenant/ID/version.

The fifty-millisecond target includes queuing, internal networking, search and merging, excluding upstream embedding. Independent full scans imply 307.2 GB/query or 61.44 TB/s at 200/s. This rejects an unvalidated default corpus scan, while small exact subsets or validated batched exact search remain alternatives.

展开内存与副本账Memory and replication budget

307.2 GB≈286.1 GiB，四片各≈71.53 GiB。128 GiB×70%=89.6 GiB 热数据预算，只余约 18.07 GiB 放图、ID、标量索引与版本态；二副本原向量约 572.2 GiB。构建峰值、日志、备份与运行态另算。原向量冷放 SSD 可以省 RAM，但要另测随机 I/O 尾延迟。

307.2 GB≈286.1 GiB, or about 71.53 GiB/shard. A 70% hot-state budget on 128 GiB leaves 89.6−71.53≈18.07 GiB for graph, IDs, scalar indexes and versions. Two raw copies total about 572.2 GiB. Add build peaks, logs, backups and runtime; SSD raw storage trades RAM for measured random-I/O latency.

HNSW：上层导航，底层扩大候选HNSW: navigate above, broaden below

HNSW 在随机稀疏层上沿更近的点导航，再逐层下降；图中 F 在两层是同一 ID，箭头是副本内邻接/距离访问，不是 RPC。底层候选队列扩大搜索范围，但仍可能漏掉真近邻 [3]。

A4 的 M=16 影响邻接规模，ef_construction=128 影响建图探索，ef_search=64 是查询候选宽度；它与 k=10 分开，既不是访问 64 点的上限，也不是 Recall 保证。热图冷向量、严过滤与大量删除都要单独量完整查询尾延迟。

更新删除能力依赖具体实现。Faiss HNSW 文档明确不支持移除向量 [1]；在线层可用版本/墓碑禁止旧点返回，再异步重建。旧点提供内部邻接不等于允许它进入结果。

HNSW navigates sparse random upper layers and descends; F is one ID at two levels. Arrows are local adjacency/distance accesses, not RPCs. Bottom-layer exploration broadens candidates but can still miss true neighbors [3].

M=16 budgets adjacency, ef_construction=128 controls build exploration and ef_search=64 controls query width. These differ from k=10; width is neither a sixty-four-visit cap nor a recall guarantee. Measure cold-vector, restrictive-filter and deletion-heavy tails separately.

Update/delete support is implementation-specific. Faiss HNSW does not support removing vectors [1]. Service-level versions/tombstones may hide old points until rebuilding; internal navigation does not make a point eligible for results.

邻接槽位的简化预算A simplified adjacency-slot budget

假设底层最多 2M 个 4 B 邻接 ID：2×16×4=128 B/点，1 亿点为 12.8 GB、每片 3.2 GB。这不是完整 HNSW 占用：高层、容器、对齐、版本与引擎对象另算；8 B ID 使这项翻倍。

Assuming 2M four-byte base-layer IDs gives 128 B/point, 12.8 GB/100M and 3.2 GB/shard. Add upper layers, containers, alignment, versions and engine objects; eight-byte IDs double this term.

IVF-PQ：少探 list，少读候选字节IVF-PQ: fewer lists and smaller candidates

IVF 用训练质心把数据分入 list，查询只探 nprobe 个；IVF-Flat 在探到的 list 内比原向量，IVF-PQ 比短码。PQ 把向量分子空间训练 codebook，residual IVF-PQ 编码相对粗质心的残差，查询用查表距离 [1][4]。IVF 减少候选数，PQ 减少每个候选字节；Flat PQ 仍是全码扫描。

768/96=8 维一段，每段 8 bit，共 96 B code；加 8 B ID，1 亿条为 10.4 GB。3,072/96=32 倍只比较原向量与短码，不能套到整个服务。原向量若用于 rescore 仍需保留。

重算只修正短名单内部排序，补不回未探 list 或图中漏点。训练分布漂移会改变 list 倾斜和量化误差；新 codebook 必须重编码并发布完整 bundle，不能就地解释旧码。

IVF assigns vectors to trained coarse lists and probes nprobe lists. IVF-Flat compares raw vectors; IVF-PQ scores subspace codes. Residual IVF-PQ encodes residuals to coarse centroids and uses lookup-table distances [1][4]. IVF reduces candidate count; PQ reduces candidate bytes. Flat PQ still scans all codes.

768/96 gives eight dimensions/subspace. Eight-bit codes total 96 B/vector; with eight-byte IDs, 100M use 10.4 GB. The 3,072/96=32 ratio compares raw vectors with codes, not whole-service storage. Retain raw vectors if rescoring requires them.

Rescoring corrects shortlist order, not unprobed lists or missed graph points. Distribution drift affects list skew and quantization error. A new codebook requires recoding and complete-bundle publication rather than reinterpreting old codes.

With uniform lists: 25M/4,096≈6,103.5/list; sixteen probes scan about 97,656.25 records, or 10.15625 MB/shard at 104 B each. Four shards imply 40.625 MB/query and 8.125 GB/s at 200/s. These logical estimates exclude skew, centroid scoring, cache reuse, CPU and random I/O; they do not establish p95.

过滤：结果资格与导航资格分开Filtering: eligibility differs from navigation

ANN 可以少找；权限、版本和 schema 不能近似。小允许集可精确扫，大集合可用 filter-aware ANN 或有界补扫；无论路线，候选进入 local top-k 前都要复查同一快照的完整谓词与 live 版本。

ANN can miss neighbors; permissions, versions and schema remain exact. Use exact small-set scans or filter-aware ANN/bounded refill, with complete predicates and live-version checks before local top-k in the same snapshot.

public static Result select(Schema schema, String queryModel, String tenant,
    String category, List<Double> query, Map<Key, Point> pinnedLive,
    List<Candidate> stream, int k, int inspectLimit) {
  if (!schema.model().equals(queryModel) || k < 1 || k > 100 ||
      inspectLimit < k || inspectLimit > 100) throw new IllegalArgumentException("request");
  double[] q = checked(schema, query);
  Map<Key, Point> live = Map.copyOf(pinnedLive); // one immutable read cut
  Set<Key> allowed = new HashSet<>();
  for (Point p : live.values())
    if (!p.deleted() && p.key().tenant().equals(tenant) &&
        p.schemaId().equals(schema.id()) && p.category().equals(category))
      allowed.add(p.key());
  Map<Key, Hit> hits = new HashMap<>();
  int inspected = 0;
  for (Candidate c : stream) {
    if (inspected == inspectLimit) break;
    inspected++; // denied, stale and duplicate candidates also cost budget
    if (!schema.id().equals(c.schemaId())) throw new IllegalStateException("mixed schema");
    Point p = live.get(c.key());
    if (p == null || !allowed.contains(c.key()) || p.version() != c.version()) continue;
    if (hits.containsKey(c.key())) continue;
    double d = distance(schema, q, checked(schema, p.vector()));
    hits.put(c.key(), new Hit(c.key(), p.version(), d));
  }
  List<Hit> ranked = hits.values().stream()
      .sorted(Comparator.comparingDouble(Hit::distance)
          .thenComparing(h -> h.key().id())).limit(k).toList();
  String status = ranked.size() == allowed.size() ? "ALLOWED_SET_EXHAUSTED"
      : ranked.size() == k ? "K_REACHED" : "APPROX_SHORTFALL";
  return new Result(ranked, status, inspected);
}

这段可运行 Java17 标准库示例取自 VectorCandidates.java。输入 pinnedLive 是受信副本在固定 cut 的不可变状态；Key 含 tenant/id，Point 含版本、schema、metadata 与原向量。queryModel 必须匹配服务端 schema；checked 拒绝维度/非有限值，cosine 拒绝零向量并统一归一化，distance 把三种 metric 都转成“小为近”，算术溢出也拒绝。

候选流只是引擎给出的 ID/version，不接受其 payload/score 作为权威。代码在过滤和版本检查后才读原向量重算，重复、墓碑和拒绝项都消耗检查预算，最多重算 100 个。演示用 Map 全量数允许点，不适用于亿级生产规划；实际需同快照标量索引/bitset。没有运行 HNSW、IVF 或 ACORN，也没有证明召回。

K_REACHED 表示凑到 k，仍可能漏真近邻；ALLOWED_SET_EXHAUSTED 仅在已返回全部允许点时成立；其余为 APPROX_SHORTFALL。全局 status 还要汇总各片搜索状态。允许点只有三条与预算不足只找到三条不同，缺片又是另一类失败。

图中 A、B 合格，X 不合格；砍掉 X 的邻接会阻断 B。ACORN-1 的扩邻居思路允许发现此类路径，但不是任意谓词连通性保证 [5]。内部可读 X 邻接的前提是服务可信且允许这种隔离边界；需要防邻接侧信道时拆物理索引。pgvector 固定 v0.8.0 文档说明近似扫描后过滤、可选有上限的迭代扫描 [6]，不能把本图当它的实现。

Keys contain tenant/ID; points contain revision, schema, metadata and raw vectors. The server schema must match queryModel. checked validates dimensions/finite values, rejects zero cosine vectors and normalizes consistently. distance converts all three metrics to low-first distances and rejects overflow.

The engine supplies candidate IDs/versions; its payload/score is not authoritative. Filter/version checks precede raw-vector rescoring. Duplicate, denied and deleted candidates consume inspection budget; at most 100 are rescored. The model counts allowed points by scanning a Map; production needs same-snapshot scalar indexes/bitsets. It executes no HNSW, IVF or ACORN and proves no recall level.

K_REACHED means k were found, with possible nearest-neighbor misses. ALLOWED_SET_EXHAUSTED requires returning every allowed point; otherwise report APPROX_SHORTFALL. Aggregate per-shard search states globally. A genuinely three-point allowed set, budget-limited three hits and a missing shard are distinct outcomes.

为什么 k/s 只是期望Why k/s is only an expectation

独立均匀 s=0.001 时，100 个候选平均只剩 0.1 条；期望凑 10 条要 10/0.001=10,000 个。期望 10 不保证实际满 10，更不保证召回；谓词与向量相关时估算会失效。A7 的 5,000 点精确扫描为 15.36 MB，但随机 I/O 与截止时间会改变合适阈值。

At independently uniform s=0.001, one hundred candidates yield 0.1 match on average; expecting ten takes 10,000. Expectation guarantees neither fill nor recall, and predicate/vector correlation breaks the estimate. A7’s exact scan of 5,000 points reads 15.36 MB; random I/O and deadlines determine the measured threshold.

写入：持久接收与连续可搜分开Writes: durable receipt differs from contiguous visibility

202 证明日志已持久接收；只有连续 search-ready 前缀才能给读取使用。版本/metadata/向量缺一项都不能跨过该 LSN。growing、sealed 与单片 Manifest 是本章生命周期设计，下面的 SQLite 仅验证本地事务边界。

A 202 receipt proves durable acceptance; reads require a contiguous search-ready prefix. Missing vector, metadata or version state blocks that LSN. Growing, sealed and shard Manifest are this chapter’s design; the SQLite model below verifies only local transaction boundaries.

def apply_next(self, space, shard, fail_before_commit=False):
    with self.tx():  # actual SQLite BEGIN IMMEDIATE / COMMIT
        p = self.db.execute("SELECT * FROM progress WHERE space=? AND shard=?", (space,shard)).fetchone()
        lsn = p["applied"] + 1
        e = self.db.execute("SELECT body FROM event WHERE space=? AND shard=? AND lsn=?", (space,shard,lsn)).fetchone()
        if e is None:
            return False  # never jump across a hole
        body = json.loads(e["body"])
        old = self.db.execute("SELECT version,body FROM mvcc WHERE space=? AND shard=? AND tenant=? AND id=? ORDER BY version DESC LIMIT 1",
                              (space,shard,body["tenant"],body["id"])).fetchone()
        same = self.db.execute("SELECT body FROM seen_version WHERE space=? AND shard=? AND tenant=? AND id=? AND version=?",
                               (space,shard,body["tenant"],body["id"],body["version"])).fetchone()
        if same is not None and same["body"] != e["body"]:
            raise Rejected("same version, different payload; stop the prefix")
        self.db.execute("INSERT OR IGNORE INTO seen_version VALUES (?,?,?,?,?,?)",
                        (space,shard,body["tenant"],body["id"],body["version"],e["body"]))
        if old is None or body["version"] > old["version"]:
            self.db.execute("INSERT INTO mvcc VALUES (?,?,?,?,?,?,?)",
                            (space,shard,lsn,body["tenant"],body["id"],body["version"],e["body"]))
        # A stale event is a deterministic no-op, including an old upsert after delete.
        self.db.execute("UPDATE progress SET applied=? WHERE space=? AND shard=?", (lsn,space,shard))
        if fail_before_commit:
            raise Rejected("injected rollback")
    return True  # this transaction committed vector + metadata + version + watermark

完整 catalog.py 的 accept 在一个 BEGIN IMMEDIATE 事务内写 operation_id/规范化正文与 LSN，并推进 durable，提交后才返回 space/epoch/LSN；同 ID 同正文返回原位点，异正文冲突。版本来自可信上游，旧版本事件是 no-op，同版本异正文停止连续 apply，必须修复源事件/有序处置后恢复，不默默跳过。示例永久保留幂等记录，生产保留期需覆盖重试窗口。

上段真实事务把向量、metadata、版本（含 tombstone）与 applied 同时提交，异常全部回滚 [8]。SQLite MVCC 行与不可变 JSON root 代表同一可读状态，没有把独立向量库写入包进 SQLite 事务。真实引擎应先完成各结构到 cut 的写入，再发布共同不可变根/MVCC 读视图；出现洞时不能用“最大已完成 LSN”充当连续位点。图的复制 WAL 另依赖复制协议和故障模型，本例没有验证节点/磁盘丢失。

Builder 从 cut=b 的一致数据构建不可变段，增量继续写；验证 schema/codebook/checksum 后，由目标副本实际加载并回传绑定 root hash、cut 和进程 incarnation 的可读回执，再替换单片 manifest。旧 growing/sealed 路线在新状态就绪前继续服务。生产回执过期或加载资源丢失须重验；读时仍可失败，发布不能保证副本永不故障。

一次查询不仅 pin manifest 名称，还要把 sealed≤b + delta(b,cut]、live-version 和 payload 固定在实际 cut；只检查 applied≥cut 然后读取当前 mutable delta，会在重试时读到不同数据。可用 MVCC 按 cut 选行，或写时复制/不可变根。本例 stage_root 从已 applied 的历史行选择 cut 并保存独立 JSON，不冻结后续写。

删除 token 追齐后，同 ID 旧向量不能再返回；compact 仅回收字节与改善遍历。旧 pinned 查询仍按删前快照读，权限撤销不能只靠该快照。写后读 token 只是该片最少包含位点，不保证向量属于真 top-k，也不是固定快照或跨片事务；Milvus v2.6.x 的 Guarantee/Service timestamp 比较也区分“更新已包含”与等待追齐 [7]。

accept in catalog.py commits operation ID/canonical body/LSN and durable progress together with BEGIN IMMEDIATE, then returns space/epoch/LSN. Identical retries return the old position; changed bodies conflict. Trusted upstream supplies revisions. Older events are no-ops; same-version conflicting bodies stop apply until repaired or explicitly resolved in order. Deduplication is retained forever in this model; production retention must cover retries.

The displayed transaction commits vector, metadata, version/tombstone and applied together or rolls everything back [8]. SQLite MVCC rows and immutable JSON roots model coherent readable state; SQLite does not transact independent vector-database writes. A real engine completes every structure through cut before publishing shared immutable roots/MVCC views. Maximum individually completed LSN is insufficient. Replicated WAL in the diagram additionally depends on its replication/failure contract; node/disk-loss durability was not tested.

Builder constructs immutable segments from consistent cut b while ingestion continues. After schema/codebook/checksum verification, target replicas load the root and return readiness bound to root hash, cut and process incarnation. Replace the shard manifest only then; keep the old path meanwhile. Revalidate expired receipts or lost resources. Publication cannot keep replicas permanently available.

Pin the actual cut across sealed≤b + delta(b,cut], live versions and payload. Checking applied≥cut while reading the current mutable delta produces moving reads on retry. Use MVCC at cut or copy-on-write/immutable roots. stage_root selects historical rows through an applied cut and stores independent JSON while later writes continue.

After a delete token is covered, older versions cannot return; compaction reclaims bytes and traversal performance. Old pinned queries may retain pre-delete state, so permission revocation needs authority checks. A write token is a shard minimum, not a guarantee of top-k membership, a fixed snapshot or a cross-shard transaction. Milvus v2.6.x compares Guarantee/Service timestamps to wait for included updates [7].

完整 bundle：全分片发布、固定读取、缺片失败Complete bundles: publish all shards and read fixed cuts

def publish(self, alias, expected_seq, bundle, barrier):
    with self.tx():  # all roots and the alias CAS share one authority transaction
        b = self.db.execute("SELECT * FROM bundle WHERE id=?", (bundle,)).fetchone()
        if b is None:
            raise Rejected("unknown bundle")
        required = set(self.schema(b["space"])["shards"])
        roots = self.db.execute("SELECT * FROM root WHERE bundle=?", (bundle,)).fetchall()
        if set(barrier) != required or {r["shard"] for r in roots} != required:
            raise Rejected("missing shard or barrier")
        for r in roots:
            epoch, minimum = barrier[r["shard"]]
            if r["epoch"] != epoch or r["cut"] < minimum or digest(json.loads(r["document"])) != r["hash"]:
                raise Rejected("stale or corrupt root")
        self.db.execute("INSERT OR IGNORE INTO alias VALUES (?,0,NULL)", (alias,))
        changed = self.db.execute("UPDATE alias SET seq=seq+1,bundle=? WHERE name=? AND seq=?",
                                  (bundle,alias,expected_seq)).rowcount
        if changed != 1:
            raise Rejected("publication CAS lost")
        self.db.execute("UPDATE bundle SET published=1 WHERE id=?", (bundle,))
    return expected_seq + 1

bundle 绑定不可变 space/schema、route、codebook 和精确的必需分片集合；每片 root 绑定 epoch/cut、完整读状态与 checksum。上段是可运行 Python/SQLite 摘录：全部 roots、可信 barrier 位点向量与 alias 的 seq CAS 在一个权威数据库事务内核对/提交，竞争发布只有一个胜者；seq 单调递增防止 alias 名称来回切换掩盖旧发布。

示例 root 的字节就在 SQLite 内，stage_root 已校验 cut≤applied 并写不可变 JSON；因此 hash 验证能复算这些字节，不代表远端向量引擎已经加载。生产中把上一节的真实加载回执登记为 staged root 的前提，authority 仍只能原子切目录引用。新 manifest 未齐、任一片旧/损坏、CAS 失败均不切 alias；失败者重取当前状态后重新构建/核验。

pin 在同一 authority 事务中读取一次 alias/bundle/all roots 并登记 query pin；所有 fan-out 和同片重试都携 query/attempt、bundle/root hash 与相同的实际 cut。完整代码的 gather 只接收当前 attempt，拒绝混 bundle/移动 cut，同 attempt 重复只计一次。截止缺片默认 UNAVAILABLE、complete=false 且不输出普通结果；上游显式允许才返回 PARTIAL/covered/missing。完整空集才可解释为该搜索未返回匹配，ANN 空集仍不是精确无近邻证明。

每片 local top-k 必须先去重/过滤并按同一距离排序，再合并最多 4×10=40 项；精确 local top-k 足够覆盖全局 top-k（同距用稳定 ID 排序），ANN 的每片漏项仍存在。query pin 未释放或 alias 仍引用时不可退休旧 bundle；示例无自动超时回收，进程崩溃可能泄漏 pin。生产若用租约，过期 worker 必须停止访问旧资源，不能只删 pin 就回收文件。

固定每片 cut 的位点向量不等于跨片单一时刻或原子事务快照。此设计无跨片原子写。默认查询可读已发布旧 bundle；写 token 绑定 space/schema、分片和 epoch/LSN，模型切换后数值巧合相等也不能跨 space 使用；携 token 但 bundle 不覆盖时，等待/建立可覆盖的完整 bundle 或失败，不能悄悄读旧。若要求“最多旧 2 s”，还需有时钟误差与采样年龄界限的日志屏障证明，并在超时/证明失效时拒绝；本例没有实现该时间承诺。

A bundle binds immutable space/schema, routing, codebook and the exact required shard set. Each root binds epoch/cut, coherent state and checksum. This runnable Python/SQLite excerpt validates roots, a trusted barrier vector and alias sequence CAS in one authority transaction. Concurrent publication has one winner; monotonic sequence numbers prevent an alias round trip from hiding stale publication.

Model root bytes live inside SQLite. stage_root checks cut≤applied and writes immutable JSON, so hashes verify those bytes; this does not prove remote vector-engine loading. Production staging requires the previous section’s actual load receipts. The authority only switches catalog references atomically. Missing/stale/corrupt shards or CAS failure leave the alias unchanged; losers reread and rebuild/revalidate.

pin reads alias/bundle/all roots and registers a query pin in one authority transaction. Fan-out and same-shard retries carry query/attempt, bundle/root hash and the same actual cut. gather accepts only the active attempt, rejects mixed bundles/moving cuts and counts identical duplicates once. A deadline with missing shards returns UNAVAILABLE, complete=false and no normal hits. Explicit opt-in permits PARTIAL with covered/missing sets. Even a complete ANN empty response is not proof of an exact empty nearest-neighbor set.

Filter/deduplicate and sort local top-k under the same metric before merging at most forty items. Exact local top-k covers global top-k under stable ID tie-breaking; ANN omissions remain. Serving aliases or query pins prevent retirement. The model has no automatic pin expiry, so a crashed query can leak a pin. Production leases require expired workers to stop resource access before reclamation.

A fixed per-shard cut vector is not a single cross-shard instant or atomic transaction snapshot. There are no cross-shard atomic writes here. Default reads may use an older published bundle. Write tokens bind space/schema, shard and epoch/LSN; coincident numeric positions after a model switch do not authorize a cross-space token. An uncovered token requires waiting/building a covering bundle or failure. A two-second bound additionally needs log/time barriers with bounded clock uncertainty and sampling age, and rejection on expiry/timeout; that time guarantee is not implemented.

迁移、回退与故障容量Migration, rollback and failure capacity

索引重建保留同一 embedding schema，但每片新 codebook/索引要先按快照构建，回放包含 delete 的日志直到选定 barrier，加载并形成所有固定 roots，再 CAS 发布完整 bundle。换 embedding 时另建 space，上游必须提供新模型向量；源变更游标要同时驱动旧/新模型并协调屏障，不能把旧向量重新贴 model 标签。扩容换 route 则复制快照、追增量、验证新分片全集后一次发布，并提供旧 token 的路由转换或明确拒绝。

回退需要旧编码器与旧 space 仍持续摄取，重新生成覆盖当前新鲜度要求的 roots/bundle；仅保留老文件不能安全承接新读。旧请求继续使用自己的 pins。若新一代尚未齐，继续旧版本或失败，不能混着搜两种模型。示例只验证已提供向量的 space 切换，不执行 embedding、物理搬片或真实增量迁移。

四片不是每片 50/s：全局 200/s 会产生每片 200/s、合计 800 次片搜索/s。两副本各预算 120/s，稳态各接 100/s（83.3%），一份故障只余 120/s；要维持 200/s 就测得更高幸存容量或增加冗余并限流。四片各自 95% 赶上阈值，独立假设下同时赶上仅 0.95⁴≈81.45%；完整查询 p95 必须实测。

Index-only rebuilds retain embedding schema. Build a snapshot, replay logs including deletes through the chosen barrier, load all fixed roots, then CAS-publish the complete bundle. A model change uses another space with newly supplied embeddings. A source cursor must drive both models and coordinate barriers; relabeling old vectors is invalid. Resharding copies snapshots, replays deltas, verifies the complete new partition set and publishes one route, translating old tokens or rejecting them.

Rollback needs the old encoder/space kept current and new roots covering today’s freshness requirements. Retained old files alone cannot serve fresh reads. Existing requests keep their pins. Incomplete generations continue on the old version or fail; do not mix model spaces. The example validates switching spaces with already-supplied vectors, not embedding, physical resharding or real migration streams.

Each of four shards still sees 200/s, totaling 800 shard searches/s. Two illustrative 120/s replicas receive 100/s each in steady state (83.3%); one loss leaves only 120/s. Benchmark more survivor capacity or add redundancy and admission control. If each of four shards meets a threshold 95% of the time independently, all meet it only 0.95⁴≈81.45%; measure complete-query p95.

验收：召回、可见性、隔离分别测Evaluate recall, visibility and isolation separately

A12 冻结 query、schema、身份、filter 与数据快照，在同一允许集上精确算 ground truth；K=min(k,允许数)，Recall=|返回∩ground truth|/K。K=0 单列空集正确性，9/10=0.9，平均≥0.95 不能代表每请求≥0.95。分严过滤/相关性、小租户/热点、删除/growing、冷热页；调参集和独立回归集分开，同时量完整查询 p95/超时率和资源。

可见性反例：WAL 回执丢失后重试、apply 中途失败、旧 upsert 跟在 delete 后、同版本异正文、构建 CAS 输、发布缺片、旧查询跨新发布、token 超出 bundle、同片迟到/重复回复。隔离反例放一个更近的他租户点，必须零 ID/payload/score 输出。凑够十条无法证明这些保证。
