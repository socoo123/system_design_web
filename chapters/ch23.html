先说清结算事实、可见投影、最终名次三个承诺：写成功能恢复，读榜可有已说明的延迟，奖励只认验证过的不可变快照。

Separate durable scoring, visible projection, and final positions: acknowledged facts are recoverable, displays may lag under an explicit contract, and rewards use validated immutable snapshots.

先定成功、排序和预算Define success, order, and budgets

游戏服提交可纠错的绝对总分；Score DB 与 outbox 同事务确认，Redis 是可重建投影。同分先达秒更早者靠前，同秒用逆固定宽度 ID。先按榜拆，再按热度决定是否切一张榜。

主线限定同地域、同一权威库，同赛季全球与固定区服两视图；不处理客户端自报加分、跨区服转移或多人共同更新一行总分。主榜给唯一序号，允许新修订降分。若输入是独立对局增量，先在权威账本逐局去重求和，不能套用后面的绝对快照覆盖。

Game servers submit correctable absolute totals. Score DB and outbox commit together; Redis is rebuildable. Ties prefer an earlier achievement second, then reverse fixed-width ID. Separate boards before deciding whether to partition one hot board.

The mainline uses one region and one authoritative DB, with global and fixed-region views per season. Client score claims, region moves, and multiple independent writers of one total are outside it. Positions are ordinal and newer revisions may lower scores. Independent per-match deltas need an authoritative deduplicated ledger sum before absolute projection.

1 · 结算事实、事件身份与版本投影1 · Durable settlement, identity, and versioned projection

图第2–3帧是写成功的边界，第4–5帧才是热榜可见性。一笔结算产生两条独立目的地投影；任一Redis失败不撤销持久分数。游戏服重试保留同一业务身份，不能把超时当失败另造一次结算。

Frames 2–3 define successful scoring; frames 4–5 add visibility. One settlement creates two independently acknowledged projection destinations. Redis failure never reverses the durable fact. A timed-out game server retries the same business identity.

身份防重复，来源版本防乱序Identity prevents duplicates; source version handles order

唯一身份是 (game, season, player, match_id, kind, revision)。游戏/玩家/赛季归属由已认证游戏服与固定成员关系核准，不接受任意客户端board_id。身份绑定完整规范化意图：来源序号、绝对分、达成秒和比较器版本；同身份不同意图返回冲突，同身份同意图回放原回执。处罚用新revision与更高序号，不能改旧回执。

authority_seq 在 (game,season,player) 内持久单调、故障切换也不重置；更高序号的完整快照必须包含此前所有已接纳对局，并同时权威给定score与achieved_second。连续同分是否沿用原秒、处罚后回到旧分数取哪个新秒，都由来源按规范顺序算好；接收库不能凭已见历史猜测。这个前提由游戏服计分账本保证，数据库只验证版本不回退，不能从一个整数推导出“没有漏局”。v9先到可覆盖完整v8；若两条是各自独立的+10，丢弃v8就会少算。

Identity is (game, season, player, match_id, kind, revision). Authenticated authority and fixed membership validate scope rather than trusting a client board_id. Bind the complete canonical intent: source sequence, absolute score, achievement second, and comparator version. Changed intent conflicts; identical retries return the original receipt. A penalty has a new revision and higher sequence.

authority_seq is durably monotonic within (game,season,player), including failover. Each newer snapshot must include all previously accepted matches and authoritatively specify both score and achieved_second. The source computes unchanged-score time and a correction returning to an old score in canonical order; the receiver never infers time from arrival history. The game scoring ledger provides that premise; a DB version check alone cannot prove no match was omitted. A complete v9 may supersede v8; discarding an independent +10 event would lose points.

# PostgreSQL 18-shaped pseudocode; READ COMMITTED, all rows in one database.

    require old.intent == intent else ROLLBACK and CONFLICT

    VALUES (:scope,:player,0,0,0)

save_receipt(id, COMMITTED(authority_seq, absolute_score, t))

上例的唯一约束、玩家行锁、事务与outbox都在同一权威库；共享赛季行锁允许正常并发，截止控制器用排他锁等待全部在途结算后关门。[15] 记分前错误全回滚；COMMIT超时只代表未知，带原身份查询/重试。原回执v1不随当前v9改写，GET当前分数另查。

去重记录至少保留到旧赛季永久停止接纳、允许的重试/备份恢复/消息重放均被栅住且在途请求排空；本例不做TTL或身份GC。归档后未知旧身份只能查询/拒绝，不能当新结算。两目的地各记ACK，global成功不代表region成功。outbox同事务消除漏通知窗口，接收端仍要幂等。[6]

Uniqueness, player row lock, transaction, and outbox share one authority. Shared season-row locks permit concurrent writes; the closer takes an exclusive lock and waits for all in-flight settlements before fencing. [15] Precommit errors roll back. A COMMIT timeout is unknown: query/retry the same identity. Original v1 remains v1 after current v9; GET current state separately.

Retain dedupe until the old season permanently rejects new identities, all allowed retry/backup/replay paths are fenced, and in-flight work drains. This example performs no identity TTL/GC. Unknown archived identities query or reject, never become new scoring. Track each destination ACK separately. An outbox closes the notification gap, while consumers still need idempotency. [6]

把绝对版本投影到同槽键Project absolute versions to co-located keys

下面是可运行Redis 7+脚本，输入是已提交且已验证的投影行；scores与state位于同一个board/bucket/epoch hash tag。Hash的控制字段由控制器设置，业务写者不能改；p:member存 version:C。先校验类型、范围、scope和epoch，再比较版本；更新用绝对值，合法降分也接纳。

This runnable Redis 7+ script consumes validated committed projection rows. scores and state share one board/bucket/epoch hash tag. Only the controller may change hash control fields; p:member stores version:C. Validate types, bounds, scope, and epoch before comparing versions. Absolute replacement permits legitimate downward corrections.

-- Redis 7+; KEYS = scores ZSET, state HASH, with one board/bucket/epoch hash tag.
-- ARGV = scope, epoch, 12-digit member, version, exact integer composite C.
local function integer(s, lo, hi)
  local n = tonumber(s)
  if not n or n < lo or n > hi or n ~= math.floor(n)
      or string.format('%.0f', n) ~= s then error('invalid integer') end
  return n
end
local ztype, htype = redis.call('TYPE', KEYS[1]).ok, redis.call('TYPE', KEYS[2]).ok
if (ztype ~= 'none' and ztype ~= 'zset') or htype ~= 'hash' then
  return redis.error_reply('bad key type')
end
local scope, epoch, member = ARGV[1], ARGV[2], ARGV[3]
local v, c = integer(ARGV[4], 1, 1000000000), integer(ARGV[5], 0, 3000004000000)
if #member ~= 12 or not string.match(member, '^%d+$') then error('member') end
local mode = redis.call('HGET', KEYS[2], '__mode')
if redis.call('HGET', KEYS[2], '__scope') ~= scope
    or redis.call('HGET', KEYS[2], '__epoch') ~= epoch
    or (mode ~= 'LOADING' and mode ~= 'SERVING') then
  return redis.error_reply('fenced epoch')
end
local old = redis.call('HGET', KEYS[2], 'p:' .. member)
if old then
  local ov, oc = string.match(old, '^(%d+):(%d+)$')
  ov, oc = integer(ov, 1, 1000000000), integer(oc, 0, 3000004000000)
  if tonumber(redis.call('ZSCORE', KEYS[1], member)) ~= oc then
    return redis.error_reply('projection mismatch: rebuild required')
  end
  if v < ov then return 'STALE' end
  if v == ov and c ~= oc then return redis.error_reply('version conflict') end
  if v == ov then return 'REPLAY' end
elseif redis.call('ZSCORE', KEYS[1], member) then
  return redis.error_reply('missing version: rebuild required')
end
redis.call('ZADD', KEYS[1], ARGV[5], member) -- absolute value; lower C is valid
redis.call('HSET', KEYS[2], 'p:' .. member, ARGV[4] .. ':' .. ARGV[5])
return 'APPLIED'
-- Runtime write error is NOT rolled back: quarantine this epoch, do not checkpoint.

APPLIED/REPLAY/STALE才允许把该目的地标完成；REPLAY还要求同版本同C且ZSET/状态一致。消费水位只越过连续完成前缀。脚本的隔离性不提供SQL式回滚：即使先ZADD后HSET，运行时错误仍可能留下半步。[5][13] 因而错误/类型损坏/故障提升触发整epoch隔离（路由先撤健康资格；成员及版本一起丢失无法靠两个空读检测），停止服务和推进，控制器核对或重建后再开放；未知网络结果重试同事件，不能靠本地Set宣称跨故障幂等。

脚本只覆盖健康单节点中的两键，不实现控制器、故障探测、跨节点一致性或来源账本。示例在真实Redis里复现了写后Lua错误仍留值，并验证坏类型在写前被拒；没有做OOM、主从切换或集群实验。

Only APPLIED/REPLAY/STALE complete that destination. REPLAY also requires equal C and consistent ZSET/state; checkpoints cross only a completed delivered prefix. Script isolation does not provide SQL rollback: even ZADD before HSET can leave a partial effect on runtime error. [5][13] Errors, corruption, or promotion first withdraw serving health and quarantine the entire epoch (two missing member records cannot detect their own loss), stop serving/checkpointing, and require controller repair or rebuild. Unknown network outcomes retry the same event.

The script covers two keys on a healthy server. It implements no controller, failure detector, cross-node consistency, or upstream ledger. Real Redis probes retain a write after an injected Lua error and reject bad key types before mutation. OOM, failover, and Cluster were not tested.

2 · 同分全序、精度与名次语义2 · Total ties, precision, and rank semantics

排序规则先固定，数据结构再跟上。本章全序是基础分降序、达成秒升序、12位ASCII玩家ID降序；图中P7是 000000000007 的缩写。这给每个人唯一序号，主榜不承诺同分共享名次。

Fix the order before choosing its structure. Use base score descending, achievement second ascending, then descending 12-digit ASCII player ID. P7 abbreviates 000000000007 in the diagram. This produces ordinal positions rather than shared tie ranks.

赛季相对秒 0≤t≤2,592,000，整数分 0≤S≤10⁶。取T=3,000,000、B=T+1，C=S×B+(T−t)。高1分带来的B大于所有tie差；最大C=3,000,004,000,000，小于Redis精确整数边界2⁵³。输入越界必须拒绝并重新设计编码，不能悄悄扩赛季或拼小数时间。[1]

同score的ZSET按member字节序排列，REV把它反转，所以同秒同分P7在P3前，与插入先后无关。[4] 以下Java17把相同规则用于分桶归并和分页；本地比较器不提供分布式快照。

With 0≤t≤2,592,000 season-relative seconds and integer 0≤S≤10⁶, choose T=3,000,000, B=T+1, and C=S×B+(T−t). A point dominates every tie difference. Maximum C=3,000,004,000,000 lies below Redis’s exact-integer bound 2⁵³. Reject out-of-contract inputs and redesign the encoding when limits change. [1]

Equal-score ZSET members compare by bytes; REV reverses that order, so P7 precedes P3 regardless of insertion time. [4] The Java 17 comparator applies the same order during merge and pagination. A local comparator supplies no distributed snapshot.

public record Entry(String member, int score, int second, long version) {
    public Entry {
        if (member == null || !member.matches("[0-9]{12}")
                || score < 0 || score > 1_000_000
                || second < 0 || second > 2_592_000
                || version < 1 || version > 1_000_000_000L)
            throw new IllegalArgumentException("out of contract");
    }
    public long composite() {
        return score * 3_000_001L + (3_000_000L - second);
    }
}
public static final Comparator<Entry> ORDER = Comparator
        .comparingLong(Entry::composite).reversed()
        .thenComparing(Entry::member, Comparator.reverseOrder());

来源完整快照定义达成秒，接收端与分数/版本一起覆盖。来源按规范计分顺序处理连续同分时保留原秒，基础分改变后回到旧值则由新修订定义新的达成秒。首个合法0分也携带真实秒，不能继承占位行的0；旧身份重试仍回原值。反例v1=(100,10)、v2=(200,20)、v3处罚=(100,30)：无论按1→2→3还是1→3→2投递，最终都必须是v3的(100,30)，不能因接收时恰好同分变成(100,10)。

命令口径：top100是 ZRANGE key 0 99 REV WITHSCORES；个人降序序号是 ZREVRANK key member 加1；ZRANK没有REV参数。[2][3][4] 只保最高且绝不降分才可用GT；CH只改变返回计数。普通ZADD更新既有成员返回0，不代表写失败。[1]

The authoritative snapshot supplies achievement time, replaced together with score/version. In canonical scoring order the source preserves time across consecutive unchanged scores; after the score changes, returning to an old value uses the new revision’s authoritative time. A first zero score also supplies its real time rather than inheriting the placeholder’s zero. For v1=(100,10), v2=(200,20), v3 penalty=(100,30), both 1→2→3 and 1→3→2 must end at v3=(100,30), never (100,10) inferred from receiver history.

Top100 uses ZRANGE key 0 99 REV WITHSCORES. Personal ordinal position is ZREVRANK plus one; ZRANK has no REV parameter. [2][3][4] GT fits an increasing high-score-only rule. CH changes the return count; ordinary ZADD returning zero for an existing member is not a failure. [1]

3 · 更新、序号、附近与分页的一致性3 · Consistency across updates, rank, neighbors, and pages

活榜游标不能承诺不重不漏A live cursor cannot promise gap-free browsing

活榜用offset翻页，别人越过边界会让人重复或漏掉。完整元组 (C,member) 的keyset能定位边界，但同一玩家跨请求改分仍可能跨界，继续不能承诺全量不重不漏。存储epoch只标布局代次，SERVING epoch内数据仍会改。

本章精确浏览接口改为不可变snapshot_id：服务端保留完整排序结果，游标绑定scope、snapshot_id、比较器版本和offset；HTTP层验签、防篡改并核对访问权限后才调用下面纯函数。到期返回410并让用户重开，不悄悄接最新榜。签名和快照仓库是明确依赖，本例未实现。

Live offset pages can repeat or omit players when updates cross the boundary. Keyset (C,member) identifies a complete boundary but a moving player can still cross it between calls. A storage epoch identifies layout; data in a SERVING epoch keeps changing.

Exact browsing uses an immutable snapshot_id with a retained ordered result. Bind scope, snapshot ID, comparator, and offset in a signed cursor; the HTTP adapter verifies signature and access before this pure function. Expiry returns 410 and starts a new browse, never silently switches datasets. Cursor signing and snapshot storage are required adapters, unimplemented here.

public record Cursor(String scope, String snapshot, String order, int offset) {}
public record Page(List<Entry> rows, Cursor next) {}

public static Page page(Snapshot s, Cursor c, int limit, long now) {
    if (now >= s.retainUntil()) throw new IllegalStateException("410 expired");
    if (limit < 1 || limit > 100) throw new IllegalArgumentException("limit");
    int start = c == null ? 0 : c.offset();
    if (c != null && (!s.scope().equals(c.scope())
            || !s.id().equals(c.snapshot()) || !s.order().equals(c.order())))
        throw new IllegalArgumentException("cursor binding");
    if (start < 0 || start > s.rows().size())
        throw new IllegalArgumentException("offset");
    int end = start + Math.min(limit, s.rows().size() - start);
    Cursor next = end == s.rows().size() ? null
            : new Cursor(s.scope(), s.id(), s.order(), end);
    return new Page(List.copyOf(s.rows().subList(start, end)), next);
}

验证反例：初次顺序[P9,P7,P3]，第一页[P9,P7]后P3升到榜首；再读活榜offset=2得到P7，重复P7且漏P3。冻结快照仍用原排序，第二页只回P3。此函数仅分页已经固定的列表，不把Java内存对象当成跨片快照实现。

Counterexample: [P9,P7,P3] yields first page [P9,P7]. P3 moves to first; live offset=2 repeats P7 and misses P3. The retained snapshot still returns P3 on page two. This function pages a fixed list; a Java object does not create a distributed snapshot.

4 · 热点分片与全球topK的精度边界4 · Hot-board shards and global topK exactness

按榜拆key是默认；只有单热榜超预算才切玩家桶。Cluster分布的是key，一个ZSET不自动按成员拆分。需要同脚本的两键使用例如 lb:{g1:s17:global:b0:E7}:scores 与同tag的state；region/bucket/epoch都是范围的一部分。[8]

Separate board keys first; partition players only when one hot board exceeds its budget. Cluster distributes keys, not members inside one ZSET. Co-locate scores/state using a tag such as lb:{g1:s17:global:b0:E7}; region, bucket, and epoch belong to scope. [8]

A9假设单key预算10k更新/s，基准全球2,893.5/s不迫使切桶。放大10倍后28,935/s，ceil(28,935/10,000)=3桶；极端集中同一热区服时全球和该区服共6桶。图A/B仅示意。DB、relay、网络仍要按新规模测，不能用除法宣布端到端达标。

topK精确性的证明只针对同一不可变集合。不在本桶前K的人，至少已有K个本桶玩家领先，故不在全球前K。每桶至多K，按相同全序合并，全部桶成功才返回。manifest必须绑定snapshot_id、scope、比较器、路由版本及完整桶集合；同一个可变epoch字符串不足。

Assume a teaching 10k updates/s/key budget. Baseline global 2,893.5/s does not require buckets. At 10×, ceil(28,935/10,000)=3; global plus one maximally hot region needs six total. A/B are illustrative. Re-test DB, relay, and network; this division proves no end-to-end capacity.

The topK proof concerns one immutable set. Outside local topK means at least K local players precede the candidate, so it cannot be global topK. Merge at most K per bucket with the same total order and require all buckets. A manifest binds snapshot ID, scope, comparator, routing version, and the entire bucket set. A shared mutable epoch string is insufficient.

public static List<Entry> topK(Manifest m, List<Head> heads, int k) {
    if (k < 1 || k > 100) throw new IllegalArgumentException("k");
    Set<String> seenBuckets = new HashSet<>(), seenPlayers = new HashSet<>();
    List<Entry> candidates = new ArrayList<>();
    for (Head h : heads) {
        if (!m.buckets().contains(h.bucket()) || !seenBuckets.add(h.bucket())
                || !m.scope().equals(h.scope()) || !m.snapshot().equals(h.snapshot())
                || !m.routing().equals(h.routing()) || !m.order().equals(h.order())
                || !h.complete() || h.requested() != k || h.rows().size() > k)
            throw new IllegalStateException("incomplete or mixed snapshot");
        Entry previous = null;
        for (Entry e : h.rows()) {
            if (!seenPlayers.add(e.member())
                    || (previous != null && ORDER.compare(previous, e) > 0))
                throw new IllegalStateException("duplicate player or unsorted head");
            candidates.add(e); previous = e;
        }
    }
    if (!seenBuckets.equals(m.buckets()))
        throw new IllegalStateException("missing bucket");
    return candidates.stream().sorted(ORDER).limit(k).toList();
}

代码拒绝缺桶、混快照、错路由/比较器、重复玩家、未排序和不完整回包。存储适配器必须真实读取该冻结数据集的前min(K,N)条并标完整；Java检查不能证明一个失实的complete字段。2桶K=100最多200个候选，3桶最多300；本例为清楚直接排序，成本O(bK log(bK))，生产可用堆归并。

混时刻反例：A=10/B=20时读A=10；之后A降5，再B降0后读B=0。归并得到A10，但真实三个时点冠军分别B20、B20、A5，结果从未是同一时刻的榜首。只有一份共同不可变数据集才允许exact标签；活榜结果标live/mixed-time。

The code rejects missing buckets, mixed snapshots, route/comparator mismatches, duplicate players, unsorted heads, and partial replies. Storage must actually fetch the frozen first min(K,N) rows and attest completeness; Java cannot validate a dishonest complete field. Two K=100 buckets yield at most 200 candidates, three 300. This simple implementation sorts in O(bK log(bK)); production may heap-merge.

Mixed-time counterexample: read A=10 while B=20. A falls to5, then B to0; read B=0. Merge returns A10, while the actual winners were B20, B20, and A5. The result was never one instant’s top1. Reserve exact for a common immutable dataset; label live bucket reads mixed-time.

个人全球序号与附近比topK更贵Global personal positions and neighbors cost more

全球序号=1+各桶“严格更高C人数”+“同C且member靠前人数”。ZCOUNT (C +inf只处理第一项，不能漏同秒ID兜底。[11] 可为每桶另建score全为0的固定宽度全序token索引，再词典范围计数；这会增加内存和每次改分的原子更新工作，不能直接对不同score的主ZSET套BYLEX。[17]

Global ordinal position is one plus each bucket’s strictly-higher-C count and equal-C members ahead by the ID tie. ZCOUNT (C +inf covers only the former. [11] An extra all-score-zero fixed-width total-order token index supports lex counts but costs memory and atomic update work. Do not apply BYLEX to mixed scores in the main ZSET. [17]

Global neighbors need each bucket’s nearest five on either side of the complete token, merged with a position from the same snapshot. Local r±5 misses interleaved buckets. A missing bucket fails/waits exact personal reads; an old complete head follows the 30 s contract. Score-range shards can add higher-range counts, but migration needs duplicate/disappearance protection and the leading range can overheat. Those indexes and migrations are outside this example.

5 · 故障恢复、epoch与安全切换5 · Failure recovery, epochs, and safe cutover

Redis可恢复不代表消费确认一定被副本保住。故障提升可能丢掉已ACK的投影尾部；外部checkpoint=42不是新主拥有v42的证明。头部旧值有时间上限，个人读503，禁止把约1,736.1/s读峰值全部改打权威库做名次COUNT。

Recoverable Redis does not mean a replica retained every acknowledged projection. Promotion may lose an applied suffix; external checkpoint=42 does not prove the new primary has v42. Bound stale heads, return 503 for personal reads, and avoid redirecting all 1,736.1/s peak reads into authoritative rank counts.

Redis异步复制与AOF everysec可缩短恢复，不能承担本章已确认分数的耐久承诺；everysec通常可能丢约1秒数据。[7] 读并发/超时、计分、outbox和重建各留预算。监控最老未应用时间、连续已完成前缀与每目的地错误，不只检查消费者存活。

重建先创建隔离E+1并标LOADING。基线分数/版本快照与增量起点必须无缝衔接；PostgreSQL逻辑槽导出快照可提供“该状态之后的全部变化进入流”的适配器契约。[16] 普通SELECT快照再猜一个MAX(outbox_id)不满足这个条件；槽/日志保留不足就失败并重新建基线，不能跳过缺口。

Async Redis replication and AOF everysec can speed recovery, but cannot own acknowledged-score durability; everysec may typically lose about a second. [7] Budget reads, scoring, outbox, and rebuilding separately. Monitor oldest unapplied age, continuous completion, and per-destination errors, not only liveness.

Create isolated E+1 in LOADING mode. Baseline score/version snapshot and replay start must join without a gap. PostgreSQL logical-slot exported snapshots provide a state after which all changes enter the stream. [16] A plain SELECT snapshot followed by guessed MAX(outbox_id) does not. Lost slot/log retention requires a fresh baseline instead of skipping a gap.

快照行和尾流都走版本门，旧基线不覆盖先到的新版本。切换前短暂停此game/season权威入口：用赛季gate排他锁排空在途事务，持久标PAUSED并记录提交流屏障W；继续写请求拒绝/重试，不持锁等重建。E+1全部目的地追过W后停止该epoch写者，在这个固定集合上验证人数、逐玩家版本/C、比较器、路由与topK；再由有fencing的控制器CAS目录的旧代次到E+1，设SERVING并恢复OPEN。失败保持暂停或回原健康epoch，不提前宣称就绪。

目录读取须固定一次请求的epoch，读脚本再核对；旧E留到在途请求排空。目录CAS只换路由，不自动让多个桶同时取样；精确跨桶查询仍要共同snapshot_id。这里描述控制协议，示例没有实现CDC、暂停控制器、租约/fencing或目录服务。

Both base rows and tail events pass the version gate, so stale base rows cannot overwrite newer versions. Before cutover, briefly pause game/season authority: the exclusive gate drains in-flight transactions, persists PAUSED, and records commit-stream barrier W. Reject/retry subsequent writes rather than holding a lock throughout rebuilding. After E+1 covers W at every destination, stop its writers and validate player counts, per-player version/C, order, routing, and topK on that fixed set. A fenced controller then CASes the old directory generation to E+1, opens SERVING, and restores OPEN. Failure stays paused or returns to the healthy old epoch.

Pin one request’s directory epoch and recheck it in the script. Retain old E until in-flight requests drain. Directory CAS changes routing, not cross-bucket sampling; exact reads still require a common snapshot ID. This is a control protocol, without a CDC adapter, pause controller, lease/fencing service, or directory implementation here.

重建理想算术：20M项共享总预算100k项/s，持续新投影5,787/s，净94,213/s，20M÷94,213≈212.3秒；是忽略DB读、Hash、网络、重试与最后暂停的理想下界，不是RTO。新到流量≥总预算就追不平。校验也不能混合活动时刻，否则比较不一致可能只是两边正在变。

Ideal rebuild arithmetic: 20M entries at a shared 100k/s, minus 5,787/s incoming updates, leaves 94,213/s; 20M/94,213≈212.3 s. This lower bound omits DB reads, hashes, network, retries, and final pause; it is no RTO. Arrival at or above total capacity never catches up. Validation also needs a fixed dataset rather than comparing two changing moments.

6 · 赛季截止、水位与最终快照6 · Season close, frontiers, and final snapshots

先关闭事实入口，再排空全部目的地，最后固定奖励输入。同一个赛季gate把结算与截止串起来，不能先读热榜再尝试阻止晚提交。

Fence facts, drain every destination, then freeze reward input. The same season gate serializes settlement and cutoff. Reading the hot head before fencing late commits cannot establish finality.

状态为OPEN→CLOSING→FROZEN→FINAL。截止控制器取赛季排他行锁，等所有共享结算事务提交后持久切CLOSING；新身份停止接纳，原身份仍可查原回执。迟到/在途对局的宽限政策必须预先确定，宽限期间仍属接纳阶段；结束宽限并关门后才记最终W。禁止静默把旧赛季请求改写成新赛季。

W按提交有序流和真实交付记录定义连续前缀，不等于最大自增ID，也不是要求等待不存在的数字。41可能晚于42提交；看到42或数字跳到45，都不足以证明此前所有实际任务完成。CDC从事务提交边界交付，投影确认还必须覆盖global/region每个目的地；普通轮询可用关门后固定的全部outbox身份集合逐项核销，而不能仅取MAX(id)。

OPEN→CLOSING→FROZEN→FINAL. The closer takes the exclusive season-row lock, waits for shared settlement transactions, and persists CLOSING. New identities stop; known identities may replay receipts. Define grace/in-flight match policy beforehand; accepting during grace remains admission. Record final W only after grace ends and the gate closes. Never silently reroute an old-season command to a new one.

W covers commit-ordered streams and actual delivered records, not maximum auto-increment ID or every numeric gap. Transaction41 may commit after42; seeing42 or a jump to45 proves no completed prefix. CDC delivers transaction boundaries, while completion still includes every global/regional destination. A polling design may capture the finite accepted outbox identity set after fencing and resolve every member, never just MAX(id).

所有目的地覆盖W后，停止旧epoch写者并将模式设FROZEN；验证固定集合的人数、版本/C、路由、比较器和topK，发布不可变manifest与snapshot_id后才FINAL。B落后则停在CLOSING，不能把B当空榜或沿绿箭头直接发奖。恢复进程必须继续同一个截止记录，不凭一次本地“成功”布尔值重启结算。

奖励命令用 (game,season,snapshot_id,player,reward_kind) 绑定同一奖励意图；下游持久去重和资金对账仍由 Ch24负责。冻结后处罚生成新快照版本与明确差额/追回任务，不能改旧snapshot或因snapshot_id变了重发全部原奖。归档并验证可恢复、排空读者/重放者后才清理旧Redis；TTL释放内存，不能作为结算屏障。

Once every destination covers W, stop old-epoch writers, set FROZEN, validate counts, version/C, routing, comparator, and topK, and publish an immutable manifest/snapshot ID before FINAL. A lagging B leaves CLOSING; do not treat it as empty or bypass snapshot validation. Recovery continues the same durable close record rather than starting finalization from a local success flag.

Bind reward intent to (game,season,snapshot_id,player,reward_kind); downstream durable idempotency and monetary reconciliation belong to Ch24. Post-freeze penalties produce a new snapshot version and explicit adjustment/clawback tasks, without rewriting the old snapshot or reissuing every original prize under a new ID. Archive/validate and drain readers/replayers before Redis cleanup. TTL frees memory; it is no settlement barrier.

复盘：把保证说到边界Review: attach every guarantee to its boundary

一分钟主线：服务端计分权威提交完整绝对快照，赛季/玩家/对局/修订身份与原回执同库去重，分数/outbox同事务。版本门接受降分、拒旧事件；单榜脚本给一次内部一致的观察，分页与奖励要不可变快照。先按榜拆，单热榜才分桶；全球精确要同数据集、同路由、全片完成。故障用持久事实重建，不能把旧checkpoint当新Redis的证明。

追问“必须实时”：先改延迟契约，再压测持久确认和投影。可在提交后短等自己的projected_v，超预算回committed/pending；不要把新分未可见说成计分失败，也不要凭自己新分伪造全球名次。

One-minute path: trusted game scoring emits a complete absolute snapshot. Scoped settlement/revision identity and original receipt dedupe in the authority; score/outbox commit together. Versions permit corrections and reject old events. One single-board script gives one coherent observation; paging and rewards need immutable snapshots. Separate boards, then partition hot boards. Exact global reads need one dataset, routing, and every shard. Rebuild from durable facts, not an old checkpoint certificate.

For “must be real time,” change the latency contract and measure durable commit plus projection. Bound any wait for projected_v after commit, then return committed/pending. Invisible new scores are not failed scoring; the caller’s new score alone cannot manufacture a global rank.

① Same identity, changed score: conflict. ② v9 omits independent v8 delta: never discard v8. ③ Same storage epoch across shards: still mixed-time. ④ Pipelined rank/range: others may interleave. ⑤ Lua runtime error: prior writes can remain. ⑥ New snapshot ID: no permission to reissue all prizes.
