本章核心：先发布可查版本，再用有权访问的证据回答Core: publish versions and bound evidence

本章设计一个只使用内部语料的企业问答后端，也就是闭库 RAG。系统先把文档处理成可查询的已发布版本，再用用户有权访问的证据生成可追溯的回答。推理队列与 GPU 由 Ch29 讨论，索引算法留给 Ch31。

设计时要作出三个决定：摄取服务持久保存任务后才确认接收，原文和两路索引都就绪后才发布；每次查询固定整份配置组合（bundle），但权限仍按当前权威记录检查；引用的来源身份可以按规则校验，证据是否支持陈述则仍可能判断出错。

接下来沿六组动态图走通正常路径，再看四种反例：只有一路索引成功、父块包含越权内容、支持判断期间撤权，以及双池迁移后回退。六段代码分别放在需要解释对应操作的位置。

Build closed-corpus enterprise Q&A: publish searchable document revisions, then turn authorized evidence into traceable answers. Ch29 owns inference queues and GPUs; Ch31 covers indexing algorithms.

Make three decisions: persist ingest before acceptance and publish after both lanes are visible; pin the whole query bundle without freezing access; check citation identity mechanically while treating semantic support as fallible.

Follow the six retained decks, then test partial indexing, unauthorized parents, revocation during a slow judge, and rollback. Six nearby code blocks expose the deciding operations.

30 秒开场：先约定成功和撤权意味着什么Opening: define success and revocation

语料来自内部 wiki 和 PDF，不用公网材料补齐缺失证据。开场先问清文档格式、内容和权限的变更频率，延迟目标针对第一句还是完整答案，引用是否要跳回精确原版本，以及同租户内是否还有文档或段落级访问控制规则（ACL）。属于同一租户，不代表能读所有材料；证据不足时允许明确拒答。

RAG 原论文把参数模型与外部非参数记忆结合起来 [1]。本章使用的文档目录服务（Catalog）、权限复查和发布事务，都是为这道题作出的工程选择。本章把成功定义为 RAG 已向用户发送一句通过来源身份校验和支持门槛的回答；仅仅由模型生成 token 还不算。权限检查后仍可能发生撤销，已经发送的字节无法收回。

本题采用以下教学基线：10 万篇文档，每篇 2,000 token；按 512/64 切分；峰值每秒 40 次请求；两路各取 100 个候选，最多重排 80 对；证据最多 8 块、4,096 token，其余输入最多 1,024 token，输出最多 512 token；第一句合格输出的 p95 目标为 3 秒。这些都是本题假设，不代表厂商能力。

The corpus is internal wiki/PDF, without public-web gap filling. Clarify document formats, content/policy changes, first-sentence versus completion targets, exact-version citations, and document/span ACLs within a tenant. Same-tenant access is insufficient; missing evidence may yield refusal.

The RAG paper combines parametric and nonparametric memory [1]. Catalog, policy checks and publication transactions here are engineering choices. Success means RAG releases an approved sentence, beyond model token production. Revocation may race with sending; emitted bytes cannot be recalled.

Teaching baseline: 100,000 documents × 2,000 tokens, 512/64 splitting, 40 req/s, 100 hits per lane and 80 rerank pairs; up to eight spans/4,096 serialized evidence tokens, 1,024 other input and 512 output; a three-second p95 first-approved-sentence target. These are assumptions, not vendor capacity.

查询流程：固定配置组合，持续核对权限Query loop: pin bundles, keep policy live

图 1 中的三类调用都由 RAG 发起并接收结果：索引返回候选 ID，重排服务（Reranker）返回排序，推理服务（Inference）返回草稿。通过检查的答案再沿 RAG → Gateway → Client 发送。每次请求固定一份配置组合，其中包括编码器（encoder）的完整身份、切分器（splitter）、BM25 与稠密（Dense）索引池，以及重排、提示模板和分词器的版本；同一个问题处理中途不换代。

网关（Gateway）只传递已验证的租户和用户身份（tenant/subject），当前用户组成员资格由权威权限服务读取。两路检索使用相同范围。读取原文前，RAG 还要确认候选属于当前租户，来自该池当前已发布版本（current revision），其精确 ID、内容哈希和子块角色与发布清单（manifest）相符；文档 ACL 和覆盖全部跨度的 ACL 也必须允许访问。普通安全过滤器（security filter）只比对主体标识（principal）字符串，本身不完成认证和授权 [6]。

RAG owns all deck-one calls: indexes return IDs, Reranker returns order, and Inference returns a draft. Approved output travels RAG→Gateway→Client. One immutable bundle pins encoder identity, splitter, both index pools, and rerank/prompt/tokenizer versions throughout a question.

Gateway passes verified tenant/subject; authoritative policy supplies current membership. Both lanes carry the same scope. Before text reads, verify tenant, pool-specific current revision, published-manifest ID/hash/role and document/whole-span ACLs. Ordinary principal-string security filters do not perform authentication or authorization [6].

下面的编排伪代码接收可信身份、原问题和基于单调时钟的截止时间，返回有证据的句子，或明确拒答、报错。候选的权威筛选由 Authority.filter_ids 完成，不交给模型判断。

它在权威库中把候选与该租户、文档、索引池的已发布记录 published(tenant,doc,pool) 关联，再核对发布清单中子块（child）的 ID 和哈希、当前成员资格，以及覆盖全部跨度的 ACL。跨租户 ID 在读取正文前就被丢弃。远程重排、生成和支持判断服务，也必须位于获准处理该租户数据的边界内。

This orchestration pseudocode takes verified identity, the original question and a monotonic deadline; it returns grounded sentences or refusal/error. Authority.filter_ids joins candidates to authoritative published(tenant,doc,pool) and its manifest child ID/hash, current membership and every covered span ACL; it rejects foreign-tenant IDs before reading text. Rerank, generation and judge services must be approved processors for that tenant.

query(verified_identity, question, deadline):
  # Identity comes from authentication; body tenant/groups are never trusted.
  principal = (verified_identity.tenant, verified_identity.subject)
  bundle = Catalog.read_whole_bundle()       # immutable model/splitter/lanes/pack
  scope = Authority.current_membership(principal)  # timeout => deny
  key = (principal, scope.epoch, bundle.id, hash(exact_question_and_options))
  hits = candidate_cache.get(key)             # IDs only; no authorization proof
  if hits is absent:
    vector = embed(bundle.encoder, question, deadline)
    hits = parallel_search(
      bundle.bm25, bundle.dense, vector, question,
      tenant=principal.tenant, groups=scope.groups,
      pool=bundle.pool, limit_per_lane=100, deadline=deadline)
    candidate_cache.put(key, hits, bounded_ttl)
  # Read primary authority, not cached ACLs or a lagging replica.
  # Join published manifest ID/hash/child role + tenant/doc/pool/current_rev,
  # live membership + whole-span ACL. Parents must be manifest text entries.
  eligible = Authority.filter_ids(principal, bundle, hits)
  # Preserve original lane ranks; discard duplicates within each lane.
  order = rrf(eligible).take(80)
  text = ChunkStore.read_exact_ids_and_verify_hashes(order)
  if any returned tenant/revision/hash differs: fail_closed()
  ranked = rerank(question, text, max_pairs=80, deadline=deadline)
  if rerank times out: ranked = evaluated_RRF_fallback(order)
  pack = pack_with_parent_checks_and_full_token_count(ranked, bundle)
  if deadline expired or pack is empty: return insufficient_evidence()
  Authority.check_all_pack_dependencies(principal, bundle, pack)
  # Any failure discards pack; no generator sees unauthorized text.
  draft = Inference.generate(question, pack, tools=NONE, deadline=deadline)
  return release_buffered_sentences(principal, bundle, pack, draft)
  # Cancellation/deadline propagates to every child call; raw answers never cache.

候选缓存只保存 ID。缓存键包含租户和用户（tenant/subject）、成员资格代次、完整配置组合，以及精确原问题和选项的摘要；命中后仍要重新核对权威状态。正文缓存只按 tenant/doc/revision/span/hash 获取不可变内容，而且必须先鉴权。

本章关闭答案缓存。如果启用，就要保存整份证据包（Evidence Pack）的依赖，并在每次缓存命中和发送前复查。问题语义相似、缓存 TTL 尚未到期，都不能证明用户仍有权限。

A10 的路径预算为 30+60+max(80,100)+40+250+20=500 ms，700−500=200 ms 留给有界排队和补充召回。BM25 实际上可以与问题向量编码（query embed）重叠执行，这里为保守估算而顺排。这是单次请求的条件预算，不能把它理解为组件 p95 相加。

排队数量、问题与子块的配对数、输入长度和截止时间都要有限制。没有足够证据时就拒答，不启动脱离证据的模型回答；取消信号要传递到全部子调用。

Candidate caches store IDs only, keyed by tenant/subject, membership epoch, full bundle and exact question/options digest; every hit still reauthorizes. Immutable text caches use tenant/document/revision/span/hash and require authorization first. Answer caching is disabled here. Enabling it requires retaining and rechecking all pack dependencies; similarity and TTL never prove access.

The A10 conditional budget is 30+60+max(80,100)+40+250+20=500 ms, leaving 200 of 700 ms for bounded queues/refill. BM25 can overlap query embedding. This conservative budget is not a sum of component p95s. Bound queues, pairs, lengths and deadlines, propagate cancellation, and refuse rather than generate without evidence.

估算：逐篇计算尾块，再算每次请求的工作量Sizing: count final chunks and request work

每篇 2,000-token 文档按 512-token 上限、448-token 步长切分，会得到 5 块，尾块为 208 token；10 万篇合计 50 万块。裸向量占 50 万×768×4=1.536 GB≈1.431 GiB。重排上限是 40×80=3,200 对/秒；这只说明工作量被限制住了，不能证明某块 GPU 能达到相应吞吐。

4,096-token 证据预算包含编号、来源和分隔符，因此不保证能装下 8 个各含 512 token 的原文块。完整 prompt 还须用生成模型的分词器重新计数，确保不超过 5,120 token，再预留 512 token 输出，所以模型上下文至少要有 5,632 token。扩展父块或处理中英文时，都不能拿字符数代替 token 数。

A 2,000-token document yields five 512-cap/448-stride chunks, ending with 208 tokens; 100,000 documents yield 500,000 chunks. Raw vectors occupy 1.536 GB≈1.431 GiB. Reranking caps at 40×80=3,200 pairs/s; less work does not establish GPU throughput.

The 4,096-token evidence allowance includes IDs, provenance and delimiters, so eight full 512-token text spans may not fit. Recount the complete prompt with the generation tokenizer to ≤5,120 and reserve 512 output tokens, requiring at least 5,632 context. Characters cannot replace tokens for expanded parents or multilingual content.

中文

A1 假设原始正文共有 100,000 × 2,000 = 200,000,000 token。每篇文档都要单独计算尾块，不能把所有正文连起来除以步长。长度 L ≤ 512 时只有一块，否则块数为 1 + ceil((L − 512) / 448)。2,000-token 示例得到 5 块，起点依次为 0、448、896、1,344、1,792，尾块只有 208 token。因此，10 万篇 × 5 = 50 万块。结构切分、重复标题和短文长度分布都会改变结果，真实容量要从发布清单（manifest）汇总。

每篇实际送入向量编码器的正文是 4 × 512 + 208 = 2,256 token，比原文的 2,000 token 多 256，即增加 12.8%。相邻块重叠比例 64/512 = 12.5%，与语料膨胀比例使用的分母不同。全量示例要嵌入 2.256 亿 token，尚未计算标题、提示前缀和失败重试。每天变更 1,000 篇，就会生成 5,000 个新块、嵌入 225.6 万 token。若不清理旧版本，索引会随每日新版本持续增大，不能把 1% 的变更率理解为每天只覆盖原有数据的 1%。

A3 的向量体积是 500,000 × 768 × 4 = 1,536,000,000 B = 1.536 GB ≈ 1.431 GiB。这里 GB 使用十进制，GiB 使用 230。保存两份需要 3.072 GB；迁移时保留两个池，且每池保存两份，就需要 6.144 GB 裸向量。原文跨度、BM25 倒排、ANN 结构、元数据和暂存空间要另外清点，不能无依据地把全部存储统一“乘 1.5”。float16 只会把每个元素的字节数减半，检索质量是否可接受仍要测量。

峰值重排工作量是 40 × 80 = 3,200 query–chunk pairs/s；如果每次都对全库计算，就是 40 × 500,000 = 20,000,000 pairs/s，两者相差 6,250 倍。这个算式只说明工作减少，不能证明单块 GPU 能完成。生成输入上限为 5,120 token，对应峰值 204,800 输入 token/s；输出上限为 512 token，满额时是 20,480 输出 token/s。平均输出量和满足目标时的实际吞吐要在 Ch29 压测，不能从“40 QPS 很小”推断生成成本低。

选型也不能靠“百万条”作硬分界。把业务元数据和向量放在同一个库，可以减少事务协调，但 ANN 过滤、更新频率、租户选择性和延迟目标仍可能成为瓶颈 [5]。专用引擎便于独立扩展，代价是要协调两个存储的版本和删除。面试时先根据上述工作量、过滤条件和压测结果决定服务边界；这里不列随时间变化的 API 价格，也不把一次性摄取账单与每日查询账单混在一起比较。

English

A1 holds 200 million source tokens, but every document has its own final chunk. Use one chunk for L ≤ 512, otherwise 1 + ceil((L − 512)/448). The 2,000-token example yields five starts: 0,448,896,1344,1792; the final span contains 208 tokens. Thus 100,000 documents yield 500,000 chunks. Real structure, repeated headings, and length distributions require manifest counts.

Embedded text per document is 4 × 512 + 208 = 2,256 tokens, 12.8% above the original. This differs from the 12.5% overlap denominator. Full ingest uses 225.6 million illustrative tokens before headings, prefixes, or retries; daily change of 1,000 documents produces 5,000 chunks and 2.256 million tokens. Retained old versions add storage.

Raw vectors occupy 500,000 × 768 × 4 = 1,536,000,000 B = 1.536 GB ≈ 1.431 GiB. Two copies use 3.072 GB; two migration pools with two copies each use 6.144 GB. Account separately for text, inverted and ANN indexes, metadata, and staging. Float16 halves element bytes, while quality still needs evaluation.

Peak reranking is 3,200 pairs/s versus 20 million pairs/s over the whole corpus, a 6,250× work difference rather than a GPU capacity claim. At 40 requests/s, 5,120 input tokens imply at most 204,800 input tokens/s and 512 output tokens imply at most 20,480 output tokens/s. Benchmark means and SLO attainment separately in Ch29.

A million vectors is not a universal engine threshold. Colocated business metadata can simplify transactions, but filtering, update rates, tenant selectivity, and latency remain workload constraints [5]. Dedicated engines buy independent scaling and add version/delete coordination. Use measurements, not stale API prices or comparisons between one-time ingest and daily serving bills.

摄取：持久接收任务，索引可查后发布Ingest: durable acceptance, visible publication

Catalog 先在同一个事务中保存源版本、稳定的事件回执和持久任务（job），提交后才返回 202。因此，“已接收”（accepted）只表示任务已保存，不表示文档已经可查。

已发布指针按租户、文档和索引池维护，即 published(tenant,doc,pool)。迁移期间，g1 和 g2 各有自己的当前版本（current revision）。全局删除标记和 ACL 独立保存，发布内容不能恢复旧权限。

源游标（cursor）必须可排序，或者由连接器维护单调递增的版本。如果同一事件键携带不同输入，系统必须报冲突。

Catalog commits the source revision, stable event receipt and durable job before returning 202; accepted is not searchable. Publication is per published(tenant,doc,pool), with separate current revisions for g1/g2. Tombstones and ACLs remain global; content publication never restores old policy. Require an ordered source cursor or connector-maintained monotonic version; reuse of an event key with different input conflicts.

accept(source_event):                         # trusted connector, monotone cursor
  BEGIN Catalog
  LOCK doc(tenant, doc_id)                    # same lock order in every writer
  if event_key exists:
    require stored canonical_event == source_event; return saved_job_ids
  require source_event.cursor > doc.source_cursor  # older events cannot revive
  UPDATE doc SET target_rev=event.rev, source_cursor=event.cursor
  INSERT immutable_revision AND jobs_for_live_pools AND event_receipt
  COMMIT                                     # only now send 202 + job IDs

work(job_id, owner):
  BEGIN Catalog; LOCK doc THEN job
  t = database_clock_after_locks()
  if job.done: COMMIT; return job.saved_result
  require job.ready OR job.lease_until <= t
  UPDATE job SET owner=owner, epoch=epoch+1, lease_until=t+lease
  COMMIT                                     # lost ACK => reread this claim
  expected = deterministic_split(job.source_bytes, job.splitter)
  manifest = create_or_read_canonical_manifest(expected, job.encoder)
  # Unique manifest key chooses persistent embedding bytes; retries reuse them.
  for span in manifest.text:
    id = (tenant, doc, rev, pool, splitter, span.offsets)
    ChunkStore.put_if_absent_or_identical(id, span.bytes_and_metadata)
    if span.is_child:
      BM25.put_if_absent_or_identical(id, span.hash_and_terms)
      Dense.put_if_absent_or_identical(id, span.hash_and_vector)
  # Manifest.text covers children + parents; both index lanes cover child IDs.
  # Outside Catalog locks: exact IDs/hashes, correct generation, both lanes.
  receipts = verify_manifest_visibility(manifest, pool.search_reader_contract)
  # A write ACK or a few successful canaries are insufficient receipts.
  BEGIN Catalog; LOCK doc THEN job
  t = database_clock_after_locks()
  require owner/epoch still match AND job.lease_until > t
  require NOT doc.tombstone AND doc.target_rev == job.rev
  require text receipt == manifest.text IDs/hashes
  require BM25 receipt == Dense receipt == manifest.children IDs/hashes
  require receipts.pool == job.pool AND receipts.splitter == job.splitter
  UPSERT published(tenant, doc, pool) SET current_rev=job.rev, manifest=receipts
  UPDATE job SET done=true, saved_result=manifest_id  # same transaction
  COMMIT                                     # unknown COMMIT => reread, no blind undo
  # Old workers may finish identical staging writes, never publish after takeover.
  # ACL authority is separate: publishing content cannot restore an old ACL.

下面是事务伪代码。外部写入和可见性核对都在 Catalog 锁外执行；所有写入者都先锁文档记录（doc），再锁任务记录（job）。获得锁后才采样租约时间，只有持有者和代次（owner/epoch）匹配、租约未过期、文档未删除且目标版本仍匹配，才允许发布。实际行锁语义参考 PostgreSQL18 [12]。

租约约束的是发布操作，不会让外部索引自动拒绝旧进程的写入。旧进程仍可能写暂存产物，因此外部键必须包含不可变版本，而且已有内容只有完全相同时才能复用，以此限制陈旧写入的影响。

发布清单（manifest）记录全部期望 ID、原文哈希、向量产物哈希、模型和切分器及索引池身份，以及两路回执。原文集合（text）包含子块（child）和可引用父块（parent），两路索引集合只包含子块。候选必须匹配已发布清单中的子块 ID 和哈希，父块必须匹配其中的原文条目；即使租户、版本和池都相同，也不能把清单外的额外暂存内容当作证据。

embedding 计算可能存在数值不确定性，因此先按唯一清单键持久选定一份规范产物，重试时复用同一份字节。同键出现不同产物时，不能静默覆盖。可见性检查 verify_manifest_visibility 必须逐项核对，并满足实际服务读者的可见性契约，不能只用少量探针（canary）代替全量检查。以 Elasticsearch 为例，refresh 让写入可搜索，与写入确认不同 [11]；本地教学模型没有实现该厂商的可见性屏障。

任一路失败，产物就留在暂存区，旧的已发布版本继续服务。发布版本和保存任务完成结果在同一个 Catalog 事务中提交；确认回执（ACK）丢失时，重新读取已保存的结果。

索引中可能残留旧版本候选，取证前要剔除，并在预算内补充召回，不能为了凑够数量而放松 ACL。单文档 CAS 不提供全语料快照；READY 也只表示已验证相应可见性条件，不代表索引之后永远不会故障。

This is transaction pseudocode. External writes/visibility checks run outside Catalog locks. All writers lock doc→job; sample lease time after locks, then require matching owner/epoch, unexpired lease, live document and current target revision. The lease fences publication, not every external write; immutable versioned keys and identical-only reuse bound stale staging. See PostgreSQL18 row-lock semantics [12].

A manifest records every expected ID, text/vector artifact hash, model/splitter/pool identity and both receipts. Text includes children and citable parents; index sets contain children only. Reject IDs/hashes outside the published manifest and required role, even for same-tenant/revision/pool staging. Persist one canonical embedding artifact under a unique manifest key and reuse its bytes across retries, since recomputation may differ numerically. Visibility verification checks every item against the serving-reader contract, beyond a canary. Elasticsearch refresh is one example of making writes searchable separately from write acknowledgements [11]; our local model does not implement that vendor barrier.

Partial failures stay staged while old current serves. Publication and saved completion share the Catalog transaction; lost ACKs reread it. Reject old-revision candidates and refill within budget without relaxing ACLs. Per-document CAS does not provide a corpus-wide snapshot, and READY cannot promise perpetual index availability.

切分：保留来源信息，再决定是否扩展父块Chunking: provenance before parent expansion

解析器（Parser）先保留 PDF 页码和坐标、标题路径、表格列名及单位，再按结构、句子和 token 逐步切小。如果表格单元格只剩“12”，就无法据此证明业务允许值为 12。本章的 512/64 只是实验基线；Microsoft 指南建议从 512-token 块长和 25% 重叠比例起步，具体设置仍须按语料评测 [2]。相邻块重叠（overlap）能补足部分边界，但会复制 token，也不保证跨页前提齐全。

Preserve PDF pages/coordinates, heading paths and table columns/units before structure-, sentence- and token-based splitting. A contextless cell containing “12” cannot establish an allowed value. Our 512/64 is an experimental baseline; Microsoft offers a 512/25% starting recommendation, to be evaluated on the corpus [2]. Overlap costs tokens and does not guarantee distant premises.

来源身份至少包含租户、文档、版本、索引池、切分器版本、原文跨度和内容哈希，对应 tenant/doc/revision/pool/splitter/span 及 hash；另外保存页码（page）、父块（parent）和源位置（source locator）。查询只取精确版本，不能用最新父段补旧子块。用户点击来源时要重新鉴权，并遵守删除标记。

small-to-big 是可选的扩展读取：先召回子块（child），再读取同版本、且属于已发布 manifest.text 的父块（parent）。父段覆盖的全部跨度都要重新授权；多个子块指向同一父块时，只扩展一次。

父块如果包含无权读取的私密段、超过预算或版本不匹配，就退回已授权子块，必要时拒答。相关性不能决定访问权限。只有标注评测集中“子块已命中但缺少前提”的错误减少，才值得承担父块读取、存储和 ACL 检查的额外成本。

Source identity includes tenant/document/revision/pool/splitter/span and content hash, with page, parent and locator. Read exact revisions rather than replacing old children with latest parents. Citation clicks reauthorize and honor tombstones.

Optional small-to-big fetches a same-revision parent after a child hit, requiring published-manifest text membership. Authorize every parent span and expand each parent once. Mixed-permission, oversized or mismatched parents fall back to authorized children, then refusal if needed. Relevance never grants access. Add parent reads/storage/policy complexity only when labeled errors show recalled children missing premises.

混合检索：保留原排名，去重后限制重排工作量Hybrid: preserve ranks and bound reranking

BM25 补充术语和错误码的词面召回，稠密检索（dense）补充经过评测的改写和跨语言召回；如果要求精确短语，仍须显式添加短语条件。两路各取 100 个候选，先在权威库筛选资格，再按完整来源 ID 去重。

倒数排名融合（RRF）按每路的 1/(60+rank) 求和：排名从 1 开始，某路未命中就贡献 0。常数 60 沿用 Elastic 默认值作为实验起点 [3]。过滤后要保留原排名，不能把原来的第 99 名变成第 1 名；同一路重复出现同一来源时，只按最好的原排名贡献一次。

BM25 covers terms/codes, while evaluated dense models cover paraphrases/languages; exact phrases still need explicit constraints. Retrieve 100 per lane, authorize and deduplicate qualified identities. RRF sums 1/(60+rank), starting at one, with zero for absence; 60 follows Elastic’s default as a starting point [3]. Filtering retains rank 99 as 99, and duplicates contribute once per lane.

public record Hit(String qualifiedId, int originalRank) {}
public record Scored(String qualifiedId, double score) {}
public static List<Scored> rrf(List<List<Hit>> lanes, int cap) {
  if (cap < 1 || cap > 80) throw new IllegalArgumentException("cap 1..80");
  Map<String, Double> score = new HashMap<>();
  for (List<Hit> lane : lanes) {
    Map<String, Integer> best = new HashMap<>();
    for (Hit hit : lane) {
      if (hit.originalRank() < 1 || hit.originalRank() > 100)
        throw new IllegalArgumentException("rank 1..100");
      best.merge(hit.qualifiedId(), hit.originalRank(), Math::min);
    }
    // Eligibility filtering preserves original ranks; duplicates count once/lane.
    best.forEach((id, rank) -> score.merge(id, 1.0 / (60 + rank), Double::sum));
  }
  return score.entrySet().stream()
    .map(e -> new Scored(e.getKey(), e.getValue()))
    .sorted(Comparator.comparingDouble(Scored::score).reversed()
      .thenComparing(Scored::qualifiedId))
    .limit(cap).toList();
}

下面摘录的是 Java17 标准库实现，完整可运行类在 examples/ch30/RagCore.java。每条输入候选（Hit）必须已经通过权限和当前版本检查，完整来源标识 qualifiedId 包含租户和版本；本函数不负责鉴权。相同分数按 ID 稳定排序，最多返回 80 项。A 在两路排第 1/10，得分约 0.03068；B 排第 5/5，得分约 0.03077，因此 B 稍靠前。

RRF 丢弃原始分数的分差，也找不回两路都漏掉的证据。有标注数据时，可以另测经过校准的加权融合。

向量过滤未必发生在 ANN 扫描之前。固定到 v0.8.0 的 pgvector 文档说明，近似扫描后才过滤，迭代扫描（iterative scans）会继续查找，直到数量足够或触及上限 [5]。对于小租户，要测量分区、先精确过滤再检索，以及有界补充召回的效果，不能去掉租户或 ACL 条件。CrossEncoder 只处理有界短名单 [4]；超时时只使用已评测的 RRF 回退，权限或证据不足仍须拒答。

This Java17 standard-library excerpt is part of runnable examples/ch30/RagCore.java. Hits must already be authorized/current, and qualified IDs include tenant and revision; this function does not authorize. Ties sort by ID, with at most 80 results. A at ranks 1/10 scores 0.03068; B at 5/5 scores 0.03077. RRF loses score margins and cannot recover evidence both lanes missed; calibrated weighted fusion is another measured option.

ANN filtering need not precede scanning: pinned pgvector v0.8.0 documents post-scan filtering and capped iterative scans [5]. Measure partitioning, exact filtered search and bounded refill for small tenants, retaining all access conditions. CrossEncoder operates only on a bounded shortlist [4]. A timeout may use evaluated RRF fallback; missing authorized evidence still refuses.

证据打包：按完整提示输入计算 token 预算Pack evidence with the complete token budget

public record Span(String tenant, String doc, long rev, String pool,
                   int start, int end, String text) {}
public record Pack(List<Span> spans, String prompt, int inputTokens) {}
public interface Renderer {
  String evidence(List<Span> spans);           // includes IDs/locators/delimiters
  String prompt(List<Span> spans);             // complete roles + question + evidence
}
public static Optional<Pack> pack(List<Span> ranked, Renderer render,
    ToIntFunction<String> generationTokens, int contextLimit) {
  List<Span> chosen = new ArrayList<>();
  if (generationTokens.applyAsInt(render.prompt(List.of())) > 1024)
    return Optional.empty();                  // no silent question truncation
  for (Span candidate : ranked) {             // already authorized exact revisions
    if (candidate.start() < 0 || candidate.end() <= candidate.start())
      throw new IllegalArgumentException("invalid span");
    boolean overlaps = chosen.stream().anyMatch(s ->
      s.tenant().equals(candidate.tenant()) && s.doc().equals(candidate.doc())
      && s.rev() == candidate.rev() && s.pool().equals(candidate.pool())
      && s.start() < candidate.end() && candidate.start() < s.end());
    if (overlaps) continue;                    // conservative: keep higher-ranked span
    List<Span> trial = new ArrayList<>(chosen); trial.add(candidate);
    int evidence = generationTokens.applyAsInt(render.evidence(trial));
    int input = generationTokens.applyAsInt(render.prompt(trial));
    if (evidence > 4096 || input > 5120 || (long) input + 512 > contextLimit)
      continue;                               // try a smaller later span, no truncation
    chosen = trial;
    if (chosen.size() == 8) break;
  }
  if (chosen.isEmpty()) return Optional.empty();
  String prompt = render.prompt(chosen);
  return Optional.of(new Pack(List.copyOf(chosen), prompt,
    generationTokens.applyAsInt(prompt)));
}

传入的排序结果（ranked）包含已完成父块检查、用户仍有权使用的精确版本跨度，且来自同一索引池。跨度重叠时，保守地只保留排名靠前的一项，不把中间空隙合并进来；这种做法可能牺牲召回。

序列化组件 Renderer 负责生成含编号、来源和分隔符的证据文本，以及完整角色信息和 prompt。计数函数 generationTokens 必须使用部署模型的分词器及聊天模板，对完整字符串重新计数，不能直接相加逐段 token 数。本地运行只用字符计数测试数据（fixture）验证分支，不证明模型分词器的实际行为。

按排名依次尝试，最多选入 8 段。过大的段跳过，继续考虑后面较小的段；不截断句子或表格来“刚好塞满”。证据≤4,096、完整输入≤5,120、输入+512≤context，三个约束必须同时成立。装包后再复查整包权限，然后才交给推理服务。

《Lost in the Middle》发现，证据在长上下文中的位置会影响所测模型的表现 [9]。多放材料不能替代质量评测。

Ranked input contains authorized, same-pool revision spans after parent checks. Conservatively keep the higher-ranked overlapping span without merging gaps; this can lose recall. Renderer serializes IDs/provenance/delimiters and the complete role/prompt. generationTokens must use the deployed model tokenizer/chat template on complete strings, beyond summing individual counts. Local execution uses a character-count fixture to test branches, not model tokenization.

Try at most eight spans, skipping oversized ones while considering smaller later spans; do not truncate claims/tables to fill the budget. Enforce evidence ≤4,096, complete input ≤5,120 and input + 512 ≤context together. Reauthorize the whole pack before inference. Evidence position affected models tested in Lost in the Middle [9]; additional context needs evaluation.

引用与发送：来源身份可校验，语义支持仍需判断Citations and release: identity is not semantic proof

证据包就是实际进入 prompt 的集合，引用编号只在本次请求内稳定。即使召回了第 9 块，只要没有入包，就不能引用。

RAG 先按句缓冲草稿，检查能否解析、编号是否有效、来源版本和条件是否匹配，再判断证据是否支持陈述。ALCE 区分引用支持和引用质量 [7]；模型判断仍可能错误放行。对于需要证据的句子，不能只删掉伪造脚注，却把没有依据的断言留在答案里。

Evidence Pack is exactly what entered the prompt, with request-local IDs. A recalled but unpacked ninth chunk is not citable. Buffer draft sentences; check parsing, IDs and source identity/conditions before support. ALCE distinguishes citation support/quality [7], but model judgments remain fallible. Never retain an unsupported claim after merely removing its fake footnote.

这段伪代码把来源身份和陈述支持分开检查。对于受控领域的结构化事实，规则核对实体、数值、单位和条件。例如，“报销上限 120 元”不能引用“满 120 元免运费”。这只适用于受控结构（schema）和可确定的规则。

自由文本由固定版本的支持判断器处理。结果为 UNKNOWN 或超时时，拦住整句，最多进行一次有界重写；不能据此声称已经证明“无幻觉”。句子拆分和“是否需要证据”的判断，本身也是解析器及模型必须提供的契约，要测试绕过和误判。

最危险的反例是：证据包里既有公开 A，也有用户原本有权读取的私密 B；模型用过 B，本句却只标 A。支持判断较慢，期间 B 的权限被撤销。如果只重查 A，就可能泄漏 B。因此，判断结束后、每句发送前，都要按固定顺序加锁读取当前成员资格，以及整个证据包依赖的文档状态、该池当前版本和全部跨度 ACL。任一相关代次变化、撤权或删除，都要取消输出并丢弃整份草稿。改用新包必须重新生成，不能从旧回答删一个引用就继续发送。

这是本章采用的保守产品策略：即使没有撤权，证据依赖的同池当前版本更新也会使旧草稿失效。权限只保证在检查的线性化点有效。检查结束到发送之间仍有空隙；在线性化点落在撤权之后的复查不会通过，但已通过检查的内容或已发出的字节仍可能在撤权后到达。

如果要求更强的撤权确认，就必须明确撤权与活跃查询的串行关系及排空（drain）规则；已发送的网络字节无法追回。Catalog 超时就停止发送，用户点击来源时也要重新检查精确版本。

The pseudocode separates two layers. Controlled facts compare entity/value/unit/conditions: a 120-unit expense cap cannot cite a free-shipping threshold of 120. This requires a controlled schema and deterministic rules. Free text uses a pinned fallible judge; UNKNOWN/timeouts block, with at most one rewrite. Claim segmentation/evidence requirements also need bypass and error tests.

Dangerous counterexample: public A and private B entered the prompt; the model used B but cites only A. B is revoked while support judgment is slow. Rechecking A alone can leak. After judging and before every send, lock/read current membership and all pack document/current/whole-span ACL dependencies in canonical order. Any changed epoch, revocation or delete cancels and discards the entire draft; a new pack requires regeneration.

This conservative product policy also invalidates drafts on pool-current changes. Authorization holds at the check’s linearization point; a check/send gap remains. Checks after revocation fail, while previously approved/in-flight bytes may arrive. Stronger revocation acknowledgement needs query serialization/drain and cannot retract sent bytes. Authority timeouts stop release, and citation clicks reauthorize exact revisions.

展开信任边界：文档攻击、模型处理与日志Expand trust boundaries: document attacks and logs

检索材料中的“忽略此前指令”或“发送秘密”属于文档攻击。Microsoft Prompt Shields 区分这类攻击，但不独立验证材料来源 [10]。材料只能作为带来源的数据，不能提升成系统指令（system）。本题的生成器没有外部工具；分隔符、检测器和提示都不能提供绝对防护，检测通过也不代表材料可信。

模型、重排和支持判断服务只能接收已授权内容。如果使用外部托管处理器，必须采用租户允许的数据处理及保留配置。日志尽量少保存敏感正文和答案，并按租户、权限及保留期限管理访问。调用轨迹（trace）记录配置组合、精确证据 ID、失败原因和时延；调试页面也不能跨租户复制原文。

Retrieved commands that override instructions or request secrets are document attacks. Microsoft Prompt Shields distinguishes them and does not independently verify provenance [10]. Evidence is sourced data, never elevated system instructions. This generator has no external tools; delimiters, detectors and prompts remain imperfect, and a clean detector result does not establish trust.

Inference, rerank and judge processors receive only authorized content. Hosted processors require tenant-approved data handling/retention. Minimize sensitive text in logs, enforce tenant/policy access and retention, and retain bundle/exact evidence IDs, reasons and timing without copying cross-tenant content into debugging pages.

新鲜度与迁移：新池可切换，旧池能回退Freshness and migration: dual pools must support rollback

内容更新先暂存、后发布，准备期间继续用旧的已发布版本服务。不能先删旧版本造成空窗，也不能把所有版本混进 prompt。5 分钟内可查是 A9 的教学目标，要测量源变更到发布的延迟（lag），并关注最早失败而尚未完成的任务。

删除或撤权时，先提交权威删除标记或 ACL 新代次，再异步清理所有版本、两路索引和原文。搜索结果为零，不能证明物理数据已经擦除，或备份已经清理。

即使向量维度相同，embedding 的分词器、前缀、池化（pooling）或归一化变化，也可能改变坐标含义。新配置组合要同时绑定 m2/g2、对应切分方式和两路索引；切分改变时，BM25 文档也要换代。图 6 的两条查询路径属于不同请求群，每个请求只使用一份配置组合，权限仍查全局最新状态。

Stage updates before publication, allowing old current to serve during preparation. Do not delete first or mix revisions into prompts. The five-minute A9 target measures source-to-publication lag and oldest failed jobs. Deletes/revocations commit authority first, then purge every revision, both lanes and text. Zero search hits do not prove physical/backup erasure.

Even equal-dimensional embeddings may change coordinates through tokenizers, prefixes, pooling or normalization. New bundles pin m2/g2, splitter and both lanes; changed chunks also require new BM25 documents. Deck six’s paths are separate request cohorts, each using one bundle while policy remains globally live.

  BEGIN Catalog; LOCK bundle_pointer
  require current_bundle == g1 AND g2.complete_through >= barrier
  CAS bundle_pointer FROM g1 TO g2              # all immutable fields together
  COMMIT
  continue_replay(g1 AND g2)                    # retain old encoder too
  # New requests pin g2; old requests keep g1. ACL/tombstone stays live globally.

rollback(g2, g1):
  barrier = source.current_cursor()
  require g1.model_available AND log_retention_covers(g1.cursor, barrier)
  replay_and_reconcile_all_changes(g1, through=barrier)  # especially deletes
  require g1.searchable_through >= barrier AND g1.evaluation_passes
  CAS Catalog.bundle_pointer FROM g2 TO g1
  # Missing logs/encoder/coverage => do not claim rollback is safe; rebuild instead.

retire(g1):
  require no_active_g1_requests AND rollback_retention_expired
  stop_g1_replay(); purge_g1_indexes_and_unpinned_text_by_manifest()
  # Without consistent snapshots + retained logs, choose a write freeze or declare
  # a weaker reconciliation contract. An index alias cannot create a source barrier.

下面的伪代码接收两套完整配置，并要求数据源支持快照和保留变更日志，最终完成一次 CAS 切流，或明确失败。回放屏障要覆盖所有源分区，变更不仅包含新增和更新（upsert），也包含删除（delete）及 ACL。搜索可见性、源分区覆盖和标注评测都满足要求后，才能切换。数据源如果没有一致快照或可保留日志，就要选择冻结写入窗口，或明确采用更弱的对账保证，不能凭空假设存在水位。

切换后继续把变更送入两池，并保留旧编码器。回退前，旧池必须追到新的变更屏障，且删除对账通过；日志有缺口或旧模型已下线时，需要重建，不能只切别名就宣称已经恢复。

只有旧请求排空且回退期结束后，才能回收旧池。引用需要的版本原文还要单独遵守保留政策；权限撤销后，旧 URL 也不能成为绕过检查的入口。

The inputs are complete old/new configurations and source snapshot/retained-log contracts; output is a CAS switch or explicit failure. The barrier covers every source partition and replays deletes/ACL events alongside upserts. Require search visibility, source coverage and labeled evaluation. Without consistent snapshots/log retention, freeze writes or declare weaker reconciliation.

After switching, feed both pools and retain the old encoder. Rollback requires catching the old pool up to a new barrier and reconciling deletes. Log gaps or a retired encoder require rebuilding; aliases alone do not recover correctness. Retire only after request drain and rollback expiry; exact citation text follows its own retention, always honoring revocation.

评测与反例：找出证据在哪一层丢失Evaluation and counterexamples: locate lost evidence

A11 固定 200 个标注问题，记录提问主体（principal）、文档、版本、跨度（doc/revision/span）及答案标签，并把调参集和独立回归集分开。按术语、改写、中英、表格、多段、冲突、无答案和撤权场景分层比较；切分方式改变后，跨度标签也要重新映射。

分别报告召回、重排和最终证据包三个阶段的 Recall@k。应找回 5 段证据而取到 4 段时，召回率为 0.8。平均倒数排名（MRR）只看首个相关项，可能掩盖另一个必要前提没有取到的问题。

答案侧分别报告正确性、上下文忠实度、编号有效性、引用支持和覆盖，以及拒答情况。RAGAS 按陈述估计上下文支持 [8]：5 条陈述中有 4 条被判断为有支持，结果也为 0.8，但这不是检索召回率，更不能证明材料本身正确。判断器的错误放行和错误拒绝需要人工校准；权限隔离不能交给模型评分决定。

同时测量首个合格句的 p95、完整答案耗时、超时和降级比例、配对数、输入输出 token 及摄取延迟。若试验把重排候选从 80 增至 160，40 QPS 下的上限就会从 3,200 增至 6,400 对/秒；如果最终证据没有改善且超过 SLO，就应回退。本章没有对真实语料、厂商检索服务或 LLM 做压测。

Freeze 200 labeled queries with principals, document/revision/spans and answers; separate tuning from held-out regression. Slice terms, paraphrases, languages, tables, multiple spans, conflicts, absent answers and revocation. Remap span labels after splitter changes. Measure Recall@k at recall, rerank and final-pack stages; four of five is 0.8. First-relevant MRR may hide another missing premise.

Report correctness, faithfulness, ID validity, citation support/coverage and refusals separately. RAGAS estimates statement support from context [8]; four of five is also 0.8, distinct from retrieval recall or source truth. Human-calibrate judge false acceptance/rejection; models never decide access.

Measure first-approved-sentence p95, completion, timeouts/degradation, pairs, tokens and ingest lag. Raising 80→160 doubles the 40-QPS cap from 3,200→6,400 pairs/s; revert without evidence gains if the SLO fails. No live corpus, vendor retrieval or LLM benchmark is claimed.
