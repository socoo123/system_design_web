30 秒开场：先定答案的契约Opening: define the answer contract

中文

我设计闭库企业问答，语料是内部 wiki 与 PDF。Connector 把源版本和摄取任务写进 Catalog；Ingest 保留布局、切分、嵌入，等 Chunk Store 和两路 Hybrid Index 都可用才发布 current。在线 RAG 根据已验证身份绑定一份 query bundle，BM25 与稠密召回并行，用 RRF 合并，再对有界短名单 rerank。证据按 token 预算拼给现有推理服务，答案按句校验来源与支持关系后返回。删除先隐藏再清理，换 embedding 用新池回填和整份 bundle 切流。

先问七件事：文档类型、文档和权限变更频率、用户要完整答案还是第一句、来源是否必须可点击、租户与文档 ACL 是否都存在、中英术语是否很多、是否允许公网搜索。本章固定闭库，不靠联网填缺失证据；引用必须能点到本轮用过的原文版本。没有足够证据时允许说不知道，这是一项可测试的产品行为。

RAG 把外部检索证据和生成结合起来，原始论文展示了参数模型与非参数记忆的结合 [1]。本章的持久任务、权限复查和版本发布是工程设计，不能说成论文已经给出这些服务边界。生成的队列与 GPU 状态见 Ch29；本章把推理当服务调用，索引算法留给 Ch31。编排框架可以替换，服务责任仍须成立。

English

This closed-corpus enterprise Q&A service reads wiki and PDF revisions. Connector durably records revisions and jobs in Catalog. Ingest preserves layout, splits, and embeds; current publishes only after Chunk Store and both Hybrid Index lanes are ready. RAG authenticates, pins a query bundle, recalls lexical and dense evidence in parallel, fuses by RRF, and reranks a bounded shortlist. Evidence fits a token budget and goes to existing inference. Sentences pass source and support checks before release. Deletion hides first; embedding migration backfills another pool and switches the whole bundle.

Clarify document types, content and permission update rates, complete-answer versus first-sentence targets, clickable citations, tenant and document ACLs, terminology/languages, and public-web search. Here the corpus is closed, citations resolve to the exact used revision, and insufficient evidence permits an explicit refusal.

The original RAG paper combines parametric models and nonparametric retrieval memory [1]. Durable jobs, access checks, and version publication here are engineering design choices rather than services specified by that paper. Ch29 owns generation queues and GPU state; Ch31 opens the retrieval engine. Framework choice does not replace service ownership.

查询闭环：每个后端都回到 RAGQuery loop: each backend returns to RAG

中文

一条 POST /v1/rag/query 包含 question、客户端 request_id 和展示偏好。Gateway 解析身份、按租户限制并发与输入长度，把可信 principal 交给 RAG；tenant_id 和 groups 不从正文照抄。RAG 分配 trace_id，读 query bundle，保存本轮的模型、索引代次和配置版本。超长问题先拒绝，避免 embedding 服务和生成服务各自截断成不同问题。

第一组不是 Hybrid Index 把结果直接推给 Reranker，也不是 Reranker 把 prompt 交给 Inference。三次调用的 owner 都是 RAG：召回返回候选 ID，rerank 返回排序，生成返回 draft。这样取消、截止时间、证据映射和输出状态有同一归属。生成完成后沿 RAG → Gateway → Client 回程；如果网关已经关闭连接，RAG 取消下游，不再花算力生成无人读取的答案。

权限必须同时落在 BM25 与 Dense 两路，而且从可信身份构造过滤。Microsoft 的 security trimming 文档明确说，普通 principal 字符串比较本身不负责认证授权 [6]。这是索引表达范围的方法，认证和权威 ACL 校验仍由本设计承担。任一检索返回别的租户 ID，都在读原文之前丢弃并记录隔离错误；不会把它交给模型后再要求模型忽略。

A10 的路径预算按 30 + 60 + max(80, 100) + 40 + 250 + 20 = 500 ms 算。实际 BM25 可以在 query embedding 期间先启动，这里为易口算按等 embedding 后同时发两路估，属于保守条件预算。700 − 500 = 200 ms 给有界排队与补召回。它不是“各组件 p95 相加等于端到端 p95”，上线须按同一 trace 测首句、完整回答和失败比例。

检索或 Reranker 队列必须有长度与时间上限。预算已耗尽就不要启动生成；一条请求取消后，尚在队列里的 embedding、rerank 和生成工作都应带同一取消身份。检索失败只能在经过评测的降级路线内处理：稠密不可用时可用 BM25，rerank 超时时可用 RRF；证据和权限不足则返回拒答或服务错误，不能回到模型裸答当作成功。

English

The illustrative POST /v1/rag/query carries question, request ID, and display preferences. Gateway verifies identity, limits tenant concurrency and input length, and passes a trusted principal. RAG creates a trace, pins model/index/configuration, and rejects oversized questions before downstream services truncate differently.

RAG owns all three calls: retrieval returns candidate IDs, reranking returns order, and inference returns a draft. Cancellation, deadlines, evidence maps, and output share one owner. Released answers return RAG → Gateway → Client; a closed upstream connection cancels downstream work.

Both BM25 and Dense carry scope derived from trusted identity. Microsoft’s security-filter pattern performs string comparison rather than authentication/authorization [6]; this design supplies those responsibilities and authoritative ACL checks. Discard cross-tenant IDs before reading text or invoking the model.

A10 budgets 30 + 60 + max(80,100) + 40 + 250 + 20 = 500 ms. BM25 could start during query embedding; the illustration conservatively waits and then starts both lanes. The remaining 200 ms cover bounded queues/refill. This is not a sum of component p95s; measure first sentence, completion, and failures on end-to-end traces.

Bound queues by both count and deadline. Do not start generation after the preparation budget expires. Propagate cancellation to embedding, rerank, and inference. Tested degradation may use BM25 alone or RRF order; insufficient authorized evidence yields refusal/error rather than an ungrounded model answer.

估算：算尾块，也算每次查询的工作Estimate final chunks and work per query

中文

A1 总正文为 100,000 × 2,000 = 200,000,000 token。但每篇文档都要收一个尾块，不能把所有正文连起来除步长。若长度 L ≤ 512 就一块，否则 1 + ceil((L − 512) / 448)。2,000-token 示例得到 5 块，起点依次 0、448、896、1,344、1,792，最后一块只有 208 token。10 万篇 × 5 = 50 万块；结构切分、标题重复与短文分布会改变这个数，真实容量要从 manifest 汇总。

每篇实际嵌入的正文是 4 × 512 + 208 = 2,256 token，比 2,000 多 256，即 12.8%；overlap 比例 64/512 = 12.5% 和语料膨胀比例不是同一个分母。全量示例嵌入 2.256 亿 token，标题、提示前缀和失败重试还没算。每日变更 1,000 篇，生成 5,000 新块、嵌入 225.6 万 token；若不清旧版本，索引会每天继续涨，不是每天只覆盖 1%。

A3 的向量体积是 500,000 × 768 × 4 = 1,536,000,000 B = 1.536 GB ≈ 1.431 GiB。这里 GB 用十进制，GiB 用 230。两份副本是 3.072 GB；迁移双池且每池两份是 6.144 GB 裸向量。原文跨度、BM25 倒排、ANN 结构、元数据和暂存空间另外清点，不能给全部存储套一个没有出处的“乘 1.5”。float16 只把元素字节减半，检索质量是否接受仍要测。

峰值 rerank 是 40 × 80 = 3,200 query–chunk pairs/s；若每次对全库算，就是 40 × 500,000 = 20,000,000 pairs/s，相差 6,250 倍。这个算式只证明工作减少，不证明单 GPU 做得完。生成输入上限 5,120 token，峰值为 204,800 输入 token/s；输出上限 512，满额时是 20,480 输出 token/s。平均输出与达标吞吐要交给 Ch29 的压测，不能从“40 QPS 很小”推出生成便宜。

选型也不能靠“百万条”硬分界。业务元数据和向量同库能降低事务协调，但 ANN 过滤、更新频率、租户选择性和延迟目标仍可能成为瓶颈 [5]。专用引擎方便独立扩展，代价是两个存储的版本与删除协调。面试先用上述工作量、过滤条件和压测结果决定服务边界；这里不报随时间变化的 API 价格，也不把摄取一次性的账单和每日查询账单混在一起。

English

A1 holds 200 million source tokens, but every document has its own final chunk. Use one chunk for L ≤ 512, otherwise 1 + ceil((L − 512)/448). The 2,000-token example yields five starts: 0,448,896,1344,1792; the final span contains 208 tokens. Thus 100,000 documents yield 500,000 chunks. Real structure, repeated headings, and length distributions require manifest counts.

Embedded text per document is 4 × 512 + 208 = 2,256 tokens, 12.8% above the original. This differs from the 12.5% overlap denominator. Full ingest uses 225.6 million illustrative tokens before headings, prefixes, or retries; daily change of 1,000 documents produces 5,000 chunks and 2.256 million tokens. Retained old versions add storage.

Raw vectors occupy 500,000 × 768 × 4 = 1,536,000,000 B = 1.536 GB ≈ 1.431 GiB. Two copies use 3.072 GB; two migration pools with two copies each use 6.144 GB. Account separately for text, inverted and ANN indexes, metadata, and staging. Float16 halves element bytes, while quality still needs evaluation.

Peak reranking is 3,200 pairs/s versus 20 million pairs/s over the whole corpus, a 6,250× work difference rather than a GPU capacity claim. At 40 requests/s, 5,120 input tokens imply at most 204,800 input tokens/s and 512 output tokens imply at most 20,480 output tokens/s. Benchmark means and SLO attainment separately in Ch29.

A million vectors is not a universal engine threshold. Colocated business metadata can simplify transactions, but filtering, update rates, tenant selectivity, and latency remain workload constraints [5]. Dedicated engines buy independent scaling and add version/delete coordination. Use measurements, not stale API prices or comparisons between one-time ingest and daily serving bills.

摄取：已接收、已写入、可搜索是三件事Ingest: accepted, written, and searchable differ

中文

Connector 读取源系统的一份 revision，保存 source locator、内容 hash、ACL version 和删除事件。Catalog 同事务写源版本状态与持久 job，提交后返回 accepted。任务可以直接由 Ingest 轮询领取，不必为这个量级另画一个 Queue。若后来换成消息队列，仍要由持久 job/outbox 驱动通知，不能“先回 202，再异步 enqueue”；那段进程崩溃会让用户等一个不存在的任务。

Ingest 领取 job 后保存 lease_epoch、重试次数与截止时间。写入采用 tenant/doc/revision/splitter/span 的稳定键，重复执行覆盖同一内容；内容不同而键相同属于错误。租约过期的 worker 仍可能写出 staging，因此发布 current 必须 CAS 源 revision 和有效租约代次。CAS 条件还包括文档未删除、源 revision 仍是待发布目标；tombstone 后旧 worker 只能留下不可见 staging。仅靠锁超时不能阻止旧进程恢复后把 rev6 写成最新，异步索引也不是能帮你拒绝所有陈旧写的权威存储。

新 revision 先写不可变 Chunk Store，再写 BM25 与 Dense 条目。manifest 列出预期 chunk_id、数量、内容 hash 和两路回执。引擎的写入成功可能还没对搜索可见，要定义 receipt 是已持久、已刷新可搜索，还是仅进入内部队列；若引擎没有对应屏障，就轮询查询 canary 和 manifest 对账。几条 canary 只能证明探针可见，不能替代全量条目核对。

只有预期条目全部可读、两路索引可见，才把 manifest 标 READY 并 CAS Catalog.current。Catalog 的 current 与 source job 完成状态在本库同事务更新；这是发布控制点，不是跨三个存储的原子提交。旧 rev7 在 rev8 准备时继续可用。正文 hash 未变化也不一定跳过任务：权限、source locator、切分配置变化分别维护，ACL 更新必须传播和立即约束查询。

索引尚有旧条目时，查询先做索引范围过滤，再在取原文时批量核对 Catalog.current；不匹配的条目不进入 rerank 与 prompt。若两路索引是最终一致，过滤旧条目可能让前 100 个候选不足，必须在预算内多取或返回“暂无足够证据”，不能承诺 READY 后每个查询副本立刻达到同一召回率。若要求查询看到全语料同一快照，需要整份索引代次与发布屏障，不能把单 doc 的 CAS 扩大解释。

故障时分别收尾：Chunk Store 成功但索引失败，重试索引且 current 不变；两路成功但发布前崩溃，重领读取 receipt 后再 CAS；发布成功而任务 ACK 丢失，重复处理读到既有结果。定期从源清单对 Catalog、manifest 和索引做差集，发现漏删、少块和孤儿 staging。清理旧原文还须等活跃请求引用与保留期限结束，不能把引用链接变成同名最新页。

English

Connector persists source locator, content hash, ACL revision, and deletes. Catalog commits source metadata and durable job together before accepted. Ingest can poll jobs at this scale. A future queue should be driven by durable jobs/outbox, avoiding acknowledgement-before-enqueue loss.

Leases carry epochs, retries, and deadlines. Stable tenant/document/revision/splitter/span keys make retries idempotent. An expired worker may still write staging, so publishing current CAS-checks both source revision and lease epoch. CAS also requires an undeleted document and the still-expected source revision. A tombstoned document admits only invisible stale staging, never publication. Lease expiry alone cannot fence stale workers in every external index.

Stage immutable text, then BM25 and dense entries. Manifest records expected IDs/counts/hashes and receipts. Distinguish durable write acknowledgement from search visibility. Use supported barriers or visibility probes plus full manifest reconciliation; a few canaries do not prove all entries ready.

Publish only after all expected entries are readable and both lanes searchable. Current and job completion update atomically within Catalog, without a cross-store atomic commit. Rev7 remains active during rev8 preparation. Unchanged text hash does not suppress ACL, locator, or splitter changes.

Scope-filter indexes and verify Catalog.current when fetching text. Discard inactive revisions before rerank/prompt. Eventual search visibility may reduce eligible candidates; bounded refill or insufficient-evidence behavior is required. Per-document CAS does not promise a corpus-wide snapshot. Such a requirement needs a complete index-generation publication barrier.

Retry partial indexing without changing current; recover receipts after prepublication crashes; return saved results after a lost job acknowledgement. Periodically reconcile source, Catalog, manifests, and indexes for missing chunks, deletes, and orphan staging. Retain exact old text while pinned requests and retention policy require it.

切分：检索单位、上下文和来源一起保留Chunking: retain retrieval units, context, and provenance

中文

Parser 先做版面提取，再切文本。PDF 要保留页码与文字坐标，移掉反复出现的页眉页脚，但不能把表格标题和单位删掉；OCR 不确定的文字带质量标记。wiki 保留标题层级、列表与链接。代码按符号和函数边界，表格带列名和相关行；一个只剩“12”的格子，即使 embedding 很相似，也不能证明某产品允许值就是 12。解析失真会同时污染 BM25、向量和来源展示。

先按段落、标题分，再在过长结构内递归按句和 token 缩小。A2 的 512/64 是演示参数，不是“2026 通用标准”。Microsoft 的当前指南同时列出 10–15% overlap 的固定切分例子，并在起始建议中用 512 token、25% overlap [2]；两者是不同实践建议。这里选择 12.5% 作为受控实验基线，比较零 overlap、更大 overlap 和结构切分，不能引用指南替自己宣布最优。

小块让相关信号集中，却可能丢掉标题、定义或前提；大块减少缺上下文，却把多个主题压进一个向量，并挤掉其他证据。overlap 能覆盖相邻边界，不能保证跨两页的关系都在一个块里；还会复制 token、造成多个近重复命中。评价要包含跨边界问题、表格问题和专有名词，不能只挑每段开头那种问题。

Chunk Store 保留 chunk_id、doc_id、source_revision、splitter_version、span offsets、heading、page、parent_id 与 ACL version。向量模型及 tokenizer/pooling 等坐标定义属于 query bundle。citation 显示 source locator 与精确跨度；用户点开时服务端重新鉴权，不能把旧 URL 当永久公开凭证。来源页面已经改版时，展示“用于回答的 rev7”，而不是让用户看到一篇内容不一致的 rev8。

父子块把小块检索与大段上下文分开。索引只放子块向量，命中后按 parent_id 批量读同版本父段。多个子块指向同父段只扩一次。父段权限按全部跨度复查；若一个大节混入另一权限区，不能用子块可见性推导整节可见。超出证据预算、版本已失效或父块不可读时退回子块，必要时拒答；不会用最新父段去拼旧 child。

本章允许普通结构块作为起点，不强制语义切分和父子块。语义边界检测增加离线模型工作，且会随模型变化，必须记录切分版本；父子块增加存储、回表和权限逻辑。选它们的理由应是黄金集里“相关子块已经命中但缺前提”的错误下降。若失败是根本没召回相关块，先改解析、召回和过滤，扩父块并不能补回一个从未出现的 ID。

English

Parser preserves layout before splitting. Keep PDF pages/coordinates, table headings/units, wiki heading paths, and code boundaries. Remove repeated headers carefully and flag uncertain OCR. Contextless table cells cannot establish a numeric claim; parsing errors contaminate all retrieval and citation layers.

Split by structure, then recursively bound oversized sections by sentences/tokens. A2 is illustrative rather than a universal current standard. Microsoft lists a 10–15% fixed-size overlap example and separately recommends 512 tokens with 25% starting overlap [2]. Our 12.5% baseline is a controlled experiment, compared against other settings.

Small chunks focus retrieval but can omit definitions or premises. Large chunks dilute relevance and consume evidence space. Overlap covers adjacent boundaries without guaranteeing distant relationships, and adds duplicates/tokens. Include boundary, table, and identifier questions in evaluation.

Hybrid：融合的是排名，rerank 有明确上限Hybrid: fuse ranks and bound reranking

中文

BM25 对错误码、名称和确切词串有用，但它不是精确短语过滤器；用户明确要引号内的短语时，还要使用引擎的短语条件。稠密模型补改写和跨语言，前提是模型确实覆盖本章的语言与领域。两路各取 100 是 A4，去重后最多 200，交给融合的是可访问且 active 的 chunk；重名不同版本不被视作同一证据。

RRF 不用原始分数相加，公式为 score(d) = Σ 1 / (k + rank_i(d))，排名从 1 起，某路缺席贡献 0。Elastic 官方实现的 rank_constant 默认 60 [3]，本章沿用当起点。第一路第 1、第二路第 10 的 A 得 0.03068；两路都第 5 的 B 得 0.03077，B 略前。常数影响后排的贡献，融合窗口也会限制可能入选的集合，增大窗口不等于无成本提高质量。

不能把“BM25 和余弦量纲不同”说成永远不能线性融合。未经校准的裸加不成立；有标注集时可以做标准化、权重学习或其他融合，与 RRF 在独立集上比较。RRF 的代价是丢弃分数差距，而且无法救回两路都漏掉的段落。图上的默认选择是一个稳健的起点，结论靠评测，而不是算法名字本身。

带过滤不保证内部 pre-filter。pgvector v0.8.0 原文说明近似索引扫描后执行过滤，可能不足目标条数，iterative scans 会继续扫描直到够数或触及上限 [5]。所以“WHERE tenant_id”并不自动带来足量召回。租户只占少量数据时，可考虑分区、局部索引或精确过滤后的检索，并分别测 Recall、扫描量和延迟；不能用放松 ACL 来凑齐 100 条。

Reranker 将 question 与候选文本联合打分，先召回再对短名单处理是 Sentence Transformers 展示的用法 [4]。候选必须已经通过权限与版本校验，模型服务本身也是受信数据处理边界。限制 pair 数、单段长度和批等待，超过截止时间取消并使用已评测的 RRF 顺序；降级比例要计入质量报表，不混进正常 rerank 的指标掩盖。

最后按证据跨度去重与 token 总数取至多 8 块。A5 的 4,096 + 1,024 = 5,120 输入，再留 512 输出，需要至少 5,632 上下文；实际模型 tokenization 不一致时按生成模型重新数。重要证据排序和长上下文利用需要实验，Lost in the Middle 展示过位置改变对所测模型的影响 [9]，不能据此断言所有新模型都只能看开头结尾。增加上下文仍需看支持率与成本是否改善。

English

BM25 supports codes and literal terms but does not replace explicit phrase constraints. Dense retrieval supports paraphrases/languages when the chosen model covers them. Each A4 lane returns 100; up to 200 unique eligible active chunks enter fusion. Distinct revisions are not identical evidence.

RRF uses Σ 1/(k + rank_i(d)), ranks starting at one and zero contribution for a missing lane. Elastic defaults rank_constant to 60 [3]. A at ranks 1/10 scores 0.03068; B at 5/5 scores 0.03077. The constant and retrieval windows affect lower-ranked influence and eligible recall.

Uncalibrated raw-score addition is unjustified, but normalized/learned weighted fusion can be evaluated on held-out labels. RRF discards score margins and cannot recover chunks missed by both lanes. The chosen default remains a measured starting point.

Filtering does not imply internal prefiltering. pgvector v0.8.0 applies filtering after approximate index scans; iterative scans continue until enough results or a scan cap [5]. Measure filtered recall and latency, considering partitioning, partial indexes, or exact filtered search without weakening access.

Sentence Transformers demonstrates retrieving before cross-encoder reranking [4]. Apply it only to authorized, active candidates, and bound pair count, span length, and batch wait. Cancel at deadline and use a tested RRF fallback, reporting degradation separately.

Deduplicate spans and choose at most eight within 4,096 evidence tokens. Adding 1,024 other input and 512 reserved output requires at least 5,632 context tokens; recount with the generation tokenizer. Lost in the Middle studied position sensitivity in tested models [9], not a universal law for all newer models. Evaluate evidence ordering, support, and cost.

中文

Evidence Pack 是去重、授权、版本检查与预算裁剪之后，实际放入 prompt 的内容。保存本轮 ID → doc/revision/span 的映射，例如 1..8；召回过但没放进 prompt 的第 9 块不能引用。每块用明确的数据边界隔开，指令要求根据材料作答且不执行材料中的命令，遇到冲突来源注明冲突。只加一行“请引用来源”不能让这些身份约束自动成立。

检索文字里出现“忽略此前命令”“发送秘密”属于文档攻击风险，Microsoft 的 Prompt Shields 文档专门区分文档攻击 [10]。这里把材料作为数据，限制 prompt 边界，保留源信任和异常记录；闭库问答不授予生成器外部工具权限。过滤、提示分隔和检测都有局限，测试集中要含恶意材料，不把一个检测通过标志当作材料已可信的证明。

用户点来源时重新鉴权并读取精确版本，删除后可以返回“来源已撤销”，不能绕过 tombstone 展示保留的旧原文。回答日志只记必要的 request 身份、配置版本、选中证据标识、拒答原因与时延；敏感原文和答案按访问权限与保留政策管理。追溯需要的是可重建当时决策的记录，不是把所有租户内容复制进一个公开调试页面。

评测：先定位哪一层掉了证据Evaluation: locate the layer that lost evidence

中文

A11 的 200 个问题都带 principal、固定源快照、标注相关跨度与可接受答案；按错误码、改写、中英跨语言、表格、跨段、冲突材料、无答案和权限变化分层。修改切分后 chunk_id 变了，人标以 doc/revision/span 保存，再映射新块，不然“旧 chunk id 没命中”只是标注过期。调参集和回归集分开，模型、配置、裁判版本以及人工抽查规则一起记录。

为什么不先只做向量？可以把纯向量当实验基线，但本题有错误码、术语与中英改写，需要比较互补两路。增加 BM25 的代价是倒排存储、过滤一致性与删除协调；若黄金集证明单路已经达标，可以少一条路，而不是用“主流”两个字代替论证。

文档更新后为什么仍看到旧内容？区分源更新尚未摄取、索引写入尚未可查、current 尚未发布、活跃查询已经 pin 的证据。查 trace 的 doc/revision、manifest 状态与源版本，不能只刷新浏览器。如果产品要求每个回答使用回答开始时的最新文档，就在取证时按 current；如果要回答整个过程中绝不变旧，就必须定义版本变化时取消或重检索，增加时延和重试。

Rerank 贵怎么办？先看 3,200 对/秒和候选长度、模型批形状及排队，实验减少候选、更小判断模型或回退 RRF。它不能修复召回遗漏；若相关段落从未进名单，投入更贵 rerank 只是更仔细地给错误候选排序。拒答率与支持率也要一起看，不能只靠少发答案提高“准确率”。

最后 20 秒收尾：摄取先持久接收，再 staging、两路可查、CAS 发布；查询由 RAG 拿身份与 bundle，hybrid、RRF、有界 rerank、Evidence Pack、校验释放，回程经过网关。失败不靠裸答补洞，删除先 deny 后 purge，模型改版用双池加整份配置切流。合上页重新画出两条闭环，再用第三组解释小块和父块、第五组解释真编号为什么仍可能不支持答案。

English

Pure dense retrieval is a valid experimental baseline. This workload motivates testing complementary lexical and multilingual semantic lanes; BM25 costs storage, consistent filtering, and delete coordination. Remove it if labeled evidence supports a simpler design.

Staleness may occur before ingest, search visibility, current publication, or in already pinned evidence. Inspect doc/revision, manifest, and source state. “Latest at evidence fetch” differs from “never becomes stale during an answer”; the latter needs cancellation/retrieval on version change.

For costly reranking, measure 3,200 pairs/s, lengths, batch shapes, and queues. Test smaller candidate caps/models or RRF fallback. Expensive reranking cannot recover omitted evidence; evaluate refusals and support together rather than increasing accuracy by answering fewer queries.

Close with durable acceptance, staged readiness, and CAS publication; RAG-owned authenticated hybrid/RRF/rerank/evidence/validated release with Gateway returns. Refuse missing evidence, deny before purge, and migrate complete bundles across current dual pools. Redraw both loops, then explain parent access and why valid IDs can still cite unsupported claims.
