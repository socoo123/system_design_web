30 秒开场与边界The 30-second open and scope

中文

两个 endpoint：POST /v1/links 创建短码，GET /{code} 跳转。读远多于写。我先画 create 与 redirect 的高层路径，再深入三件事：短码分配、热点缓存、失败时如何降级。默认返回 302，并显式控制缓存；统计事件异步出关键路径。

先假设支持过期、撤销、自定义 alias 和点击统计；custom domain、全球多活与完整风控平台不在第一版范围。短码是定位符，不是访问控制。

English

Two endpoints: POST /v1/links creates a code and GET /{code} redirects. Reads dominate writes. I will draw create and redirect first, then go deep on code allocation, hot-key caching, and failure behavior. The default is a 302 with explicit cache control; click events leave the critical path asynchronously.

Assume expiry, revocation, custom aliases, and click analytics. Custom domains, global active-active, and a full abuse platform are outside version one. A short code is a locator, not access control.

API、幂等与最小数据模型API, idempotency, and the minimum data model

中文

POST /v1/links 接受 long_url、可选 custom_alias 与 expires_at；header 带 Idempotency-Key。alias 已占用返回 409。GET /{code} 成功返回 302 Location；unknown 返回 404，expired / revoked 返回 410 或产品定义的安全页。

不要默认全局做 target_url → code 去重：同一落地页可能属于不同 owner、campaign、expiry。幂等按 owner + key 定界。

English

POST /v1/links accepts long_url, optional custom_alias and expires_at, plus an Idempotency-Key header. A taken alias returns 409. GET /{code} returns 302 Location; unknown is 404, while expired or revoked becomes 410 or a product safety page.

Do not globally deduplicate target_url → code. The same landing page can belong to different owners, campaigns, or expiries. Scope idempotency by owner and key.

Link(code PK, target_url, owner_id, status, created_at, expires_at, version)
Idempotency(owner_id, key, code, expires_at, PRIMARY KEY(owner_id, key))

写路径：唯一性落在条件写，不落在运气Write path: uniqueness comes from conditional writes, not luck

读路径：302、缓存与统计各走自己的线Read path: separate the 302, caching, and analytics lines

短码与 ID：把长度算出来Codes and IDs: derive the length

中文

6 位 base62 的空间是 568 亿。号段让多个实例拿到不重叠的小 ID，再做 base62。它紧凑且无碰撞，但顺序可枚举。需要不可预测时，可选择足够熵的随机 token 或对连续 ID 做可逆置换；代价是碰撞处理或密钥管理。

English

Six base62 characters give 56.8 billion values. Segments lease disjoint small IDs to instances before base62 encoding. This is compact and collision-free but enumerable. If unpredictability matters, use a sufficiently random token or a keyed permutation, accepting collision handling or key management.

热点缓存：挡住爆款，也挡住击穿Hot-key caching: absorb popularity and stampedes

失败与降级：读写故障域要分开Failure and degradation: isolate read and write domains

KV 的可用性与一致性 trade-off 可延伸阅读 Dynamo，但具体行为必须由本题语义决定。[8]Dynamo is useful background for availability/consistency trade-offs, but this service still needs explicit product semantics. [8]

安全与滥用：短码不是秘密Security and abuse: a short code is not a secret

收尾：三个 trade-off，不说“完美”Close with three trade-offs, not “perfect”

中文

trade-off面试口述
统计完整 vs 延迟 / 流量302 + no-store 保证每次回源；短 TTL 或 edge analytics 可换更低延迟，但统计语义会变
紧凑顺序码 vs 不可预测segment + base62 紧凑无碰撞但可枚举；随机 token 要足够熵与唯一约束
撤销新鲜度 vs redirect 可用性主动失效 + 短 TTL 缩小窗口；存储故障时是否读 stale 必须写成产品策略

最后 20 秒：create 用幂等键和条件写，redirect 用 Local LRU → Redis → Mapping Store，302 明确 no-store，点击事件异步。号段给小 ID，base62 固定宽度要 padding；Snowflake 不适合 6 位码。热点用 singleflight，故障按读写域降级。

English

Trade-offInterview line
Complete analytics vs latency / traffic302 plus no-store returns every click; short TTL or edge analytics lowers latency but changes counting semantics
Compact sequence vs unpredictabilitySegment plus base62 is compact and collision-free but enumerable; random tokens need entropy and uniqueness checks
Fresh revocation vs redirect availabilityInvalidation plus short TTL narrows the window; stale reads during store failure are a product decision

Final twenty seconds: create uses an idempotency key and conditional writes. Redirect uses Local LRU → Redis → Mapping Store, returns a 302 with no-store, and publishes clicks asynchronously. Segments produce small IDs; fixed-width base62 needs padding; Snowflake does not fit six characters. Singleflight protects hot keys, and failures degrade by read/write domain.
