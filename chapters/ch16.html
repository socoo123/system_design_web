设计评论系统 Design a comment system

主线约 40 分钟 · 前置：Ch03、Ch10 · 6 组、30 帧演进图 ~40 min core · after Ch03 and Ch10 · 6 decks, 30 evolution frames

三个决定：关系、可见性与接受语义Three decisions: relationships, visibility and acceptance

  • 存真关系，读有限切片：parent_id 保存直接父节点，root_id 支持每楼分页；20 楼各 3 条预览。
  • 游标只锚位置：公开正文依当前审核状态；历史公开的楼可留无正文容器，从未公开的评论不出现在公共列表。
  • 区分两种接受：正文和 outbox 同事务后回 202；点赞内存接受允许丢失，成员、计数和增量仍必须同原子边界。
  • Store real links, read bounded slices: parent_id stores direct parentage; root_id supports per-thread paging, with twenty roots and three previews each.
  • Cursors anchor position: bodies follow current moderation. Previously public roots can retain bodyless containers; never-public comments stay out of shared lists.
  • Separate acceptance contracts: commit body and outbox before 202. Memory-accepted likes may be lost, but membership, total and delta still change atomically.

30 秒开场与必要预算The 30-second open and useful budgets

我设计帖子评论：存任意深度的真实父子关系，界面只展示一级楼与摊平回复。按时间倒序，一级与每楼各用复合游标；正文先审后发，作者单独查 pending 状态。热点读走旁路缓存，故障时限制回源；撤回正文的服务端发送窗口目标为 5 秒。

范围不含关注图、推荐排序、跨地域双活。下面数字均为教学假设，需用完整页面请求压测；不是某个平台的生产能力。

Design comments under a post, storing arbitrary parent depth while rendering roots and flattened replies. Use newest-first composite cursors for roots and each thread. 16.1 · 读写主线：权威库决定正文16.1 · Main path: authority owns bodies

Edge 做令牌校验与入口配额；API 再鉴权帖子、校验长度和回复目标。每跳有截止时间，429 表示入口配额不足，503 表示无法安全完成。202 pending 只表示正文、请求回执和审核 outbox 已提交，不表示公开；提交超时是结果未知，重试原键与原意图找回同一 comment_id。

List cache 是旁路：命中由 API 返回，miss 由 API 查 Primary 并回填。正文切片键绑定 post、root 范围、排序、cursor、页大小与格式版本；每次命中仍鉴权。作者的待审正文、拒绝原因和用户是否已赞不进入共享缓存。计数批量补齐，避免每次点赞都重建整个列表。

Edge validates tokens and entry quotas; API authorizes the post and validates length and parent. Bound every hop. 429 means entry quota; 503 means safe completion is unavailable. 202 pending means body, receipt and moderation outbox committed, not public visibility. A commit timeout is unknown: replay the original key and intent to recover the same comment_id.

List cache is look-aside: API returns hits and queries Primary on misses. Body-slice keys bind post, root scope, order, cursor, page size and format version. Authorize even hits. Private pending bodies, rejection reasons and caller like membership never enter shared pages. Hydrate counts separately instead of invalidating a whole page for each like.

16.2 · 保存真关系，每楼独立限额16.2 · Real parentage, independent thread limits

comment(post_id,id,parent_id,root_id,author_id,body,status,version,ever_public,created_at)。一级 parent_id=NULL、root_id=id；回复的 root_id 从已鉴权父行继承，客户端不能指定归属。父、root 与排序字段创建后不可变，ID 不复用。同帖子复合外键 (post_id,parent_id)、(post_id,root_id) 防止跨帖挂接；外键不能代替检查父节点所属的 root。[7]

插入时校验目标当前 visible、所属 root 曾公开；同一帖子 guard 事务内创建、编辑、删除和审核串行，关系不会由并发改挂。图中 103 的 parent=101、root=100，显示“回复 @101”；目标后来被隐藏时只显示通用占位，不重新联出其作者、正文或引用摘要。邻接表不重写后代，但索引插入仍有成本。

comment(post_id,id,parent_id,root_id,author_id,body,status,version,ever_public,created_at). Roots have null parent_id and root_id=id. Derive a reply’s root from the authorized parent, never client input. Parentage and ordering fields are immutable; ids are never reused. Composite foreign keys (post_id,parent_id) and (post_id,root_id) reject cross-post links, but cannot prove parent/root agreement. [7]

Creation requires a visible target and a previously public root. Create, edit, delete and moderation share a post guard transaction. Reply 103 has parent=101 and root=100; if its target later disappears, show a generic placeholder without joining withdrawn author, body or quote data. Adjacency avoids descendant rewrites, not index-maintenance cost.

SQL：20 个容器，再对每个 root 取 3 条SQL: twenty containers, then three replies per root

下面是 PostgreSQL 18 教学 SQL，参数已鉴权并通过游标签名校验。先选 20 楼，再用 LATERAL 做每楼 LIMIT 3；一次往返仍含最多 20 次索引探测。全局 root_id IN (…) LIMIT 60 会让热楼独占。[2][3]

The PostgreSQL 18 teaching SQL assumes authorization and cursor validation. Choose twenty roots, then LATERAL LIMIT 3 for each: one round trip still contains up to twenty probes. Global IN (…) LIMIT 60 can give every slot to one thread. [2][3]

-- PostgreSQL 18 teaching query; authenticated public post, signed cursor.
CREATE INDEX root_page ON comment (post_id, created_at DESC, id DESC)
  WHERE parent_id IS NULL AND ever_public;
CREATE INDEX reply_page ON comment (post_id, root_id, created_at DESC, id DESC)
  WHERE parent_id IS NOT NULL AND status = 'visible';

WITH roots AS (
  SELECT id, created_at,
         CASE WHEN status = 'visible' THEN 'visible' ELSE 'unavailable' END AS public_state,
         CASE WHEN status = 'visible' THEN body END AS body,
         CASE WHEN status = 'visible' THEN author_id END AS author_id
  FROM comment
  WHERE post_id = :post AND parent_id IS NULL AND ever_public
    AND (created_at, id) < (:before_time, :before_id)
  ORDER BY created_at DESC, id DESC LIMIT 20
)
SELECT r.*, c.id AS reply_id, c.created_at AS reply_time,
       c.parent_id, c.body AS reply_body, c.author_id AS reply_author
FROM roots r
LEFT JOIN LATERAL (
  SELECT id, created_at, parent_id, body, author_id
  FROM comment
  WHERE post_id = :post AND root_id = r.id
    AND parent_id IS NOT NULL AND status = 'visible'
  ORDER BY created_at DESC, id DESC LIMIT 3
) c ON true
ORDER BY r.created_at DESC, r.id DESC, c.created_at DESC, c.id DESC;
-- First page omits the before predicate; never use a made-up max timestamp.
-- Group by r.id into <=20 containers and <=60 distinct preview bodies.
-- Never load quote/body/profile fields from a hidden reply target.
-- Each thread's continuation starts after its LAST PREVIEW, not its root.
SELECT id, parent_id, created_at, body, author_id FROM comment
WHERE post_id = :post AND root_id = :root AND parent_id IS NOT NULL
  AND status = 'visible' AND (created_at, id) < (:before_time, :before_id)
ORDER BY created_at DESC, id DESC LIMIT 20;

墓碑也必须进一级查询：ever_public 只在首次通过审核时置 true，之后不清除。曾公开的 root 当前不是 visible 时，只返回 unavailable、公共结构 ID 与原排序时间，不返回当前审核状态、body、作者或引用。从未公开的 pending/rejected/deleted root 完全不入公共页。已公开回复可留在旧楼容器下，删除不级联；编辑重审也隐藏新旧正文。

首屏最多 20 个楼容器、60 条回复，即至多 80 条正文，1 KB/条约 80 KB，包装另计。单楼 10 万回复的整树读取约 50–100 MB。展开游标接在该楼最后一条预览后，独立再取 20 条；满页可返回续游标，末尾允许多一次空查询。reply_count 是有去重的可见回复投影，不统计 pending，也不保证立即等于本页数量。

Root queries must include tombstones: ever_public becomes true on first approval and never resets. A previously public root that is no longer visible exposes only unavailable, public structural ids and its original ordering time, without current moderation state, body, author or quotes. Never-public roots stay out entirely. Public replies can remain under old containers; deletion does not cascade, and edits hide both old and new bodies during review.

The screen has at most twenty containers plus sixty replies, hence at most eighty bodies: roughly 80 KB at 1 KB each, before wrappers. Loading a 100,000-reply thread would cost 50–100 MB. Expansion starts after that thread’s last preview, with its own twenty-row page. Full pages may issue a cursor and require a final empty query. reply_count is a deduplicated visible-reply projection, excluding pending; it need not immediately equal page membership.

16.3 · 游标锚住位置，审核仍会改变集合16.3 · A cursor anchors position while visibility changes

排序统一为 (created_at,id) DESC，下一页严格使用 < (:time,:id)。只放时间会漏掉同时间评论。图中第一页 105/104/103，顶部插入 106 后 OFFSET 3 可能再给 103；复合锚点继续取 102/101/100。匹配部分 B-tree 能省去历史前缀跳过工作；仍需查真实计划、MVCC 扫描与尾延迟。[1][2]

签名载荷绑定 format,post,scope(root-or-id),order,limit,last(time,id),expires。验签、过期与上下文不符均拒绝；签名不能代替鉴权。一级只翻 ever_public 容器，楼内只翻当前 visible 回复；每次展开也确认该 root 属于帖子且曾公开。

Use (created_at,id) DESC and strictly seek below (:time,:id). Timestamp-only cursors skip ties. After page 105/104/103, a new 106 can cause OFFSET 3 to repeat 103, while the composite anchor continues to 102/101/100. Matching partial B-trees avoid positional prefix work, but actual plans, MVCC scans and tail latency still need measurement. [1][2]

Sign format, post, scope(root-or-id), order, limit, last(time,id) and expiry. Reject signature, expiry or context mismatches. Signing is not authorization. Root pages contain ever_public containers; thread pages contain current visible replies. Expansion also validates the root’s post and public history.

实时页不是快照：旧 pending 晚通过且位于已越过区间，下翻不会补回，刷新才发现。删除/编辑即时改变候选正文；Read Committed 的两次 SELECT 可见不同提交。[9] 稳定遍历可保存带版本 ID 结果集，热度排序也需 ranking_version；即便顺序冻结，撤回正文仍须过滤。

A live page is not a snapshot: a late approval above a passed anchor needs refresh. Deletion and editing change body membership; successive Read Committed SELECTs can observe different commits. [9] Stable traversal can retain versioned ids, and ranking needs ranking_version. Frozen order still must filter withdrawn bodies.

16.4 · 点赞：成员、总数和脏增量一起变16.4 · Likes: change membership, total and dirty delta together

接口表达目标状态，不直接 INCR。以下可执行 Lua 教学示例把一个评论的成员字段 u:user_id=0/1、total、delta 放在同一 hash，校验后只做一次 HSET。身份来自鉴权，不接受客户端冒用 user_id。连续重试同一目标不会再次计数；不同目标按服务端执行顺序生效，延迟旧 like 可以覆盖新 unlike。本章选择“最后收到的状态”，若要用户操作顺序，须另加持久的每用户版本与条件更新。

Lua 执行不穿插，但出错不提供 SQL 式回滚。先检查类型、数字范围和 ready；单次 HSET 避免先改成员再 INCR 的部分失败。[4] 一个 hash 自然同槽；拆多键时也必须同槽，单条热评仍集中到一个槽。[5]

Use desired state, not a direct INCR. This executable Lua teaching example stores u:user_id=0/1, total and delta in one comment hash, validates, then performs one HSET. User identity comes from authentication. Consecutive retries do not recount. Different targets follow execution order: a delayed old like can overwrite a later unlike. This chapter chooses last received state; operation-order semantics require durable per-user versions and conditional updates.

Lua prevents interleaving but does not provide SQL-style rollback. Validate types, numeric bounds and ready before one HSET, avoiding partial membership-then-INCR failure. [4] One hash naturally occupies one slot; multiple keys must share a slot too. A hot comment remains concentrated. [5]

-- Redis 7.2+ teaching example: one complete, non-expiring comment hash.
-- KEYS[1]=like:{comment:100}; ARGV=authenticated user id, desired 0/1.
local key, user, wanted = KEYS[1], ARGV[1], ARGV[2]
if not user or not string.match(user, '^%d+$') or
   (wanted ~= '0' and wanted ~= '1') then return redis.error_reply('INPUT') end
if redis.call('TYPE', key).ok ~= 'hash' then return redis.error_reply('NOT_READY') end
local v = redis.call('HMGET', key, 'ready', 'total', 'delta', 'u:' .. user)
local function integer(s)
  if not s or not string.match(s, '^%-?%d+$') then return nil end
  local n = tonumber(s)
  if not n or math.abs(n) > 1000000000000 then return nil end
  return n
end
local total, dirty = integer(v[2]), integer(v[3])
local old = v[4] or '0'
if v[1] ~= '1' or not total or total < 0 or not dirty or
   (old ~= '0' and old ~= '1') then return redis.error_reply('CORRUPT') end
local delta = tonumber(wanted) - tonumber(old)
local next_total, next_dirty = total + delta, dirty + delta
if next_total < 0 or next_total > 1000000000000 or
   math.abs(next_dirty) > 1000000000000 then return redis.error_reply('RANGE') end
if delta ~= 0 then
  -- One mutation: no member write followed by a possibly failing INCR.
  redis.call('HSET', key, 'u:' .. user, wanted,
             'total', string.format('%.0f', next_total),
             'delta', string.format('%.0f', next_dirty))
end
return {delta, next_total, next_dirty}

ready 仅在成员全集与 total 一致时设置；新评论可初始化全空。hash 不设置 TTL，不允许单独逐成员过期或逐键淘汰，保留 0 字段有空间代价。重启、故障切换或快照恢复后，入口恢复栅栏先暂停所有点赞写；即使旧 hash 仍有 ready=1，也不能直接恢复服务。键丢失、类型损坏或成员不完整时拒绝写，不能只用持久总数初始化一个空成员集合，否则旧用户重试又加一。

Set ready only with complete membership matching total; a fresh comment can start empty. Use no hash TTL, member expiry or independent key eviction; retained zero fields consume space. After restart, failover or snapshot restore, an entry recovery gate pauses all like writes, even if an old hash still says ready=1. Missing, corrupt or incomplete state refuses writes. Never combine a saved total with empty membership: returning users would be counted again.

冻结批次，再用唯一账本刷库Freeze a batch, then flush through a unique ledger

冻结操作在同一 hash 原子写 b:UUID=delta 并清当前 delta，新点赞继续累积；批次不可修改，UUID 永不复用；每条评论仅一批 in-flight，确认旧批后才冻结下一批，避免减量先于其加量入库。Counter flush 只重试同一 ID 与载荷，提交确认后才按 ID 清批。读 delta→刷库→清零会抹掉中途新点赞。下列 SQL 将唯一账本与加数放在同一事务；冲突后重新读并比较载荷，不能把同批号不同 delta 也当成功。[7]

Rotate atomically inside the hash: store b:UUID=delta and zero the current delta while new likes continue. Batches are immutable and ids never reused. Allow only one in-flight batch per comment; acknowledge it before rotating the next, so decrements cannot flush ahead of their increments. Flush retries identical id and payload; clear that exact batch only after commit ACK. Read/flush/zero erases intervening changes. The SQL commits the unique ledger and increment together, then rereads and compares payload after conflict. A reused id with changed delta is an error. [7]

-- PostgreSQL 18 teaching fragment: frozen batch from a trusted flusher.
-- Ledger PK=(comment_id,batch_id); payload stores immutable delta.
BEGIN;
WITH first_apply AS (
  INSERT INTO applied_like_batch(comment_id, batch_id, delta)
  VALUES (:comment, :batch, :delta)
  ON CONFLICT (comment_id, batch_id) DO NOTHING
  RETURNING delta
)
UPDATE like_count SET total = total + first_apply.delta
FROM first_apply WHERE like_count.comment_id = :comment;
-- Require a pre-existing count row; on missing row ROLLBACK, never ACK.
-- Read the ledger in a NEW statement (READ COMMITTED conflict may wait).
SELECT delta FROM applied_like_batch
WHERE comment_id = :comment AND batch_id = :batch;
-- Require stored delta = :delta; changed payload is an error, ROLLBACK.
COMMIT;
-- ACK only after commit. An unknown outcome retries this SAME id + delta.
-- Frozen bytes and ids survive flusher restart; ids never repeat.

接受不等于耐久：A8 允许内存成员与未刷批次丢失，10 秒只是正常刷周期；积压会扩大丢失窗口，副本/AOF 配置也会改变窗口。[10] 1,000 个脏评论每 10 秒刷一次，约 100 笔计数事务/s，并没有消灭 5,787/s 的成员更新。缓存丢失后展示最后持久计数并标滞后，暂停点赞写；没有耐久明细就无法精确恢复成员或重建总数。恢复栅栏属于部署契约，Lua 不实现检测或重建；没有明细时只能保持只读，或由产品明确开启新一代并清零计数/成员、隔离旧批次，不得自动续写。要求不丢时，先提交唯一成员事实与 outbox，再异步投影，接口接受点随之改变。

Accepted does not mean durable: A8 permits losing memory membership and unflushed batches. Ten seconds is a normal interval; backlog widens the loss window, while replication/AOF choices change it. [10] 1,000 dirty comments per ten seconds means about 100 count transactions/s, without removing 5,787/s membership updates. After state loss, show the persisted count as stale and pause writes. Without durable facts, exact membership and totals cannot be rebuilt. The recovery gate is a deployment contract; this Lua does not detect restarts or rebuild facts. Without facts, stay read-only or explicitly reset the product to a fresh generation with zero count/members and fenced old batches. Never resume automatically. Lossless acceptance requires durable unique membership plus outbox before asynchronous projection.

16.5 · 审核：先提交意图，再拒绝旧结果16.5 · Moderation: commit intent, then fence stale decisions

同一帖子分片的权威库保存 Comment、Receipt 与 Outbox，预建 post guard 行。创建/编辑/删除/审核先锁该行直到提交，明确串行边界；热门帖写会受限，拆锁或拆库须重新证明约束。请求回执唯一键为 (post_id,author_id,request_key)，意图含 post、parent、正文、附件与策略版本；同键换回复目标也拒绝。

以下是事务伪代码，不是完整后端。relay 只读已提交 outbox，获得队列持久接收后标 sent，回包丢失会重投。Worker 用被审版本、摘要与 pending 状态判定；可见性事件也与状态同事务，避免第二处双写。[6]

One post-shard authority stores Comment, Receipt and Outbox with a pre-created post guard. Create/edit/delete/moderation lock that row through commit: clear serialization, with a hot-post bottleneck. Finer locks or split stores require new proofs. Receipt uniqueness is (post_id,author_id,request_key); intent binds post, parent, body, attachments and policy version. Changing the target under the same key is rejected.

This is transaction pseudocode, not a complete backend. Relay polls committed outbox and marks sent after durable queue acceptance; lost replies can duplicate delivery. Worker matches reviewed version, digest and pending state. Visibility events commit with state too, avoiding another dual write. [6]

submit(auth, request_key, post, parent, body):
  intent = canonical(post, parent, body, attachments, policy_version)
  transaction on ONE post-shard authority:
    lock pre-created post guard; authorize(auth, post)
    old = receipt(post, auth.user, request_key)  # unique within this post
    if old: require old.intent == intent; return old.result
    target = resolve_parent_in_this_post(parent)
    require target is null OR (target.visible AND target.root.ever_public)
    comment_id = fresh_unique_id()  # never reused
    root = target.root_id if target else comment_id
    insert pending(comment_id, post, parent, root, body, digest(body), version=1)
    insert audit_outbox(comment_id, version=1, immutable_body_digest)
    insert receipt(post, auth.user, request_key, intent, comment_id)
  return 202 pending  # unknown commit: retry original key and intent

apply_decision(trusted_event, approved):
  transaction on the SAME authority:
    lock post guard  # edit/delete/approval all use this guard
    c = comment(trusted_event.post, trusted_event.comment)
    if c.version != trusted_event.version OR c.status != pending: return NOOP
    require c.body_digest == trusted_event.reviewed_digest
    c.status = visible if approved else rejected
    if approved: c.ever_public = true
    save(c)
    insert visibility_outbox(trusted_event.event_id, c.id, c.version, c.status)
  ACK event only after commit; duplicate decision sees non-pending -> NOOP
# Edit/delete increments content version, changes status, emits outbox together.
# Deleted: clear body, profile and quote payloads; retain structural ids only.
# Visibility-count consumers persist (event_id, effect) with increment together.

失败轨迹：approve(v8) 先到则公开 v8；之后 delete 提升为 deleted(v9) 并清正文。delete 先到则旧 approve 的条件不匹配，不复活、不重复增加可见回复数。重复 approve 因状态已不为 pending 而无操作；编辑先转 pending(v9)，旧版结果同样失效。可见回复投影消费事件须将唯一 event_id 与增减同事务。

A9 的 10×100=1,000/s 低于 1,157.407/s 峰值，十分钟积压 (1,157.407−1,000)×600≈94,444。20 个 Worker 可提供假设的 2,000/s，峰值利用约 57.9%。监控最老 pending、失败重试和 outbox 滞后；异常任务进可追踪失败状态。先发后审能降低等待，却引入违规曝光与撤回成本，必须另定产品策略。

Failure trace: if approve(v8) wins, it publishes before delete advances to deleted(v9) and clears the body. If delete wins, stale approval does not match: no revival or extra visible-reply increment. Duplicate approvals are no-ops after leaving pending. Editing advances to pending(v9), fencing old decisions too. Count consumers commit unique event_id and arithmetic together.

Ten workers at 100/s provide 1,000/s below the 1,157.407/s peak. Ten-minute backlog is (1,157.407−1,000)×600≈94,444. Twenty assumed workers provide 2,000/s at about 57.9% peak utilization. Monitor oldest pending, retry/failure state and outbox age. Post-publish moderation reduces waiting but adds exposure and withdrawal cost, requiring a different product policy.

16.6 · 缓存故障：配额、旧回填与撤回窗口16.6 · Cache failure: quotas, stale fills and withdrawal

整层故障时约 8,681 页/s 都想回源，预算 600，只靠库无法接住 14.47 倍流量，最坏约 8,081/s 拒绝并带 Retry-After。单飞合并同键，不同 cursor 仍消耗全局配额。跨实例租约需代际 token；失效在缓存侧原子换 token 并删页，fill 也原子核对 token 与写入，不能先检查后另发 SET。论文租约支持此机制，不支持本章容量目标。[8]

仅删 key 仍会复活：v8 慢查询→删除提交 v9→删缓存→v8 迟到回填。token 拒绝旧 fill，但失效也可能延迟，所以正文还要绝对 not_after。时间从新权威查询开始前起算，不能在旧事务/滞后副本内读，也不能在迟到回填时重置 TTL。

Whole-cache failure sends about 8,681 pages/s toward a 600 budget, 14.47× capacity; worst-case excess of about 8,081/s is refused with Retry-After. Coalescing merges one key; different cursors still consume global quota. Cross-instance leases need generation tokens. Cache-side invalidation rotates token and deletes atomically; fill also checks and writes atomically, never check then separate SET. The lease paper supports this mechanism, not our capacity targets. [8]

Deleting a key can revive content: slow v8 query → deletion commits v9 → cache deletion → delayed v8 fill. Tokens fence that fill, but delayed invalidation also requires absolute not_after. Start time before a fresh authority query, excluding old transactions and lagging replicas. Late fill must not restart TTL.

public_page(auth, query):
  authorize_post(auth, query.post)  # also required on a cache hit
  ctx = validate_signed_cursor(query)  # post, scope, order, limit, expiry
  key = body_slice_key(ctx)  # excludes pending/private author state
  hit = cache.get(key)
  if hit and safe_to_send(hit.not_after): return public_projection(hit)
  lease = cache.try_lease(key)  # OWNER(token), BUSY, or CACHE_UNAVAILABLE
  if lease == BUSY:
    page = cache.wait_for_fill(key, bounded_deadline)
    return public_projection(page) if page and safe_to_send(page.not_after) else 503
  # Only OWNER or unavailable-cache bypass can consume an origin-page permit.
  if not global_origin_quota.try_acquire():
    if lease is OWNER: cache.release_if_current(key, lease.token)
    return 503 Retry-After
  started = clock.now()
  not_after = started + (5 seconds - clock_error_and_send_margin)
  page = authority.fresh_statement_query(ctx)  # no older transaction/replica
  if not safe_to_send(not_after): return 503  # never restart the 5 seconds
  if lease is OWNER:
    cache.fill_if_current(key, lease.token, page, not_after)
    # ONE cache-side atomic check+write; invalidation rotates/revokes token.
  return public_projection(page) if safe_to_send(not_after) else 503

invalidate(committed_visibility_event):
  cache.rotate_token_and_delete(affected_key)  # atomic, repeated is safe
# Fill rejection may still return a pre-delete snapshot inside its 5 s bound.
# Lease loss/restart never resets not_after. An unavailable authority fails closed.
# Requires bounded clock error/output delay; already sent copies cannot be recalled.

safe_to_send 在返回前比较当前时间、not_after 与已知输出余量，预留跨机时钟误差；不满足就 503。5 秒是健康时钟/预算契约下，服务端最后允许发送旧正文的目标，不是客户端离线副本删除保证，也不是本轮实测 SLO。失效成功会更早收敛，失效延迟仍不许旧值续命。权限每请求检查；点赞数字可以滞后，过期正文不能作为陈旧兜底。

按 post_id 分片可让树、回执和审核事务局部化，不能消除热帖写热点。极热帖若拆到楼级，会引入楼路由和一级合并；小规模可先不缓存，证明完整页预算够再加。每次替代都应重算事务边界与失败结果。

safe_to_send checks time, not_after and a known send margin before returning, with cross-machine clock error reserved. Otherwise return 503. Five seconds is the target last server send of stale bodies under those clock/budget contracts, not removal of offline client copies or a measured SLO. Timely invalidation converges earlier; delayed invalidation still cannot renew old data. Authorize each request. Counts may lag; expired bodies cannot be stale fallback.

Post sharding localizes trees, receipts and moderation transactions without removing hot-post writes. Thread sharding adds routing and root merge. Small installations may omit cache after validating complete page capacity. Re-evaluate transaction boundaries and failure behavior with each alternative.

复盘：沿一条路径讲完边界Recap: explain one path and its limits

一页 20 楼，每楼 3 条；复合 cursor 分别续根页和楼内页。真实 parent/root 不变，曾公开的楼保留脱敏容器，当前正文只在 visible 时出现。正文与 outbox 提交后 202，审核版本条件更新拒绝旧结果。点赞同 hash 原子更新，冻结批次与唯一账本防重复刷库；成员丢失就暂停，不能从整数恢复集合。缓存命中仍鉴权，回源有配额，正文有效期不因迟到回填延长。

Twenty roots and three previews each, with separate composite continuations. Immutable parent/root links preserve structure; previously public roots retain sanitized containers while only visible bodies appear. Commit body and outbox before 202; versioned moderation rejects stale results. Likes update one hash atomically; frozen batches and a unique ledger prevent repeated flushes. Lost membership pauses writes; an integer cannot restore a set. Authorize cache hits, cap origin and never renew body validity on late fill.
